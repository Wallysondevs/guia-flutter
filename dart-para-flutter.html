O Dart que Você Precisa

Um app Flutter é um programa Dart. Não existe uma "linguagem do Flutter": as telas, os botões e as regras do app são classes, funções e listas de Dart. Esta aula é uma revisão dirigida: só os pedaços do Dart que aparecem em todo app Flutter, cada um mostrado primeiro em Dart puro e depois no lugar em que você vai encontrá-lo no Flutter. Se algum deles for novidade, a aula indica onde estudar no Guia Dart.

Você vai aprender (ou relembrar)
  • Classes com parâmetros nomeados, required e valor padrão: o jeito como todo widget recebe as opções.
  • final e const, e por que o Flutter gosta tanto de const.
  • Null safety: o ? no tipo, o ?? e o ?..
  • Funções anônimas e a seta =>: o que vai no onPressed de um botão.
  • Listas com if, for e ... dentro dos colchetes: o jeito de montar os children.
  • extends, @override e super.key: a primeira linha de todo widget.
  • async/await, para quando o app espera alguma coisa.
  • Os erros de compilação mais comuns nesses pontos, com a mensagem real.

Os programas de Dart puro desta aula foram rodados com dart run na máquina da Ana, com o Dart 3.13.5, a mesma versão que vem dentro do Flutter do guia (o Flutter traz o Dart junto: aula Instalar o Flutter).

A ideia: a ficha de pedido

Na lanchonete, o pedido é uma ficha com campos: lanche, bebida, observação. Alguns campos são obrigatórios (sem lanche, não tem pedido), outros têm um valor que vale se ninguém escrever nada ("bebida: nenhuma"), e a observação pode ficar em branco.

Um widget do Flutter funciona igualzinho. Quando você escreve Text('Oi', style: ..., maxLines: 2), está preenchendo a ficha do Text: o texto é obrigatório, o resto é opcional e tem padrão. Os pedaços de Dart desta aula são justamente as regras dessa ficha.

1. Classes com parâmetros nomeados

A Ana quer guardar as receitas do app. Cada receita tem um nome, o tempo de preparo e se é doce:

class Receita {
  final String nome;
  final int minutos;
  final bool doce;

  const Receita({required this.nome, required this.minutos, this.doce = true});

  @override
  String toString() => '$nome ($minutos min)';
}

void main() {
  const bolo = Receita(nome: 'Bolo de cenoura', minutos: 50);
  final pao = Receita(minutos: 20, nome: 'Pão de queijo', doce: false);
  print(bolo);
  print(pao);
  print(bolo.doce);
  print(pao.doce);
}

$ dart run receita.dart
Bolo de cenoura (50 min)
Pão de queijo (20 min)
true
false
final String nome;
Um campo que recebe valor uma vez, no construtor, e nunca mais muda. Nos widgets, todos os campos são final.
{ ... }
As chaves em volta dos parâmetros do construtor os tornam nomeados: quem cria a receita escreve o nome de cada um (nome: ...) e pode passá-los em qualquer ordem. Repare que o pao passou minutos antes de nome.
required this.nome
required torna o parâmetro obrigatório. O this.nome guarda o valor direto no campo nome, sem precisar de corpo no construtor.
this.doce = true
Um parâmetro opcional com valor padrão. O bolo não disse nada sobre doce e ficou com true.
const Receita(...)
Um construtor const: permite criar receitas constantes, prontas na hora da compilação (seção 2).
@override String toString()
Troca o texto que o print mostra para um objeto. A seta => é o atalho de uma função de uma linha só (seção 4).

No Flutter, é exatamente assim que você usa os widgets prontos. O Text tem um parâmetro posicional (o texto) e vários nomeados opcionais; o Padding tem um nomeado obrigatório (padding) e o child opcional:

Padding(
  padding: const EdgeInsets.all(16),   // required
  child: Text(                         // opcional
    'Bolo de cenoura',                 // posicional
    maxLines: 1,                       // nomeado, opcional
  ),
)
A vírgula do fim

Repare na vírgula depois do último parâmetro (maxLines: 1,). O Dart aceita essa "vírgula sobrando", e no Flutter ela é costume: com ela, o formatador (dart format) põe cada parâmetro numa linha, e a árvore de widgets fica fácil de ler.

2. final × const

As duas palavras dizem "isto não muda", mas em momentos diferentes:

final
O valor é decidido quando o programa roda e depois fica travado. Serve para qualquer valor, até para um que vem da internet.
const
O valor é decidido na compilação, antes de o programa rodar. Só vale para coisas que o compilador já sabe: números, textos escritos no código, e objetos com construtor const cujos parâmetros também são constantes.

Tentar trocar um final nem compila:

void main() {
  final nome = 'Bolo de cenoura';
  nome = 'Bolo de fubá';
  print(nome);
}

$ dart run final-erro.dart
final-erro.dart:3:3: Error: Can't assign to the final variable 'nome'.
  nome = 'Bolo de fubá';
  ^^^^

"Não dá para atribuir à variável final nome". O 3:3 é linha 3, coluna 3, e os ^^^^ apontam o nome que foi alterado. Como é erro de compilação, nada roda.

No Flutter, const aparece o tempo todo: const Text('Oi'), const EdgeInsets.all(16), const MeuApp(). Um widget const é criado uma vez só, e o Flutter sabe que ele nunca muda; quando a tela é redesenhada, ele pula esse pedaço. É uma economia de graça.

3. Null safety: ?, ?? e ?.

No Dart, uma variável String nunca é null. Para aceitar "nada", o tipo ganha um ?:

void main() {
  String? dica;
  print(dica);
  print(dica ?? 'sem dica');
  print(dica?.length);
  dica = 'Use cenoura bem fresca';
  print(dica.length);
}

$ dart run nulo.dart
null
sem dica
null
22
String? dica;
Uma String que pode ser null. Sem valor inicial, começa com null.
dica ?? 'sem dica'
"Se dica for null, use 'sem dica'". Muito usado para mostrar um texto padrão na tela.
dica?.length
"Se dica não for null, pegue o tamanho; se for, o resultado é null", sem dar erro.
dica.length
Depois de dica receber um texto, o Dart sabe que ela não é mais null e deixa usar .length direto (a frase tem 22 caracteres).

Pôr null numa String sem ? é recusado na compilação:

$ dart run nulo-erro.dart
nulo-erro.dart:2:17: Error: A value of type 'Null' can't be assigned to a variable of type 'String'.
  String dica = null;
                ^

No Flutter, os parâmetros opcionais dos widgets são quase todos tipos com ?: o appBar de um Scaffold é um PreferredSizeWidget? (pode não ter barra), o onPressed de um botão é um VoidCallback? (com null, o botão fica desativado, cinza: aula Botões).

4. Funções anônimas e a seta =>

No Dart, uma função é um valor como outro qualquer: dá para guardá-la numa variável e passá-la para outra função. É assim que um botão sabe o que fazer quando for tocado:

void quandoTocar(String nome, void Function() acao) {
  print('Tocou em $nome');
  acao();
}

int dobro(int n) => n * 2;

void main() {
  quandoTocar('Salvar', () {
    print('Receita salva!');
  });
  quandoTocar('Apagar', () => print('Receita apagada!'));
  print(dobro(21));
}

$ dart run funcoes.dart
Tocou em Salvar
Receita salva!
Tocou em Apagar
Receita apagada!
42
void Function() acao
Um parâmetro cujo tipo é "uma função sem parâmetros que não devolve nada". No Flutter, esse tipo tem um apelido: VoidCallback.
() { ... }
Uma função anônima (sem nome), escrita ali mesmo, na chamada. Os parênteses vazios dizem que ela não recebe nada.
() => print(...)
A mesma coisa, com a seta: => x é o atalho de { return x; }. Use quando a função cabe numa expressão só.
int dobro(int n) => n * 2;
A seta também vale para funções com nome.

No Flutter, você escreve funções anônimas em todo botão:

ElevatedButton(
  onPressed: () {
    print('Receita salva!');
  },
  child: const Text('Salvar'),
)

Um erro clássico é chamar a função em vez de passá-la: onPressed: salvar() roda o salvar na hora de montar a tela (e entrega o resultado, não a função). O certo é onPressed: salvar, sem parênteses, ou onPressed: () => salvar().

5. Listas com if, for e ...

Dentro dos colchetes de uma lista, o Dart aceita um if (o item só entra se a condição for verdadeira), um for (gera vários itens) e o ... (o spread, "espalhar": despeja os itens de outra lista):

void main() {
  final temCalda = true;
  final ingredientes = [
    'cenoura',
    'ovos',
    'açúcar',
    if (temCalda) 'chocolate',
    for (final n in [1, 2]) 'passo $n',
  ];
  print(ingredientes);

  final extras = ['fermento', 'óleo'];
  final todos = [...ingredientes, ...extras];
  print(todos.length);

  final itens = ingredientes.map((i) => '- $i').toList();
  print(itens);
}

$ dart run listas.dart
[cenoura, ovos, açúcar, chocolate, passo 1, passo 2]
8
[- cenoura, - ovos, - açúcar, - chocolate, - passo 1, - passo 2]
if (temCalda) 'chocolate'
Um if de coleção: sem chaves e sem ;. Com temCalda falso, o item simplesmente não entraria.
for (final n in [1, 2]) 'passo $n'
Um for de coleção: gerou dois itens.
[...ingredientes, ...extras]
Junta as duas listas numa nova: 6 + 2 = 8 itens.
.map((i) => '- $i').toList()
Transforma cada item com uma função anônima e volta a fazer uma lista.

No Flutter, essa é a forma de montar os children de uma Column:

Column(
  children: [
    const Text('Bolo de cenoura'),
    if (temCalda) const Text('com calda de chocolate'),
    for (final i in ingredientes) Text('- $i'),
  ],
)

6. extends, @override e super.key

Todo widget que você cria é uma classe que estende (herda de) um widget do Flutter. Este exemplo de Dart puro imita o formato, com uma classe Peca no papel do widget:

class Peca {
  final String? chave;
  const Peca({this.chave});

  String desenhar() => 'uma peça';
}

class Titulo extends Peca {
  final String texto;
  const Titulo(this.texto, {super.chave});

  @override
  String desenhar() => 'o título "$texto"';
}

void main() {
  const t = Titulo('Receitas da Ana', chave: 'topo');
  print(t.desenhar());
  print(t.chave);
  print(t is Peca);
}

$ dart run heranca.dart
o título "Receitas da Ana"
topo
true
class Titulo extends Peca
Titulo herda tudo de Peca e é uma Peca (o t is Peca deu true).
{super.chave}
Um super parâmetro: recebe o chave e o repassa direto ao construtor da classe-mãe. É o atalho de {String? chave}) : super(chave: chave).
@override
Avisa que desenhar substitui o método de mesmo nome da classe-mãe. Se você errar o nome, o analisador reclama.

No Flutter, a mesma forma aparece no começo de todo widget seu. Compare linha por linha:

class Titulo extends StatelessWidget {
  final String texto;
  const Titulo(this.texto, {super.key});

  @override
  Widget build(BuildContext context) {
    return Text(texto);
  }
}

O super.key repassa a key (uma etiqueta opcional que identifica o widget: aula Keys) para o StatelessWidget, e o build com @override é o método que o Flutter chama para saber o que desenhar (aula StatelessWidget).

7. async e await

Buscar uma receita na internet ou ler um arquivo demora. Uma função async devolve um Future (uma "promessa" de valor), e o await espera o valor chegar sem travar o resto do programa:

Future<String> buscarReceita() async {
  await Future.delayed(const Duration(seconds: 1));
  return 'Bolo de cenoura';
}

void main() async {
  print('Buscando...');
  final r = await buscarReceita();
  print('Chegou: $r');
}

$ dart run espera.dart
Buscando...
Chegou: Bolo de cenoura   « um segundo depois

No Flutter, você vai usar isso nas aulas de internet e dados (FutureBuilder, http). Por enquanto, basta reconhecer o formato.

Quando dá errado

Esqueceu um parâmetro required 
class Receita {
  final String nome;
  final int minutos;

  const Receita({required this.nome, required this.minutos});
}

void main() {
  const bolo = Receita(nome: 'Bolo de cenoura');
  print(bolo.nome);
}

$ dart run faltou.dart
faltou.dart:9:23: Error: Required named parameter 'minutos' must be provided.
  const bolo = Receita(nome: 'Bolo de cenoura');
                      ^
faltou.dart:5:9: Context: Found this candidate, but the arguments don't match.
  const Receita({required this.nome, required this.minutos});
        ^^^^^^^

É o erro que você mais vai ver no começo do Flutter (é o que aparece, por exemplo, num Padding sem o padding). Linha por linha:

faltou.dart:9:23:
Arquivo, linha 9, coluna 23: o parêntese que abre a chamada.
Error: Required named parameter 'minutos' must be provided.
"O parâmetro nomeado obrigatório minutos precisa ser informado."
a linha de código e o ^
A linha copiada do seu arquivo, com o ^ embaixo do ponto do problema.
Context: Found this candidate, but the arguments don't match.
Uma "dica de contexto": "encontrei este construtor, mas os argumentos não batem". Ela mostra a linha 5, onde o construtor foi declarado, com ^^^^^^^ embaixo do nome. É ali que você confere quais parâmetros ele exige.

Como consertar: passe o que falta, Receita(nome: 'Bolo de cenoura', minutos: 50).

null onde não cabe

A mensagem A value of type 'Null' can't be assigned to a variable of type 'String' (seção 3) quer dizer: o tipo não tem ?, então null não entra. Como consertar: dê um valor de verdade ou, se "nada" fizer sentido ali, mude o tipo para String?.

Mudar um final

Can't assign to the final variable 'nome' (seção 2). Como consertar: se o valor precisa mudar, use var. Num widget, porém, os campos ficam final: o que muda na tela mora no estado, e isso é assunto da aula StatefulWidget.

Resumo

  • Um app Flutter é Dart puro: widgets são classes, e você os cria preenchendo parâmetros.
  • Parâmetros nomeados ({...}), com required ou valor padrão, são o jeito de todo widget receber opções.
  • final trava ao rodar; const fica pronto na compilação. Widgets const economizam trabalho do Flutter.
  • Tipos sem ? nunca são null; ?? dá um valor padrão e ?. acessa com segurança.
  • Funções anônimas (() {} e () =>) são o que vai nos onPressed. Passe a função, não a chame.
  • if, for e ... dentro dos colchetes montam os children.
  • Todo widget seu tem extends, super.key e um build com @override.
  • O erro mais comum do começo: Required named parameter '...' must be provided.
