Flutter go_router

Nas aulas Navigator e Rotas Nomeadas, a Ana aprendeu a empilhar e desempilhar telas. Funciona, mas o app dela cresceu: agora tem receitas com número (a receita 7), uma busca, uma área só para quem fez login e uma versão web, onde cada tela precisa de um endereço que dê para copiar e mandar no WhatsApp (/receita/7). Para isso, a equipe do Flutter mantém o pacote go_router: você descreve as telas do app como uma lista de endereços (caminhos, como num site), e o pacote cuida da pilha, do botão voltar e da barra de endereço do navegador.

Você vai aprender
  • A instalar o pacote com flutter pub add go_router e o que muda no pubspec.yaml.
  • A descrever as rotas com GoRouter e GoRoute e a ligar tudo com MaterialApp.router.
  • A diferença entre context.go (ir para um endereço) e context.push (empilhar).
  • A passar dados pelo endereço: parâmetros no caminho (/receita/:id) e na busca (?q=bolo).
  • A aninhar rotas para o botão voltar aparecer sozinho.
  • A trocar a página de erro e a redirecionar quem não fez login (redirect).
  • Os erros mais comuns: no routes for location, No GoRouter found in context e There is nothing to pop.
Esta aula usa um pacote de fora

O go_router não vem com o Flutter: ele é baixado do pub.dev, o "repositório de pacotes" do Dart e do Flutter. No seu projeto, você precisa instalá-lo (seção 1). Nas caixas "Experimente" desta aula não precisa: o DartPad, que roda os apps do editor do guia, já traz o go_router entre os pacotes dele. A versão usada aqui é a go_router 18.1.0, com o Flutter 3.47. O laboratório de fotos do guia compila um arquivo só, sem pacotes; por isso esta aula descreve as telas em vez de mostrar fotos, e você confere cada uma rodando as caixas.

A ideia: o endereço da casa

Com o Navigator.push, navegar é como dar instruções a um motorista: "segue reto, vira à direita, agora à esquerda". Para voltar ao mesmo lugar outro dia, você precisa repetir o caminho inteiro. Com o go_router, cada tela tem um endereço, como uma casa: "Rua das Receitas, número 7". Você diz o endereço e o motorista descobre sozinho o caminho, de qualquer lugar onde esteja.

1. Instalando o pacote

Dentro da pasta do projeto, um comando acrescenta o pacote:

$ cd receitas_da_ana
$ flutter pub add go_router
« a saída (a lista dos pacotes baixados) não foi colhida no laboratório do guia, que ainda não tem terminal com o pub.dev

O comando faz duas coisas: escreve a dependência no pubspec.yaml (a "lista de ingredientes" do projeto, aula As Pastas de um Projeto) e baixa o pacote (o mesmo que flutter pub get). No pubspec.yaml, a seção dependencies ganha uma linha:

dependencies:
  flutter:
    sdk: flutter
  cupertino_icons: ^1.0.8
  go_router: ^18.1.0
go_router: ^18.1.0
O nome do pacote e a versão. O ^ quer dizer "esta ou qualquer 18.x mais nova": o pub aceita correções e novidades, mas não uma 19, que poderia quebrar o seu código.

Também dá para escrever a linha à mão no pubspec.yaml e rodar flutter pub get; o resultado é o mesmo.

2. As primeiras rotas

Duas telas: a lista de receitas, no endereço / (a "porta de entrada"), e a tela "Sobre", em /sobre:

import 'package:flutter/material.dart';
import 'package:go_router/go_router.dart';

void main() => runApp(const ReceitasApp());

final _rotas = GoRouter(
  routes: [
    GoRoute(
      path: '/',
      builder: (context, state) => const InicioTela(),
    ),
    GoRoute(
      path: '/sobre',
      builder: (context, state) => const SobreTela(),
    ),
  ],
);

class ReceitasApp extends StatelessWidget {
  const ReceitasApp({super.key});

  @override
  Widget build(BuildContext context) {
    return MaterialApp.router(
      debugShowCheckedModeBanner: false,
      theme: ThemeData(colorSchemeSeed: Colors.orange),
      routerConfig: _rotas,
    );
  }
}

class InicioTela extends StatelessWidget {
  const InicioTela({super.key});

  @override
  Widget build(BuildContext context) {
    return Scaffold(
      appBar: AppBar(title: const Text('Receitas da Ana')),
      body: Center(
        child: FilledButton(
          onPressed: () => context.go('/sobre'),
          child: const Text('Sobre o app'),
        ),
      ),
    );
  }
}

class SobreTela extends StatelessWidget {
  const SobreTela({super.key});

  @override
  Widget build(BuildContext context) {
    return Scaffold(
      appBar: AppBar(title: const Text('Sobre')),
      body: const Center(child: Text('Feito pela Ana, com carinho.')),
    );
  }
}
import 'package:go_router/go_router.dart';
Traz o pacote para o arquivo. Sem o flutter pub add antes, esta linha não compila.
GoRouter(routes: [...])
O "mapa" do app. Fica numa variável de nível de arquivo (final _rotas), fora de qualquer build: o mapa é criado uma vez só, quando o app abre. O app começa no endereço / (dá para mudar com initialLocation: '/sobre').
GoRoute(path:, builder:)
Uma rota: o caminho e a função que monta a tela. O builder recebe o context e o state (o "estado da rota": o endereço completo, os parâmetros; seção 4).
MaterialApp.router(routerConfig: _rotas)
Uma versão do MaterialApp que, em vez de home e routes, recebe um roteador pronto. O resto (theme, title…) continua igual.
context.go('/sobre')
"Vá para o endereço /sobre". O go é um método que o pacote acrescenta ao context (uma extensão, aula O Dart que Você Precisa).

O que você deve ver ao rodar (na caixa "Experimente" logo abaixo, ou no seu computador): a tela "Receitas da Ana" com o botão "Sobre o app" no meio; no toque, a tela troca para "Sobre", com o texto "Feito pela Ana, com carinho.". Na versão web, a barra de endereço do navegador muda para /sobre (ou #/sobre, conforme a configuração de URLs do app).

Cadê a seta de voltar?

Rodando o exemplo, a tela "Sobre" abre sem a seta de voltar na AppBar. Não é defeito: o go troca o endereço, e o endereço /sobre, do jeito que o mapa foi escrito, não está "dentro" de /. Para o go_router, a pilha é calculada a partir do endereço, e a pilha de /sobre tem uma tela só. As duas saídas, push e as sub-rotas, estão nas seções 3 e 5.

3. go ou push?

O pacote tem os dois jeitos de navegar, e a diferença é a pilha de telas:

FilledButton(
  onPressed: () => context.go('/sobre'),     // vai para o endereço
  child: const Text('go'),
),
FilledButton(
  onPressed: () => context.push('/sobre'),   // empilha por cima da tela atual
  child: const Text('push'),
),
context.go('/sobre')
Troca o endereço. A pilha passa a ser a do endereço novo, calculada pelo mapa; a tela de onde você saiu some da pilha (a não ser que o mapa diga que /sobre fica "dentro" dela, seção 5). É o jeito "de site": cada tela tem um lugar fixo.
context.push('/sobre')
Empilha a tela de /sobre por cima da atual, como o Navigator.push. A seta de voltar aparece e leva de volta. Bom para telas "de passagem", que você abre e fecha (um detalhe, um formulário).
context.pop()
Tira a tela de cima da pilha, como o Navigator.pop. Também aceita um resultado: context.pop(true).

4. Dados no endereço: :id e ?q=

A Ana tem uma tela de detalhe para cada receita. Em vez de criar uma rota por receita, ela escreve um caminho com um "buraco", o parâmetro :id:

final _rotas = GoRouter(
  routes: [
    GoRoute(
      path: '/',
      builder: (context, state) => const InicioTela(),
    ),
    GoRoute(
      path: '/receita/:id',
      builder: (context, state) {
        final id = state.pathParameters['id']!;
        return ReceitaTela(id: id);
      },
    ),
    GoRoute(
      path: '/busca',
      builder: (context, state) {
        final termo = state.uri.queryParameters['q'] ?? '';
        return BuscaTela(termo: termo);
      },
    ),
  ],
);
'/receita/:id'
Os dois-pontos marcam um parâmetro: /receita/7, /receita/42 e /receita/bolo caem todos nesta rota, com id valendo '7', '42' e 'bolo'.
state.pathParameters['id']!
Um Map com os parâmetros do caminho. O valor é sempre texto (String): para usar como número, converta com int.parse(id). O ! diz ao Dart "aqui com certeza tem valor"; se você errar o nome (['ID']), vem null e o ! quebra (veja Quando dá errado).
state.uri.queryParameters['q']
Os parâmetros de busca, os que vêm depois do ?: em /busca?q=bolo, q vale 'bolo'. São opcionais (o endereço /busca sozinho também casa com a rota), por isso o ?? '': "se não veio, use texto vazio".

Para navegar, basta montar o endereço com interpolação: context.go('/receita/$id'), context.go('/busca?q=bolo'). A tela recebe o dado pelo construtor, como em Passando Dados entre Telas.

E para passar um objeto inteiro?

O endereço só carrega texto. Para passar um objeto (uma Receita com nome, foto e ingredientes), existe o extra: context.go('/receita/7', extra: receita), lido com state.extra as Receita. Mas o extra não vai no endereço: se alguém abrir o link /receita/7 direto, ele chega null. Prefira passar o id e buscar a receita a partir dele.

5. Sub-rotas: a seta de voltar de graça

Uma receita "fica dentro" da lista de receitas. Dizendo isso ao mapa, com routes: dentro do GoRoute, o go('/receita/7') monta a pilha inteira: a lista embaixo, o detalhe em cima, e a seta de voltar aparece sozinha:

final _rotas = GoRouter(
  routes: [
    GoRoute(
      path: '/',
      builder: (context, state) => const InicioTela(),
      routes: [
        GoRoute(
          path: 'receita/:id',
          builder: (context, state) =>
              ReceitaTela(id: state.pathParameters['id']!),
        ),
        GoRoute(
          path: 'sobre',
          builder: (context, state) => const SobreTela(),
        ),
      ],
    ),
  ],
);
routes: [...] dentro do GoRoute
As sub-rotas: rotas que ficam "dentro" de /. O endereço completo é a soma: / + receita/:id = /receita/:id.
path: 'receita/:id' (sem a barra no começo)
Nas sub-rotas, o caminho é relativo ao de cima e não começa com /. Só as rotas do primeiro nível começam com barra.

Agora, context.go('/receita/7') mostra a receita com a seta de voltar, e a seta leva à lista, mesmo que a Ana tenha aberto o link /receita/7 direto no navegador. É a grande vantagem do go_router: a pilha vem do endereço, não do caminho que a Ana fez.

6. Página de erro e redirect

Endereço que não existe

Se o app recebe um endereço que não está no mapa (um link velho, um erro de digitação), o go_router mostra uma página de erro própria, em inglês, com o título Page Not Found, a mensagem GoException: no routes for location: /endereço e um botão Home que leva a /. Para trocá-la por uma sua, use o errorBuilder:

final _rotas = GoRouter(
  errorBuilder: (context, state) => Scaffold(
    appBar: AppBar(title: const Text('Ops!')),
    body: Center(child: Text('Não achei a página ${state.uri}')),
  ),
  routes: [ ... ],
);

O porteiro: redirect

A área "Minhas receitas" é só para quem fez login. Em vez de conferir isso em cada botão, a Ana põe um porteiro no mapa: antes de cada navegação, o redirect é chamado e pode mandar para outro endereço:

var logada = false;

final _rotas = GoRouter(
  redirect: (context, state) {
    final indoParaMinhas = state.matchedLocation.startsWith('/minhas');
    if (indoParaMinhas && !logada) return '/login';
    return null;
  },
  routes: [ ... ],
);
redirect: (context, state) { ... }
Chamado a cada navegação, antes de a tela aparecer.
state.matchedLocation
O endereço para onde a Ana está indo (sem a parte do ?).
return '/login';
"Em vez disso, vá para /login."
return null;
"Pode passar": segue para o endereço pedido. Esquecer este return null no fim é um erro comum: sem ele, o Dart não deixa compilar (a função precisa devolver algo em todo caminho).

(Aqui o logada é uma variável solta só para mostrar a ideia; num app de verdade, o login fica num objeto de estado, aula Provider.)

Quando dá errado

Ilustrativo

as mensagens desta seção foram tiradas do código-fonte do go_router 18.1.0 e do Flutter 3.47, não de um app rodado no laboratório (ele não tem pacotes). Rode o erro numa caixa "Experimente" para vê-lo no console do DartPad.

Endereço escrito errado: no routes for location 
onPressed: () => context.go('/receitas/7'),   // a rota é /receita/:id

O app não quebra: ele mostra a página de erro Page Not Found, com o texto GoException: no routes for location: /receitas/7 ("nenhuma rota para o endereço /receitas/7"). O go_router compara o endereço com o mapa, letra por letra (diferenciando maiúsculas de minúsculas), e nenhuma rota casou. Como consertar: confira o endereço contra os path do mapa. Para errar menos, use nomes (goNamed) em vez de escrever o caminho em todo lugar.

No GoRouter found in context 
return MaterialApp(
  home: const InicioTela(),
);

A Ana usou o MaterialApp comum e, no botão, chamou context.go('/sobre'). No toque, o Flutter acusa o erro No GoRouter found in context ("nenhum GoRouter encontrado no context"). O context.go procura o roteador subindo pela árvore, e ele não está lá: quem coloca o roteador na árvore é o MaterialApp.router(routerConfig: ...). Como consertar: troque MaterialApp(home: ...) por MaterialApp.router(routerConfig: _rotas).

There is nothing to pop 
onPressed: () => context.pop(),

Um botão "Fechar" na tela /sobre, aberta com go numa rota de primeiro nível (seção 2). No toque: There is nothing to pop ("não há nada para desempilhar"). A pilha de /sobre tem uma tela só, e não dá para tirar a última. Como consertar: abra a tela com context.push, ou faça de sobre uma sub-rota de / (seção 5), ou, num botão "Fechar" que deve sempre funcionar, confira antes com context.canPop() e, se não der, use context.go('/').

O nome do parâmetro errado 
GoRoute(
  path: '/receita/:id',
  builder: (context, state) => ReceitaTela(id: state.pathParameters['codigo']!),
),

O caminho chama o parâmetro de id, mas o builder pede 'codigo'. O Map devolve null, e o ! quebra com Null check operator used on a null value ("operador de checagem de nulo usado num valor nulo"), na hora de montar a tela. Como consertar: use no pathParameters[...] exatamente o nome que está depois dos dois-pontos no path.

Resumo

  • O go_router é um pacote do pub.dev, mantido pela equipe do Flutter: instale com flutter pub add go_router.
  • Cada tela tem um endereço: GoRouter(routes: [GoRoute(path:, builder:)]), ligado com MaterialApp.router(routerConfig:).
  • context.go vai para um endereço (a pilha vem do mapa); context.push empilha; context.pop desempilha.
  • Parâmetros: /receita/:id → state.pathParameters['id']; ?q= → state.uri.queryParameters['q']. Sempre texto.
  • Sub-rotas (routes: dentro do GoRoute, caminho sem barra) dão a seta de voltar mesmo quando o app abre direto no endereço.
  • errorBuilder troca a página "Page Not Found"; redirect é o porteiro (devolve outro endereço ou null).
