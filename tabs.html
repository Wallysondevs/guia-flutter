Flutter Abas (TabBar)

Na tela de receitas, a Ana quer separar Doces, Salgados e Bebidas. Não são partes diferentes do app (como "Receitas" e "Compras", que ficam na barra de baixo): são três "gavetinhas" da mesma tela. Para isso existem as abas: uma fileira de títulos logo abaixo da AppBar, com um tracinho embaixo da aba atual. Você toca no título ou arrasta o conteúdo para o lado, e a aba troca. No Flutter, são três peças que trabalham juntas: TabBar, TabBarView e um controlador.

Você vai aprender
  • As três peças das abas: DefaultTabController, TabBar e TabBarView, e por que elas precisam combinar.
  • A pôr as abas na AppBar com o parâmetro bottom.
  • A fazer abas com texto, ícone ou os dois (Tab).
  • A fazer abas roláveis quando há muitas (isScrollable).
  • A trocar de aba por código (DefaultTabController.of(context).animateTo).
  • Quando vale a pena criar o seu próprio TabController.
  • Os erros reais: No TabController for TabBar e o length que não bate com o número de abas.

Tudo nesta aula foi compilado com o Flutter 3.47 no laboratório do guia. Você precisa conhecer o Scaffold e a AppBar e os ícones.

A ideia: o fichário com divisórias

A Ana guarda as receitas em papel num fichário com divisórias coloridas: "Doces", "Salgados", "Bebidas". As orelhas das divisórias ficam à vista em cima; ela puxa uma e o fichário abre naquela parte.

No fichárioNo Flutter
As orelhas das divisórias, à vistaO TabBar, com um Tab por divisória
As folhas de cada parteO TabBarView, com uma tela por aba
O "marcador" que sabe em que parte o fichário está abertoO controlador (DefaultTabController), que avisa as duas peças
Quantas divisórias o fichário temO length do controlador: tem de ser igual ao número de abas e de telas

1. As primeiras abas

import 'package:flutter/material.dart';

void main() => runApp(const ReceitasApp());

class ReceitasApp extends StatelessWidget {
  const ReceitasApp({super.key});

  @override
  Widget build(BuildContext context) {
    return MaterialApp(
      debugShowCheckedModeBanner: false,
      theme: ThemeData(colorSchemeSeed: Colors.orange),
      home: const ReceitasPage(),
    );
  }
}

class ReceitasPage extends StatelessWidget {
  const ReceitasPage({super.key});

  @override
  Widget build(BuildContext context) {
    return DefaultTabController(
      length: 3,
      child: Scaffold(
        appBar: AppBar(
          title: const Text('Receitas da Ana'),
          bottom: const TabBar(
            tabs: [
              Tab(text: 'Doces'),
              Tab(text: 'Salgados'),
              Tab(text: 'Bebidas'),
            ],
          ),
        ),
        body: const TabBarView(
          children: [
            Center(child: Text('Bolo de cenoura')),
            Center(child: Text('Coxinha')),
            Center(child: Text('Suco de maracujá')),
          ],
        ),
      ),
    );
  }
}
DefaultTabController(length: 3, child: ...)
O "marcador" das abas: guarda qual aba está aberta e anima a troca. Ele fica em volta do Scaffold, para que as duas peças lá dentro (o TabBar e o TabBarView) o encontrem. O length é o número de abas.
AppBar(bottom: ...)
O bottom ("parte de baixo") da AppBar é uma faixa extra sob o título, feita para coisas como as abas. A AppBar fica mais alta para caber.
TabBar(tabs: [...])
A fileira de títulos. Cada Tab é uma aba; o text é o título. O TabBar desenha o tracinho (o indicador) sob a aba atual e cuida do toque.
TabBarView(children: [...])
O conteúdo: uma tela para cada aba, na mesma ordem. Arrastar o dedo para o lado troca de aba, e o indicador acompanha.

Repare: nenhum setState

2. Abas com ícone

O Tab aceita um icon, sozinho ou junto com o text. Com os dois, o ícone fica em cima e o texto embaixo, e a faixa das abas fica mais alta:

bottom: const TabBar(
  tabs: [
    Tab(icon: Icon(Icons.cake), text: 'Doces'),
    Tab(icon: Icon(Icons.lunch_dining), text: 'Salgados'),
    Tab(icon: Icon(Icons.local_drink), text: 'Bebidas'),
  ],
),
Tab(text: ...)
Só o título.
Tab(icon: ...)
Só o ícone. Economiza espaço, mas a Ana tem de adivinhar o que cada ícone quer dizer.
Tab(icon: ..., text: ...)
Os dois, um sobre o outro. É o mais claro quando cabe.
Tab(child: ...)
Qualquer widget seu, quando nenhum dos formatos prontos serve (por exemplo, um título com um Badge).

3. Muitas abas: isScrollable

Por padrão, o TabBar divide a largura da tela em partes iguais, uma por aba. Com três abas, ótimo. Com sete, os títulos ficam espremidos e cortados. A saída é deixar a fileira rolar para o lado:

import 'package:flutter/material.dart';

void main() => runApp(const ReceitasApp());

class ReceitasApp extends StatelessWidget {
  const ReceitasApp({super.key});

  @override
  Widget build(BuildContext context) {
    return MaterialApp(
      debugShowCheckedModeBanner: false,
      theme: ThemeData(colorSchemeSeed: Colors.orange),
      home: const CardapioPage(),
    );
  }
}

class CardapioPage extends StatelessWidget {
  const CardapioPage({super.key});

  static const _dias = [
    'Domingo', 'Segunda', 'Terça', 'Quarta', 'Quinta', 'Sexta', 'Sábado',
  ];

  @override
  Widget build(BuildContext context) {
    return DefaultTabController(
      length: _dias.length,
      child: Scaffold(
        appBar: AppBar(
          title: const Text('Cardápio da semana'),
          bottom: TabBar(
            isScrollable: true,
            tabAlignment: TabAlignment.start,
            tabs: [for (final dia in _dias) Tab(text: dia)],
          ),
        ),
        body: TabBarView(
          children: [
            for (final dia in _dias) Center(child: Text('Almoço de $dia')),
          ],
        ),
      ),
    );
  }
}
isScrollable: true
Cada aba fica com a largura do próprio título, e a fileira rola para o lado quando não cabe. Ao tocar numa aba perto da borda, a fileira rola sozinha para mostrá-la.
tabAlignment: TabAlignment.start
Encosta as abas no começo da fileira. Sem ele, as abas roláveis do Material 3 começam com um pequeno recuo à esquerda (o padrão, TabAlignment.startOffset).
length: _dias.length
O length vem da própria lista, e os tabs e os children são gerados dela com for. Assim os três números nunca desencontram: é a melhor proteção contra o erro de length (veja Quando dá errado).

4. Trocando de aba por código

A Ana quer um botão "Ver as bebidas" na aba de doces. O DefaultTabController pode ser encontrado de qualquer ponto abaixo dele com DefaultTabController.of(context), e o animateTo(índice) troca de aba com animação. Como na aula Drawer, o context tem de estar abaixo do controlador; por isso o botão fica num Builder:

body: TabBarView(
  children: [
    Center(
      child: Builder(
        builder: (ctx) => FilledButton(
          onPressed: () => DefaultTabController.of(ctx).animateTo(2),
          child: const Text('Ver as bebidas'),
        ),
      ),
    ),
    const Center(child: Text('Coxinha')),
    const Center(child: Text('Suco de maracujá')),
  ],
),
DefaultTabController.of(ctx)
Sobe pela árvore a partir do botão até achar o controlador.
.animateTo(2)
Vai para a aba de índice 2 ("Bebidas"; a contagem começa em 0), com a mesma animação do toque. O .index do controlador diz qual aba está aberta agora.

Formas diferentes de fazer

O seu próprio TabController

O DefaultTabController é o jeito fácil: ele cria e descarta o controlador sozinho. Quando a página precisa reagir à troca de aba (por exemplo, mudar o botão flutuante conforme a aba) ou mexer no controlador de fora da árvore, você pode criar o controlador na mão. Ele precisa de um "relógio" para animar, que vem do SingleTickerProviderStateMixin, e tem de ser descartado no dispose:

class _ReceitasPageState extends State<ReceitasPage>
    with SingleTickerProviderStateMixin {
  late final TabController _abas = TabController(length: 3, vsync: this);

  @override
  void dispose() {
    _abas.dispose();
    super.dispose();
  }

  @override
  Widget build(BuildContext context) {
    return Scaffold(
      appBar: AppBar(
        title: const Text('Receitas da Ana'),
        bottom: TabBar(
          controller: _abas,
          tabs: const [Tab(text: 'Doces'), Tab(text: 'Salgados'), Tab(text: 'Bebidas')],
        ),
      ),
      body: TabBarView(
        controller: _abas,
        children: const [
          Center(child: Text('Bolo de cenoura')),
          Center(child: Text('Coxinha')),
          Center(child: Text('Suco de maracujá')),
        ],
      ),
    );
  }
}
with SingleTickerProviderStateMixin
Dá ao State um ticker, o "relógio" que bate a cada quadro da tela e move a animação do indicador. Por isso a página precisa ser um StatefulWidget.
TabController(length: 3, vsync: this)
O controlador, com o número de abas e o relógio (vsync: this, "use o relógio deste State").
controller: _abas
O mesmo controlador entregue às duas peças. Sem o DefaultTabController, é isso que as liga.
_abas.dispose()
Desliga o controlador quando a tela sai. O porquê do dispose está em Ciclo de Vida do Widget.
JeitoQuando usar
DefaultTabControllerQuase sempre: abas simples, sem precisar saber da troca fora delas
DefaultTabController.of(ctx).animateTo(i)Um botão dentro das abas que leva a outra aba
TabController próprioA página reage à aba atual (ouvindo o controlador) ou o número de abas muda com o app rodando

Abas, barra de baixo ou gaveta?

CasoEscolha
Partes "irmãs" de uma mesma tela (Doces / Salgados / Bebidas)Abas
As 3 a 5 partes principais do appBarra de navegação inferior
Muitas partes, ou partes pouco usadasGaveta

As três convivem: um app pode ter a barra de baixo com "Receitas" e "Compras" e, dentro de "Receitas", as abas Doces/Salgados/Bebidas.

O TabBarView dentro de uma Column

Se você puser o TabBarView numa Column (por exemplo, com um texto em cima), ele não sabe que altura ter: ele quer ocupar todo o espaço, e a Column oferece espaço sem limite. O resultado é o erro de tamanho que você conheceu em Como o Flutter Calcula Tamanhos. Como consertar: envolva o TabBarView num Expanded, que dá a ele "o que sobrar" da altura.

import 'package:flutter/material.dart';

void main() => runApp(const ComprasApp());

class ComprasApp extends StatelessWidget {
  const ComprasApp({super.key});

  @override
  Widget build(BuildContext context) {
    return MaterialApp(
      debugShowCheckedModeBanner: false,
      theme: ThemeData(colorSchemeSeed: Colors.green),
      home: const ComprasPage(),
    );
  }
}

class ComprasPage extends StatelessWidget {
  const ComprasPage({super.key});

  @override
  Widget build(BuildContext context) {
    return DefaultTabController(
      length: 2,
      child: Scaffold(
        appBar: AppBar(
          title: const Text('Lista de compras'),
          bottom: const TabBar(
            tabs: [Tab(text: 'Mercado'), Tab(text: 'Feira')],
          ),
        ),
        body: const TabBarView(
          children: [
            Center(child: Text('Arroz, feijão, café')),
            Center(child: Text('Banana, tomate, alface')),
          ],
        ),
      ),
    );
  }
}

Resumo

  • Abas = três peças: o controlador (DefaultTabController), a fileira de títulos (TabBar) e o conteúdo (TabBarView).
  • O DefaultTabController fica em volta do Scaffold; o TabBar vai no bottom da AppBar; o TabBarView no body.
  • O length, os tabs e os children precisam ter o mesmo tamanho e a mesma ordem. Gere os três de uma lista só.
  • Tab aceita text, icon, os dois ou um child qualquer. Muitas abas: isScrollable: true.
  • Trocar por código: DefaultTabController.of(ctx).animateTo(i). Controle total: o seu TabController, com SingleTickerProviderStateMixin e dispose.
  • Sem controlador: No TabController for TabBar. Tamanhos diferentes: Controller's length property … does not match ….
