Flutter TextField

Até aqui, os seus apps só mostravam coisas e reagiam a botões. Mas quase todo app precisa que a pessoa escreva: o nome no cadastro, a busca, a senha, o item da lista de compras. Para isso existe o TextField ("campo de texto"): a caixinha em que se toca, o teclado sobe e a pessoa digita.

Você vai aprender
  • Como pôr um TextField na tela e enfeitá-lo com rótulo, dica, ícone e borda (InputDecoration).
  • Duas formas de saber o que a pessoa digitou: onChanged (a cada letra) e TextEditingController (quando você precisar).
  • Como limpar o campo, preencher um valor inicial e por que o controlador precisa de dispose.
  • Como pedir o teclado certo (número, e-mail, telefone), esconder a senha e limitar o tamanho.
  • O erro real mais comum: o TextField dentro de uma Row sem largura.

Você já viu StatefulWidget e setState; vamos precisar dos dois. Os apps rodaram no Flutter do laboratório, e as fotos são das telas de verdade.

A ideia: o formulário de papel

Pense numa ficha de papel na recepção do médico. Cada linha em branco tem, em cima, um rótulo ("Nome completo"), às vezes um exemplo em letra clarinha ("ex.: Ana Souza"), e embaixo um espaço para escrever. O TextField é essa linha em branco. Ele vem em duas partes:

  • o campo em si, que guarda o texto e abre o teclado;
  • a decoração (InputDecoration): o rótulo, o exemplo, o ícone, a borda e a mensagem de erro.

E tem uma diferença do papel: a recepcionista só lê a ficha no fim, mas o app pode "espiar" cada letra enquanto ela é escrita.

Um TextField() sem nada: uma linha fininha, que ocupa a largura toda. Tocou nela, a linha fica colorida (o campo ganhou o foco) e o teclado do celular sobe.

Funciona, mas a pessoa não sabe o que escrever ali. Vamos decorar.

3. Lendo o que foi digitado, letra a letra: onChanged

O jeito mais direto de saber o que a pessoa escreve é o onChanged ("ao mudar"): uma função que o Flutter chama a cada letra digitada ou apagada, com o texto inteiro do campo. A Ana quer um cartão de boas-vindas que mostra o nome enquanto ele é digitado:

import 'package:flutter/material.dart';

void main() => runApp(const MaterialApp(home: BoasVindas()));

class BoasVindas extends StatefulWidget {
  const BoasVindas({super.key});

  @override
  State<BoasVindas> createState() => _BoasVindasState();
}

class _BoasVindasState extends State<BoasVindas> {
  String nome = '';

  @override
  Widget build(BuildContext context) {
    return Scaffold(
      appBar: AppBar(title: const Text('Boas-vindas')),
      body: Padding(
        padding: const EdgeInsets.all(16),
        child: Column(
          children: [
            TextField(
              decoration: const InputDecoration(
                labelText: 'Seu nome',
                border: OutlineInputBorder(),
              ),
              onChanged: (texto) {
                setState(() {
                  nome = texto;
                });
              },
            ),
            const SizedBox(height: 24),
            Text(
              nome.isEmpty ? 'Digite o seu nome' : 'Olá, $nome!',
              style: const TextStyle(fontSize: 24),
            ),
          ],
        ),
      ),
    );
  }
}
String nome = ''
O estado da tela: o último nome digitado. Começa vazio.
onChanged: (texto) { … }
Recebe o texto inteiro do campo (não só a letra nova). Digitou "A", chega 'A'; depois "n", chega 'An'; depois "a", 'Ana'.
setState(() { nome = texto; })
Guarda o texto e manda redesenhar, para o Text de baixo mostrar o nome novo.
nome.isEmpty ? … : …
Se ainda não tem nome, mostra um convite; se tem, a saudação.

4. O controlador: TextEditingController

O onChanged é ótimo para reagir a cada letra. Mas e quando você só quer o texto na hora de um botão, ou quer mudar o texto do campo pelo código (limpar depois de salvar, por exemplo)? Para isso existe o controlador: um objeto que fica "ligado" ao campo e sabe o texto dele a qualquer momento.

A lista de compras da Ana, agora com um campo para acrescentar itens:

import 'package:flutter/material.dart';

void main() => runApp(const MaterialApp(home: ListaDeCompras()));

class ListaDeCompras extends StatefulWidget {
  const ListaDeCompras({super.key});

  @override
  State<ListaDeCompras> createState() => _ListaDeComprasState();
}

class _ListaDeComprasState extends State<ListaDeCompras> {
  final List<String> itens = ['Leite', 'Pão'];
  final TextEditingController controle = TextEditingController();

  void acrescentar() {
    final texto = controle.text.trim();
    if (texto.isEmpty) return;
    setState(() {
      itens.add(texto);
    });
    controle.clear();
  }

  @override
  void dispose() {
    controle.dispose();
    super.dispose();
  }

  @override
  Widget build(BuildContext context) {
    return Scaffold(
      appBar: AppBar(title: const Text('Lista de compras')),
      body: Column(
        children: [
          Padding(
            padding: const EdgeInsets.all(16),
            child: TextField(
              controller: controle,
              decoration: InputDecoration(
                labelText: 'Novo item',
                border: const OutlineInputBorder(),
                suffixIcon: IconButton(
                  icon: const Icon(Icons.add),
                  onPressed: acrescentar,
                ),
              ),
              onSubmitted: (_) => acrescentar(),
            ),
          ),
          Expanded(
            child: ListView(
              children: [for (final item in itens) ListTile(title: Text(item))],
            ),
          ),
        ],
      ),
    );
  }
}
final TextEditingController controle = TextEditingController();
Cria o controlador no State, uma vez só. Se você o criasse dentro do build, a cada redesenho nasceria um controlador novo, vazio, e o texto digitado sumiria.
controller: controle
Liga o campo ao controlador.
controle.text
O texto que está no campo agora. O .trim() tira os espaços do começo e do fim (para " " não virar um item).
controle.clear()
Apaga o campo, pronto para o próximo item. Também dá para escrever no campo: controle.text = 'Café';.
dispose()
Quando a tela sai de cena, o controlador tem de ser jogado fora com controle.dispose(). Ele guarda "ouvintes" (quem quer saber das mudanças); sem o dispose, eles ficam presos na memória. Veja Ciclo de Vida do Widget.
suffixIcon: IconButton(…)
O botão "+" dentro do campo, no fim.
onSubmitted: (_) => acrescentar()
Chamado quando a pessoa aperta a tecla de confirmar do teclado (o "Enter"). Assim dá para acrescentar sem tirar o dedo do teclado. O _ é o texto, que não usamos porque já está no controlador.

5. O teclado certo, a senha e os limites

O TextField tem vários parâmetros para combinar o campo com o que se espera nele:

Column(
  children: [
    const TextField(
      keyboardType: TextInputType.emailAddress,
      decoration: InputDecoration(labelText: 'E-mail'),
    ),
    const TextField(
      keyboardType: TextInputType.number,
      decoration: InputDecoration(labelText: 'Idade'),
    ),
    const TextField(
      obscureText: true,
      decoration: InputDecoration(labelText: 'Senha'),
    ),
    const TextField(
      maxLength: 20,
      decoration: InputDecoration(labelText: 'Apelido'),
    ),
    const TextField(
      maxLines: 4,
      decoration: InputDecoration(labelText: 'Observações'),
    ),
  ],
)
keyboardType: TextInputType.emailAddress
Pede ao celular o teclado de e-mail (com o @ à mão). Outros: .number (só números), .phone, .url, .multiline. É só o teclado: a pessoa ainda pode colar letras num campo de número. Para conferir o que foi digitado, use validação (próxima aula, Formulários e Validação).
obscureText: true
Esconde as letras com bolinhas: o campo de senha.
maxLength: 20
Não deixa passar de 20 letras e mostra um contador 0/20 embaixo, à direita.
maxLines: 4
Deixa o campo com 4 linhas de altura, para textos longos. O padrão é 1: uma linha só, que rola para o lado.

O "olhinho" da senha

Um botão para mostrar e esconder a senha é só um bool no estado e um suffixIcon:

bool escondida = true;

// no build:
TextField(
  obscureText: escondida,
  decoration: InputDecoration(
    labelText: 'Senha',
    border: const OutlineInputBorder(),
    suffixIcon: IconButton(
      icon: Icon(escondida ? Icons.visibility : Icons.visibility_off),
      onPressed: () {
        setState(() {
          escondida = !escondida;
        });
      },
    ),
  ),
)

O teclado cobre o campo

Num celular, o teclado ocupa quase metade da tela. Se o campo estiver lá embaixo numa Column que não rola, o teclado o cobre, ou aparecem as listras amarelas e pretas do overflow embaixo da tela. Como consertar: ponha o conteúdo dentro de um SingleChildScrollView (veja Rolagem) ou de um ListView; o Scaffold encolhe o corpo quando o teclado sobe, e a rolagem deixa a pessoa chegar ao campo.

import 'package:flutter/material.dart';

void main() => runApp(const MaterialApp(home: Legenda()));

class Legenda extends StatefulWidget {
  const Legenda({super.key});

  @override
  State<Legenda> createState() => _LegendaState();
}

class _LegendaState extends State<Legenda> {
  String legenda = '';

  @override
  Widget build(BuildContext context) {
    return Scaffold(
      appBar: AppBar(title: const Text('Legenda da foto')),
      body: Padding(
        padding: const EdgeInsets.all(16),
        child: Column(
          children: [
            TextField(
              maxLines: 3,
              decoration: const InputDecoration(
                labelText: 'Legenda',
                border: OutlineInputBorder(),
              ),
              onChanged: (texto) {
                setState(() {
                  legenda = texto;
                });
              },
            ),
            const SizedBox(height: 16),
            Text('Letras: ${legenda.length}'),
          ],
        ),
      ),
    );
  }
}

Repare na solução: o TextField perdeu o const (agora ele tem uma função, o onChanged, que não é constante), e o const passou para o InputDecoration, que continua sem mudar. O mesmo vale para o Text, que agora mostra um valor que muda.

Resumo

  • O TextField é o campo em que a pessoa digita; o InputDecoration é a roupa dele: rótulo, dica, ajuda, ícones e borda.
  • onChanged chega a cada letra com o texto inteiro; onSubmitted, quando a pessoa confirma no teclado.
  • O TextEditingController lê, muda e limpa o campo a qualquer momento. Crie-o no State, nunca no build, e chame dispose() nele.
  • keyboardType escolhe o teclado (não valida nada); obscureText esconde a senha; maxLength e maxLines controlam o tamanho.
  • Dentro de uma Row, o TextField precisa de uma largura: embrulhe-o num Expanded.
