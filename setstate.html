Flutter setState

Na aula StatefulWidget você viu que o estado mora numa classe State e que, para mudar a tela, a gente escreve setState(() { … }). Nesta aula você vai ver o que acontece de verdade quando o setState roda, olhando o console a cada toque, e o erro mais comum de quem está começando: mudar o valor e esquecer o setState.

Você vai aprender
  • As duas coisas que o setState faz: muda o valor e avisa o Flutter para chamar o build de novo.
  • Como ver o build rodando a cada toque, com debugPrint no console.
  • O que acontece quando você esquece o setState: o valor muda, a tela não.
  • Como mudar vários valores de uma vez e onde pôr a lógica (um método como _colocar).
  • Como usar o setState com uma espera (async/await) e o erro real de pôr o async no lugar errado.

As telas e as mensagens de console desta aula vieram de um Flutter de verdade, no laboratório da Ana, em tamanho de celular, com fotos antes e depois dos toques.

A ideia: mudar o número e tocar a campainha

Na padaria, a atendente muda o número do quadro de "Senha atendida". Mas os clientes estão olhando o celular: ninguém percebe a mudança. Por isso ela também toca a campainha, e aí todo mundo olha o quadro de novo.

O setState faz as duas coisas juntas:

  1. Muda o número: roda o código que você pôs dentro dele (_itens++).
  2. Toca a campainha: marca o widget como "sujo" (dirty, "precisa redesenhar"). No próximo quadro da tela, o Flutter chama o build de novo, e o build lê o valor novo.

Mudar o número sem tocar a campainha é o erro clássico da seção 2.

1. A sacola de compras

A Ana quer um contador de itens para a lista de compras. Desta vez, a mudança fica num método próprio, o _colocar, e o build escreve uma linha no console cada vez que roda:

import 'package:flutter/material.dart';

void main() => runApp(const MeuApp());

class MeuApp extends StatelessWidget {
  const MeuApp({super.key});

  @override
  Widget build(BuildContext context) {
    return MaterialApp(
      home: Scaffold(
        appBar: AppBar(title: const Text('Lista de compras')),
        body: const Center(child: Sacola()),
      ),
    );
  }
}

class Sacola extends StatefulWidget {
  const Sacola({super.key});

  @override
  State<Sacola> createState() => _SacolaState();
}

class _SacolaState extends State<Sacola> {
  int _itens = 0;

  void _colocar() {
    setState(() {
      _itens++;
    });
  }

  @override
  Widget build(BuildContext context) {
    debugPrint('build: _itens = $_itens');
    return Column(
      mainAxisSize: MainAxisSize.min,
      children: [
        Text('Itens na sacola: $_itens', style: const TextStyle(fontSize: 26)),
        const SizedBox(height: 16),
        FilledButton.icon(
          onPressed: _colocar,
          icon: const Icon(Icons.add),
          label: const Text('Colocar na sacola'),
        ),
      ],
    );
  }
}
void _colocar() { setState(() { _itens++; }); }
Um método do State com a ação do botão. O nome começa com _ porque só este estado usa. Separar a ação num método deixa o build mais limpo, e o mesmo método pode servir a dois botões.
setState(() { … })
O setState recebe uma função sem parâmetros (o () { … }), roda essa função na hora e depois agenda um novo build. Dentro dela vai só a mudança do estado.
debugPrint('build: _itens = $_itens');
Escreve uma linha no console (o terminal do flutter run, ou o Debug Console do VS Code). É o print recomendado no Flutter: ele não perde linhas quando são muitas de uma vez. Aqui ele serve de "dedo-duro": mostra quando o build roda.
onPressed: _colocar
O botão recebe o próprio método, sem parênteses: "quando tocar, chame o _colocar". Com parênteses (_colocar()), ele seria chamado na hora do build, e não no toque.
FilledButton.icon(icon: …, label: …)
Um botão cheio com ícone e texto (veja Botões).

3. Formas diferentes de escrever

As três formas abaixo fazem a mesma coisa:

// 1. A mudança dentro do setState (a forma recomendada)
void _colocar() {
  setState(() {
    _itens++;
  });
}

// 2. A versão curta, com => (só para uma linha)
void _colocar() => setState(() => _itens++);

// 3. Mudar antes e chamar o setState vazio
void _colocar() {
  _itens++;
  setState(() {});
}

A forma 3 funciona porque o que redesenha a tela é a chamada do setState, não o que está dentro dele. Mesmo assim, prefira a forma 1: quem lê o código vê na hora o que mudou. Também dá para mudar vários valores num setState só, e o Flutter redesenha uma vez:

setState(() {
  _itens = 0;
  _total = 0.0;
  _cupom = null;
});
SituaçãoComo escrever
Uma mudança simplessetState(() { _itens++; });
Várias mudanças juntasTodas dentro do mesmo setState
Lógica comprida (contas, ifs)Faça as contas antes e ponha no setState só as atribuições
Trabalho demorado (internet, espera)Espere fora do setState; chame o setState depois (seção 4)

4. setState com espera: "Buscando…"

A Ana quer um botão que busca o preço do café. A busca demora (aqui, uma espera de 2 segundos com Future.delayed faz o papel da internet). Enquanto espera, a tela deve mostrar "Buscando..." e o botão deve ficar desligado:

class _PrecoState extends State<Preco> {
  String _texto = 'Toque para ver o preço do café';
  bool _buscando = false;

  Future<void> _buscar() async {
    setState(() {
      _buscando = true;
      _texto = 'Buscando...';
    });
    await Future.delayed(const Duration(seconds: 2));
    setState(() {
      _buscando = false;
      _texto = 'Café 500 g: R\$ 18,90';
    });
  }

  @override
  Widget build(BuildContext context) {
    return Column(
      mainAxisSize: MainAxisSize.min,
      children: [
        Text(_texto, style: const TextStyle(fontSize: 22)),
        const SizedBox(height: 16),
        FilledButton(
          onPressed: _buscando ? null : _buscar,
          child: const Text('Ver preço'),
        ),
      ],
    );
  }
}
Future<void> _buscar() async
O método é async: pode usar await para esperar (veja O Dart que Você Precisa).
o 1º setState
Antes de esperar: liga o _buscando e troca o texto. A tela mostra "Buscando..." na hora.
await Future.delayed(const Duration(seconds: 2));
A espera, fora de qualquer setState. O app continua respondendo enquanto isso.
o 2º setState
Depois da espera: desliga o _buscando e põe o preço.
onPressed: _buscando ? null : _buscar
Com onPressed: null, o botão fica desligado (cinza, não responde). Assim ninguém dispara duas buscas ao mesmo tempo.

Dois setState, dois redesenhos: um antes da espera e outro depois. Buscar dados de verdade na internet tem aula própria: Buscando Dados na Internet (e, para telas que dependem de uma busca, o FutureBuilder).

Quando dá errado

Esqueceu o setState

Visto na seção 2: o valor muda (o debugPrint mostra), mas a tela não, e não aparece erro nenhum. Como consertar: faça a mudança dentro de setState(() { … }).

Pôs o async dentro do setState

Parece uma boa ideia esperar dentro do próprio setState:

  void _buscar() {
    setState(() async {
      _texto = 'Buscando...';
      await Future.delayed(const Duration(seconds: 2));
      _texto = 'Café 500 g: R\$ 18,90';
    });
  }

No toque, o console mostrou:

[erro na página] setState() callback argument returned a Future.
The setState() method on _PrecoState#827d0 was called with a closure or method that returned a Future. Maybe it is marked as "async".
Instead of performing asynchronous work inside a call to setState(), first execute the work (without updating the widget state), and then synchronously update the state inside a call to setState().
[erro na página] Unexpected null value.

Linha por linha: setState() callback argument returned a Future é "a função passada ao setState devolveu um Future" (toda função async devolve um Future). A segunda linha confirma: Maybe it is marked as "async", "talvez ela esteja marcada como async". A terceira dá a solução: "em vez de fazer trabalho assíncrono dentro do setState, faça o trabalho primeiro (sem mexer no estado) e depois atualize o estado de forma síncrona dentro de um setState". O [erro na página] no começo é a marca que o console do navegador do lab põe nos erros que ninguém tratou, e o Unexpected null value. é um efeito colateral desse primeiro erro no Flutter web. Como consertar: o setState tem de ser rápido e síncrono: espere fora dele, como na seção 4.

Chamou o método em vez de passá-lo 
          onPressed: _colocar(),
\n
lib/main.dart:44:22: Error: This expression has type 'void' and can't be used.\n          onPressed: _colocar(),\n                     ^\n
\n

"Esta expressão tem o tipo void e não pode ser usada." Com os parênteses, o Dart entende que você quer chamar o _colocar ali mesmo e usar o resultado como a ação do botão. Só que o método é void (não devolve nada), então não há resultado para usar, e o app nem compila. O ^ aponta a coluna 22 da linha 44, o começo do _colocar(). Como consertar: passe o método sem parênteses (onPressed: _colocar) ou embrulhe numa função (onPressed: () => _colocar()).

Resumo

  • setState(() { … }) faz duas coisas: roda a mudança e agenda um novo build. É o build novo que mostra o valor novo.
  • Sem o setState, o valor muda na memória, mas a tela fica igual, e sem erro nenhum. Um debugPrint no método e outro no build denunciam o problema.
  • Ponha a ação num método (_colocar) e passe-o ao botão sem parênteses: onPressed: _colocar.
  • Várias mudanças podem ir num setState só.
  • Esperas (await) ficam fora do setState; uma função async dentro dele dá setState() callback argument returned a Future.
