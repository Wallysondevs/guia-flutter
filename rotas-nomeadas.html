Flutter Rotas Nomeadas

Na aula Navegação, cada push construía a tela ali mesmo: MaterialPageRoute(builder: (context) => const TelaReceita()). Num app com 15 telas, esse código se espalha por todo canto. As rotas nomeadas organizam isso: você dá um nome a cada tela, num lugar só, e depois chama a tela pelo nome: Navigator.pushNamed(context, '/receita').

Você vai aprender
  • Como montar a tabela de rotas (routes) e a primeira tela (initialRoute) no MaterialApp.
  • Como abrir uma tela pelo nome com Navigator.pushNamed (e as versões pushReplacementNamed e companhia).
  • Por que guardar os nomes em constantes.
  • Como tratar uma rota que não existe com onUnknownRoute, e o que é o onGenerateRoute.
  • Quando as rotas nomeadas são uma boa ideia, e quando a documentação do Flutter recomenda outra coisa.
  • Os erros reais: a rota que não existe e o home junto com a rota '/'.

A ideia: os ramais da empresa

Numa empresa grande, ninguém decora o celular de cada setor. Existe uma lista de ramais na recepção: "Financeiro: 201. Suporte: 305." Quem quer falar com o suporte só disca 305, e a central sabe para onde ligar.

  • A lista de ramais é a tabela routes do MaterialApp: cada nome aponta para a função que constrói a tela.
  • Discar o ramal é o Navigator.pushNamed(context, '/suporte').
  • Se alguém discar um ramal que não existe, a central precisa dizer alguma coisa: é o onUnknownRoute.

Os nomes parecem endereços de site ('/', '/receita', '/sobre') de propósito: no Flutter web, eles viram mesmo o endereço da página. O '/' é a tela inicial, como a página principal de um site.

1. A tabela de rotas

import 'package:flutter/material.dart';

void main() => runApp(const AppReceitas());

class AppReceitas extends StatelessWidget {
  const AppReceitas({super.key});

  @override
  Widget build(BuildContext context) {
    return MaterialApp(
      initialRoute: '/',
      routes: {
        '/': (context) => const TelaInicial(),
        '/receita': (context) => const TelaReceita(),
        '/sobre': (context) => const TelaSobre(),
      },
    );
  }
}

class TelaInicial extends StatelessWidget {
  const TelaInicial({super.key});

  @override
  Widget build(BuildContext context) {
    return Scaffold(
      appBar: AppBar(title: const Text('Receitas da Ana')),
      body: Center(
        child: Column(
          mainAxisSize: MainAxisSize.min,
          children: [
            FilledButton(
              onPressed: () => Navigator.pushNamed(context, '/receita'),
              child: const Text('Ver o bolo de cenoura'),
            ),
            TextButton(
              onPressed: () => Navigator.pushNamed(context, '/sobre'),
              child: const Text('Sobre o app'),
            ),
          ],
        ),
      ),
    );
  }
}

class TelaReceita extends StatelessWidget {
  const TelaReceita({super.key});

  @override
  Widget build(BuildContext context) {
    return Scaffold(
      appBar: AppBar(title: const Text('Bolo de cenoura')),
      body: const Center(child: Text('3 cenouras, 3 ovos, 2 xícaras de farinha')),
    );
  }
}

class TelaSobre extends StatelessWidget {
  const TelaSobre({super.key});

  @override
  Widget build(BuildContext context) {
    return Scaffold(
      appBar: AppBar(title: const Text('Sobre')),
      body: const Center(child: Text('Receitas da Ana, versão 1.0')),
    );
  }
}
routes: { '/': …, '/receita': …, '/sobre': … }
Um Map (veja o Guia Dart): a chave é o nome da rota, um String; o valor é uma função que recebe o context e devolve a tela. É a "lista de ramais".
'/': (context) => const TelaInicial()
A rota '/' é a tela de entrada. Com ela na tabela, não se usa o home (os dois juntos dão erro; veja Quando dá errado).
initialRoute: '/'
Com qual rota o app começa. '/' já é o padrão, então aqui ele só deixa explícito; serve para começar em outra (initialRoute: '/sobre', por exemplo, enquanto você testa essa tela).
Navigator.pushNamed(context, '/receita')
Procura '/receita' na tabela, constrói a tela e faz o push, exatamente como o Navigator.push com MaterialPageRoute. Voltar continua igual: a seta da AppBar ou Navigator.pop(context).
class AppReceitas
O MaterialApp ficou num widget próprio, e as telas, cada uma no seu. Repare que agora nenhuma tela sabe construir as outras: a TelaInicial só conhece os nomes.

2. Os outros comandos, com Named

Cada comando da aula Navegação tem a sua versão por nome:

Com a rota construídaCom o nome
Navigator.push(context, MaterialPageRoute(…))Navigator.pushNamed(context, '/receita')
Navigator.pushReplacement(context, …)Navigator.pushReplacementNamed(context, '/inicio')
Navigator.pushAndRemoveUntil(context, …, (r) => false)Navigator.pushNamedAndRemoveUntil(context, '/login', (r) => false)
Navigator.popUntil(context, (r) => r.isFirst)Navigator.popUntil(context, ModalRoute.withName('/'))

O pop não muda: voltar não precisa de nome.

3. Nomes em constantes

Com os nomes espalhados como texto solto, um erro de digitação ('/receitas' em vez de '/receita') só aparece quando alguém toca no botão, com o app rodando. Guarde os nomes em constantes, num lugar só:

class Rotas {
  static const inicio = '/';
  static const receita = '/receita';
  static const sobre = '/sobre';
}

// na tabela:
routes: {
  Rotas.inicio: (context) => const TelaInicial(),
  Rotas.receita: (context) => const TelaReceita(),
  Rotas.sobre: (context) => const TelaSobre(),
},

// no botão:
Navigator.pushNamed(context, Rotas.receita);

Agora, se você escrever Rotas.receitas, o Dart reclama antes de rodar, e o editor ainda completa o nome para você.

4. A rota que não existe: onUnknownRoute

E se alguém pedir uma rota que não está na tabela? (No Flutter web isso acontece de verdade: basta digitar um endereço errado no navegador.) Sem preparo, é erro (veja Quando dá errado). Com o onUnknownRoute, você mostra uma tela de "não encontrado":

MaterialApp(
  initialRoute: '/',
  routes: { … },
  onUnknownRoute: (settings) {
    return MaterialPageRoute(
      builder: (context) => Scaffold(
        appBar: AppBar(title: const Text('Ops!')),
        body: Center(child: Text('A tela ${settings.name} não existe')),
      ),
    );
  },
)
onUnknownRoute: (settings) { … }
Chamado quando ninguém soube construir a rota pedida. Recebe um RouteSettings, com o name pedido (e os arguments, que você vai ver na próxima aula).
return MaterialPageRoute(…)
Aqui você devolve a rota pronta (não só a tela).

E o onGenerateRoute?

É o "plano B" da tabela: quando o nome não está em routes, o Flutter chama o onGenerateRoute(settings) antes de desistir. Ele serve para rotas que a tabela fixa não resolve, como nomes com partes que mudam ('/receita/42') ou telas que precisam de dados (próxima aula). A ordem que o Flutter segue é a que aparece na própria mensagem de erro logo abaixo: home → routes → onGenerateRoute → onUnknownRoute.

Quando usar rotas nomeadas

A documentação oficial do Flutter (a página Navigation and routing, em docs.flutter.dev) diz que as rotas nomeadas não são recomendadas para a maioria dos apps: elas não deixam personalizar bem o que acontece quando um link de fora abre o app (os deep links), e no Flutter web o botão "avançar" do navegador não funciona com elas. No lugar delas, a recomendação é um pacote de rotas como o go_router, ou o próprio Navigator com MaterialPageRoute da aula anterior.

SituaçãoO que usar
Poucas telas, app de celularNavigator.push com MaterialPageRoute (aula Navegação)
Várias telas, quer os nomes num lugar só, sem links de foraRotas nomeadas (esta aula)
Web, links que abrem telas internas (deep links), app grandego_router (aula go_router)

Mesmo assim, vale conhecer as rotas nomeadas: estão em muito código e tutorial, e o go_router usa a mesma ideia de "caminhos" ('/receita').

Resumo

  • Rotas nomeadas dão um nome a cada tela, numa tabela só: routes no MaterialApp, com '/' como entrada (sem home).
  • Navigator.pushNamed(context, '/nome') abre pelo nome; o pop continua igual.
  • Guarde os nomes em constantes para o Dart pegar os erros de digitação.
  • Rota que não existe: erro Could not find a generator for route, a não ser que haja onGenerateRoute ou onUnknownRoute.
  • Para web, links de fora e apps grandes, a documentação recomenda um pacote como o go_router.
