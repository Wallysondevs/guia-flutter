flutter doctor

Instalar o Flutter é só a primeira parte. Para fazer um app de Android, falta o Android SDK; para testar na web, falta um Chrome; para um programa de Linux, faltam compiladores. Ninguém precisa decorar essa lista: o comando flutter doctor ("doutor") faz um exame da sua máquina e diz, item por item, o que está pronto e o que falta, com a dica de como resolver.

Você vai aprender
  • A rodar o flutter doctor e a ler o resultado.
  • O que querem dizer os sinais [✓], [✗] e !.
  • O que é cada categoria: Flutter, Android toolchain, Chrome, Linux toolchain, Connected device, Network resources.
  • O flutter doctor -v, com os detalhes.
  • O flutter doctor --android-licenses e o flutter devices.
  • Que um [✗] nem sempre é problema: depende de para onde você vai fazer apps.

Todas as saídas desta aula saíram da máquina da Ana: um Ubuntu recém-instalado, com o Flutter 3.47.7 em /home/ana/flutter (aula Instalar o Flutter) e mais nada: sem Android Studio, sem Chrome. É a situação de quem acabou de instalar. Num trecho, a versão do kernel do Linux foi cortada e trocada por ….

A ideia: o check-up

No check-up, o médico não faz uma pergunta só: confere a pressão, o coração, a visão, cada coisa numa linha da ficha, com um "ok" ou um "atenção". No fim, entrega a ficha e diz o que você precisa fazer.

2. Categoria por categoria

Flutter

[✓] Flutter (Channel stable, 3.47.7, on Ubuntu 26.04.1 LTS …, locale pt_BR.UTF-8): o próprio SDK está ok. Mostra o canal (stable), a versão (3.47.7), o sistema (Ubuntu 26.04.1) e o idioma da máquina (pt_BR.UTF-8). Se esta categoria der [✗] ou [!], o problema é na instalação do Flutter em si, e é o primeiro a resolver.

Android toolchain

"Ferramentas do Android: para desenvolver para aparelhos Android". Unable to locate Android SDK: "não foi possível achar o Android SDK". O próprio doutor dá a receita, linha por linha:

Install Android Studio from: https://developer.android.com/studio/index.html
"Instale o Android Studio a partir deste endereço."
On first launch it will assist you in installing the Android SDK components.
"Ao abrir pela primeira vez, ele vai ajudar você a instalar os componentes do Android SDK."
(or visit https://flutter.dev/to/linux-android-setup ...)
"Ou visite este endereço para instruções detalhadas" (a página de configuração do Android para Linux).
If the Android SDK has been installed to a custom location, please use `flutter config --android-sdk` ...
"Se o Android SDK foi instalado num lugar diferente do padrão, use flutter config --android-sdk para informar o lugar."

Os passos do Android Studio (SDK Manager, emulador) estão na aula VS Code e Android Studio.

Chrome

"Chrome: para desenvolver para a web". O Flutter procurou o Chrome com o nome google-chrome e não achou. Try setting CHROME_EXECUTABLE to a Chrome executable: "tente apontar a variável CHROME_EXECUTABLE para um executável do Chrome". Instalar o Google Chrome resolve; se você usa o Chromium ou o Chrome está num lugar diferente, a variável CHROME_EXECUTABLE diz onde ele está.

Linux toolchain

"Ferramentas do Linux: para desenvolver programas de Linux". Faltam quatro programas de compilação: clang++ (o compilador de C++), CMake e ninja (que organizam a compilação) e pkg-config (que acha as bibliotecas). A dica do doutor diz que eles provavelmente estão disponíveis na sua distribuição, com o nome do pacote: apt install clang, apt install cmake, apt install ninja-build, apt install pkg-config. Essa categoria só aparece no Linux; no Windows, no lugar dela aparece Visual Studio (para programas de Windows) e, no Mac, Xcode (para iOS e macOS).

Connected device

"Aparelho conectado (1 disponível)". Mesmo sem Android e sem Chrome, há um aparelho: o próprio computador, como programa de Linux (o detalhe aparece no -v, logo abaixo). Quando você abrir um emulador ou ligar um celular no cabo, o número aumenta.

Network resources

"Recursos de rede": o Flutter conseguiu falar com os servidores de que precisa (os de pacotes, por exemplo). Se der [✗], confira a internet, o proxy ou o firewall.

4. Os comandos vizinhos

flutter devices: quais aparelhos estão disponíveis

$ flutter devices
Found 1 connected device:
  Linux (desktop) • linux • linux-x64 • Ubuntu 26.04.1 LTS …

Run "flutter emulators" to list and start any available device emulators.

If you expected another device to be detected, please run "flutter doctor" to diagnose potential issues. You may also try increasing the time to wait for connected devices with the "--device-timeout" flag. Visit https://flutter.dev/setup/ for troubleshooting tips.

"Encontrei 1 aparelho conectado", e duas dicas: "rode flutter emulators para listar e abrir emuladores" e "se você esperava outro aparelho, rode o flutter doctor para descobrir o problema, ou aumente o tempo de espera com --device-timeout".

flutter emulators: os emuladores de Android

$ flutter emulators
Unable to find any emulator sources. Please ensure you have some
Android AVD images available.

"Não encontrei nenhuma fonte de emuladores. Confira se você tem imagens de AVD do Android." AVD (Android Virtual Device) é o celular de mentira que você cria no Device Manager do Android Studio. Sem Android Studio, não há nenhum.

flutter doctor --android-licenses: aceitar as licenças

Depois de instalar o Android Studio e o SDK, o doutor costuma pedir que você aceite as licenças de uso do Android SDK. Esse comando mostra cada licença e pergunta se você aceita (responda y, de yes, depois de ler). No fim, a documentação oficial diz que aparece "All SDK package licenses accepted." ("todas as licenças aceitas"). Na máquina da Ana, ainda sem o Android SDK, ele só pode responder:

$ flutter doctor --android-licenses
Unable to locate Android SDK.

Um [✗] é sempre problema?

Não. Cada categoria corresponde a uma plataforma. Se você só vai fazer apps de Android, o [✗] do Linux toolchain não atrapalha em nada; o [✗] do Chrome também não. O que importa é ter [✓] no Flutter e nas plataformas que você vai usar.

Você quer fazer apps paraPrecisa de [✓] em
AndroidFlutter, Android toolchain (e Android Studio, quando aparecer) e Connected device com um emulador ou celular
WebFlutter e Chrome
iOS / macOSFlutter e Xcode (só num Mac)
WindowsFlutter e Visual Studio (só no Windows)
LinuxFlutter e Linux toolchain (só no Linux)

Para não ver o [✗] de uma plataforma que você nunca vai usar, dá para desligá-la. Por exemplo, flutter config --no-enable-linux-desktop desliga a de Linux.

Quando dá errado

"Unable to locate Android SDK" mesmo com o Android Studio instalado

O Android Studio foi instalado, mas nunca foi aberto (o SDK só é baixado no primeiro uso), ou o SDK foi para uma pasta diferente da padrão. Como consertar: abra o Android Studio e termine a configuração inicial; se o SDK estiver em outro lugar, informe a pasta com flutter config --android-sdk CAMINHO e rode o flutter doctor de novo.

O aviso das licenças do Android

Com o SDK instalado, o próximo aviso costuma ser o das licenças não aceitas, com a dica de rodar flutter doctor --android-licenses (ilustrativo: a máquina da Ana não tem o Android SDK). Como consertar: rode o comando, leia e aceite as licenças com y.

"Cannot find Chrome" tendo o Chromium

O Flutter procura o Chrome pelo nome google-chrome. Se você usa o Chromium, aponte o executável: export CHROME_EXECUTABLE=/usr/bin/chromium (no ~/.bashrc, para valer sempre; o caminho depende do sistema).

O doutor demora ou trava em "Network resources"

Sem internet (ou atrás de um proxy), o exame de rede espera e depois dá [✗]. As outras categorias não dependem dele. Como consertar: confira a conexão; numa rede com proxy, configure as variáveis HTTP_PROXY e HTTPS_PROXY.

Resumo

  • flutter doctor examina a máquina e mostra uma linha por categoria: [✓] ok, [!] aviso, [✗] falta algo.
  • Embaixo de cada problema vem a receita de como resolver (em inglês): leia com calma.
  • Numa máquina nova, é normal ver [✗] no Android, no Chrome e no Linux toolchain.
  • Só importam as categorias das plataformas que você vai usar; para Android: Flutter, Android toolchain e um aparelho conectado.
  • flutter doctor -v mostra os detalhes; --android-licenses aceita as licenças; flutter devices e flutter emulators listam os aparelhos.
  • Depois de cada "tratamento", rode o flutter doctor de novo.
