Flutter Projeto: Quiz

Um quiz é um jogo pequeno, mas tem tudo o que um app de verdade tem: dados (as perguntas), estado (em que pergunta você está, quantas acertou), telas que mudam (pergunta, resultado) e reação ao toque. A Ana vai fazer o Quiz da Ana, com perguntas de confeitaria e de Flutter, para brincar com as clientes na fila da padaria. O app cresce em 3 versões, cada uma com o código completo, fotos reais e uma missão no editor.

Você vai aprender
  • Versão 1: a classe Pergunta e a tela de uma pergunta, com um botão por resposta gerado com for.
  • Versão 2: o estado do jogo (_indice e _acertos), a troca de pergunta a cada toque e a tela de resultado com "Jogar de novo".
  • Versão 3: mostrar certo e errado com cores, esperar o botão "Próxima" e uma barra de progresso.
  • O erro real RangeError ao passar da última pergunta, com a tela vermelha do modo debug.

Aulas que ajudam: StatefulWidget, setState, Botões, Row e Column e Alinhamento.

O plano

Pense num programa de auditório: o apresentador tem um bloco de fichas (as perguntas), sabe em qual ficha está e anota os pontos num quadro. A cada resposta, ele confere, anota e passa para a próxima ficha. Quando as fichas acabam, anuncia o resultado. No app:

  • as fichas são uma lista constante de objetos Pergunta;
  • "em qual ficha estou" e "quantos pontos" são o estado: _indice e _acertos;
  • a tela mostra a pergunta da vez ou o resultado, conforme o estado.
QuizApp (MaterialApp)
└── QuizPage (Scaffold, com estado: _indice, _acertos)
    └── body:
        ├── se ainda há perguntas → Padding → Column
        │   ├── 'Pergunta 1 de 3'
        │   ├── o texto da pergunta
        │   └── um OutlinedButton por opção
        └── se acabaram → Center → Column
            ├── troféu, 'Você acertou 2 de 3!'
            └── FilledButton 'Jogar de novo'

void main() => runApp(const QuizApp());

class Pergunta {

Cada ficha: o texto, a lista de opções e a posição da opção certa (contando do 0). Em "Qual ingrediente faz o bolo crescer?", a certa é 1, o 'Fermento'.
const perguntas = [ … ];
As três perguntas do jogo, numa lista constante.
final pergunta = perguntas[0];
Nesta versão, a tela sempre mostra a primeira. A versão 2 troca o 0 por uma variável.
crossAxisAlignment: CrossAxisAlignment.stretch
Estica os filhos da coluna na largura toda: por isso os botões ocupam a tela de lado a lado (veja Alinhamento).
Text('Pergunta 1 de ${perguntas.length}', style: textos.labelLarge)
A "plaquinha" de progresso, com o total vindo da lista. Os estilos labelLarge e headlineSmall vêm do tema (veja Temas).
for (final opcao in pergunta.opcoes) Padding(…, child: OutlinedButton(…))
Um botão por opção, gerado com o for dentro da lista de filhos. O Padding só com bottom: 12 separa um botão do outro.
onPressed: () {}
Uma função que não faz nada. Ela é necessária: com onPressed: null, o botão ficaria cinza, desativado.

A pergunta grande quebrou em duas linhas sozinha, porque o Text tem a largura da coluna. Os quatro botões ocupam a largura toda (o stretch) e têm o mesmo espaço entre si (o Padding de 12). A cor roxa do texto dos botões vem da semente Colors.purple.

Versão 2: o jogo funcionando

Agora o toque vale ponto. A página vira StatefulWidget com dois números no estado: _indice (a pergunta da vez) e _acertos. Cada toque confere a resposta, soma o ponto se for o caso e passa para a próxima. Quando o índice passa da última pergunta, aparece a tela de resultado.

import 'package:flutter/material.dart';

void main() => runApp(const QuizApp());

class Pergunta {
  const Pergunta(this.texto, this.opcoes, this.correta);

  final String texto;
  final List<String> opcoes;
  final int correta;
}

const perguntas = [
  Pergunta(
    'Qual ingrediente faz o bolo crescer?',
    ['Sal', 'Fermento', 'Açúcar', 'Óleo'],
    1,
  ),
  Pergunta(
    'Em que país nasceu o brigadeiro?',
    ['Portugal', 'França', 'Brasil', 'Itália'],
    2,
  ),
  Pergunta(
    'Qual destes é um widget do Flutter?',
    ['Column', 'Tabela', 'Pasta', 'Janela'],
    0,
  ),
];

class QuizApp extends StatelessWidget {
  const QuizApp({super.key});

  @override
  Widget build(BuildContext context) {
    return MaterialApp(
      title: 'Quiz da Ana',
      debugShowCheckedModeBanner: false,
      theme: ThemeData(colorSchemeSeed: Colors.purple),
      home: const QuizPage(),
    );
  }
}

class QuizPage extends StatefulWidget {
  const QuizPage({super.key});

  @override
  State<QuizPage> createState() => _QuizPageState();
}

class _QuizPageState extends State<QuizPage> {
  int _indice = 0;
  int _acertos = 0;

  void _responder(int escolhida) {
    setState(() {
      if (escolhida == perguntas[_indice].correta) {
        _acertos++;
      }
      _indice++;
    });
  }

  void _reiniciar() {
    setState(() {
      _indice = 0;
      _acertos = 0;
    });
  }

  @override
  Widget build(BuildContext context) {
    final textos = Theme.of(context).textTheme;
    return Scaffold(
      appBar: AppBar(title: const Text('Quiz da Ana')),
      body: _indice >= perguntas.length
          ? _resultado(textos)
          : _pergunta(textos),
    );
  }

  Widget _pergunta(TextTheme textos) {
    final pergunta = perguntas[_indice];
    return Padding(
      padding: const EdgeInsets.all(24),
      child: Column(
        crossAxisAlignment: CrossAxisAlignment.stretch,
        children: [
          Text(
            'Pergunta ${_indice + 1} de ${perguntas.length}',
            style: textos.labelLarge,
          ),
          const SizedBox(height: 8),
          Text(pergunta.texto, style: textos.headlineSmall),
          const SizedBox(height: 24),
          for (var i = 0; i < pergunta.opcoes.length; i++)
            Padding(
              padding: const EdgeInsets.only(bottom: 12),
              child: OutlinedButton(
                onPressed: () => _responder(i),
                child: Text(pergunta.opcoes[i]),
              ),
            ),
        ],
      ),
    );
  }

  Widget _resultado(TextTheme textos) {
    return Center(
      child: Column(
        mainAxisSize: MainAxisSize.min,
        children: [
          const Icon(Icons.emoji_events, size: 96, color: Colors.amber),
          const SizedBox(height: 16),
          Text(
            'Você acertou $_acertos de ${perguntas.length}!',
            style: textos.headlineSmall,
          ),
          const SizedBox(height: 24),
          FilledButton(
            onPressed: _reiniciar,
            child: const Text('Jogar de novo'),
          ),
        ],
      ),
    );
  }
}
int _indice = 0; int _acertos = 0;
O estado do jogo. Começa na pergunta 0, com zero acertos.
void _responder(int escolhida)
Recebe a posição do botão tocado. Dentro do setState, compara com a correta da pergunta da vez, soma 1 em _acertos se acertou (_acertos++ é o mesmo que _acertos = _acertos + 1) e avança o _indice.
void _reiniciar()
Zera os dois números: o jogo volta à primeira pergunta.
body: _indice >= perguntas.length ? _resultado(textos) : _pergunta(textos)
A decisão da tela: se o índice já passou da última pergunta (com 3 perguntas, as posições são 0, 1 e 2; o índice 3 quer dizer "acabou"), mostra o resultado; senão, a pergunta. É esta linha que impede o erro da seção Quando dá errado.
Widget _pergunta(TextTheme textos) e Widget _resultado(TextTheme textos)
Dois métodos que devolvem pedaços da tela. Separar o build em métodos deixa cada parte curta e com nome. (Para pedaços maiores ou reaproveitados, o melhor é um widget próprio, como o PainelClima do Projeto Previsão do Tempo.)
for (var i = 0; i < pergunta.opcoes.length; i++) … onPressed: () => _responder(i)
Agora o for é com índice, porque o botão precisa saber qual posição representa. Cada botão guarda o seu próprio i (no Dart, cada volta do for tem a sua variável).
Icon(Icons.emoji_events, size: 96, color: Colors.amber)
O troféu da tela de resultado.

No lab, um clique em "Fermento" (a certa) trocou a tela na hora: Pergunta 2 de 3 e a pergunta do brigadeiro, com as opções novas. Nada no código "apagou" a pergunta antiga: o _indice mudou de 0 para 1, e o build desenhou a pergunta da posição 1. (O contorno um pouco mais escuro em "França" é só o ponteiro do mouse do lab, parado ali depois do clique.)

Na mesma rodada, mais dois cliques: "Portugal" (errada; a certa era Brasil) e "Column" (certa). O _indice chegou a 3, igual ao tamanho da lista, e o body trocou para o resultado: Você acertou 2 de 3!. Tocar em "Jogar de novo" zera tudo e volta à pergunta 1.

Missão: jogue uma partida inteira. Depois, troque o texto do botão final de 'Jogar de novo' para 'Recomeçar' e confira se ele volta mesmo para a pergunta 1 com zero acertos.

int? _escolhida;
A opção tocada na pergunta da vez, ou null se a pessoa ainda não respondeu. O ? deixa a variável aceitar nulo. Um único campo responde duas perguntas: "já respondeu?" (_escolhida != null) e "o quê?".
if (_escolhida != null) return;
Depois de responder, novos toques nas opções são ignorados. Sem isso, dava para tocar na certa depois de errar e ganhar o ponto.
void _proxima() { … _escolhida = null; _indice++; … }
Agora é o botão Próxima que avança, e ele "limpa" a escolha para a pergunta seguinte começar sem cores.
Color? _corDaOpcao(int i)
Decide a cor de cada botão: nenhuma antes de responder; verde para a certa; vermelho para a escolhida errada; nenhuma para as outras.
OutlinedButton.styleFrom(backgroundColor: _corDaOpcao(i))
Muda o fundo do botão. Quando a cor é null, o botão fica com o fundo padrão. Mais sobre estilos de botão em Botões.
if (_escolhida != null) FilledButton(…)
Um if dentro da lista de filhos (o "collection if"): o botão Próxima só existe depois da resposta. Na última pergunta, o texto vira "Ver resultado".
LinearProgressIndicator(value: (_indice + 1) / perguntas.length)
A barra de progresso. O value vai de 0 a 1: na pergunta 1 de 3, 1 / 3, um terço da barra.

Formas diferentes de fazer

Uma tela só, ou uma rota para o resultado?

Aqui, o resultado é outra "cara" da mesma tela, escolhida pelo _indice. Outra forma é abrir uma tela nova com Navigator.push (como no Projeto App de Receitas), passando os acertos pelo construtor. Qual usar: se o resultado é só um aviso e um botão, a mesma tela basta e o estado fica num lugar só. Se o resultado ganhar mais coisas (revisar as respostas, compartilhar), uma tela própria organiza melhor, e a seta de voltar passa a existir.

Métodos que devolvem widgets, ou widgets próprios?

Os métodos _pergunta e _resultado são práticos porque enxergam o estado (_indice, _acertos) direto. Um widget próprio (class TelaResultado extends StatelessWidget) precisaria receber esses valores e o _reiniciar por parâmetro, mas pode ser const, testado sozinho e reaproveitado. Qual usar: métodos para pedaços pequenos que só existem nesta tela; widgets quando o pedaço crescer (veja StatelessWidget).

4. Desafio: embaralhar

Faça as perguntas virem em ordem diferente a cada partida. Dica: guarde no estado uma cópia da lista (List<Pergunta> _ordem = [...perguntas];), chame _ordem.shuffle() no initState e no _reiniciar, e use _ordem[_indice] no lugar de perguntas[_indice].

Resumo

  • Os dados do jogo são uma lista de objetos Pergunta; o estado é "onde estou" (_indice) e "quanto fiz" (_acertos).
  • A tela é escolhida pelo estado: pergunta enquanto houver, resultado quando o índice chegar ao tamanho da lista.
  • for e if dentro da lista de filhos geram botões e escondem o que ainda não deve aparecer.
  • Um campo que pode ser nulo (int? _escolhida) guarda "ainda não respondeu" e "respondeu tal opção" ao mesmo tempo.
  • Ler uma posição que não existe numa lista dá RangeError; confira o tamanho antes.
