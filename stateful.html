Flutter StatefulWidget

Até aqui, todas as telas que você montou eram paradas: o texto, as cores e os ícones ficavam do jeito que o código mandou, do começo ao fim. Mas um app de verdade reage: o coração fica vermelho quando você curte, o número do carrinho sobe, o campo mostra o que você digitou. Para uma parte da tela mudar, ela precisa lembrar de alguma coisa. Essa memória se chama estado (em inglês, state), e o widget que tem estado é o StatefulWidget ("widget com estado").

Você vai aprender
  • O que é estado e a diferença entre StatelessWidget e StatefulWidget.
  • Por que um StatefulWidget são duas classes: o widget e o seu State.
  • O que fazem o createState, o build dentro do State e o setState.
  • Como o State lê os parâmetros do widget com widget.nome.
  • O erro real de tentar mudar um valor num StatelessWidget.

Todas as telas desta aula foram tiradas de um Flutter de verdade, no laboratório da Ana, em tamanho de celular: uma foto antes e outra depois do toque no botão.

A ideia: a placa e o quadro de giz

Na frente da padaria tem duas coisas escritas. Uma é a placa com o nome da padaria, pintada na parede: ela nunca muda. A outra é o quadro de giz com "Pão de queijo saindo: 3 fornadas hoje": a atendente apaga e reescreve o número ao longo do dia.

  • O StatelessWidget (aula StatelessWidget) é a placa: desenha o que recebeu e pronto.
  • O StatefulWidget é o quadro de giz: guarda um valor (o número de fornadas) e, quando o valor muda, se desenha de novo com o número novo.

O "apagar e reescrever" tem um nome no Flutter: setState ("mude o estado"). Ele tem aula própria, a próxima (setState); aqui você vai usá-lo do jeito mais simples.

1. O primeiro StatefulWidget: porções do bolo

A Ana quer, na receita do bolo, um botão que aumente o número de porções. O número começa em 4 e sobe a cada toque:

import 'package:flutter/material.dart';

void main() => runApp(const MeuApp());

class MeuApp extends StatelessWidget {
  const MeuApp({super.key});

  @override
  Widget build(BuildContext context) {
    return MaterialApp(
      home: Scaffold(
        appBar: AppBar(title: const Text('Receitas da Ana')),
        body: const Center(child: Porcoes()),
      ),
    );
  }
}

class Porcoes extends StatefulWidget {
  const Porcoes({super.key});

  @override
  State<Porcoes> createState() => _PorcoesState();
}

class _PorcoesState extends State<Porcoes> {
  int _porcoes = 4;

  @override
  Widget build(BuildContext context) {
    return Column(
      mainAxisSize: MainAxisSize.min,
      children: [
        Text('Bolo de cenoura: $_porcoes porções',
            style: const TextStyle(fontSize: 24)),
        const SizedBox(height: 16),
        FilledButton(
          onPressed: () {
            setState(() {
              _porcoes++;
            });
          },
          child: const Text('Mais uma porção'),
        ),
      ],
    );
  }
}

Repare que o widget das porções é feito de duas classes. Por partes:

class Porcoes extends StatefulWidget
O widget. Ele mesmo não guarda nada que muda; é só a "ficha" que diz qual State usar. Assim como o StatelessWidget, ele tem construtor const e a key (veja Keys).
State<Porcoes> createState() => _PorcoesState();
"Criar o estado." O Flutter chama este método uma vez, quando o widget aparece na tela pela primeira vez, e guarda o objeto _PorcoesState que ele devolve. É a única coisa que a classe do widget precisa fazer.
class _PorcoesState extends State<Porcoes>
O estado: a classe que guarda os valores que mudam e que desenha a tela. O <Porcoes> diz de qual widget ela é. O sublinhado no começo do nome (_) faz a classe ser privada do arquivo: ninguém de fora precisa mexer nela.
int _porcoes = 4;
O valor que muda, guardado num campo do State. Este campo não é final: ele vai receber valores novos. Também começa com _, porque só este State mexe nele.
Widget build(BuildContext context)
O mesmo build do StatelessWidget, só que aqui, dentro do State. Ele lê o _porcoes atual e monta a tela com ele.
setState(() { _porcoes++; });
Muda o valor e avisa o Flutter: "o estado mudou, chame o meu build de novo". Sem esse aviso, o número mudaria na memória, mas a tela continuaria mostrando o antigo (veja setState).

A tela logo que o app abre, e depois de a Ana tocar duas vezes no botão:

Só o número mudou: de 4 porções para 6 porções, um a mais por toque. O título, o botão e a posição de tudo continuaram iguais.

O que aconteceu a cada toque

  1. O app abre. O Flutter vê o widget Porcoes, chama o createState e ganha um _PorcoesState com _porcoes = 4.
  2. O Flutter chama o build desse estado: a tela mostra 4 porções.
  3. A Ana toca no botão. O onPressed roda o setState, que soma 1 (agora 5) e marca o widget como "precisa redesenhar".
  4. No próximo quadro da tela (a tela do celular é atualizada umas 60 vezes por segundo, ou mais nas telas mais rápidas), ele chama o build de novo, que agora monta 5 porções.

O objeto _PorcoesState é o mesmo o tempo todo; por isso ele lembra o número. Já os widgets que o build devolve (o Column, o Text, o botão) são criados de novo a cada build: eles são baratos, são só a "descrição" da tela.

2. Cada widget com o seu próprio estado

Um StatefulWidget pode receber parâmetros, como qualquer widget, e pode aparecer várias vezes na tela. Cada cópia tem o seu State separado. A Ana fez uma lista de receitas com um coração em cada uma:

import 'package:flutter/material.dart';

void main() => runApp(const MeuApp());

class MeuApp extends StatelessWidget {
  const MeuApp({super.key});

  @override
  Widget build(BuildContext context) {
    return MaterialApp(
      home: Scaffold(
        appBar: AppBar(title: const Text('Receitas da Ana')),
        body: const Column(
          children: [
            ReceitaFavorita(nome: 'Bolo de cenoura'),
            ReceitaFavorita(nome: 'Pão de queijo'),
            ReceitaFavorita(nome: 'Brigadeiro'),
          ],
        ),
      ),
    );
  }
}

class ReceitaFavorita extends StatefulWidget {
  const ReceitaFavorita({super.key, required this.nome});

  final String nome;

  @override
  State<ReceitaFavorita> createState() => _ReceitaFavoritaState();
}

class _ReceitaFavoritaState extends State<ReceitaFavorita> {
  bool _favorita = false;

  @override
  Widget build(BuildContext context) {
    return ListTile(
      title: Text(widget.nome),
      trailing: IconButton(
        icon: Icon(_favorita ? Icons.favorite : Icons.favorite_border),
        color: Colors.red,
        tooltip: 'Favoritar ${widget.nome}',
        onPressed: () {
          setState(() {
            _favorita = !_favorita;
          });
        },
      ),
    );
  }
}
const ReceitaFavorita({super.key, required this.nome});
O parâmetro nome fica no widget, num campo final. Parâmetros são o que o pai manda; eles não mudam enquanto o widget está na tela.
bool _favorita = false;
O estado: cada receita começa "não favorita".
widget.nome
Dentro do State, a palavra widget é o widget dono deste estado. É assim que o State lê os parâmetros: widget.nome, e não só nome.
_favorita ? Icons.favorite : Icons.favorite_border
Escolhe o ícone pelo estado: coração cheio se for favorita, só o contorno se não for.
tooltip: 'Favoritar ${widget.nome}'
A dica que aparece quando a pessoa segura o dedo (ou o mouse) no ícone. Ela também é o que o leitor de tela fala para quem não enxerga: um botão só com ícone deve ter sempre um tooltip.
_favorita = !_favorita;
Inverte o valor: false vira true e vice-versa.

3. Criando um StatefulWidget no editor

As duas classes são um bocado de texto para digitar. Os editores escrevem o esqueleto para você:

  • VS Code (com a extensão Flutter): digite stful e aperte Enter. Aparece o esqueleto com o cursor no nome; digite Porcoes e as duas classes ganham o nome certo.
  • Android Studio: o mesmo atalho, stful + Tab.
  • Já tem um StatelessWidget e quer transformá-lo? Ponha o cursor no nome da classe, aperte Ctrl+. (VS Code) ou Alt+Enter (Android Studio) e escolha Convert to StatefulWidget.

Veja a aula VS Code e Android Studio para instalar as extensões.

Stateless ou Stateful: qual usar

PerguntaSe a resposta for "sim"
Esta parte da tela muda sozinha depois de aparecer (toque, digitação, tempo passando)?StatefulWidget
Ela só mostra o que recebeu nos parâmetros?StatelessWidget
O valor que muda é usado por vários widgets (o total do carrinho no topo e nos itens)?Guarde o estado no pai deles: Elevando o Estado

A regra de boa prática é: comece com StatelessWidget e só troque quando precisar. E deixe o StatefulWidget o menor possível: no exemplo 1, só o Porcoes tem estado; o MeuApp, o AppBar e o resto continuam StatelessWidget. Assim, cada setState redesenha só o pedaço que mudou.

Quando dá errado

Tentou mudar um valor dentro de um StatelessWidget 
  const Porcoes({super.key});

  final int porcoes = 4;

  @override
  Widget build(BuildContext context) {
    return Column(
      mainAxisSize: MainAxisSize.min,
      children: [
        Text('Bolo de cenoura: $porcoes porções',
            style: const TextStyle(fontSize: 24)),
        const SizedBox(height: 16),
        FilledButton(
          onPressed: () {
            porcoes++;
          },
          child: const Text('Mais uma porção'),
        ),
      ],
    );
  }
}
lib/main.dart:34:13: Error: The setter 'porcoes' isn't defined for the type 'Porcoes'.
 - 'Porcoes' is from 'package:app/main.dart' ('lib/main.dart').
Try correcting the name to the name of an existing setter, or defining a setter or field named 'porcoes'.
            porcoes++;
            ^^^^^^^

O app nem chega a abrir: o compilador recusa o código. Linha por linha: lib/main.dart:34:13 é o arquivo, a linha 34 (no app completo) e a coluna 13, onde está o porcoes++. The setter 'porcoes' isn't defined for the type 'Porcoes' quer dizer "não existe um setter (um jeito de gravar um valor novo) chamado porcoes na classe Porcoes". Não existe porque o campo é final: dá para ler, mas não para mudar. A linha Try correcting the name… é uma sugestão genérica ("corrija o nome ou crie um setter"), que aqui não ajuda. E os ^^^^^^^ sublinham o trecho culpado. Como consertar: o StatelessWidget não foi feito para mudar; os campos dele são final. Transforme-o num StatefulWidget (o atalho Convert to StatefulWidget), mova o valor para o State, sem final, e mude-o dentro de um setState.

Leu o parâmetro sem o widget. 
      title: Text(nome),
lib/main.dart:40:19: Error: The getter 'nome' isn't defined for the type '_ReceitaFavoritaState'.
 - '_ReceitaFavoritaState' is from 'package:app/main.dart' ('lib/main.dart').
Try correcting the name to the name of an existing getter, or defining a getter or field named 'nome'.
      title: Text(nome),
                  ^^^^

"Não existe um getter (um jeito de ler) chamado nome no tipo _ReceitaFavoritaState." O nome é um campo do widget (ReceitaFavorita), não do estado: são duas classes diferentes, e uma não enxerga os campos da outra diretamente. Como consertar: dentro do State, os parâmetros do widget ficam em widget: Text(widget.nome).

Guardou o estado no widget, e não no State

Se você puser o int porcoes = 4; na classe Porcoes (a do widget) em vez de na _PorcoesState, vai contra a regra de que widgets são imutáveis (não mudam depois de criados), e o valor se perde: o widget é recriado a cada build do pai, e o número volta a valer 4. Só o State sobrevive aos build. Regra: o que muda mora no State; o que vem de fora mora no widget, como final.

Resumo

  • Estado é o que uma parte da tela precisa lembrar e que pode mudar depois que ela aparece.
  • Um StatefulWidget são duas classes: o widget (parâmetros final e o createState) e o State (os valores que mudam e o build).
  • O State é criado uma vez e sobrevive aos build; por isso ele lembra. Os widgets do build são recriados a cada vez.
  • Para mudar a tela: mude o valor dentro de setState(() { … }). Para ler um parâmetro: widget.nome.
  • Comece com StatelessWidget; use StatefulWidget só no pedaço que muda.
