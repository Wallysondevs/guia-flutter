Flutter Projeto: Previsão do Tempo

A Ana entrega bolos de bicicleta e quer saber, antes de sair, se vai chover. Neste projeto ela faz um app de previsão do tempo que mostra a cidade, a temperatura, o céu e o vento. É o primeiro projeto do guia em que os dados vêm de fora, de uma API (um serviço na internet que responde com dados), e por isso demoram um pouco para chegar. O app cresce em 3 versões: primeiro a tela, depois a espera, depois os dados de verdade.

Você vai aprender
  • Versão 1: montar a tela com dados fixos, antes de pensar em internet.
  • Versão 2: separar os dados numa classe Clima, buscar com uma função async que devolve um Future, e mostrar "carregando…" com FutureBuilder.
  • Versão 3: ler o JSON real da API Open-Meteo com jsonDecode e um construtor fromJson, com botão de atualizar e uma tela de erro com "Tentar de novo".
  • Como trocar o JSON guardado pelo pacote http, para buscar a previsão ao vivo.
  • O erro real de ler uma chave que não existe no JSON.

Aulas que ajudam: FutureBuilder, Buscando Dados na Internet, JSON e Classes de Modelo e StatefulWidget.

O plano: primeiro a tela, depois os dados

Um erro comum é começar pela parte difícil (a internet) e só depois descobrir como a tela vai ficar. A Ana faz ao contrário, como quem monta a vitrine da loja antes de os produtos chegarem:

  1. Versão 1: a vitrine. A tela pronta, com números escritos à mão.
  2. Versão 2: o "aguarde". Os dados passam a vir de uma função que demora (como a internet demora), e a tela mostra uma rodinha enquanto espera.
  3. Versão 3: o produto de verdade. A função lê a resposta real da API, no formato JSON, e transforma em um objeto Clima.

A API usada é a Open-Meteo, gratuita e sem cadastro. No terminal, a Ana pediu o tempo atual de São Paulo (latitude -23,55, longitude -46,63) com o curl, um programa que faz pedidos à internet:

$ curl -s "https://api.open-meteo.com/v1/forecast?latitude=-23.55&longitude=-46.63&current=temperature_2m,weather_code,wind_speed_10m&timezone=America%2FSao_Paulo"
{"latitude":-23.514938,"longitude":-46.610504,"generationtime_ms":0.1862049102783203,"utc_offset_seconds":-10800,"timezone":"America/Sao_Paulo","timezone_abbreviation":"GMT-3","elevation":737.0,"current_units":{"time":"iso8601","interval":"seconds","temperature_2m":"°C","weather_code":"wmo code","wind_speed_10m":"km/h"},"current":{"time":"2026-10-19T17:45","interval":900,"temperature_2m":16.3,"weather_code":2,"wind_speed_10m":9.7}}

Tudo numa linha só, mas a parte que interessa está no fim, no bloco "current" ("atual"): "temperature_2m":16.3 (16,3 °C a 2 metros do chão), "weather_code":2 (o código do céu: 2 é "parcialmente nublado") e "wind_speed_10m":9.7 (vento de 9,7 km/h). São esses três números que o app vai mostrar.

Versão 2: esperar pelos dados (Future e FutureBuilder)

Pedir dados à internet não é instantâneo: pode levar meio segundo, pode levar cinco. O Dart representa "um valor que vai chegar depois" com um Future (futuro). Nesta versão, a função buscarClima finge ser a internet: espera 2 segundos e devolve os dados. A tela, enquanto isso, mostra uma rodinha girando. Três novidades: a classe Clima, a função assíncrona e o FutureBuilder.

import 'package:flutter/material.dart';

void main() => runApp(const ClimaApp());

class Clima {
  const Clima({
    required this.cidade,
    required this.temperatura,
    required this.codigo,
    required this.vento,
  });

  final String cidade;
  final double temperatura;
  final int codigo;
  final double vento;

  String get descricao => switch (codigo) {
        0 => 'Céu limpo',
        1 || 2 => 'Parcialmente nublado',
        3 => 'Nublado',
        >= 51 && <= 67 => 'Chuva',
        _ => 'Tempo variado',
      };

  IconData get icone => switch (codigo) {
        0 => Icons.wb_sunny,
        1 || 2 || 3 => Icons.wb_cloudy,
        _ => Icons.grain,
      };
}

Future<Clima> buscarClima() async {
  await Future.delayed(const Duration(seconds: 2));
  return const Clima(
    cidade: 'São Paulo',
    temperatura: 16.3,
    codigo: 2,
    vento: 9.7,
  );
}

class ClimaApp extends StatelessWidget {
  const ClimaApp({super.key});

  @override
  Widget build(BuildContext context) {
    return MaterialApp(
      title: 'Previsão do Tempo',
      debugShowCheckedModeBanner: false,
      theme: ThemeData(colorSchemeSeed: Colors.blue),
      home: const ClimaPage(),
    );
  }
}

class ClimaPage extends StatefulWidget {
  const ClimaPage({super.key});

  @override
  State<ClimaPage> createState() => _ClimaPageState();
}

class _ClimaPageState extends State<ClimaPage> {
  late Future<Clima> _futuro;

  @override
  void initState() {
    super.initState();
    _futuro = buscarClima();
  }

  @override
  Widget build(BuildContext context) {
    return Scaffold(
      appBar: AppBar(title: const Text('Previsão do Tempo')),
      body: FutureBuilder<Clima>(
        future: _futuro,
        builder: (context, snapshot) {
          if (snapshot.connectionState != ConnectionState.done) {
            return const Center(child: CircularProgressIndicator());
          }
          if (snapshot.hasError) {
            return Center(child: Text('Erro: ${snapshot.error}'));
          }
          return PainelClima(clima: snapshot.data!);
        },
      ),
    );
  }
}

class PainelClima extends StatelessWidget {
  const PainelClima({super.key, required this.clima});

  final Clima clima;

  @override
  Widget build(BuildContext context) {
    return Center(
      child: Column(
        mainAxisSize: MainAxisSize.min,
        children: [
          Text(clima.cidade, style: const TextStyle(fontSize: 28)),
          const SizedBox(height: 8),
          Icon(clima.icone, size: 96, color: Colors.blueGrey),
          Text(
            '${clima.temperatura.round()} °C',
            style: const TextStyle(fontSize: 64, fontWeight: FontWeight.w300),
          ),
          Text(clima.descricao),
          const SizedBox(height: 16),
          Row(
            mainAxisSize: MainAxisSize.min,
            children: [
              const Icon(Icons.air),
              const SizedBox(width: 4),
              Text('Vento: ${clima.vento.round()} km/h'),
            ],
          ),
        ],
      ),
    );
  }
}
class Clima { … final double temperatura; final int codigo; … }
A classe de modelo com os dados de um momento: cidade, temperatura, código do céu e vento.
String get descricao => switch (codigo) { … }
Um getter que traduz o código do céu em texto, com a expressão switch do Dart 3. 1 || 2 quer dizer "1 ou 2"; >= 51 && <= 67 é "de 51 a 67" (os códigos de chuva da tabela WMO que a Open-Meteo usa); _ é "qualquer outro".
IconData get icone => switch (codigo) { … }
A mesma ideia para o ícone. Assim a tela não precisa saber nada sobre códigos: ela só pede clima.descricao e clima.icone.
Future<Clima> buscarClima() async { await Future.delayed(…); return … }
A função que "busca" o tempo. O async permite usar await, que espera o atraso de 2 segundos sem travar o app. O tipo de retorno é Future<Clima>: "um Clima, mais tarde".
late Future<Clima> _futuro; … initState() { _futuro = buscarClima(); }
A busca começa uma vez, quando a tela nasce, e o Future fica guardado no estado. Se você chamasse buscarClima() dentro do build, uma busca nova começaria a cada redesenho (veja Ciclo de Vida do Widget).
FutureBuilder<Clima>(future: _futuro, builder: (context, snapshot) { … })
Um widget que se redesenha quando o Future muda de situação. O snapshot ("retrato") diz em que pé está: esperando, com dados ou com erro.
if (snapshot.connectionState != ConnectionState.done)
Enquanto não terminou, mostra o CircularProgressIndicator, a rodinha de "carregando".
if (snapshot.hasError)
Se a busca falhou, mostra o erro (a versão 3 caprichou nesta parte).
return PainelClima(clima: snapshot.data!);
Chegou: snapshot.data é o Clima. O ! diz ao Dart "aqui não é nulo", e é seguro porque os dois if de cima já trataram os outros casos.
class PainelClima
A tela da versão 1, agora num widget separado, que recebe um Clima e mostra os valores dele. clima.temperatura.round() arredonda 16,3 para 16.

Enquanto o Future não termina, o FutureBuilder mostra só o CircularProgressIndicator no meio da tela. A rodinha é animada: o arco cresce e encolhe enquanto gira, e a foto o pegou bem curtinho, quase um ponto. No celular, você a vê girando.

Depois dos 2 segundos, o Future terminou, o FutureBuilder redesenhou e o PainelClima apareceu. A tela é idêntica à da versão 1, e é esse o objetivo: os números agora vêm de um objeto Clima (16,3 arredondado para 16; 9,7 para 10), e a descrição e o ícone vêm dos getters (código 2 → "Parcialmente nublado" e nuvem).

Versão 3: o JSON de verdade

Agora a função lê a resposta real da Open-Meteo (a mesma do curl lá em cima, só com os campos que o app usa e organizada em várias linhas). A resposta chega como texto; o jsonDecode transforma esse texto em mapas e listas do Dart, e um construtor Clima.fromJson tira de lá os três números. Também entram um botão de atualizar na barra e uma tela de erro mais simpática.

import 'dart:convert';

import 'package:flutter/material.dart';

void main() => runApp(const ClimaApp());

// A resposta que a Open-Meteo deu para São Paulo (copiada do terminal).
const respostaDaApi = r'''
{
  "timezone": "America/Sao_Paulo",
  "current_units": {
    "temperature_2m": "°C",
    "weather_code": "wmo code",
    "wind_speed_10m": "km/h"
  },
  "current": {
    "time": "2026-10-19T17:45",
    "temperature_2m": 16.3,
    "weather_code": 2,
    "wind_speed_10m": 9.7
  }
}
''';

class Clima {
  const Clima({
    required this.cidade,
    required this.temperatura,
    required this.codigo,
    required this.vento,
  });

  factory Clima.fromJson(String cidade, Map<String, dynamic> json) {
    final atual = json['current'] as Map<String, dynamic>;
    return Clima(
      cidade: cidade,
      temperatura: (atual['temperature_2m'] as num).toDouble(),
      codigo: atual['weather_code'] as int,
      vento: (atual['wind_speed_10m'] as num).toDouble(),
    );
  }

  final String cidade;
  final double temperatura;
  final int codigo;
  final double vento;

  String get descricao => switch (codigo) {
        0 => 'Céu limpo',
        1 || 2 => 'Parcialmente nublado',
        3 => 'Nublado',
        >= 51 && <= 67 => 'Chuva',
        _ => 'Tempo variado',
      };

  IconData get icone => switch (codigo) {
        0 => Icons.wb_sunny,
        1 || 2 || 3 => Icons.wb_cloudy,
        _ => Icons.grain,
      };
}

Future<Clima> buscarClima() async {
  await Future.delayed(const Duration(seconds: 1));
  final json = jsonDecode(respostaDaApi) as Map<String, dynamic>;
  return Clima.fromJson('São Paulo', json);
}

class ClimaApp extends StatelessWidget {
  const ClimaApp({super.key});

  @override
  Widget build(BuildContext context) {
    return MaterialApp(
      title: 'Previsão do Tempo',
      debugShowCheckedModeBanner: false,
      theme: ThemeData(colorSchemeSeed: Colors.blue),
      home: const ClimaPage(),
    );
  }
}

class ClimaPage extends StatefulWidget {
  const ClimaPage({super.key});

  @override
  State<ClimaPage> createState() => _ClimaPageState();
}

class _ClimaPageState extends State<ClimaPage> {
  late Future<Clima> _futuro;

  @override
  void initState() {
    super.initState();
    _futuro = buscarClima();
  }

  void _atualizar() {
    setState(() {
      _futuro = buscarClima();
    });
  }

  @override
  Widget build(BuildContext context) {
    return Scaffold(
      appBar: AppBar(
        title: const Text('Previsão do Tempo'),
        actions: [
          IconButton(
            onPressed: _atualizar,
            icon: const Icon(Icons.refresh),
            tooltip: 'Atualizar',
          ),
        ],
      ),

A biblioteca do Dart que tem o jsonDecode. Ela já vem com o Dart: não precisa instalar nada.
const respostaDaApi = r''' … ''';
A resposta da API guardada num texto de várias linhas (as três aspas). O r na frente faz um texto "cru": o Dart não tenta interpretar $ nem \ lá dentro.
factory Clima.fromJson(String cidade, Map<String, dynamic> json)
Um construtor que cria um Clima a partir do mapa do JSON. factory é o tipo de construtor que pode fazer contas antes de criar o objeto.
final atual = json['current'] as Map<String, dynamic>;
Pega o bloco "current". O as diz ao Dart o tipo esperado (no JSON, tudo chega como dynamic, "qualquer coisa").
(atual['temperature_2m'] as num).toDouble()
A temperatura. No JSON ela pode vir como 16.3 ou como 16; o num aceita os dois, e o toDouble() converte para double. É o jeito seguro de ler números com vírgula de um JSON.
jsonDecode(respostaDaApi) as Map<String, dynamic>
Transforma o texto no mapa. O bloco de fora do JSON (as chaves { }) vira um Map.
void _atualizar() { setState(() { _futuro = buscarClima(); }); }
Para buscar de novo, crie um Future novo dentro de setState: o FutureBuilder percebe a troca, volta para "carregando" e espera o novo resultado.
actions: [IconButton(… Icons.refresh …)]
O botão de atualizar, à direita na AppBar.
if (snapshot.hasError) { … 'Tentar de novo' … }
A tela de erro: um ícone de nuvem riscada, a mensagem e um botão que chama o mesmo _atualizar.

Os mesmos valores, agora tirados do JSON real (a foto foi tirada 1,5 segundo depois de abrir, quando a espera de 1 segundo já tinha passado). A única diferença visível é o ícone de atualizar no canto da barra. Tocar nele faz a rodinha voltar por um segundo e os dados aparecerem de novo.

As linhas com + são os pacotes que entraram: o http (versão 1.6.0) e três pacotes de que ele precisa. As linhas com "available" só avisam que existem versões mais novas de outros pacotes; não são erro. No pubspec.yaml, apareceu a linha http: ^1.6.0.

Depois, troque a função (o resto do app fica igual, e a constante respostaDaApi pode ser apagada):

import 'package:http/http.dart' as http;

Future<Clima> buscarClima() async {
  final url = Uri.parse(
    'https://api.open-meteo.com/v1/forecast'
    '?latitude=-23.55&longitude=-46.63'
    '&current=temperature_2m,weather_code,wind_speed_10m',
  );
  final resposta = await http.get(url);
  if (resposta.statusCode != 200) {
    throw Exception('a API respondeu ${resposta.statusCode}');
  }
  final json = jsonDecode(resposta.body) as Map<String, dynamic>;
  return Clima.fromJson('São Paulo', json);
}
Ilustrativo

No lab, a versão 3 com esta função no lugar passou no flutter analyze sem nenhum problema, mas não foi fotografada: o laboratório de fotos compila os apps sem pacotes externos. A resposta da API, porém, é a real (a do curl), e é com ela que a versão 3 roda. A aula Buscando Dados na Internet explica o http.get, o statusCode e a permissão de internet no Android.

Formas diferentes de fazer

FutureBuilder ou guardar o resultado no estado?

Em vez do FutureBuilder, dá para guardar o próprio Clima no estado e cuidar da espera "na mão":

Clima? _clima;      // null enquanto não chegou
Object? _erro;

Future<void> _carregar() async {
  try {
    final clima = await buscarClima();
    setState(() => _clima = clima);
  } catch (e) {
    setState(() => _erro = e);
  }
}

// no build:
// if (_erro != null) … else if (_clima == null) CircularProgressIndicator() else PainelClima(clima: _clima!)

Qual usar: o FutureBuilder é ótimo para "buscar uma vez e mostrar". Quando a tela também precisa mudar os dados que chegaram (editar, combinar com outras buscas), guardar o resultado no estado costuma ficar mais claro. Em apps maiores, isso sai da tela e vai para uma camada de estado (veja Por que Gerenciar o Estado).

Quando dá errado

A chave que não existe no JSON

Um erro de digitação no nome de um campo é o erro mais comum com JSON. Aqui, a temperatura foi lida com o nome em português, que a API nunca mandou:

temperatura: atual['temperatura'] as double,

O app compila, porque para o Dart atual['temperatura'] é uma consulta normal a um mapa. O problema só aparece com o app rodando:

A mensagem da exceção, como saiu no lab:

TypeError: null: type 'Null' is not a subtype of type 'double'
TypeError
"Erro de tipo": um valor não era do tipo que o código prometeu.
null:
O valor que causou o problema. Como a chave 'temperatura' não existe no mapa, atual['temperatura'] devolveu null.
type 'Null' is not a subtype of type 'double'
"O tipo Null não é um subtipo de double": o as double exigiu um número, e chegou "nada".

Repare que o app não quebrou: a exceção aconteceu dentro do buscarClima, o Future terminou com erro, e o FutureBuilder caiu no snapshot.hasError, mostrando a tela de erro que a versão 3 preparou. Essa é a vantagem de tratar o erro: em vez de uma tela vermelha, a pessoa vê uma mensagem e um botão. (O texto exato da mensagem pode variar um pouco entre plataformas; esta foi a do navegador.)

Como resolver: confira o nome do campo na resposta real (o curl do começo da aula serve para isso) e copie de lá, em vez de digitar. Para JSONs grandes, existem geradores de fromJson (veja JSON e Classes de Modelo).

4. Desafio: a sensação térmica

A Open-Meteo também tem o campo apparent_temperature (a sensação térmica). Acrescente um campo sensacao na classe Clima, leia-o no fromJson e mostre Sensação: 15 °C abaixo da descrição. No JSON guardado, acrescente "apparent_temperature": 15.2 dentro de "current".

Resumo

  • Monte a tela com dados fixos primeiro; depois troque a origem dos dados.
  • Dados que demoram são um Future; a função que busca é async e usa await.
  • Comece a busca no initState, guarde o Future no estado e use FutureBuilder para mostrar carregando, erro ou dados.
  • Para buscar de novo, crie um Future novo dentro de setState.
  • jsonDecode transforma o texto da API em mapas; um fromJson transforma o mapa em objeto. Leia números com (… as num).toDouble() e copie os nomes dos campos da resposta real.
