Flutter MaterialApp

Na aula Seu Primeiro App, um Text sozinho na tela precisou de ajuda até para saber a direção das letras. O MaterialApp é o widget que resolve isso e muito mais de uma vez só: ele monta a "casa" onde o app mora, com tema, cores, fontes, direção do texto e o sistema de telas. Quase todo app Flutter tem um, logo no topo da árvore.

Você vai aprender
  • O que o MaterialApp faz por você, sem que você peça.
  • O parâmetro home: a tela inicial.
  • O title: o nome do app para o sistema.
  • A faixa DEBUG do canto e o debugShowCheckedModeBanner.
  • O theme com uma cor-semente (ColorScheme.fromSeed), para o app inteiro ganhar as cores da Ana.
  • Os erros reais: um Scaffold sem MaterialApp e um MaterialApp sem tela inicial.

Todos os apps desta aula foram compilados com o Flutter estável do laboratório e fotografados numa tela do tamanho de um celular.

A ideia: o prédio antes dos apartamentos

Antes de alguém decorar um apartamento, o prédio precisa existir: a portaria, o elevador, a luz e a água que chegam em todos os andares. Ninguém instala a rede elétrica de novo em cada sala.

O MaterialApp é o prédio. Ele não é uma tela: ele é a estrutura que todas as telas do app compartilham.

No prédioNo MaterialApp
A luz e a água que chegam em todo andarO tema (cores, fontes) e a direção do texto, que valem para todos os widgets abaixo dele
O apartamento onde você entra primeiroO home: a tela inicial
O elevador que leva de um andar a outroO Navigator, que troca de tela (aula Navigator)
O nome na fachadaO title

1. O mínimo: home

import 'package:flutter/material.dart';

void main() {
  runApp(const MeuApp());
}

class MeuApp extends StatelessWidget {
  const MeuApp({super.key});

  @override
  Widget build(BuildContext context) {
    return const MaterialApp(
      home: Scaffold(
        body: Center(
          child: Text('Receitas da Ana'),
        ),
      ),
    );
  }
}
MaterialApp( ... )
O app no estilo Material, o padrão visual criado pelo Google (é o visual do Android). O Flutter usa o Material 3, a versão mais nova desse padrão.
home:
"Casa": o widget da tela inicial, a primeira que aparece quando o app abre. Normalmente é um Scaffold (aula Scaffold e AppBar) ou um widget seu que devolve um Scaffold.
Scaffold(body: ...)
A estrutura da tela. Aqui só com o body, o conteúdo.

Só com isso, o MaterialApp já entregou uma porção de coisas que você não pediu:

  • Direção do texto: o Text não precisou de textDirection.
  • Fonte e cor do texto do tema padrão do Material 3.
  • Cores de fundo, de botões e de barras (o esquema de cores padrão).
  • O Navigator, pronto para abrir outras telas.
  • A faixa DEBUG no canto (seção 3).

2. title: o nome do app para o sistema

O title é um texto curto com o nome do app. Ele não aparece na tela do app: quem usa é o sistema. No Android, ele aparece na lista de apps recentes; num app que roda no navegador (Flutter web), vira o título da aba.

    return const MaterialApp(
      title: 'Receitas da Ana',
      home: Scaffold(
        body: Center(
          child: Text('Receitas da Ana'),
        ),
      ),
    );
title: 'Receitas da Ana'
O nome do app. Não confunda com o título da barra do topo da tela, que é o AppBar do Scaffold (aula Scaffold e AppBar).
E o nome embaixo do ícone?

O nome que aparece embaixo do ícone do app, na tela inicial do celular, não vem do title. Ele fica nos arquivos de cada plataforma (no Android, o android:label do AndroidManifest.xml; aula Gerando o APK).

3. A faixa DEBUG: debugShowCheckedModeBanner

Em todas as fotos até aqui apareceu uma faixa vermelha escrita DEBUG, atravessada no canto de cima, à direita. Quem a põe é o MaterialApp: ela avisa que o app está rodando no modo de depuração (debug), o modo de desenvolvimento, com as ferramentas de achar erros ligadas. Para escondê-la:

    return const MaterialApp(
      title: 'Receitas da Ana',
      debugShowCheckedModeBanner: false,
      home: Scaffold(
        body: Center(
          child: Text('Receitas da Ana'),
        ),
      ),
    );
debugShowCheckedModeBanner: false
"Mostrar a faixa do modo de depuração": false esconde a faixa. O padrão é true. Ela só existe no modo debug (o modo do flutter run, aula Rodando o App); no app que vai para a loja (modo release) ela some sozinha.
Esconder ou não?

A faixa não atrapalha nada e lembra você de que está no modo debug, que é mais lento que o app final. Esconda quando for tirar fotos da tela ou mostrar o app para alguém. Neste guia, a maioria dos exemplos deixa a faixa, porque é assim que você vai ver o app no seu computador.

4. theme: as cores do app inteiro

O theme recebe um ThemeData, o "manual de estilo" do app: cores, fontes, formato dos botões. O jeito mais simples de dar uma cara ao app é escolher uma cor-semente e deixar o Material 3 calcular as outras a partir dela:

import 'package:flutter/material.dart';

void main() {
  runApp(const MeuApp());
}

class MeuApp extends StatelessWidget {
  const MeuApp({super.key});

  @override
  Widget build(BuildContext context) {
    return MaterialApp(
      title: 'Receitas da Ana',
      theme: ThemeData(
        colorScheme: ColorScheme.fromSeed(seedColor: Colors.orange),
      ),
      home: Scaffold(
        appBar: AppBar(
          title: const Text('Receitas da Ana'),
        ),
        body: const Center(
          child: Text('Bolo de cenoura'),
        ),
        floatingActionButton: FloatingActionButton(
          onPressed: () {},
          child: const Icon(Icons.add),
        ),
      ),
    );
  }
}
theme: ThemeData(...)
O tema do app. Vale para todas as telas abaixo do MaterialApp.
colorScheme: ColorScheme.fromSeed(seedColor: Colors.orange)
"Esquema de cores a partir de uma semente": você dá uma cor (laranja, a cor da cenoura) e o Material 3 gera uma paleta inteira que combina com ela: a cor dos botões, dos fundos, dos textos sobre essas cores.
AppBar e FloatingActionButton
A barra do topo e o botão redondo flutuante, que entraram aqui só para você ver o tema funcionando. Os dois são explicados nas aulas Scaffold e AppBar e Botões.
MaterialApp sem const
Repare que o const saiu de antes do MaterialApp e foi para dentro, nas partes que não mudam. ThemeData(...) e ColorScheme.fromSeed(...) são calculados quando o app roda, e por isso não podem ser const (veja o cenário em Quando dá errado).

Para ver o que a semente mudou, o lab fotografou o mesmo app duas vezes: primeiro sem o theme, depois com a semente laranja:

Repare que o Material 3 não usa o laranja puro em lugar nenhum: ele gera tons suaves a partir da semente (o fundo quase branco puxado para o pêssego, o botão laranja-claro, o + marrom para dar contraste). É de propósito: as cores calculadas sempre combinam entre si e têm contraste suficiente para leitura. A barra do topo, no Material 3, tem a mesma cor do fundo.

Temas têm muito mais: tema escuro, fontes, estilo de cada tipo de botão. Isso fica para o nível 2, nas aulas Temas (ThemeData), Material 3 e ColorScheme e Tema Escuro.

Formas diferentes: MaterialApp, CupertinoApp e WidgetsApp

O MaterialApp não é o único "prédio" possível:

WidgetVisualQuando usar
MaterialAppMaterial (Android, Google)Quase sempre. Funciona em todas as plataformas e é o que este guia usa.
CupertinoAppiOS (Apple)Quando o app precisa parecer um app nativo de iPhone em tudo. Vem do import 'package:flutter/cupertino.dart';.
WidgetsAppNenhumRaro: quando você vai desenhar todo o visual do zero. É a base dos dois de cima.

E dentro do MaterialApp, o home não é o único jeito de dizer qual é a tela inicial: dá para usar routes e initialRoute, com nomes para cada tela. Isso é assunto da aula Rotas Nomeadas; até lá, use o home.

Quando dá errado

const antes de um MaterialApp com ThemeData

A Ana tinha o const MaterialApp(...) da seção 1 e só acrescentou o theme (o começo do arquivo é igual ao da seção 1; o return está na linha 12):

    return const MaterialApp(
      theme: ThemeData(
        colorScheme: ColorScheme.fromSeed(seedColor: Colors.orange),
      ),
      home: Scaffold(
        body: Center(
          child: Text('Receitas da Ana'),
        ),
      ),
    );
  }
}

O app nem chegou a abrir: o compilador do flutter run recusou o código.

lib/main.dart:14:34: Error: Cannot invoke a non-'const' factory where a const expression is expected.
Try using a constructor or factory that is 'const'.
        colorScheme: ColorScheme.fromSeed(seedColor: Colors.orange),
                                 ^^^^^^^^
lib/main.dart:13:14: Error: Cannot invoke a non-'const' factory where a const expression is expected.
Try using a constructor or factory that is 'const'.
      theme: ThemeData(
             ^^^^^^^^^
lib/main.dart:14:34:
Arquivo, linha 14, coluna 34: o fromSeed.
Cannot invoke a non-'const' factory where a const expression is expected.
"Não dá para chamar uma factory que não é const onde se espera uma expressão const". O const do MaterialApp vale para tudo o que está dentro dele, e o ColorScheme.fromSeed e o ThemeData(...) calculam as cores na hora em que o app roda: não podem ser const.
Try using a constructor or factory that is 'const'.
"Tente usar um construtor que seja const": a dica genérica do Dart. Aqui, o conserto é o contrário: tirar o const.

Como consertar: tire o const de antes do MaterialApp e ponha-o nas partes de dentro que não mudam, como na seção 4: home: const Scaffold(...).

MaterialApp sem home: tela branca, sem erro 
    return const MaterialApp(
      title: 'Receitas da Ana',
    );

A Ana esqueceu a tela inicial. O app abriu, a faixa DEBUG apareceu (então o MaterialApp está lá), mas não há nada para mostrar, e o console ficou quieto: nenhuma mensagem de erro no Flutter 3.47.7. Como consertar: dê ao MaterialApp um home: (ou as rotas, aula Rotas Nomeadas).

Um Scaffold sem MaterialApp

Se o MaterialApp fica de fora e o runApp recebe direto um Scaffold, a tela fica vermelha de erro: o Scaffold precisa de coisas que só o MaterialApp fornece. A mensagem real, explicada, está na aula Scaffold e AppBar.

Resumo

  • O MaterialApp é a estrutura do app inteiro: direção do texto, tema, fontes e navegação para todos os widgets abaixo dele. Fica no topo da árvore, um só por app.
  • home é a tela inicial, normalmente um Scaffold.
  • title é o nome do app para o sistema; não aparece na tela.
  • A faixa DEBUG só existe no modo debug; debugShowCheckedModeBanner: false a esconde.
  • theme: ThemeData(colorScheme: ColorScheme.fromSeed(seedColor: ...)) pinta o app inteiro a partir de uma cor.
  • ThemeData(...) não pode ser const: tire o const de antes do MaterialApp e ponha-o nas partes que não mudam.
