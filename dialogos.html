Flutter Diálogos e SnackBar

Às vezes o app precisa interromper a pessoa: "Apagar a receita? Não dá para desfazer." Outras vezes, só avisar de leve, sem atrapalhar: "Caneca no carrinho." E outras, mostrar um punhado de opções: "Compartilhar por mensagem, e-mail ou link?". Para cada caso, o Material tem uma peça: o diálogo (AlertDialog), a barrinha de aviso (SnackBar) e a folha que sobe de baixo (bottom sheet).

Você vai aprender
  • Como abrir um AlertDialog com showDialog e fechá-lo com Navigator.pop.
  • Como saber qual botão a pessoa tocou: a resposta que volta no await.
  • Como impedir que o diálogo feche com um toque fora (barrierDismissible).
  • Como mostrar um SnackBar com ScaffoldMessenger, e o botão Desfazer.
  • Como abrir uma folha de opções com showModalBottomSheet.
  • O erro real do context errado: No MaterialLocalizations found.

A ideia: a campainha, o bilhete e o cardápio

  • O diálogo é a campainha: interrompe tudo, e a pessoa tem de atender (responder) antes de continuar. O fundo do app escurece e fica "travado". Use para decisões importantes.
  • O SnackBar é o bilhete preso na geladeira: aparece embaixo, fica uns segundos e some sozinho. Não trava nada. Use para confirmar que algo aconteceu.
  • A folha de baixo é o cardápio que o garçom estende na mesa: uma lista de escolhas, perto do dedo.

1. O primeiro diálogo: showDialog + AlertDialog

A Ana quer confirmar antes de apagar uma receita:

import 'package:flutter/material.dart';

void main() => runApp(const MaterialApp(home: Receita()));

class Receita extends StatefulWidget {
  const Receita({super.key});

  @override
  State<Receita> createState() => _ReceitaState();
}

class _ReceitaState extends State<Receita> {
  String situacao = 'Receita guardada';

  Future<void> perguntar() async {
    final resposta = await showDialog<bool>(
      context: context,
      builder: (context) {
        return AlertDialog(
          title: const Text('Apagar a receita?'),
          content: const Text('O bolo de cenoura vai sumir do seu caderno.'),
          actions: [
            TextButton(
              onPressed: () => Navigator.pop(context, false),
              child: const Text('Cancelar'),
            ),
            FilledButton(
              onPressed: () => Navigator.pop(context, true),
              child: const Text('Apagar'),
            ),
          ],
        );
      },
    );
    debugPrint('resposta: $resposta');
    if (resposta == true) {
      setState(() {
        situacao = 'Receita apagada';
      });
    }
  }

  @override
  Widget build(BuildContext context) {
    return Scaffold(
      appBar: AppBar(title: const Text('Bolo de cenoura')),
      body: Center(
        child: Column(
          mainAxisSize: MainAxisSize.min,
          children: [
            Text(situacao, style: const TextStyle(fontSize: 20)),
            const SizedBox(height: 16),
            FilledButton.icon(
              onPressed: perguntar,
              icon: const Icon(Icons.delete),
              label: const Text('Apagar receita'),
            ),
          ],
        ),
      ),
    );
  }
}
Future<void> perguntar() async
Uma função assíncrona: ela vai precisar esperar a pessoa responder, o que pode levar segundos ou minutos. Enquanto espera, o app continua desenhando a tela.
await showDialog<bool>(…)
Abre o diálogo por cima da tela e devolve um Future<bool?>: a resposta que vai chegar quando o diálogo fechar. O await espera essa resposta. O <bool> é o tipo da resposta.
context: context
De onde o diálogo é aberto: o context do State, que está dentro do MaterialApp. (Isso importa: veja Quando dá errado.)
builder: (context) { return AlertDialog(…); }
A função que constrói o que aparece no diálogo. Ela recebe um context novo, o do diálogo.
AlertDialog(title: …, content: …, actions: […])
A caixa pronta do Material: um título, um texto (ou qualquer widget) e uma fileira de botões no pé.
Navigator.pop(context, false)
Fecha o diálogo e manda false de volta para quem o abriu. O diálogo é uma "tela" por cima da outra, e o pop ("tirar de cima") a retira, como o botão Voltar (você vai ver o Navigator com calma em Navegação).
if (resposta == true)
A resposta é bool?: pode ser true, false ou null (se a pessoa fechou tocando fora). Comparar com true trata o null como "não".

Missão: abra o diálogo e toque fora dele, no fundo escuro: ele fecha, e a resposta é null. Para uma pergunta importante, a Ana quer obrigar a pessoa a escolher um botão. Passe barrierDismissible: false para o showDialog e tente tocar fora de novo.

      appBar: AppBar(title: const Text('Bolo de cenoura')),
      body: Center(
        child: Column(
          mainAxisSize: MainAxisSize.min,
          children: [
            Text(situacao, style: const TextStyle(fontSize: 20)),

Escreva botões que dizem o que fazem

"Apagar" e "Cancelar" são melhores que "Sim" e "Não": a pessoa entende o botão sem ler a pergunta de novo. E ponha a ação principal à direita, como o Material faz.

2. O aviso de leve: SnackBar

Na lojinha da Ana, comprar uma caneca não precisa de pergunta; só de um aviso, com a chance de desfazer:

import 'package:flutter/material.dart';

void main() => runApp(const MaterialApp(home: Carrinho()));

class Carrinho extends StatefulWidget {
  const Carrinho({super.key});

  @override
  State<Carrinho> createState() => _CarrinhoState();
}

class _CarrinhoState extends State<Carrinho> {
  int itens = 0;

  void comprar() {
    setState(() {
      itens++;
    });
    ScaffoldMessenger.of(context).showSnackBar(
      SnackBar(
        content: const Text('Caneca azul no carrinho'),
        action: SnackBarAction(
          label: 'Desfazer',
          onPressed: () {
            setState(() {
              itens--;
            });
          },
        ),
      ),
    );
  }

  void compartilhar() {
    showModalBottomSheet<void>(
      context: context,
      builder: (context) {
        return Column(
          mainAxisSize: MainAxisSize.min,
          children: [
            ListTile(
              leading: const Icon(Icons.message),
              title: const Text('Mandar por mensagem'),
              onTap: () => Navigator.pop(context),
            ),
            ListTile(
              leading: const Icon(Icons.email),
              title: const Text('Mandar por e-mail'),
              onTap: () => Navigator.pop(context),
            ),
            ListTile(
              leading: const Icon(Icons.link),
              title: const Text('Copiar o link'),
              onTap: () => Navigator.pop(context),
            ),
          ],
        );
      },
    );
  }

  @override
  Widget build(BuildContext context) {
    return Scaffold(
      appBar: AppBar(
        title: const Text('Lojinha da Ana'),
        actions: [
          IconButton(
            icon: const Icon(Icons.share),
            tooltip: 'Compartilhar',
            onPressed: compartilhar,
          ),
        ],
      ),
      body: Center(
        child: Column(
          mainAxisSize: MainAxisSize.min,
          children: [
            Text('Itens no carrinho: $itens', style: const TextStyle(fontSize: 20)),
            const SizedBox(height: 16),
            FilledButton(onPressed: comprar, child: const Text('Comprar caneca')),
          ],
        ),
      ),
    );
  }
}
ScaffoldMessenger.of(context)
O "mensageiro" que cuida das barrinhas de todos os Scaffold do app. O MaterialApp já cria um; o .of(context) o encontra.
.showSnackBar(SnackBar(…))
Mostra a barrinha no pé do Scaffold. Ela some sozinha depois de alguns segundos (o padrão do duration é 4 segundos).
content: const Text('…')
O texto do aviso. Curto: uma linha.
action: SnackBarAction(label: 'Desfazer', onPressed: …)
Um botão dentro da barrinha, opcional. Uma ação só, e de preferência a de desfazer.

A Ana tocou em Comprar caneca e, com a barrinha ainda na tela, em Desfazer:

Se a pessoa comprar várias canecas seguidas, as barrinhas entram numa fila: uma espera a outra sumir. Para trocar a barrinha atual pela nova na hora, chame ScaffoldMessenger.of(context).hideCurrentSnackBar() antes do showSnackBar.

3. A folha de opções: showModalBottomSheet

No mesmo app, o botão de compartilhar (o ícone no canto da barra) abre uma folha que sobe de baixo. Olhe a função compartilhar no código acima:

showModalBottomSheet<void>(context: …, builder: …)
Funciona como o showDialog: abre por cima da tela, escurece o fundo e devolve um Future com a resposta (aqui, void: nenhuma). Modal quer dizer que trava o resto da tela enquanto está aberta.
Column(mainAxisSize: MainAxisSize.min, …)
O min faz a folha ter só a altura das opções, em vez de subir até o meio da tela.
ListTile(…, onTap: () => Navigator.pop(context))
Cada opção é uma linha de lista. Ao tocar, a folha fecha com Navigator.pop, como o diálogo. Num app de verdade, antes do pop viria a ação (mandar a mensagem, copiar o link).

A Ana tocou no ícone de compartilhar (nas fotos, ele fica escondido debaixo da faixa DEBUG, no canto superior direito; no app de verdade ele aparece):

SituaçãoO que usar

Quando dá errado

O context de cima do MaterialApp

Um erro clássico de quem começa: escrever tudo num widget só, o mesmo que cria o MaterialApp, e usar o context dele para abrir o diálogo:

import 'package:flutter/material.dart';

void main() => runApp(const MeuApp());

class MeuApp extends StatelessWidget {
  const MeuApp({super.key});

  @override
  Widget build(BuildContext context) {
    return MaterialApp(
      home: Scaffold(
        body: Center(
          child: FilledButton(
            onPressed: () {
              showDialog<void>(
                context: context,
                builder: (context) => const AlertDialog(title: Text('Oi!')),
              );
            },
            child: const Text('Abrir'),
          ),
        ),
      ),
    );
  }
}

"Nenhuma MaterialLocalizations encontrada." São os textos prontos do Material em cada língua (o nome que o leitor de tela fala para o fundo escuro do diálogo, por exemplo), e quem os fornece é o MaterialApp.

"O widget que não achou a MaterialLocalizations acima dele foi o MeuApp." E é verdade: o MaterialApp está abaixo do MeuApp (é ele quem o cria), não acima.
#2 showDialog … #3 MeuApp.build
Quem chamou: o showDialog, dentro do build do MeuApp.

O context de um widget é a posição dele na árvore, e o .of(context) procura para cima a partir dali. O context do MeuApp fica acima do MaterialApp, então nada do MaterialApp é encontrado. O ScaffoldMessenger.of(context) com esse mesmo context falha do mesmo jeito. Como consertar: separe a tela num widget próprio, usado no home: (como em todos os exemplos desta aula: MaterialApp(home: Receita())). O context da Receita fica abaixo do MaterialApp.

Esqueceu o Navigator.pop no botão 
TextButton(
  onPressed: () {},
  child: const Text('Cancelar'),
),

Sem mensagem de erro: a pessoa toca em Cancelar e o diálogo continua lá. O AlertDialog não fecha sozinho; quem fecha é o Navigator.pop. Como consertar: onPressed: () => Navigator.pop(context), com o context que o builder recebeu.

Usou a resposta sem esperar 
final resposta = showDialog<bool>(…); // faltou o await
if (resposta == true) { … }

Sem o await, resposta não é a resposta: é o Future (a "promessa" de resposta), e um Future nunca é igual a true. O if nunca entra. Tirando o await do app da seção 1, o flutter analyze avisa:

   info • The type of the right operand ('bool') isn't a subtype or a supertype of the left operand ('Future<bool?>'). Try changing one or both of the operands • lib/main.dart:36:18 • unrelated_type_equality_checks

"O tipo da direita (bool) não tem nada a ver com o da esquerda (Future<bool?>)": comparar os dois sempre dá false. Como consertar: final resposta = await showDialog<bool>(…);, numa função async.

Repare no if (!mounted) return; da solução. Depois de um await, a tela pode ter sido fechada enquanto o app esperava; o mounted diz se este State ainda está na tela. Usar o context de uma tela que já saiu dá erro, e o flutter analyze avisa quando você esquece essa conferência (a regra use_build_context_synchronously).

Resumo

  • showDialog abre um AlertDialog por cima da tela; Navigator.pop(context, valor) fecha e manda a resposta, que chega pelo await (ou null, se a pessoa tocou fora).
  • barrierDismissible: false obriga a escolher um botão.
  • ScaffoldMessenger.of(context).showSnackBar(…) mostra um aviso que some sozinho; SnackBarAction põe um Desfazer.
  • showModalBottomSheet abre uma folha de opções que sobe de baixo.
  • O context tem de estar abaixo do MaterialApp: separe a tela num widget próprio. Depois de um await, confira mounted antes de usar o context.
