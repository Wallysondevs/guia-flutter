Flutter http

A lista de receitas, a previsão do tempo, o catálogo da loja: quase nenhum app guarda tudo dentro dele. Os dados ficam num servidor, e o app vai buscar pela internet. Nesta aula, a Ana faz o app da lojinha dela mostrar a lista de clientes que está num servidor de verdade, usando o pacote http, o jeito mais simples e oficial de fazer pedidos pela internet no Flutter.

Você vai aprender
  • Como acrescentar o pacote http ao projeto (flutter pub add http).
  • Como fazer um pedido GET: Uri.parse, http.get, statusCode e body.
  • Como transformar a resposta (texto JSON) em dados do Dart com jsonDecode.
  • Como mostrar as três telas: carregando, sucesso e erro, com um botão "Tentar de novo".
  • A permissão de internet do Android.
  • Os erros reais: o endereço errado (404), o servidor que não existe e o import esquecido.

Esta aula usa o FutureBuilder; se você pulou a aula dele, volte lá antes. Os exemplos rodaram no laboratório do guia, com o Flutter 3.47 e o pacote http 1.6, buscando dados de verdade na internet.

A ideia: pedir pelo balcão

Pense numa lanchonete com balcão. Você (o app) faz um pedido dizendo o que quer ("um suco de laranja"); o atendente (o servidor) vai lá dentro e volta com uma resposta: o suco, ou um "acabou a laranja". Na internet é igual:

  • O pedido (em inglês, request) vai para um endereço (a URL), como https://jsonplaceholder.typicode.com/users. O tipo de pedido mais comum é o GET: "me dá isso aqui".
  • A resposta (response) volta com um código de situação (o status code: 200 quer dizer "deu certo", 404 quer dizer "não achei isso") e um corpo (o body), que costuma ser um texto no formato JSON.

Nesta aula, o servidor é o JSONPlaceholder: um serviço público e gratuito, feito para quem está aprendendo, que responde com dados de mentira (10 usuários, posts, tarefas) sem pedir cadastro nem chave. É o mesmo tipo de serviço que a documentação oficial do Flutter usa nos exemplos.

1. Acrescentar o pacote http

O http não vem junto com o Flutter: é um pacote do pub.dev, mantido pela equipe do Dart. Na pasta do projeto, rode:

$ cd lojinha
$ flutter pub add http
Resolving dependencies...
Downloading packages...
+ async 2.13.1
+ boolean_selector 2.1.2
…                                « (a lista continua, em ordem alfabética)
+ http 1.6.0
+ http_parser 4.1.2
…
+ web 1.1.1
Changed 31 dependencies!
3 packages have newer versions incompatible with dependency constraints.
Try `flutter pub outdated` for more information.

"Resolvendo as dependências… baixando os pacotes…". Cada linha com + é um pacote que entrou no projeto: o http 1.6.0 e os pacotes de que ele precisa (como o http_parser). No laboratório, o projeto foi preparado do zero (sem o arquivo pubspec.lock), por isso a lista inclui também os pacotes que o próprio Flutter usa; no seu projeto, ela pode ser bem mais curta. As duas últimas linhas só avisam que existem versões mais novas de alguns pacotes que não combinam com as regras atuais: não é erro.

O comando acrescentou uma linha no pubspec.yaml, na seção dependencies, e baixou o pacote:

dependencies:
  flutter:
    sdk: flutter
  http: ^1.6.0

Na aula Pacotes do pub.dev você vê com calma o que é o ^ e como escolher pacotes.

Android: a permissão de internet

Enquanto você testa com flutter run, o app já pode usar a internet. Mas o app publicado no Android só acessa a internet se pedir permissão no arquivo android/app/src/main/AndroidManifest.xml, logo dentro da tag <manifest>:

<manifest xmlns:android="http://schemas.android.com/apk/res/android">
    <uses-permission android:name="android.permission.INTERNET" />
    <application …

Esquecer essa linha é o erro clássico do "no meu celular funciona, no APK não". (No macOS existe algo parecido: a permissão com.apple.security.network.client. As duas estão na receita oficial Fetch data from the internet, do docs.flutter.dev.)

2. Buscar e mostrar: as três telas

import 'dart:convert';

import 'package:flutter/material.dart';
import 'package:http/http.dart' as http;

void main() => runApp(const MeuApp());

class MeuApp extends StatelessWidget {
  const MeuApp({super.key});

  @override
  Widget build(BuildContext context) {
    return const MaterialApp(
      debugShowCheckedModeBanner: false,
      home: TelaClientes(),
    );
  }
}

Future<List<String>> buscarClientes() async {
  final url = Uri.parse('https://jsonplaceholder.typicode.com/users');
  final resposta = await http.get(url);
  if (resposta.statusCode != 200) {
    throw Exception('Erro ${resposta.statusCode} ao buscar os clientes');
  }
  final lista = jsonDecode(resposta.body) as List<dynamic>;
  return [for (final cliente in lista) cliente['name'] as String];
}

class TelaClientes extends StatefulWidget {
  const TelaClientes({super.key});

  @override
  State<TelaClientes> createState() => _TelaClientesState();
}

class _TelaClientesState extends State<TelaClientes> {
  late Future<List<String>> _clientes;

  @override
  void initState() {
    super.initState();
    _clientes = buscarClientes();
  }

  void _tentarDeNovo() {
    setState(() {
      _clientes = buscarClientes();
    });
  }

  @override
  Widget build(BuildContext context) {
    return Scaffold(
      appBar: AppBar(
        title: const Text('Clientes da Lojinha'),
        actions: [
          IconButton(
            tooltip: 'Atualizar',
            onPressed: _tentarDeNovo,
            icon: const Icon(Icons.refresh),
          ),
        ],
      ),
      body: FutureBuilder<List<String>>(
        future: _clientes,
        builder: (context, snapshot) {
          if (snapshot.connectionState == ConnectionState.waiting) {
            return const Center(child: CircularProgressIndicator());
          }
          if (snapshot.hasError) {
            return Center(
              child: Column(
                mainAxisSize: MainAxisSize.min,
                children: [
                  const Icon(Icons.wifi_off, size: 64),
                  Padding(
                    padding: const EdgeInsets.all(16),
                    child: Text('${snapshot.error}', textAlign: TextAlign.center),
                  ),
                  FilledButton(
                    onPressed: _tentarDeNovo,
                    child: const Text('Tentar de novo'),
                  ),
                ],
              ),
            );
          }
          final clientes = snapshot.data!;
          return ListView(
            children: [
              for (final nome in clientes)
                ListTile(
                  leading: const Icon(Icons.person),
                  title: Text(nome),
                ),
            ],
          );
        },
      ),
    );
  }
}
import 'dart:convert';
A biblioteca do Dart que tem o jsonDecode.
import 'package:http/http.dart' as http;
Importa o pacote com um apelido: daqui para baixo, tudo dele se escreve http.alguma_coisa (http.get, http.post). O apelido evita confusão com nomes iguais de outros lugares; é o jeito que a documentação do pacote recomenda.
Uri.parse('https://…/users')
O http.get não recebe um texto, e sim um Uri (um endereço já "entendido" pelo Dart). O Uri.parse faz essa conversão.
final resposta = await http.get(url);
Faz o pedido GET e espera a resposta, sem travar a tela. A resposta é um http.Response.
resposta.statusCode != 200
O código de situação. Qualquer coisa diferente de 200 aqui vira um erro com throw, e o FutureBuilder mostra a tela de erro.
jsonDecode(resposta.body) as List<dynamic>
O body é um String com o JSON. O jsonDecode o transforma em listas e mapas do Dart. Como este endereço devolve uma lista ([ {…}, {…} ]), dizemos ao Dart que é uma List com o as.
[for (final cliente in lista) cliente['name'] as String]
Cada cliente é um mapa ({"id": 1, "name": "Leanne Graham", …}); pegamos só o name. Na próxima aula, JSON e Classes de Modelo, você troca esses mapas por uma classe Cliente, bem mais segura.
late Future… _clientes (sem final) e _tentarDeNovo()
Aqui o campo não é final, porque o botão "Tentar de novo" troca o Future por um novo, dentro de um setState. O FutureBuilder percebe o Future novo e volta para a rodinha.
FilledButton(onPressed: _tentarDeNovo, …)
O botão da tela de erro (veja Botões).

As três telas, fotografadas

As três telas saem do mesmo FutureBuilder: a rodinha enquanto o http.get não volta; a lista quando volta com 200; e o ícone, a mensagem e o botão Tentar de novo quando dá erro. O botão chama _tentarDeNovo, que põe um Future novo no campo, e a rodinha volta.

Missão: a lista ficou comprida. O JSONPlaceholder aceita um "filtro" no endereço: acrescente ?_limit=3 no fim da URL (…/users?_limit=3) para receber só os 3 primeiros clientes.

3. Outras formas de fazer

Montar o endereço com Uri.https

Quando o endereço tem filtros (?_limit=3&…), montar o texto na mão é fácil de errar (um & esquecido, um espaço que não foi codificado). O Uri.https monta para você:

final url = Uri.https('jsonplaceholder.typicode.com', '/users', {'_limit': '3'});

Outros pedidos: post, put, delete

Para mandar dados (cadastrar um cliente), o pedido é POST, com o corpo em JSON:

final resposta = await http.post(
  Uri.parse('https://jsonplaceholder.typicode.com/users'),
  headers: {'Content-Type': 'application/json'},
  body: jsonEncode({'name': 'Ana Souza'}),
);

Os pedidos put (atualizar) e delete (apagar) seguem o mesmo jeito. O JSONPlaceholder finge que guardou: responde, mas não muda nada de verdade.

Um limite de tempo: timeout

Numa internet ruim, o pedido pode demorar minutos. Dá para desistir antes, com o timeout do próprio Future: await http.get(url).timeout(const Duration(seconds: 10)). Se passar do tempo, sai um TimeoutException, que cai na tela de erro.

SituaçãoQual usar
Pedidos simples (o caso deste guia)O pacote http, com http.get / http.post
Muitos pedidos ao mesmo servidor (abrir uma conexão só e reaproveitar)final cliente = http.Client(); … cliente.get(url) … e, no fim, cliente.close()
Apps maiores: interceptar todos os pedidos, enviar arquivos com progressoPacotes como o dio (veja Pacotes do pub.dev)

Quando dá errado

Endereço errado: 404

A Ana escreveu /usuarios no lugar de /users. O servidor existe, recebeu o pedido, mas não tem nada nesse caminho:

  final url = Uri.parse('https://jsonplaceholder.typicode.com/usuarios');

O app mostrou a tela de erro da seção 2: Exception: Erro 404 ao buscar os clientes. Quem escreveu essa mensagem fomos nós, no throw do if (resposta.statusCode != 200). E o console do navegador avisou: Failed to load resource: the server responded with a status of 404 () ("falhou ao carregar: o servidor respondeu com a situação 404"). Repare: um 404 não é um erro para o pacote http; o pedido deu certo, a resposta é que diz "não achei". Se você não conferir o statusCode, o app tenta decodificar a página de erro como se fosse a lista. Como consertar: confira o endereço na documentação do serviço (/users).

Servidor que não existe (ou sem internet) 
  final url = Uri.parse('https://jsonplaceholder.typicode.invalido/users');

Agora, sim, o próprio http.get lançou um erro: ClientException: Failed to fetch, uri=… ("exceção do cliente: falhou ao buscar"). O console do navegador explicou o motivo: Failed to load resource: net::ERR_NAME_NOT_RESOLVED, ou seja, o nome jsonplaceholder.typicode.invalido não existe na internet. Esse erro nem passa pelo nosso if: ele sai direto do await http.get, e o FutureBuilder o mostra em snapshot.error. Sem internet nenhuma, o efeito é parecido. (Essa é a mensagem do app rodando no navegador; num celular Android, o tipo do erro e o texto são outros, falando em host lookup, mas também caem no snapshot.hasError.)

Como consertar: confira o endereço. E, para o usuário, troque a mensagem técnica por uma amigável ("Sem conexão. Confira a internet e tente de novo.").

Esqueceu o import do pacote

Sem a linha import 'package:http/http.dart' as http;, o Dart não sabe quem é http, e o app nem compila:

lib/main.dart:21:26: Error: Undefined name 'http'.
  final resposta = await http.get(url);
                         ^^^^

"Nome não definido: http". O lib/main.dart:21:26 é o arquivo, a linha 21 e a coluna 26, onde o ^^^^ aponta: o Dart chegou no http.get e não sabe quem é http, porque o apelido só existe graças ao as http do import. (Saída do laboratório, que compila para a web; o compilador do Dart é o mesmo no flutter run do celular, que ainda acrescenta, no fim, Error: Failed to compile application..) Como consertar: ponha de volta import 'package:http/http.dart' as http; no topo do arquivo.

Rodou sem o flutter pub add http

Com o import certo, mas sem o pacote no pubspec.yaml, o laboratório compilou o app da seção 2 e recebeu:

Error: Couldn't resolve the package 'http' in 'package:http/http.dart'.
lib/main.dart:4:8: Error: Not found: 'package:http/http.dart'
import 'package:http/http.dart' as http;
       ^
lib/main.dart:22:31: Error: Method not found: 'get'.
  final resposta = await http.get(url);
                              ^^^

"Não consegui encontrar o pacote http"; "não achei package:http/http.dart" (linha 4, o import); e, como consequência, "método não encontrado: get" na linha 22. Leia sempre o primeiro erro: os outros costumam ser efeito dele. Como consertar: rode flutter pub add http na pasta do projeto.

Resumo

  • Acrescente o pacote com flutter pub add http e importe com import 'package:http/http.dart' as http;.
  • await http.get(Uri.parse(endereco)) faz o pedido; confira o statusCode (200 = deu certo) e decodifique o body com jsonDecode.
  • Mostre sempre as três telas com FutureBuilder: carregando, sucesso e erro (com um botão para tentar de novo).
  • Transforme status diferente de 200 em erro com throw; falhas de rede já chegam como erro sozinhas.
  • No Android publicado, peça a permissão android.permission.INTERNET.
