Flutter Comandos flutter

Quase tudo no Flutter se faz com um único programa de terminal, o flutter, seguido de uma palavra que diz o que fazer: flutter create, flutter run, flutter test… Esta página reúne os comandos do dia a dia, com as opções mais usadas e a saída real de cada um. O VS Code e o Android Studio chamam esses mesmos comandos por baixo dos botões (veja VS Code e Android Studio).

Todas as saídas vieram do computador da Ana (usuária ana, máquina notebook, um Ubuntu recém-instalado), com o Flutter 3.47.7 estável. Esse computador ainda não tem o Android SDK, o Chrome nem as ferramentas de Linux desktop, e alguns comandos mostram isso: é de propósito, porque são exatamente as mensagens que você vai ver antes de terminar a instalação (veja Instalar o Flutter).

flutter run

$ flutter run
Launching lib/main.dart on Linux in debug mode...
Building Linux application...
Error: CMake is required for Linux development.
It is likely available from your distribution (e.g.: apt install cmake), or can be downloaded from https://cmake.org/download/

Com um aparelho só, o flutter run escolheu o Linux sozinho e tentou compilar, mas faltou o CMake (o mesmo aviso que o flutter doctor deu). Com tudo instalado, o app abre e o terminal fica esperando as teclas abaixo. A aula Rodando o App mostra uma sessão completa.

-d chrome, -d linux, -d emulator-5554Escolhe o aparelho pelo id (o do flutter devices)

rHot reload: aplica as mudanças do código mantendo o estado
RHot restart: reinicia o app do zero (o estado se perde)

qFecha o app e sai

Conferir o código

flutter analyze

$ flutter analyze
Analyzing receitas...
No issues found! (ran in 12.9s)

Lê todo o código do projeto e lista erros, avisos e sugestões (as regras ficam em analysis_options.yaml), sem compilar nem rodar nada. Cada problema sai numa linha com o tipo (error, warning, info), a mensagem, o arquivo, a linha e o nome da regra. As mensagens mais comuns estão em Mensagens de Erro Comuns.

  material_color_utilities 0.13.0 (0.13.1 available)
  meta 1.18.3 (1.19.0 available)

O pub add escreve o pacote no pubspec.yaml e baixa; as linhas com + são os pacotes que entraram (o http e os que ele usa). O pub get só baixa o que o pubspec.yaml já pede: use-o depois de editar o arquivo à mão ou de baixar um projeto de outra pessoa. As linhas "available" são só avisos de versões novas. Para tirar um pacote: flutter pub remove nome.

Comando de projeto fora da pasta do projeto

$ flutter pub outdated
Error: No pubspec.yaml file found.
This command should be run from the root of your Flutter project.

"Nenhum pubspec.yaml encontrado. Este comando deve ser rodado na raiz do seu projeto Flutter." Os comandos pub, run, test, analyze e build trabalham no projeto da pasta atual. A Ana estava na pasta pessoal, e não dentro de loja. Como resolver: cd loja e rode de novo.

O build apk precisa do Android SDK, que a Ana ainda não instalou; com ele, o comando gera o arquivo em build/app/outputs/flutter-apk/ (veja Gerando o APK e o App Bundle). O clean apaga tudo o que a compilação gerou. Ele não mexe no seu código: é o "desligar e ligar de novo" do Flutter, útil quando uma compilação fica estranha depois de mudar pacotes ou trocar de versão. A próxima compilação demora mais, porque refaz tudo.

Comando de buildO que gera
flutter build apkUm APK para instalar direto no Android
flutter build appbundleO pacote .aab que a Google Play pede
flutter build webUm site estático em build/web/
flutter build ios / ipaO app de iPhone (só num Mac, com o Xcode)
flutter build linux / windows / macosO app de desktop (cada um no seu sistema)
