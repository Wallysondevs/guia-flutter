VS Code e Android Studio

Dá para escrever um app Flutter no Bloco de Notas e rodar tudo pelo terminal, mas ninguém faz isso. Um editor preparado para Flutter completa os nomes dos widgets enquanto você digita, sublinha os erros antes de você rodar, mostra a documentação de cada parâmetro, roda o app com uma tecla e faz o hot reload sozinho quando você salva. Os dois editores oficiais são o VS Code e o Android Studio. Esta aula mostra os dois e ajuda você a escolher.

Você vai aprender
  • O que um editor "com Flutter" faz por você.
  • A preparar o VS Code: a extensão Flutter, a paleta de comandos, a escolha do aparelho e o F5.
  • A preparar o Android Studio: o plugin Flutter, o SDK Manager e o emulador.
  • As teclas e os comandos que você vai usar todo dia.
  • Qual dos dois usar, e por que muita gente usa os dois.
  • Os problemas comuns: o editor que não acha o SDK e o aparelho que não aparece.
Ilustrativo

Os editores são programas de janela, e cada versão muda um pouco os menus. Os nomes de menus e comandos desta aula foram conferidos na documentação oficial (docs.flutter.dev/tools e docs.flutter.dev/platform-integration/android/setup), mas as telas dos editores não foram fotografadas. A tela do app e as saídas de terminal vieram do Flutter 3.47.7 do laboratório.

A ideia: a cozinha equipada

Dá para fazer um bolo com uma colher e uma tigela. Mas, numa cozinha equipada, a batedeira bate, o forno avisa quando esquentou e a balança pesa certinho. A receita é a mesma; o trabalho é muito menor.

1. VS Code

O Visual Studio Code (VS Code) é um editor gratuito da Microsoft, leve, para Windows, macOS e Linux. Sozinho, ele não sabe nada de Flutter: quem ensina é a extensão Flutter, da Dart Code, que instala junto a extensão Dart.

1.1 Preparar

  1. Instale o VS Code (code.visualstudio.com).
  2. Abra a aba de extensões (Ctrl+Shift+X), procure Flutter e clique em Install.
  3. Se o Flutter ainda não estiver instalado, a própria extensão oferece baixá-lo (aula Instalar o Flutter, seção "O jeito rápido").

1.2 O que você vai usar todo dia

Paleta de comandos (Ctrl+Shift+P)
A "central" do VS Code. Digite flutter e aparecem os comandos da extensão: Flutter: New Project (cria um projeto, como o flutter create), Flutter: Select Device (escolhe o aparelho), Flutter: Run Flutter Doctor, Flutter: Get Packages.
O aparelho, na barra de status
No canto de baixo, à direita, aparece o aparelho em que o app vai rodar (por exemplo, Chrome (web), Linux (desktop) ou o seu emulador). Clique nele para trocar.
F5 (Run › Start Debugging)
Roda o app no aparelho escolhido, em modo de depuração. É o mesmo que o flutter run (aula Rodando o App). Aparece uma barrinha de botões no alto: pausar, hot reload (o raio), hot restart (a seta circular), parar.
Ctrl+S (salvar)
Com o app rodando, salvar o arquivo faz o hot reload automaticamente (aula Hot Reload e Hot Restart).
Ctrl+. (a lâmpada)
Com o cursor num widget, mostra as correções e "refatorações" rápidas: Wrap with widget, Wrap with Padding, Wrap with Column, Remove this widget. Poupa a contagem de parênteses.
Shift+Alt+F (formatar)
Arruma a indentação do arquivo com o dart format. Com a vírgula no fim de cada parâmetro, cada widget fica numa linha (aula O Dart que Você Precisa).
Aba Problems (Ctrl+Shift+M)
A lista de erros e avisos do projeto inteiro: a mesma lista que o comando flutter analyze mostra no terminal.
Os "snippets"

Num arquivo .dart vazio, digite stless e aperte Enter: a extensão escreve o esqueleto inteiro de um StatelessWidget, e você só digita o nome. stful faz o mesmo para um StatefulWidget. Você vai conhecer os dois nas aulas StatelessWidget e StatefulWidget.

2. Android Studio

O Android Studio é o editor oficial do Google para Android. Ele é bem mais pesado que o VS Code, mas traz uma coisa que o VS Code não traz: as ferramentas do Android (o Android SDK) e o emulador, um celular Android de mentira que roda numa janela do seu computador. Para fazer app de Android, você precisa dele instalado, mesmo que escreva o código no VS Code.

2.1 Preparar

  1. Instale o Android Studio (developer.android.com/studio) e abra uma vez, aceitando a configuração padrão.
  2. Na tela Welcome to Android Studio, clique em Plugins, procure Flutter e instale (ele instala junto o plugin Dart). Reinicie o Android Studio.
  3. Abra o SDK Manager (More Actions › SDK Manager na tela de boas-vindas, ou Tools › SDK Manager com um projeto aberto). Na aba SDK Tools, confira que estão marcados: Android SDK Build-Tools, Android SDK Command-line Tools, Android Emulator e Android SDK Platform-Tools. Clique em Apply.
  4. No terminal, aceite as licenças do Android com flutter doctor --android-licenses (aula flutter doctor).
O plugin não instala o Flutter

A documentação oficial avisa: instalar o plugin Flutter no Android Studio não basta. O SDK do Flutter tem de estar instalado e no PATH (aula Instalar o Flutter). Na primeira vez, o Android Studio pergunta onde ele está: aponte a pasta develop/flutter.

2.2 O emulador

  1. Abra o Device Manager (More Actions › Virtual Device Manager, ou Tools › Device Manager).
  2. Clique no + (Create Virtual Device), escolha Phone e um modelo (um Pixel, por exemplo) e clique em Next.
  3. Escolha uma imagem do sistema (uma versão do Android) e baixe-a, se tiver o ícone de download.
  4. Em Additional settings, no item Graphics acceleration, escolha uma opção com Hardware (o emulador fica muito mais rápido).
  5. Clique em Finish e, depois, no botão de rodar (▶) ao lado do aparelho criado. Abre uma janela com um celular Android ligando.

Com o emulador aberto, ele aparece na lista de aparelhos do Flutter, tanto no Android Studio quanto no VS Code e no terminal (flutter devices).

Celular de verdade

No lugar do emulador, você pode usar o seu próprio celular Android: ative as Opções do desenvolvedor (no Android, toque 7 vezes em "Número da versão", em Configurações › Sobre o telefone) e, dentro delas, a Depuração USB; ligue o cabo e autorize o computador quando o celular perguntar. É mais leve que o emulador.

Experimente

Seja qual for o editor, o código é o mesmo. Esta missão imita o que a lâmpada ("Wrap with Padding") faz por você: encaixar um widget dentro de outro.

Missão: o texto está grudado na borda da tela. Encaixe o Text dentro de um Padding com padding: EdgeInsets.all(32), como o "Wrap with Padding" do editor faria. Dica: o Text vira o child do Padding.

import 'package:flutter/material.dart';

void main() {
  runApp(
    const MaterialApp(
      home: Scaffold(
        body: Text('Receitas da Ana: bolo de cenoura, pão de queijo e torta de limão'),
      ),
    ),
  );
}

import 'package:flutter/material.dart';

void main() {
  runApp(
    const MaterialApp(
      home: Scaffold(
        body: Padding(
          padding: EdgeInsets.all(32),
          child: Text('Receitas da Ana: bolo de cenoura, pão de queijo e torta de limão'),
        ),
      ),
    ),
  );
}

Repare na solução: o EdgeInsets.all(32) ficou sem const. Ele já está dentro de um const MaterialApp(...), e tudo o que fica dentro de um const já é constante; um segundo const ali seria só repetição. O Padding tem aula própria: Padding e Margem.

Qual usar?

A combinação mais comum: instalar os dois e programar no VS Code, usando o Android Studio só para o SDK Manager e o emulador. Se o seu computador tem pouca memória (8 GB ou menos), prefira o VS Code com um celular de verdade no cabo, no lugar do emulador. Este guia não depende de editor: tudo o que é feito por menu também tem o comando de terminal.

Quando dá errado

"Could not find a Flutter SDK"

O VS Code mostra um aviso parecido com esse quando a extensão não acha o Flutter, e o Android Studio pede o Flutter SDK path. Quase sempre o SDK não está no PATH, ou o editor foi aberto antes de você mexer no PATH. Como consertar: feche o editor por completo e abra de novo; se continuar, clique em Locate SDK e aponte a pasta develop/flutter. Confira no terminal com flutter --version (aula Instalar o Flutter).

O emulador não abre, ou é muito lento

O emulador precisa da aceleração de virtualização do processador (no Windows, o recurso Windows Hypervisor Platform; em muitos computadores, ela precisa ser ligada na BIOS) e de memória livre. Sem ela, o emulador recusa abrir ou fica lentíssimo. Como consertar: siga as instruções de aceleração do Android Studio (Configure hardware acceleration, em developer.android.com), escolha Hardware em Graphics acceleration, ou use um celular de verdade no cabo.

O hot reload "não fez nada"

Você salvou e a tela não mudou. Três suspeitos: o arquivo não foi salvo (a bolinha branca na aba do VS Code), o app não está rodando pelo editor (foi aberto por outro terminal), ou a mudança é das que o hot reload não aplica (por exemplo, no main). A aula Hot Reload e Hot Restart explica cada caso.

Resumo

  • Os editores oficiais do Flutter são o VS Code (com a extensão Flutter) e o Android Studio (com o plugin Flutter).
  • Eles completam nomes, mostram erros ao vivo e a documentação, rodam o app e fazem hot reload ao salvar.
  • No VS Code: paleta (Ctrl+Shift+P), aparelho na barra de status, F5 para rodar, Ctrl+. para a lâmpada.
  • Para Android, o Android Studio é necessário de qualquer jeito: ele traz o Android SDK (SDK Manager) e o emulador (Device Manager).
  • O plugin do editor não instala o Flutter: o SDK tem de estar instalado e no PATH.
  • Combinação comum: programar no VS Code e usar o Android Studio para o SDK e o emulador.
