Flutter Provider

Na aula InheritedWidget você viu como o Flutter entrega um dado para qualquer widget lá embaixo na árvore, sem passar de mão em mão. Funciona, mas dá trabalho: é muita classe para escrever. O provider (em inglês, "fornecedor") é um pacote que faz esse trabalho por você. Ele é, há anos, o jeito recomendado na documentação oficial do Flutter para começar a gerenciar estado que várias telas usam: o carrinho da lojinha, o usuário que fez login, o tema escolhido.

Você vai aprender
  • A instalar o pacote provider com flutter pub add.
  • A escrever uma classe de estado com ChangeNotifier e avisar as mudanças com notifyListeners().
  • A colocar o estado no topo do app com ChangeNotifierProvider.
  • A diferença entre context.watch (olhar e se redesenhar), context.read (só usar) e context.select (olhar só uma parte).
  • O widget Consumer, que redesenha só um pedacinho da tela.
  • A juntar vários estados com MultiProvider.
  • Os erros reais: ProviderNotFoundException, o watch fora do build e o notifyListeners esquecido.

Versões desta aula: provider 6.1.5+1, a versão mais nova no pub.dev em outubro de 2026, e o Flutter estável do laboratório da Ana (usuária ana, computador notebook).

A ideia: o quadro de avisos da cozinha

Na casa da Ana, a lista de compras fica num quadro de avisos na porta da geladeira. Quem acaba com o café escreve "café" no quadro. Quem vai ao mercado olha o quadro antes de sair. Ninguém precisa ligar para ninguém: o quadro está num lugar que todo mundo enxerga.

  1. O quadro é a classe de estado (o ChangeNotifier): guarda os dados e sabe mudá-los.
  2. Pendurar o quadro na porta da geladeira, onde todos passam, é o ChangeNotifierProvider: ele fica no alto da árvore de widgets, e todo widget abaixo dele alcança o quadro.
  3. Quem fica de olho no quadro (o ícone do carrinho, que mostra quantos itens tem) usa context.watch: toda vez que o quadro muda, ele se redesenha.
  4. Quem só escreve no quadro (o botão "adicionar") usa context.read: ele não precisa se redesenhar quando o quadro muda.

Sem o provider, o carrinho teria de ficar num StatefulWidget lá no alto, e a lista de itens e a função de adicionar desceriam de construtor em construtor, por widgets que nem usam esses dados (veja Passando Dados e Elevando o Estado). Com o provider, quem precisa pega direto do "quadro".

ChangeNotifierProvider<Carrinho>      « o quadro pendurado aqui em cima
 └─ MaterialApp
     └─ TelaProdutos
         ├─ AppBar
         │   └─ IconeCarrinho          « context.watch: mostra o total
         └─ ListView
             └─ ListTile (× 3)
                 └─ IconButton         « context.read: adiciona um item

2. O estado: uma classe ChangeNotifier

Primeiro, o "quadro". É uma classe Dart comum que estende ChangeNotifier (uma classe do próprio Flutter):

import 'package:flutter/foundation.dart';

class Carrinho extends ChangeNotifier {
  final List<String> _itens = [];

  List<String> get itens => List.unmodifiable(_itens);
  int get total => _itens.length;

  void adicionar(String item) {
    _itens.add(item);
    notifyListeners();
  }

  void limpar() {
    _itens.clear();
    notifyListeners();
  }
}
extends ChangeNotifier
"Avisador de mudanças". Dá à classe uma lista de ouvintes (quem quer saber quando algo muda) e o método notifyListeners().
final List<String> _itens
Os dados de verdade. O _ no começo do nome deixa a lista privada: de fora, ninguém consegue fazer carrinho._itens.add(…) escondido, sem avisar ninguém.
get itens / get total
O que os widgets podem ler. O List.unmodifiable devolve uma cópia que não aceita add: quem quiser mudar, tem de passar pelos métodos.
void adicionar(…)
O único jeito de mudar o carrinho: muda os dados e…
notifyListeners()
…avisa todos os ouvintes: "mudei!". É o equivalente do setState (veja setState): sem esta linha, os dados mudam mas a tela não fica sabendo (veja Quando dá errado).

Repare que essa classe não tem nada de tela: nenhum widget, nenhum build. Ela só guarda e muda dados. Isso é bom: dá para testar o carrinho sem abrir app nenhum.

3. Pendurar o quadro: ChangeNotifierProvider

Agora o carrinho vai para o topo do app, acima do MaterialApp, para todas as telas o alcançarem:

void main() {
  runApp(
    ChangeNotifierProvider(
      create: (context) => Carrinho(),
      child: const LojinhaApp(),
    ),
  );
}
ChangeNotifierProvider
Um widget do pacote provider. Ele cria o Carrinho, guarda e "pendura" para os filhos, e se inscreve como ouvinte: quando o carrinho chama notifyListeners(), ele avisa os widgets que estão de olho.
create: (context) => Carrinho()
Uma função que cria o estado. O provider a chama uma vez só, na primeira vez que alguém pede o carrinho, e guarda o objeto. Ele também chama o dispose() do carrinho quando sai da árvore: você não precisa se preocupar com isso.
child: const LojinhaApp()
O resto do app. Tudo o que estiver aqui dentro alcança o carrinho.
Onde colocar o provider?

O mais alto que precisa, e não mais. Um carrinho que várias telas usam vai acima do MaterialApp (porque cada tela nova do Navigator nasce debaixo dele). Um estado que só uma tela usa pode ficar só em volta dessa tela.

4. Ler o estado: context.watch e context.read

O app completo da lojinha. O import 'package:provider/provider.dart' traz os métodos watch e read para dentro do context:

import 'package:flutter/material.dart';
import 'package:provider/provider.dart';

  final List<String> _itens = [];

  List<String> get itens => List.unmodifiable(_itens);
  int get total => _itens.length;

  void adicionar(String item) {
    _itens.add(item);
    notifyListeners();
  }

  void limpar() {
    _itens.clear();
    notifyListeners();
  }
}

void main() {
  runApp(
    ChangeNotifierProvider(
      create: (context) => Carrinho(),
      child: const LojinhaApp(),
    ),
  );
}

class IconeCarrinho extends StatelessWidget {
  const IconeCarrinho({super.key});

  @override
  Widget build(BuildContext context) {
    final total = context.watch<Carrinho>().total;
    return Padding(
      padding: const EdgeInsets.only(right: 16),
      child: Badge(
        label: Text('$total'),
        child: const Icon(Icons.shopping_cart),
      ),
    );
  }
}
context.watch<Carrinho>()
"Me dê o carrinho e fique de olho nele." Devolve o Carrinho mais próximo acima deste widget, e inscreve o widget: a cada notifyListeners(), o build do IconeCarrinho roda de novo, e o número no selo muda. Use dentro do build.
context.read<Carrinho>()
"Me dê o carrinho, só isso." Não inscreve ninguém. É o certo dentro de onPressed: o botão só quer chamar adicionar; ele não muda de aparência quando o carrinho muda.
<Carrinho>
O tipo que você está procurando. O provider acha o estado pelo tipo: por isso cada tipo de estado tem a sua classe.
Badge
Um widget do Material 3 que desenha o selinho com o número sobre o ícone.

5. Consumer: redesenhar só um pedaço

O watch redesenha o widget inteiro onde ele está. Às vezes o estado é usado no meio de um build grande, e você quer redesenhar só um pedacinho. Para isso existe o widget Consumer ("consumidor"):

Consumer<Carrinho>(
  builder: (context, carrinho, child) {
    return Text('Itens no carrinho: ${carrinho.total}');
  },
)
Consumer<Carrinho>
Fica de olho no Carrinho, como o watch, mas só redesenha o que o builder devolve.
builder: (context, carrinho, child)
A função que monta o pedaço. O segundo parâmetro já é o carrinho, pronto para usar. O terceiro, child, é um widget opcional que você passa ao Consumer e que não é refeito a cada mudança (útil para um pedaço pesado que não depende do carrinho).

O watch e o Consumer fazem a mesma coisa; o Consumer é mais antigo e mais "verboso", mas é cômodo quando você não quer criar uma classe de widget nova só para isolar o redesenho.

6. context.select: olhar só uma parte

O watch redesenha a cada notifyListeners(), mesmo que a parte que o widget usa não tenha mudado. O select olha um valor só e só redesenha quando esse valor muda:

final total = context.select<Carrinho, int>((c) => c.total);
select<Carrinho, int>
O primeiro tipo é o estado; o segundo, o tipo do valor escolhido (aqui, um int).
(c) => c.total
A função que escolhe o valor. O widget só é redesenhado quando o resultado dela muda.

7. Vários estados: MultiProvider

Um app de verdade tem mais de um "quadro": o carrinho, o usuário, as preferências. Em vez de empilhar um provider dentro do outro, use o MultiProvider:

void main() {
  runApp(
    MultiProvider(
      providers: [
        ChangeNotifierProvider(create: (context) => Carrinho()),
        ChangeNotifierProvider(create: (context) => Usuario()),
        Provider(create: (context) => const Loja(nome: 'Lojinha da Ana')),
      ],
      child: const LojinhaApp(),
    ),
  );
}
providers: [ … ]
A lista de providers. Funciona exatamente como se um estivesse dentro do outro, na ordem da lista.
Provider(create: …)
O provider "simples": entrega um valor que não muda (não é ChangeNotifier), como uma configuração ou um serviço. Ninguém é redesenhado, porque ele nunca avisa mudança.

O pacote tem outros tipos (FutureProvider, StreamProvider, ProxyProvider…) para casos mais específicos; o ChangeNotifierProvider resolve a maior parte dos apps.

Formas diferentes de fazer a mesma coisa

Ler o carrinho dentro de um widget tem quatro jeitos. Todos estão no pacote:

FormaRedesenha quando muda?Quando usar
context.watch<Carrinho>()Sim, o widget inteiroDentro do build, para mostrar dados
context.select<Carrinho, int>((c) => c.total)Só quando o valor escolhido mudaDentro do build, quando o widget usa só um pedaço do estado
Consumer<Carrinho>(builder: …)Sim, só o que o builder devolvePara isolar o redesenho sem criar uma classe nova
context.read<Carrinho>()NãoEm onPressed, onTap, initState: para chamar métodos

Em código mais antigo você vai ver Provider.of<Carrinho>(context), que é o mesmo que watch, e Provider.of<Carrinho>(context, listen: false), que é o mesmo que read. Os métodos watch/read são só atalhos mais curtos.

E fora do provider? A aula Riverpod mostra o "sucessor" escrito pelo mesmo autor, e Uma Olhada no BLoC mostra outra escola. Para um estado que só um widget usa, continue com setState.

Este não dá erro nenhum. A Ana tirou o notifyListeners() do adicionar e pôs um print no lugar, para ver a lista:

Depois de dois toques, o console mostra a lista crescendo…

Carrinho: [Café]

Referência rápida

EscritaO que faz
flutter pub add providerInstala o pacote
class X extends ChangeNotifierClasse de estado que avisa mudanças
notifyListeners()"Mudei!": faz quem está de olho se redesenhar
ChangeNotifierProvider(create: (context) => X(), child: …)Cria o estado e o entrega aos widgets abaixo
MultiProvider(providers: [ … ], child: …)Vários providers de uma vez
context.watch<X>()Lê e fica de olho (no build)
context.read<X>()Só lê (em onPressed e afins)
context.select<X, T>((x) => …)Fica de olho em um valor só
Consumer<X>(builder: (context, x, child) => …)Redesenha só um pedaço

Resumo

  • O provider guarda um estado acima dos widgets que o usam, e cada widget o pega pelo tipo, sem passar de construtor em construtor.
  • A classe de estado estende ChangeNotifier; todo método que muda os dados termina com notifyListeners().
  • ChangeNotifierProvider(create: …, child: …) cria o estado e o entrega a toda a subárvore; MultiProvider junta vários.
  • context.watch no build para mostrar (e se redesenhar); context.read no onPressed para agir; select e Consumer para redesenhar menos.
  • ProviderNotFoundException = o widget não está debaixo do provider (ou pediu o tipo errado).
