Flutter Navigator: indo de uma tela para outra

Até aqui, cada app tinha uma tela só. Apps de verdade têm várias: a lista de receitas e, ao tocar numa, a tela da receita; o carrinho e a tela de pagamento; as configurações. No Flutter, cada tela é um widget (normalmente um Scaffold), e quem leva de uma para a outra é o Navigator ("navegador"): ele guarda as telas abertas numa pilha.

Você vai aprender
  • O que é a pilha de telas (as rotas) do Navigator.
  • Como abrir uma tela nova com Navigator.push e MaterialPageRoute.
  • Como voltar: Navigator.pop, a seta automática da AppBar e o botão Voltar do Android.
  • Como trocar de tela sem deixar volta (pushReplacement) e como limpar a pilha (pushAndRemoveUntil).
  • O erro real do context que não tem Navigator.

Esta aula usa telas separadas em widgets próprios, como em StatelessWidget. Passar dados de uma tela para outra (qual receita abrir, o que a tela devolveu) tem aula própria: Passando Dados entre Telas.

A ideia: a pilha de pratos

Pense numa pilha de pratos na pia. Você só mexe no prato de cima: põe um novo em cima, ou tira o de cima. O Navigator funciona igual, só que com telas (que ele chama de rotas, routes):

  1. O app abre com uma tela na pilha: a lista de receitas. É a que aparece.
  2. A Ana toca no bolo: o app faz push ("empurrar", pôr em cima) da tela do bolo. Agora a pilha tem duas telas, e a de cima é a que aparece. A lista continua lá embaixo, do jeito que estava.
  3. Ela toca na seta de voltar: o app faz pop ("tirar", o de cima). A tela do bolo sai, e a lista reaparece.
  push(bolo)              pop()
┌─────────────┐
│ Bolo        │  ← aparece
├─────────────┤        ┌─────────────┐
│ Lista       │        │ Lista       │  ← aparece de novo
└─────────────┘        └─────────────┘

1. A primeira navegação: push e pop

import 'package:flutter/material.dart';

void main() => runApp(const MaterialApp(home: TelaInicial()));

class TelaInicial extends StatelessWidget {
  const TelaInicial({super.key});

  @override
  Widget build(BuildContext context) {
    return Scaffold(
      appBar: AppBar(title: const Text('Receitas da Ana')),
      body: Center(
        child: FilledButton(
          onPressed: () {
            Navigator.push(
              context,
              MaterialPageRoute(builder: (context) => const TelaReceita()),
            );
          },
          child: const Text('Ver o bolo de cenoura'),
        ),
      ),
    );
  }
}

class TelaReceita extends StatelessWidget {
  const TelaReceita({super.key});

  @override
  Widget build(BuildContext context) {
    return Scaffold(
      appBar: AppBar(title: const Text('Bolo de cenoura')),
      body: Center(
        child: Column(
          mainAxisSize: MainAxisSize.min,
          children: [
            const Text('3 cenouras, 3 ovos, 2 xícaras de farinha'),
            const SizedBox(height: 16),
            OutlinedButton(
              onPressed: () {
                Navigator.pop(context);
              },
              child: const Text('Voltar para a lista'),
            ),
          ],
        ),
      ),
    );
  }
}
MaterialApp(home: TelaInicial())
O MaterialApp já cria um Navigator, e o home é a primeira tela da pilha.
class TelaReceita extends StatelessWidget
A segunda tela: um widget como outro qualquer, com o seu próprio Scaffold e a sua AppBar.
Navigator.push(context, …)
Põe uma tela nova em cima da pilha. O context é usado para achar o Navigator (ele procura para cima na árvore, até o do MaterialApp).
MaterialPageRoute(builder: (context) => const TelaReceita())
A rota: o "embrulho" da tela, que sabe fazer a animação de entrada e saída do jeito de cada plataforma (no Android, a tela sobe/aparece; no iPhone, desliza da direita). O builder é uma função que constrói a tela quando for a hora.
Navigator.pop(context)
Tira a tela de cima. A TelaInicial reaparece do jeito que estava.

A Ana abriu o app, tocou em Ver o bolo de cenoura e, na tela do bolo, tocou na seta do canto superior esquerdo:

A seta da AppBar aparece sozinha

Repare na segunda tela: você não escreveu nenhuma seta, mas a AppBar desenhou uma, à esquerda do título. A AppBar percebe que há uma tela embaixo na pilha e põe o botão de voltar, que faz o mesmo que o Navigator.pop(context). No Android, o botão (ou o gesto) Voltar do próprio celular também faz pop. Por isso o botão "Voltar para a lista" da segunda tela é opcional: muitos apps não têm.

E se a tela de baixo for a última? No Android, o Voltar na primeira tela fecha o app; não chame Navigator.pop na tela inicial esperando outra coisa.

2. Duas formas de escrever: Navigator.push e Navigator.of(context).push

Você vai ver as duas em tutoriais. Fazem exatamente a mesma coisa:

Navigator.push(context, MaterialPageRoute(builder: (context) => const TelaReceita()));

Navigator.of(context).push(MaterialPageRoute(builder: (context) => const TelaReceita()));

A primeira é um atalho para a segunda. O Navigator.of(context) acha o Navigator e devolve o "estado" dele, onde moram o push, o pop e os outros. Use a que achar mais fácil de ler; neste guia usamos a primeira.

3. Trocar de tela sem volta: pushReplacement

Depois do login, a pessoa vai para a tela inicial do app. Se ela apertar Voltar, não faz sentido cair de novo no login. Para isso, o pushReplacement ("empurrar substituindo") troca a tela de cima pela nova, em vez de pôr em cima:

// na tela de login, depois de conferir a senha:
Navigator.pushReplacement(
  context,
  MaterialPageRoute(builder: (context) => const TelaInicial()),
);

  antes                    depois do pushReplacement
┌─────────────┐          ┌─────────────┐
│ Login       │   →      │ Inicial     │  (sem seta de voltar)
└─────────────┘          └─────────────┘

Limpar a pilha inteira: pushAndRemoveUntil

No "Sair da conta", a pessoa pode estar 4 telas para dentro. O app tem de voltar ao login e esquecer todas as telas abertas:

Navigator.pushAndRemoveUntil(
  context,
  MaterialPageRoute(builder: (context) => const TelaLogin()),
  (rota) => false,
);

O terceiro parâmetro é uma função que olha cada rota da pilha e responde "pode ficar?". Respondendo sempre false, todas saem, e só o login fica. Para o contrário, voltar várias telas de uma vez até a primeira, existe o Navigator.popUntil(context, (rota) => rota.isFirst).

Qual usar

SituaçãoO que usar
Abrir uma tela de detalhe, com voltaNavigator.push
Voltar uma telaA seta da AppBar (automática) ou Navigator.pop(context)
Ir para uma tela sem deixar volta (login → início)Navigator.pushReplacement
Recomeçar do zero (sair da conta)Navigator.pushAndRemoveUntil(…, (rota) => false)
Voltar até a primeira telaNavigator.popUntil(context, (rota) => rota.isFirst)
Muitas telas, chamadas por nomeRotas nomeadas (aula Rotas Nomeadas)
App grande, com links da web e voltar do navegadorO pacote go_router (aula go_router)
Abas ou barra inferior (telas lado a lado, não empilhadas)Barra de Navegação Inferior e Abas

Quando dá errado

O context que não tem Navigator

O mesmo tropeço da aula Diálogos: tudo num widget só, que cria o MaterialApp, usando o context dele:

import 'package:flutter/material.dart';

void main() => runApp(const MeuApp());

class MeuApp extends StatelessWidget {
  const MeuApp({super.key});

  @override
  Widget build(BuildContext context) {
    return MaterialApp(
      home: Scaffold(
        body: Center(
          child: FilledButton(
            onPressed: () {
              Navigator.push(
                context,
                MaterialPageRoute(builder: (context) => const Text('Receita')),
              );
            },
            child: const Text('Abrir'),
          ),
        ),
      ),
    );
  }
}

Ao tocar em Abrir, nada acontece, e o console mostra (de um teste da Ana que toca no botão):

"O context usado no push ou no pop tem de ser de um widget descendente (abaixo) de um Navigator." O Navigator nasce dentro do MaterialApp; o context do MeuApp está acima dele.

Foi o push, chamado no botão que está no build do MeuApp. Repare no #1 Navigator.of: o atalho Navigator.push chama o Navigator.of(context) por dentro, e é ele que não acha o Navigator.

Como consertar: separe a tela num widget próprio e passe-o no home: (MaterialApp(home: TelaInicial())), como em todos os exemplos desta aula. Assim o context da tela fica abaixo do Navigator.

A tela nova sem Scaffold

No exemplo acima, a rota mostra só um Text('Receita'), sem Scaffold. Com o context consertado (a tela num widget próprio), fica assim:

import 'package:flutter/material.dart';

void main() => runApp(const MaterialApp(home: TelaInicial()));

class TelaInicial extends StatelessWidget {
  const TelaInicial({super.key});

  @override
  Widget build(BuildContext context) {
    return Scaffold(
      body: Center(
        child: FilledButton(
          onPressed: () {
            Navigator.push(
              context,
              MaterialPageRoute(builder: (context) => const Text('Receita')),
            );
          },
          child: const Text('Abrir'),
        ),
      ),
    );
  }
}

O texto saiu grande, vermelho e com sublinhado amarelo duplo: é o jeito do Flutter dizer "este texto não está dentro de um Material", então ele não recebeu o estilo do tema. Também não há AppBar nem seta de voltar, e o texto encosta no topo da tela. Como consertar: toda tela começa com um Scaffold (aula Scaffold e AppBar).

Referência rápida

ComandoO que faz com a pilha
Navigator.push(context, MaterialPageRoute(builder: (context) => Tela()))Põe a tela em cima
Navigator.pop(context)Tira a de cima
Navigator.pushReplacement(context, rota)Troca a de cima pela nova
Navigator.pushAndRemoveUntil(context, rota, (r) => false)Põe a nova e tira todas as outras
Navigator.popUntil(context, (r) => r.isFirst)Tira até sobrar a primeira
Navigator.canPop(context)true se há tela embaixo para voltar

Resumo

  • O Navigator guarda as telas numa pilha; aparece sempre a de cima. O MaterialApp já cria um, com o home na base.
  • Navigator.push(context, MaterialPageRoute(builder: (context) => Tela())) abre uma tela; Navigator.pop(context) volta.
  • A AppBar da tela nova ganha a seta de voltar sozinha; o Voltar do Android também faz pop.
  • pushReplacement troca a tela sem deixar volta; pushAndRemoveUntil limpa a pilha.
  • O context tem de estar abaixo do MaterialApp: cada tela num widget próprio.
