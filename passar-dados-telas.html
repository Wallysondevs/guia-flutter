Flutter: Passando Dados entre Telas

Na aula Navegação, a segunda tela era sempre a mesma: o bolo de cenoura. Mas o caderno da Ana tem dezenas de receitas, e ela não vai escrever uma tela para cada uma. Ela quer uma tela de receita que mostre a receita que foi tocada. Para isso, a primeira tela precisa mandar um dado para a segunda. E às vezes o caminho é o contrário: a segunda tela pergunta algo ("o que achou da receita?") e precisa devolver a resposta.

Você vai aprender
  • A ida: mandar um dado (um texto, um número, um objeto inteiro) para a próxima tela pelo construtor dela.
  • A volta: receber uma resposta com await Navigator.push e Navigator.pop(context, valor).
  • Como fazer a ida com rotas nomeadas: arguments e ModalRoute.of(context).
  • Os erros reais: o parâmetro obrigatório esquecido e o type 'Null' is not a subtype.

A ideia: a encomenda e o recibo

Quando a Ana manda o filho à padaria, ela entrega um bilhete: "6 pães e 1 litro de leite". Ele não precisa adivinhar: o pedido vai junto com ele. Na volta, ele traz o troco e o recibo.

  • A ida é o bilhete: no Flutter, é o parâmetro do construtor da tela nova: TelaReceita(receita: pudim). A tela recebe o dado ao nascer.
  • A volta é o troco: a tela que fecha devolve um valor no Navigator.pop(context, troco), e quem a abriu o recebe com await.

Você já viu essa volta na aula Diálogos: o diálogo também é uma rota, e o pop(context, true) do botão Apagar mandava a resposta de volta.

1. A ida: pelo construtor

A lista de receitas e uma tela de receita que serve para qualquer uma:

import 'package:flutter/material.dart';

void main() => runApp(const MaterialApp(home: ListaReceitas()));

class Receita {
  final String nome;
  final int minutos;
  final List<String> ingredientes;

  const Receita(this.nome, this.minutos, this.ingredientes);
}

const receitas = [
  Receita('Bolo de cenoura', 50, ['3 cenouras', '3 ovos', '2 xícaras de farinha']),
  Receita('Pudim', 90, ['1 lata de leite condensado', '3 ovos', '1 xícara de açúcar']),
  Receita('Brigadeiro', 20, ['1 lata de leite condensado', '1 colher de manteiga']),
];

class ListaReceitas extends StatelessWidget {
  const ListaReceitas({super.key});

  @override
  Widget build(BuildContext context) {
    return Scaffold(
      appBar: AppBar(title: const Text('Receitas da Ana')),
      body: ListView(
        children: [
          for (final receita in receitas)
            ListTile(
              title: Text(receita.nome),
              subtitle: Text('${receita.minutos} min'),
              trailing: const Icon(Icons.chevron_right),
              onTap: () {
                Navigator.push(
                  context,
                  MaterialPageRoute(
                    builder: (context) => TelaReceita(receita: receita),
                  ),
                );
              },
            ),
        ],
      ),
    );
  }
}

class TelaReceita extends StatelessWidget {
  final Receita receita;

  const TelaReceita({super.key, required this.receita});

  @override
  Widget build(BuildContext context) {
    return Scaffold(
      appBar: AppBar(title: Text(receita.nome)),
      body: ListView(
        padding: const EdgeInsets.all(16),
        children: [
          Text('Pronta em ${receita.minutos} minutos'),
          const SizedBox(height: 8),
          for (final ingrediente in receita.ingredientes) Text('• $ingrediente'),
        ],
      ),
    );
  }
}
class Receita { … }
Uma classe de dados com tudo o que uma receita tem (veja o Guia Dart, classes). Em vez de passar o nome, os minutos e os ingredientes separados, passamos o objeto inteiro.
const receitas = [ … ]
A lista de receitas. Num app de verdade, ela viria de um banco de dados ou da internet (nível 3).
final Receita receita;
A tela de receita ganha um campo: o dado que ela vai mostrar. É final porque não muda enquanto a tela existe.
const TelaReceita({super.key, required this.receita});
O construtor recebe a receita como parâmetro nomeado e obrigatório (required): não dá para abrir a tela sem dizer qual receita mostrar. O Dart confere isso antes de rodar.
TelaReceita(receita: receita)
A ida: na hora do push, a lista constrói a tela com a receita tocada. Repare que aqui não tem const: a receita muda conforme o toque.
Text(receita.nome)
Dentro da tela nova, o dado é só um campo: receita.nome, receita.minutos. (Num StatefulWidget, o State acessa o mesmo campo como widget.receita.)

2. A volta: await Navigator.push + Navigator.pop(context, valor)

Agora a tela do pudim tem um botão Avaliar, que abre uma tela com três opções. A opção escolhida tem de voltar para a tela do pudim:

import 'package:flutter/material.dart';

void main() => runApp(const MaterialApp(home: TelaReceita()));

class TelaReceita extends StatefulWidget {
  const TelaReceita({super.key});

  @override
  State<TelaReceita> createState() => _TelaReceitaState();
}

class _TelaReceitaState extends State<TelaReceita> {
  String? avaliacao;

  Future<void> avaliar() async {
    final resposta = await Navigator.push<String>(
      context,
      MaterialPageRoute(builder: (context) => const TelaAvaliar()),
    );
    debugPrint('voltou com: $resposta');
    if (resposta == null) return;
    setState(() {
      avaliacao = resposta;
    });
  }

  @override
  Widget build(BuildContext context) {
    return Scaffold(
      appBar: AppBar(title: const Text('Pudim')),
      body: Center(
        child: Column(
          mainAxisSize: MainAxisSize.min,
          children: [
            Text(avaliacao == null ? 'Ainda sem avaliação' : 'Sua avaliação: $avaliacao',
                style: const TextStyle(fontSize: 20)),
            const SizedBox(height: 16),
            FilledButton(onPressed: avaliar, child: const Text('Avaliar')),
          ],
        ),
      ),
    );
  }
}

class TelaAvaliar extends StatelessWidget {
  const TelaAvaliar({super.key});

  @override
  Widget build(BuildContext context) {
    return Scaffold(
      appBar: AppBar(title: const Text('O que achou?')),
      body: ListView(
        children: [
          for (final opcao in ['Adorei', 'Gostei', 'Não gostei'])
            ListTile(
              title: Text(opcao),
              onTap: () => Navigator.pop(context, opcao),
            ),
        ],
      ),
    );
  }
}
await Navigator.push<String>(…)
O push devolve um Future: a promessa do valor que vai voltar quando a tela nova fechar. O await espera; o <String> diz o tipo do valor. Enquanto a pessoa está na tela de avaliar, a função avaliar fica "parada" nessa linha.
Navigator.pop(context, opcao)
Na tela de avaliar: fecha a tela e manda opcao de volta. É ele que "cumpre a promessa" do push.
if (resposta == null) return;
Se a pessoa voltar pela seta (ou pelo Voltar do Android), a tela fecha sem valor, e a resposta é null. Por isso o tipo é String? e é preciso tratar o "não respondeu".
setState(() { avaliacao = resposta; })
Guarda a resposta e redesenha a tela do pudim.

A Ana tocou em Avaliar, escolheu Adorei, e a tela do pudim mostrou a resposta:

E o debugPrint mostrou no console:

voltou com: Adorei
Depois do await, confira o mounted

Neste exemplo usamos só setState, o que é seguro. Mas se depois do await você for usar o context (para um SnackBar, outro push), comece com if (!mounted) return;: enquanto a pessoa estava na outra tela, esta pode ter sido fechada. O flutter analyze avisa quando falta essa conferência (veja a missão final de Diálogos).

3. Com rotas nomeadas: arguments

Com rotas nomeadas (aula Rotas Nomeadas), a tabela constrói a tela sozinha, então não dá para passar o dado no construtor. O dado vai como arguments, e a tela o pega de volta da rota:

// a ida:
Navigator.pushNamed(context, '/receita', arguments: receita);

// na TelaReceita, dentro do build:
final receita = ModalRoute.of(context)!.settings.arguments as Receita;
arguments: receita
Qualquer objeto. O Navigator o guarda nas "configurações" da rota (o RouteSettings, aquele que aparecia como RouteSettings("/carrinho", null) na mensagem de erro da aula anterior: o null eram os argumentos).
ModalRoute.of(context)!
A rota em que esta tela está. O ! porque, em tese, um widget poderia estar fora de uma rota.
.settings.arguments as Receita
Os argumentos vêm como Object? (o Navigator não sabe o tipo). O as Receita diz ao Dart "confie em mim, é uma Receita". Se não for, é erro com o app rodando (veja abaixo).

A volta não muda: await Navigator.pushNamed<String>(…) e Navigator.pop(context, valor).

Qual usar

SituaçãoO que usar
Mandar um dado para a próxima telaParâmetro required no construtor: o Dart confere o tipo e se ele foi passado
Receber uma resposta da tela que fechouawait Navigator.push<T> + Navigator.pop(context, valor)
Mandar um dado com rotas nomeadasarguments + ModalRoute.of(context)!.settings.arguments as T (sem conferência antes de rodar)
Um dado que várias telas leem e mudam (o carrinho, o usuário logado)Não passe de mão em mão: guarde num lugar comum (aulas Elevando o Estado e Provider)

Quando dá errado

Esqueceu de passar o dado obrigatório

No app da seção 1, trocando TelaReceita(receita: receita) por TelaReceita():

$ flutter analyze lib
Analyzing lib...
  error • The named parameter 'receita' is required, but there's no corresponding argument. Try adding the required argument • lib/main.dart:37:43 • missing_required_argument
1 issue found. (ran in 5.2s)

"O parâmetro nomeado receita é obrigatório, mas não há argumento para ele." É o required trabalhando a seu favor: o erro aparece antes de rodar, apontando a linha 37 (a do builder), em vez de uma tela quebrada na mão do usuário. Como consertar: TelaReceita(receita: receita).

Rota nomeada aberta sem os arguments

A TelaReceita espera uma Receita nos argumentos, mas o botão fez só Navigator.pushNamed(context, '/receita'), sem arguments. Compila sem reclamar; o erro aparece quando a tela abre (de um teste da Ana que toca no botão):

Usou a resposta sem await

Sem o await, final resposta = Navigator.push<String>(…) guarda o Future, não a resposta, e a linha de baixo roda na hora, antes de a pessoa escolher qualquer coisa. Num Text('Sua avaliação: $resposta'), aparece uma descrição do Future (algo como "Instance of …Future…") em vez de "Adorei". Como consertar: await, numa função async.

Missão final: o nome que volta

Missão: a tela "Seu nome" tem um campo e um botão OK que só fecha a tela. Faça o OK devolver o que foi digitado: Navigator.pop(context, controle.text). A primeira tela já espera a resposta com await e mostra "Olá, …".

import 'package:flutter/material.dart';

void main() => runApp(const MaterialApp(home: Inicio()));

class Inicio extends StatefulWidget {
  const Inicio({super.key});

  @override
  State<Inicio> createState() => _InicioState();
}

class _InicioState extends State<Inicio> {
  String nome = 'visitante';

  Future<void> perguntarNome() async {
    final resposta = await Navigator.push<String>(
      context,
      MaterialPageRoute(builder: (context) => const TelaNome()),
    );
    if (resposta == null || resposta.isEmpty) return;
    setState(() {
      nome = resposta;
    });
  }

  @override
  Widget build(BuildContext context) {
    return Scaffold(
      appBar: AppBar(title: const Text('Boas-vindas')),
      body: Center(
        child: Column(
          mainAxisSize: MainAxisSize.min,
          children: [
            Text('Olá, $nome!', style: const TextStyle(fontSize: 24)),
            FilledButton(onPressed: perguntarNome, child: const Text('Mudar nome')),
          ],
        ),
      ),
    );
  }
}

class TelaNome extends StatefulWidget {
  const TelaNome({super.key});

  @override
  State<TelaNome> createState() => _TelaNomeState();
}

class _TelaNomeState extends State<TelaNome> {
  final controle = TextEditingController();

  @override
  void dispose() {
    controle.dispose();
    super.dispose();
  }

  @override
  Widget build(BuildContext context) {
    return Scaffold(
      appBar: AppBar(title: const Text('Seu nome')),
      body: Padding(
        padding: const EdgeInsets.all(16),
        child: Column(
          children: [
            TextField(
              controller: controle,
              decoration: const InputDecoration(labelText: 'Nome'),
            ),
            FilledButton(
              onPressed: () => Navigator.pop(context),
              child: const Text('OK'),
            ),
          ],
        ),
      ),
    );
  }
}

Resumo

  • Ida: a tela nova recebe o dado no construtor (final + required this.dado), e quem abre passa: TelaReceita(receita: r).
  • Volta: final r = await Navigator.push<T>(…) espera; Navigator.pop(context, valor) responde. Voltando pela seta, chega null.
  • Com rotas nomeadas: arguments na ida e ModalRoute.of(context)!.settings.arguments as T na tela; sem conferência antes de rodar.
  • Dados que muitas telas compartilham não devem ir de mão em mão: veja Elevando o Estado e Provider.
