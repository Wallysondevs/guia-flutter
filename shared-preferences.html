Flutter shared_preferences

Tudo o que você guardou até agora com setState mora na memória do app: fechou o app, sumiu. A Ana conta os bolos que vende no dia num app; se o celular reinicia na hora do almoço, a conta volta a zero. Para coisas pequenas que precisam sobreviver ao fechamento do app (um número, o tema escolhido, o nome do usuário), o Flutter usa o pacote shared_preferences ("preferências compartilhadas").

Você vai aprender
  • A diferença entre o estado na memória e um dado guardado no aparelho.
  • Como acrescentar o pacote (flutter pub add shared_preferences).
  • Como gravar, ler e apagar com SharedPreferencesAsync: setInt, getInt, remove.
  • Os tipos que ele guarda e onde cada sistema guarda.
  • A API antiga (SharedPreferences.getInstance()), que você vai ver em muitos tutoriais.
  • Os erros: o await esquecido e a chave escrita diferente.

Os exemplos rodaram no laboratório do guia (Flutter 3.47, shared_preferences 2.5), no navegador. No navegador, o pacote guarda os dados no localStorage; no celular, no lugar próprio de cada sistema (tabela mais abaixo). O código é o mesmo.

A ideia: o caderninho do caixa

A conta de cabeça (a memória) é rápida, mas se a Ana se distrai, perde. Por isso, a cada bolo vendido, ela também anota num caderninho que fica na gaveta do caixa. No dia seguinte, ou depois do almoço, é só abrir o caderninho e continuar de onde parou.

O shared_preferences é esse caderninho: um lugar com pares chave → valor ('bolos_vendidos' → 3), guardado num arquivo do aparelho, que continua lá depois que o app fecha. Ele é feito para coisas pequenas e simples. A própria página do pacote avisa: ele não deve guardar dados críticos (a gravação no disco pode não ter terminado quando o comando volta). Para listas grandes, o certo é um banco de dados (próxima aula, sqflite).

2. O contador de bolos que não esquece

import 'package:flutter/material.dart';
import 'package:shared_preferences/shared_preferences.dart';

void main() => runApp(const MeuApp());

class MeuApp extends StatelessWidget {
  const MeuApp({super.key});

  @override
  Widget build(BuildContext context) {
    return const MaterialApp(
      debugShowCheckedModeBanner: false,
      home: TelaVendas(),
    );
  }
}

class TelaVendas extends StatefulWidget {
  const TelaVendas({super.key});

  @override
  State<TelaVendas> createState() => _TelaVendasState();
}

class _TelaVendasState extends State<TelaVendas> {
  final _prefs = SharedPreferencesAsync();
  int _vendidos = 0;

  @override
  void initState() {
    super.initState();
    _carregar();
  }

  Future<void> _carregar() async {
    final salvo = await _prefs.getInt('bolos_vendidos');
    setState(() {
      _vendidos = salvo ?? 0;
    });
  }

  Future<void> _vender() async {
    setState(() {
      _vendidos++;
    });
    await _prefs.setInt('bolos_vendidos', _vendidos);
  }

  Future<void> _zerar() async {
    await _prefs.remove('bolos_vendidos');
    setState(() {
      _vendidos = 0;
    });
  }

  @override
  Widget build(BuildContext context) {
    return Scaffold(
      appBar: AppBar(
        title: const Text('Bolos da Ana'),
        actions: [
          IconButton(
            tooltip: 'Zerar',
            onPressed: _zerar,
            icon: const Icon(Icons.delete_outline),
          ),
        ],
      ),
      body: Center(
        child: Text(
          'Bolos vendidos: $_vendidos',
          style: const TextStyle(fontSize: 28),
        ),
      ),
      floatingActionButton: FloatingActionButton.extended(
        onPressed: _vender,
        icon: const Icon(Icons.cake),
        label: const Text('Vender bolo'),
      ),
    );
  }
}
import 'package:shared_preferences/shared_preferences.dart';
Traz o pacote.
final _prefs = SharedPreferencesAsync();
O "caderninho". A página do pacote recomenda, para código novo, o SharedPreferencesAsync (ou o SharedPreferencesWithCache); a forma antiga aparece na seção 3. Como o nome diz, tudo nele é assíncrono: cada leitura e gravação devolve um Future.
_carregar() no initState
Quando a tela nasce, lê o que estava guardado. O initState não pode ser async, por isso a leitura fica numa função separada (Future<void> _carregar() async) que o initState só chama.
await _prefs.getInt('bolos_vendidos')
Lê o número guardado na chave 'bolos_vendidos'. Devolve int?: null se nada foi guardado ainda (a primeira vez que o app abre).
salvo ?? 0
"Se for nulo, use 0". Depois, o setState redesenha a tela com o valor lido.
await _prefs.setInt('bolos_vendidos', _vendidos)
Grava o número novo, a cada venda. O setState vem antes: a tela muda na hora, e a gravação acontece logo depois.
await _prefs.remove('bolos_vendidos')
Apaga a chave (o botão de lixeira, Zerar). Depois disso, o getInt volta a devolver null.

Provando que ficou guardado

Para mostrar no laboratório que o número sobrevive, sem desligar nada, pusemos a TelaVendas dentro de um widget que tem um botão Fechar e abrir a tela de novo. O botão troca a key da tela, e o Flutter joga fora o State antigo (com o _vendidos da memória) e cria um novo do zero, que roda o initState e lê o caderninho de novo. É o que acontece quando o app é fechado e aberto:

// Só para o laboratório: joga fora a TelaVendas e cria outra do zero,
// como se o app tivesse sido fechado e aberto de novo.
class Reabrir extends StatefulWidget {
  const Reabrir({super.key});

  @override
  State<Reabrir> createState() => _ReabrirState();
}

class _ReabrirState extends State<Reabrir> {
  int _vez = 0;

  @override
  Widget build(BuildContext context) {
    return Column(
      children: [
        Expanded(child: TelaVendas(key: ValueKey(_vez))),
        Material(
          child: TextButton(
            onPressed: () => setState(() => _vez++),
            child: const Text('Fechar e abrir a tela de novo'),
          ),
        ),
      ],
    );
  }
}

3. Outras formas e os detalhes

Os tipos que ele guarda

TipoGravarLer
intsetInt(chave, 3)getInt(chave)
doublesetDouble(chave, 4.5)getDouble(chave)
boolsetBool(chave, true)getBool(chave)
StringsetString(chave, 'Ana')getString(chave)
List<String>setStringList(chave, ['a', 'b'])getStringList(chave)

Só esses. Para guardar um objeto (um Cliente), dá para transformar em texto com jsonEncode(cliente.toJson()) e guardar como String (veja JSON e Classes de Modelo); mas, se forem muitos, use um banco de dados.

A API antiga: SharedPreferences.getInstance()

Em quase todos os tutoriais (e em muito código de verdade) você vai ver esta forma:

final prefs = await SharedPreferences.getInstance();
final salvo = prefs.getInt('bolos_vendidos');   // sem await: lê de uma cópia na memória
await prefs.setInt('bolos_vendidos', 4);

Ela funciona, mas a página do pacote avisa que será descontinuada no futuro e incentiva quem está começando a usar o SharedPreferencesAsync ou o SharedPreferencesWithCache. A diferença que você nota: na antiga, depois do getInstance(), as leituras (getInt) não precisam de await, porque ela mantém uma cópia na memória.

SituaçãoQual usar
Código novo, leituras de vez em quandoSharedPreferencesAsync
Código novo, muitas leituras e você quer lê-las sem awaitSharedPreferencesWithCache
Projeto que já usa a forma antigaSharedPreferences.getInstance() (funciona; migre quando puder)
Listas grandes, buscas, ordenaçãoBanco de dados: sqflite
Senhas, tokensNenhum destes: use um pacote de armazenamento seguro (como o flutter_secure_storage)

Quando dá errado

Esqueceu o await na leitura 
  Future<void> _carregar() async {
    final salvo = _prefs.getInt('bolos_vendidos');
    setState(() {
      _vendidos = salvo ?? 0;
    });
  }

lib/main.dart:38:25:
Error: A value of type 'Object' can't be assigned to a variable of type 'int'.
 - 'Object' is from 'dart:core'.
      _vendidos = salvo ?? 0;
                        ^
Error: Compilation failed.

O app nem compila: "um valor do tipo Object não pode ser guardado numa variável do tipo int" (linha 38, coluna 25, onde o ^ aponta). A mensagem parece não ter nada a ver, mas faz sentido: sem o await, o salvo não é o número, e sim um Future<int?> (a senha, não o bolo; veja FutureBuilder). Um Future nunca é nulo, então o salvo ?? 0 pode dar um Future ou um int, e o tipo comum entre os dois é Object. Como consertar: final salvo = await _prefs.getInt('bolos_vendidos');. No setInt, esquecer o await compila, mas aí o código seguinte pode rodar antes de a gravação terminar.

A chave escrita de dois jeitos

A Ana grava com setInt('bolos_vendidos', …) e lê com getInt('bolo_vendidos') (sem o s). Não aparece erro nenhum: a leitura simplesmente devolve null, e o contador volta a 0 toda vez que o app abre. Como evitar: escreva a chave uma vez só, numa constante: const chaveVendidos = 'bolos_vendidos';, e use a constante nos dois lugares. Um erro de digitação no nome da constante o Dart pega na hora.

Rodou com recarga a quente logo depois do pub add (ilustrativo)

Pacotes como este têm uma parte escrita para cada sistema (Kotlin no Android, Swift no iOS). Se você acrescentar o pacote com o app rodando e só apertar r (recarga a quente), essa parte não entra no app, e a primeira chamada falha com um erro MissingPluginException ("faltou a implementação do plugin"). Como consertar: pare o app e rode flutter run de novo depois de qualquer flutter pub add (veja Hot Reload e Hot Restart).

Resumo

  • O estado do setState vive na memória e some quando o app fecha; o shared_preferences guarda pares chave → valor no aparelho.
  • Para código novo: SharedPreferencesAsync(), com await em tudo: setInt/getInt, setString/getString, remove.
  • Leia no começo (função async chamada no initState) e grave a cada mudança.
  • Só tipos simples (int, double, bool, String, List<String>) e dados pequenos, nunca críticos nem senhas.
  • Guarde o nome da chave numa constante para não escrever de dois jeitos.
