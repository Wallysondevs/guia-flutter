Flutter Temas (ThemeData)

A Ana decidiu que o app de receitas vai ser verde, a cor da horta. Ela poderia escrever color: Colors.green em cada botão, cada barra, cada ícone… e, no mês que vem, quando mudar de ideia, trocar tudo de novo, um por um. O Flutter tem um jeito melhor: o tema. Você descreve as cores, os textos e o jeito dos componentes uma vez, no MaterialApp, e todos os widgets do app seguem. Esse "manual de estilo" é o ThemeData ("dados do tema").

Você vai aprender
  • Onde mora o tema (MaterialApp(theme: ThemeData(...))) e o que ele muda.
  • A pintar o app inteiro a partir de uma cor só, com colorSchemeSeed.
  • A ler o tema dentro dos seus widgets com Theme.of(context): as cores e os estilos de texto.
  • A mudar o jeito de um tipo de componente no app todo: appBarTheme, filledButtonTheme, cardTheme.
  • A dar um tema diferente a um pedaço da tela com o widget Theme e o copyWith.
  • Os erros reais: o Theme.of que lê o tema errado e o estilo de texto que pode ser null.

Tudo nesta aula foi compilado com o Flutter 3.47 no laboratório do guia. As cores em detalhe (o ColorScheme) são o assunto da próxima aula, Material 3 e ColorScheme; o modo escuro vem logo depois, em Tema Escuro.

A ideia: o manual de identidade visual

A padaria do bairro tem um "manual da marca": a cor do toldo, a letra do cardápio, o formato das etiquetas. Quem pinta a placa nova, quem imprime o saquinho e quem faz o cardápio consultam o manual, em vez de inventar. Quando a padaria muda de cor, muda o manual, e tudo o que for feito depois sai com a cor nova.

Na padariaNo Flutter
O manual da marcaO ThemeData, no theme: do MaterialApp
As cores da marcaO colorScheme (gerado do colorSchemeSeed)
As letras do cardápio (título, texto, legenda)O textTheme
"Etiquetas sempre com cantos redondos"Os temas de componente: cardTheme, filledButtonTheme…

1. O app sem tema

Para ver o que o tema muda, primeiro uma "vitrine" com os componentes mais comuns, sem tema nenhum:

import 'package:flutter/material.dart';

void main() => runApp(const ReceitasApp());

class ReceitasApp extends StatelessWidget {
  const ReceitasApp({super.key});

  @override
  Widget build(BuildContext context) {
    return const MaterialApp(
      debugShowCheckedModeBanner: false,
      home: VitrinePage(),
    );
  }
}

class VitrinePage extends StatelessWidget {
  const VitrinePage({super.key});

  @override
  Widget build(BuildContext context) {
    return Scaffold(
      appBar: AppBar(title: const Text('Receitas da Ana')),
      body: ListView(
        padding: const EdgeInsets.all(16),
        children: [
          const Card(
            child: ListTile(
              leading: Icon(Icons.cake),
              title: Text('Bolo de cenoura'),
              subtitle: Text('40 min · fácil'),
            ),
          ),
          const SizedBox(height: 16),
          FilledButton(onPressed: () {}, child: const Text('Ver receita')),
          const SizedBox(height: 8),
          OutlinedButton(onPressed: () {}, child: const Text('Favoritar')),
          const SizedBox(height: 16),
          const Switch(value: true, onChanged: null),
        ],
      ),
      floatingActionButton: FloatingActionButton(
        onPressed: () {},
        child: const Icon(Icons.add),
      ),
    );
  }
}

Sem tema, o Flutter usa a paleta padrão do Material 3, gerada de um roxo: o botão "Ver receita" é roxo, o texto do "Favoritar" é roxo, o botão flutuante (o + no canto) é lilás e até o fundo da tela tem um leve tom rosado. O interruptor está cinza porque está desligado para toques (onChanged: null): um componente desativado usa tons neutros, com qualquer tema.

2. Uma cor para o app inteiro: colorSchemeSeed

Agora, uma linha no MaterialApp. A VitrinePage não muda nada:

    return MaterialApp(
      debugShowCheckedModeBanner: false,
      theme: ThemeData(colorSchemeSeed: Colors.green),
      home: const VitrinePage(),
    );
theme:
O parâmetro do MaterialApp que recebe o tema. Tudo o que estiver abaixo do MaterialApp (todas as telas) usa esse tema.
ThemeData(...)
O "manual": um objeto com dezenas de parâmetros (cores, textos, temas de cada componente). Você só preenche o que quer mudar; o resto fica no padrão do Material 3.
colorSchemeSeed: Colors.green
A cor-semente. A partir de uma cor só, o Flutter calcula uma paleta inteira que combina: o verde principal dos botões, um verde clarinho para fundos de destaque, o fundo levemente esverdeado, a cor do texto sobre cada fundo. É por isso que o botão cheio, o texto do botão contornado, o botão flutuante, o fundo do cartão e até o fundo da tela mudaram juntos.

Compare com a foto anterior: o "Ver receita" virou um verde-escuro, o "Favoritar" ganhou texto verde, o botão flutuante ficou verde-claro e o fundo da tela e do cartão ganharam um tom esverdeado bem leve. A AppBar continua com a cor do fundo: no Material 3, a barra de cima é discreta por padrão (a seção 4 mostra como pintá-la). Repare também que o verde do botão não é o Colors.green vivo da semente: o Flutter ajusta o tom para o texto branco ficar legível em cima dele.

Missão: experimente outra cor-semente: troque o Colors.green por Colors.purple, Colors.teal ou a sua cor favorita, e veja a vitrine inteira mudar.

3. Lendo o tema: Theme.of(context)

Os componentes do Material já consultam o tema sozinhos. Os seus widgets também podem: em vez de escrever uma cor ou um tamanho de letra à mão, peça ao tema. Assim, quando o tema mudar, eles mudam junto:

import 'package:flutter/material.dart';

void main() => runApp(const ReceitasApp());

class ReceitasApp extends StatelessWidget {
  const ReceitasApp({super.key});

  @override
  Widget build(BuildContext context) {
    return MaterialApp(
      debugShowCheckedModeBanner: false,
      theme: ThemeData(colorSchemeSeed: Colors.green),
      home: const ReceitaPage(),
    );
  }
}

class ReceitaPage extends StatelessWidget {
  const ReceitaPage({super.key});

  @override
  Widget build(BuildContext context) {
    final tema = Theme.of(context);
    return Scaffold(
      appBar: AppBar(title: const Text('Receitas da Ana')),
      body: Padding(
        padding: const EdgeInsets.all(16),
        child: Column(
          crossAxisAlignment: CrossAxisAlignment.start,
          children: [
            Text('Bolo de cenoura', style: tema.textTheme.headlineMedium),
            Text('40 minutos · rende 12 fatias', style: tema.textTheme.bodySmall),
            const SizedBox(height: 16),
            Container(
              padding: const EdgeInsets.all(12),
              color: tema.colorScheme.primaryContainer,
              child: Text(
                'Dica: use cenouras bem laranjas.',
                style: TextStyle(color: tema.colorScheme.onPrimaryContainer),
              ),
            ),
          ],
        ),
      ),
    );
  }
}
final tema = Theme.of(context);
"Me dê o tema que vale aqui." O Theme.of sobe pela árvore a partir do context até achar o tema (o do MaterialApp, ou um mais próximo, seção 5). Guardar numa variável evita repetir Theme.of(context) a cada linha.
tema.textTheme.headlineMedium
Um dos estilos de texto prontos do tema. O Material 3 tem 15, em cinco grupos de três tamanhos (Large, Medium, Small): display (enormes), headline (títulos de tela), title (títulos de seção), body (texto corrido) e label (botões e etiquetas).
tema.colorScheme.primaryContainer
Uma cor da paleta: um tom claro da cor principal, para fundos de destaque.
tema.colorScheme.onPrimaryContainer
A cor para escrever sobre o primaryContainer. No Material 3, cada cor de fundo tem a sua cor "on" ("sobre"), já escolhida para ter contraste. Usando o par, o texto sempre fica legível, até no modo escuro.
E o TextStyle com fontSize?

Na aula Estilos de Texto, a Ana escrevia TextStyle(fontSize: 28, fontWeight: FontWeight.bold). Funciona, mas cada tela acaba com um tamanho diferente. Com os estilos do tema, todo título de tela é headlineMedium, e mudar o tamanho de todos é mudar um lugar. Quando precisar ajustar só um detalhe, junte os dois: tema.textTheme.headlineMedium?.copyWith(fontWeight: FontWeight.bold) (o ?. está explicado em Quando dá errado).

4. O jeito de cada componente

A Ana quer, no app todo: a AppBar verde com letras brancas e o título no meio; os botões cheios com cantos menos redondos; e os cartões com borda fina em vez de sombra. Cada tipo de componente tem o seu "subtema" dentro do ThemeData:

    return MaterialApp(
      debugShowCheckedModeBanner: false,
      theme: ThemeData(
        colorSchemeSeed: Colors.green,
        appBarTheme: const AppBarThemeData(
          backgroundColor: Colors.green,
          foregroundColor: Colors.white,
          centerTitle: true,
        ),
        filledButtonTheme: FilledButtonThemeData(
          style: FilledButton.styleFrom(
            shape: RoundedRectangleBorder(borderRadius: BorderRadius.circular(8)),
          ),
        ),
        cardTheme: CardThemeData(
          elevation: 0,
          shape: RoundedRectangleBorder(
            side: const BorderSide(color: Colors.black26),
            borderRadius: BorderRadius.circular(12),
          ),
        ),
      ),
      home: const VitrinePage(),
    );
appBarTheme: AppBarThemeData(...)
O jeito de todas as AppBar do app: backgroundColor (fundo), foregroundColor (título e ícones) e centerTitle (título no meio). No Material 3, a barra é clara por padrão; quem quer a barra colorida pede aqui.
filledButtonTheme: FilledButtonThemeData(style: ...)
O estilo de todos os FilledButton. O FilledButton.styleFrom(...) é o mesmo que você usaria num botão só (aula Botões), agora valendo para todos. Cada tipo de botão tem o seu: elevatedButtonTheme, outlinedButtonTheme, textButtonTheme.
cardTheme: CardThemeData(...)
Todos os Card: sem sombra (elevation: 0) e com borda fina.
AppBarTheme ou AppBarThemeData?

Em tutoriais mais antigos você vai ver appBarTheme: AppBarTheme(...) e cardTheme: CardTheme(...). Nas versões recentes do Flutter, o que vai dentro do ThemeData são as classes terminadas em Data (AppBarThemeData, CardThemeData); os nomes sem Data agora são widgets que aplicam um subtema a um pedaço da árvore. No Flutter 3.47 do laboratório, o cardTheme só aceita CardThemeData.

5. Um tema só para um pedaço: Theme e copyWith

Na tela de receitas, a Ana quer que só a área de "Receitas de Natal" fique vermelha, sem mexer no resto do app. O widget Theme troca o tema para os filhos dele:

import 'package:flutter/material.dart';

void main() => runApp(const ReceitasApp());

class ReceitasApp extends StatelessWidget {
  const ReceitasApp({super.key});

  @override
  Widget build(BuildContext context) {
    return MaterialApp(
      debugShowCheckedModeBanner: false,
      theme: ThemeData(colorSchemeSeed: Colors.green),
      home: const ReceitasPage(),
    );
  }
}

class ReceitasPage extends StatelessWidget {
  const ReceitasPage({super.key});

  @override
  Widget build(BuildContext context) {
    return Scaffold(
      appBar: AppBar(title: const Text('Receitas da Ana')),
      body: Padding(
        padding: const EdgeInsets.all(16),
        child: Column(
          crossAxisAlignment: CrossAxisAlignment.stretch,
          children: [
            FilledButton(onPressed: () {}, child: const Text('Receitas do dia a dia')),
            const SizedBox(height: 16),
            Theme(
              data: ThemeData(colorSchemeSeed: Colors.red),
              child: FilledButton(
                onPressed: () {},
                child: const Text('Receitas de Natal'),
              ),
            ),
          ],
        ),
      ),
    );
  }
}
Theme(data: ..., child: ...)
Um tema que vale só para o child e tudo abaixo dele. O Theme.of(context) de quem está lá dentro acha este tema primeiro, porque ele está mais perto.
data: ThemeData(colorSchemeSeed: Colors.red)
Um tema novo, do zero. Cuidado: "do zero" quer dizer que tudo o que o tema do app tinha de especial (o cardTheme, o appBarTheme…) não vale aqui dentro.

Para herdar o tema do app e mudar só um detalhe, use o copyWith ("cópia com"): ele copia o tema atual e troca só o que você pedir:

Theme(
  data: Theme.of(context).copyWith(
    colorScheme: ColorScheme.fromSeed(seedColor: Colors.red),
  ),
  child: FilledButton(onPressed: () {}, child: const Text('Receitas de Natal')),
),

Aqui, o botão de Natal fica vermelho, mas continua com o formato definido no filledButtonTheme do app.

Formas diferentes de fazer

JeitoQuando usar
Cor escrita no widget: FilledButton.styleFrom(backgroundColor: Colors.green)Uma exceção, num lugar só. Se você se pegar repetindo, é hora de ir para o tema
ThemeData(colorSchemeSeed: ...)O começo de todo app: uma cor e o Flutter faz a paleta
ThemeData(colorScheme: ColorScheme.fromSeed(...))O mesmo, com mais controle sobre a paleta (aula Material 3 e ColorScheme)
Temas de componente (appBarTheme, cardTheme…)Mudar o jeito de um tipo de componente no app todo
Theme(data: Theme.of(context).copyWith(...))Um pedaço da tela diferente do resto, herdando o tema
Organize o tema num arquivo próprio

Quando o ThemeData cresce, ele toma conta do MaterialApp. Um costume comum é tirá-lo para uma função ou variável num arquivo lib/tema.dart: final temaClaro = ThemeData(...);, e no app, theme: temaClaro. Fica mais fácil de achar e, na aula Tema Escuro, de ter um irmão: o temaEscuro.

Quando dá errado

O Theme.of que lê o tema errado 
class ReceitasApp extends StatelessWidget {
  const ReceitasApp({super.key});

  @override
  Widget build(BuildContext context) {
    final verde = Theme.of(context).colorScheme.primary;
    return MaterialApp(
      debugShowCheckedModeBanner: false,
      theme: ThemeData(colorSchemeSeed: Colors.green),
      home: Scaffold(
        body: Center(
          child: Text('Receitas da Ana',
              style: TextStyle(fontSize: 28, color: verde)),
        ),
      ),
    );
  }
}

Nenhuma mensagem de erro, e o fundo da tela até saiu esverdeado (ele é desenhado pelo Scaffold, que fica dentro do MaterialApp). Mas o título saiu roxo. O Theme.of(context) foi chamado com o context do ReceitasApp, que fica acima do MaterialApp: ali, o tema verde ainda não existe, e o Theme.of devolve o tema padrão do Flutter, com o roxo do Material 3.

Como consertar: leia o tema abaixo do MaterialApp: dentro do build de uma tela (como a VitrinePage), ou num Builder. É a mesma regra do Scaffold.of da aula Drawer: o .of(context) procura para cima.

O estilo de texto que pode ser null 
Text(
  'Bolo de cenoura',
  style: Theme.of(context).textTheme.headlineMedium.copyWith(color: Colors.brown),
),

lib/main.dart:33:65: Error: Method 'copyWith' cannot be called on 'TextStyle?' because it is potentially null.
 - 'TextStyle' is from 'package:flutter/src/painting/text_style.dart'.     « o caminho do arquivo dentro do Flutter foi cortado
Try calling using ?. instead.
              style: Theme.of(context).textTheme.headlineMedium.copyWith(color: Colors.brown),
                                                                ^^^^^^^^

Este é um erro de compilação: o app nem chega a abrir. Linha por linha:

lib/main.dart:33:65:
O arquivo, a linha e a coluna do problema (no app completo do laboratório, que é o da seção 3 com esta troca, o Text ficou na linha 33). A coluna 65 aponta o começo do copyWith.
Method 'copyWith' cannot be called on 'TextStyle?' because it is potentially null.
"O método copyWith não pode ser chamado num TextStyle?, porque ele pode ser nulo." Os estilos do textTheme são do tipo TextStyle? (com o ?: "um TextStyle ou null"), e o Dart não deixa chamar um método em algo que pode não existir (a segurança contra nulos do Dart).
Try calling using ?. instead.
"Tente chamar com ?.": a própria mensagem dá o conserto.
As duas últimas linhas
O trecho do código, com os ^^^^^^^^ embaixo do copyWith.

Como consertar: use o ?. ("se não for nulo"): headlineMedium?.copyWith(color: Colors.brown). Se o estilo for null, o resultado também é null, e o Text aceita style: null (usa o estilo padrão). Com um ThemeData normal, os 15 estilos sempre vêm preenchidos, então na prática o texto sai marrom.

Mudei o tema e nada aconteceu

A Ana pôs colorSchemeSeed: Colors.green e o botão continuou de outra cor. Três suspeitos, nenhum com mensagem de erro:

  • Uma cor escrita no próprio widget (style: FilledButton.styleFrom(backgroundColor: Colors.blue)) vence o tema. O tema é o padrão; o widget pode sempre mandar mais.
  • Um Theme no meio do caminho com outro data (seção 5): o mais perto vence.
  • A recarga a quente: mudanças no main() ou em variáveis globais às vezes pedem o hot restart (aula Hot Reload e Hot Restart).

Resumo

  • O tema é o "manual de estilo" do app: MaterialApp(theme: ThemeData(...)). Todos os widgets abaixo seguem.
  • colorSchemeSeed gera uma paleta inteira a partir de uma cor: botões, interruptores, fundos e textos mudam juntos.
  • Os seus widgets leem o tema com Theme.of(context): .colorScheme.primary (e o par on... para o texto) e .textTheme.headlineMedium (e os outros 14 estilos).
  • Temas de componente (appBarTheme: AppBarThemeData(...), filledButtonTheme, cardTheme: CardThemeData(...)) mudam todos os componentes de um tipo.
  • Theme(data: ..., child: ...) muda o tema de um pedaço; com Theme.of(context).copyWith(...), herdando o resto.
  • O que está escrito no widget vence o tema; o tema mais perto vence o de longe; o Theme.of só enxerga temas acima do context.
