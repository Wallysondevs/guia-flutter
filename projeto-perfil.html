Flutter Projeto: Cartão de Perfil

Neste projeto você vai montar, do zero, um cartão de perfil: aquela tela com a foto redonda, o nome, a profissão, os contatos e um botão Seguir. É o primeiro app "de verdade" que junta várias aulas do Nível 1 numa tela só. A Ana vai fazer o cartão dela, que vende bolos e está aprendendo Flutter. O app cresce em 3 versões: cada uma acrescenta uma novidade, traz o código completo (é só copiar e rodar), a foto real da tela e uma missão no editor.

Você vai aprender
  • Como planejar uma tela antes de escrever código: desenhar as caixas e montar a árvore de widgets.
  • Versão 1: a base do app com MaterialApp, Scaffold, Column, CircleAvatar e Text.
  • Versão 2: um Card de contatos com ListTile e Icon.
  • Versão 3: o botão Seguir, que muda de aparência e conta os seguidores, com StatefulWidget e setState.
  • O erro real que aparece quando um valor que muda fica dentro de um const, e como resolver.

Antes de começar, convém ter visto Seu Primeiro App, Scaffold e AppBar, Row e Column e Card e ListTile. Para a versão 3, StatefulWidget e setState. Se ainda não viu alguma, tudo bem: cada peça é explicada aqui também, e o link leva à aula completa.

O plano: desenhar antes de programar

Um cartão de visita de papel tem poucas coisas, uma embaixo da outra: a foto, o nome, a profissão e os contatos. Antes de abrir o editor, a Ana fez um rascunho num papel e marcou as "caixas":

  1. Uma barra no topo com o título Meu Perfil (a AppBar).
  2. No meio da tela, uma coluna (Column) com tudo empilhado e centralizado.
  3. Na coluna: um círculo com as iniciais (CircleAvatar), o nome em letras grandes e a profissão.
  4. Depois: um cartão (Card) com três linhas de contato, cada uma com um ícone.
  5. Por fim: um botão Seguir e quantas pessoas seguem a Ana.

Transformado em árvore de widgets (cada peça dentro da outra), o plano completo fica assim:

CartaoApp (MaterialApp)
└── PerfilPage (Scaffold)
    ├── appBar: AppBar → Text('Meu Perfil')
    └── body: Center
        └── Column
            ├── CircleAvatar → Text('AS')
            ├── Text('Ana Souza')
            ├── Text('Confeiteira e dev Flutter')
            ├── Card → Column
            │   ├── ListTile (telefone)
            │   ├── ListTile (e-mail)
            │   └── ListTile (cidade)
            ├── Text('120 seguidores')
            └── FilledButton ('Seguir')

Ninguém escreve tudo isso de uma vez. O jeito profissional é ir por partes: fazer a menor versão que roda, olhar a tela, e só então acrescentar a próxima peça. Se der erro, você sabe que ele está na peça nova.

Versão 1: foto, nome e profissão

A primeira versão tem só o topo do cartão. Crie o projeto (veja Criando um Projeto) e troque todo o conteúdo de lib/main.dart por este:

import 'package:flutter/material.dart';

void main() => runApp(const CartaoApp());

class CartaoApp extends StatelessWidget {
  const CartaoApp({super.key});

  @override
  Widget build(BuildContext context) {
    return MaterialApp(
      title: 'Cartão de Perfil',
      debugShowCheckedModeBanner: false,
      theme: ThemeData(colorSchemeSeed: Colors.teal),
      home: const PerfilPage(),
    );
  }
}

class PerfilPage extends StatelessWidget {
  const PerfilPage({super.key});

  @override
  Widget build(BuildContext context) {
    return Scaffold(
      appBar: AppBar(title: const Text('Meu Perfil')),
      body: const Center(
        child: Column(
          mainAxisSize: MainAxisSize.min,
          children: [
            CircleAvatar(
              radius: 50,
              child: Text('AS', style: TextStyle(fontSize: 32)),
            ),
            SizedBox(height: 16),
            Text(
              'Ana Souza',
              style: TextStyle(fontSize: 28, fontWeight: FontWeight.bold),
            ),
            Text('Confeiteira e dev Flutter'),
          ],
        ),
      ),
    );
  }
}

O ponto de partida: o runApp recebe o widget que é o app inteiro (veja Seu Primeiro App).
class CartaoApp extends StatelessWidget
O app em si, um widget sem estado (nada nele muda depois de desenhado). Ele só monta o MaterialApp.
debugShowCheckedModeBanner: false
Esconde a faixinha vermelha "DEBUG" no canto da tela. É só estética.
theme: ThemeData(colorSchemeSeed: Colors.teal)
A cor "semente" do tema: o Material 3 gera, a partir do verde-azulado (teal), todas as cores do app (barra, círculo, botão). Mais em Material 3 e ColorScheme.
home: const PerfilPage()
A tela que aparece primeiro. Separar a tela num widget próprio deixa o código organizado: o app cuida do tema; a página cuida do conteúdo.
appBar: AppBar(title: const Text('Meu Perfil'))
A barra do topo (veja Scaffold e AppBar).
body: const Center(
O corpo da tela, centralizado. O const aqui vale para tudo que está dentro: nada disso muda, então o Flutter cria esses widgets uma vez só e os reaproveita. Guarde esse const: na versão 3 ele vai dar trabalho.
mainAxisSize: MainAxisSize.min
A coluna ocupa só a altura do conteúdo, e não a tela inteira. Assim o Center consegue centralizar o bloco todo no meio da tela (veja Alinhamento).
CircleAvatar(radius: 50, child: Text('AS', …))
Um círculo de 50 pixels de raio (100 de diâmetro), com as iniciais dentro. É o widget feito para fotos de perfil: com uma foto de verdade, você usaria backgroundImage (veja Imagens).
SizedBox(height: 16)
Um espaço vazio de 16 pixels entre o círculo e o nome (veja SizedBox e Spacer).
TextStyle(fontSize: 28, fontWeight: FontWeight.bold)
Nome grande e em negrito (veja Estilos de Texto).

O círculo saiu num verde-água claro com as letras escuras: são cores que o Material 3 tirou da semente Colors.teal, sem você escolher nenhuma delas. Repare também que a AppBar tem a mesma cor do fundo: no Material 3 ela é discreta, só com o título (a aula Scaffold e AppBar mostra como colori-la). E o bloco todo ficou no meio da tela, graças ao Center com a coluna "encolhida" (MainAxisSize.min).

Versão 2: o cartão de contatos

Agora a parte de "cartão de visita": telefone, e-mail e cidade, cada um com o seu ícone, dentro de um Card (um retângulo com cantos arredondados e um leve fundo destacado). Para cada linha, o Material já tem um widget pronto: o ListTile, que põe um ícone à esquerda (leading) e um texto (title) ao lado, com o espaçamento certo. As linhas novas vão no fim da lista children da coluna, depois da profissão. Este é o arquivo inteiro:

SizedBox(height: 24)
Separa o cartão do texto da profissão.
Card(margin: EdgeInsets.symmetric(horizontal: 24), …)
O cartão. A margin deixa 24 pixels livres à esquerda e à direita, para ele não encostar nas bordas da tela (veja Padding e Margem).
child: Column(mainAxisSize: MainAxisSize.min, …)
Uma coluna dentro do cartão, com as três linhas. É uma coluna dentro de outra coluna: a de fora empilha o cartão inteiro; a de dentro empilha os contatos.
ListTile(leading: Icon(Icons.phone), title: Text(…))
Uma linha pronta de lista: leading é o que vem "na frente" (o ícone), title é o texto principal. Os nomes dos ícones vêm da classe Icons (veja Ícones).

O cartão ocupa quase toda a largura, com a folga de 24 pixels de cada lado, e tem uma sombra bem leve na borda de baixo. Cada ListTile alinhou o ícone e o texto do mesmo jeito, sem você escrever nenhum espaçamento. Como a coluna de fora continua centralizada, o bloco inteiro (círculo, nome e cartão) subiu um pouco para continuar no meio da tela.

Versão 3: o botão Seguir

Até aqui, nada na tela muda: tudo é StatelessWidget e const. Agora a Ana quer um botão Seguir: ao tocar, ele vira Seguindo e o número de seguidores sobe 1; tocando de novo, volta ao que era. Uma tela que muda precisa de estado (state): valores que o widget guarda e que, quando mudam, fazem a tela ser desenhada de novo. Por isso a PerfilPage vira um StatefulWidget (veja StatefulWidget).

import 'package:flutter/material.dart';

void main() => runApp(const CartaoApp());

class CartaoApp extends StatelessWidget {
  const CartaoApp({super.key});

  @override
  Widget build(BuildContext context) {
    return MaterialApp(
      title: 'Cartão de Perfil',
      debugShowCheckedModeBanner: false,
      theme: ThemeData(colorSchemeSeed: Colors.teal),
      home: const PerfilPage(),
    );
  }
}

class PerfilPage extends StatefulWidget {
  const PerfilPage({super.key});

  @override
  State<PerfilPage> createState() => _PerfilPageState();
}

class _PerfilPageState extends State<PerfilPage> {
  bool _seguindo = false;
  int _seguidores = 120;

  void _alternarSeguir() {
    setState(() {
      _seguindo = !_seguindo;
      _seguidores += _seguindo ? 1 : -1;
    });
  }

  @override
  Widget build(BuildContext context) {
    return Scaffold(
      appBar: AppBar(title: const Text('Meu Perfil')),
      body: Center(
        child: Column(
          mainAxisSize: MainAxisSize.min,
          children: [
            const CircleAvatar(
              radius: 50,
              child: Text('AS', style: TextStyle(fontSize: 32)),
            ),
            const SizedBox(height: 16),
            const Text(
              'Ana Souza',
              style: TextStyle(fontSize: 28, fontWeight: FontWeight.bold),
            ),
            const Text('Confeiteira e dev Flutter'),
            const SizedBox(height: 24),
            const Card(
              margin: EdgeInsets.symmetric(horizontal: 24),
              child: Column(
                mainAxisSize: MainAxisSize.min,
                children: [
                  ListTile(
                    leading: Icon(Icons.phone),
                    title: Text('(11) 5555-0123'),
                  ),
                  ListTile(
                    leading: Icon(Icons.email),
                    title: Text('ana@exemplo.com'),
                  ),
                  ListTile(
                    leading: Icon(Icons.location_on),
                    title: Text('São Paulo, SP'),
                  ),
                ],
              ),
            ),
            const SizedBox(height: 24),
            Text('$_seguidores seguidores'),
            const SizedBox(height: 8),
            _seguindo
                ? OutlinedButton.icon(
                    onPressed: _alternarSeguir,
                    icon: const Icon(Icons.check),
                    label: const Text('Seguindo'),
                  )
                : FilledButton.icon(
                    onPressed: _alternarSeguir,
                    icon: const Icon(Icons.person_add),
                    label: const Text('Seguir'),
                  ),
          ],
        ),
      ),
    );
  }
}
class PerfilPage extends StatefulWidget
A página agora tem duas classes: o widget em si (que só cria o estado) e a classe do estado, _PerfilPageState, onde ficam os dados que mudam e o build. O _ no começo do nome deixa a classe privada ao arquivo.
bool _seguindo = false; int _seguidores = 120;
O estado: se a Ana está sendo seguida por quem usa o app, e quantos seguidores ela tem. Não são final, porque vão mudar.
void _alternarSeguir() { setState(() { … }); }
O que acontece no toque. Dentro do setState, o _seguindo inverte (! é o "não": false vira true e vice-versa) e o contador sobe ou desce 1. O setState avisa o Flutter: "o estado mudou, desenhe de novo" (veja setState).
body: Center( (sem const)
O const saiu do Center, porque agora há coisas lá dentro que mudam. Ele desceu para cada widget que continua fixo: const CircleAvatar, const Text('Ana Souza'), const Card… A seção Quando dá errado mostra o que acontece se você esquecer.
Text('$_seguidores seguidores')
O número vem do estado, com interpolação do Dart ($ antes do nome da variável). A cada setState, este texto é recriado com o valor novo.
_seguindo ? OutlinedButton.icon(…) : FilledButton.icon(…)
O operador ternário (condição ? se sim : se não) escolhe qual botão aparece: preenchido "Seguir" quando ainda não segue; só com contorno "Seguindo" quando já segue. Os dois chamam o mesmo _alternarSeguir. Os tipos de botão estão em Botões.

Quando o app abre, _seguindo é false: aparece o FilledButton, preenchido na cor principal do tema. No lab, a foto seguinte foi tirada logo depois de um clique no botão:

Um toque só mudou duas coisas na tela: o número (120 virou 121) e o botão (o preenchido deu lugar ao de contorno, com o ícone de visto). Nenhuma linha do código "mexeu" no texto ou no botão diretamente: o setState mudou o estado, e o build rodou de novo, desenhando a tela a partir dos valores novos. Tocar outra vez faz o caminho de volta.

Formas diferentes de fazer

A linha de contato: ListTile ou Row?

O ListTile é um atalho. Dá para montar a mesma linha "na mão", com um Row:

// com ListTile: o espaçamento e a altura já vêm prontos
const ListTile(
  leading: Icon(Icons.phone),
  title: Text('(11) 5555-0123'),
),

// com Row: você controla cada espaço
const Padding(
  padding: EdgeInsets.all(16),
  child: Row(
    children: [
      Icon(Icons.phone),
      SizedBox(width: 16),
      Text('(11) 5555-0123'),
    ],
  ),
),

Qual usar: para linhas de lista comuns (ícone + texto, às vezes um subtítulo e algo à direita), o ListTile economiza código e segue o padrão visual do Material 3. Use Row quando o desenho fugir desse padrão.

Repetir o ListTile ou criar um widget seu?

As três linhas de contato são quase iguais. Quando o código se repete, vale criar um widget pequeno com o que muda como parâmetro:

class LinhaContato extends StatelessWidget {
  const LinhaContato({super.key, required this.icone, required this.texto});

  final IconData icone;
  final String texto;

  @override
  Widget build(BuildContext context) {
    return ListTile(leading: Icon(icone), title: Text(texto));
  }
}

// e no cartão:
// LinhaContato(icone: Icons.phone, texto: '(11) 5555-0123'),

Qual usar: com duas ou três linhas simples, repetir o ListTile é claro o bastante. Quando cada linha ganhar mais detalhes (um toque que liga, um subtítulo), o widget próprio evita copiar e colar. Mais em StatelessWidget.

Quando dá errado

Linha por linha:

Onde está o problema: arquivo lib/main.dart, linha 77, coluna 20. É a linha do Text('$_seguidores seguidores'); a coluna 20 é onde começa o _seguidores, e os ^^^^ embaixo sublinham exatamente esse nome.
Error: Not a constant expression.
"Não é uma expressão constante." Dentro de um const, tudo precisa ser conhecido na hora de compilar. O valor de _seguidores só existe com o app rodando.
_seguindo e onPressed: _alternarSeguir
O mesmo problema em outros pontos: o valor de _seguindo e o método _alternarSeguir pertencem ao estado, que só existe em tempo de execução.
Cannot invoke a non-'const' constructor where a const expression is expected.
"Não dá para chamar um construtor que não é const onde se espera uma expressão constante." Com um onPressed que não é constante, o botão não pode ser criado como const.
Failed to compile application for the Web.
A compilação parou e o app não foi gerado. (O lab compila para o navegador, por isso a última linha fala em Web; os erros de cima vêm do compilador do Dart e apontam as mesmas linhas em qualquer plataforma.)

Repare que um const esquecido gerou seis erros. Quando aparecerem muitos erros de uma vez, olhe o primeiro: muitas vezes os outros são consequência dele.

Como resolver: tire o const do Center e ponha const só nos widgets que continuam fixos, como na versão 3. O próprio flutter analyze e o VS Code sugerem onde colocar (o aviso prefer_const_constructors).

Mudou o número, mas a tela não mudou

Se o _alternarSeguir mudar as variáveis fora do setState:

void _alternarSeguir() {
  _seguindo = !_seguindo;
  _seguidores += _seguindo ? 1 : -1;
}

não aparece erro nenhum, nem no console. As variáveis mudam na memória, mas o Flutter não fica sabendo, e a tela continua mostrando 120 seguidores e o botão "Seguir", por mais que você toque. É um dos sustos mais comuns de quem está começando. Como resolver: toda mudança de estado que deve aparecer na tela vai dentro de setState(() { … }).

Resumo

  • Antes de programar, desenhe a tela e transforme o desenho numa árvore de widgets.
  • Cresça o app em versões pequenas que rodam: se der erro, ele está na parte nova.
  • CircleAvatar faz o círculo do perfil; Card + ListTile fazem o cartão de contatos com pouco código.
  • Quando a tela precisa mudar, o widget vira StatefulWidget, os valores que mudam viram campos do estado, e toda mudança vai dentro de setState.
  • const só vale para o que é fixo: quando um valor do estado entra numa parte da árvore, o const sai de cima dela e desce para os widgets que continuam fixos.
