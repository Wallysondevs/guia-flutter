Flutter Drawer

O app de receitas da Ana cresceu: agora tem a lista de receitas, as favoritas, a lista de compras e as configurações. Não cabe tudo numa tela só, e botão para cada parte espalhado pela tela fica feio. A solução clássica dos apps Android é o menu lateral: uma "gaveta" escondida à esquerda, que desliza para dentro da tela quando você toca no ícone ☰ (o "hambúrguer") ou arrasta o dedo a partir da borda. No Flutter, essa gaveta se chama Drawer (em inglês, literalmente "gaveta").

Você vai aprender
  • A colocar uma gaveta no app com o parâmetro drawer do Scaffold, e por que o ícone ☰ aparece sozinho na AppBar.
  • A montar o conteúdo da gaveta com DrawerHeader e ListTile.
  • A fechar a gaveta depois do toque com Navigator.pop(context).
  • A trocar o que aparece na tela conforme o item escolhido (com setState).
  • A abrir a gaveta por código, com Scaffold.of(context).openDrawer(), e por que às vezes é preciso um Builder.
  • A pôr a gaveta do lado direito com endDrawer.
  • O NavigationDrawer, a gaveta no estilo Material 3, com o item escolhido destacado.
  • Os erros reais: o Scaffold.of() called with a context that does not contain a Scaffold, a gaveta que não fecha e o ☰ que sumiu.

Tudo o que você vai ver nesta aula foi compilado com o Flutter 3.47 no laboratório do guia, e as fotos são do app rodando em tamanho de celular. Para acompanhar, você precisa saber o que são o Scaffold e a AppBar, o ListTile e o setState. A gaveta também conversa com a navegação: o Navigator.pop que fecha a gaveta é o mesmo da aula Indo de uma Tela para Outra.

A ideia: a gaveta da cozinha

Na cozinha da Ana, os talheres não ficam espalhados pela bancada: ficam numa gaveta. Ela abre a gaveta, pega a colher e fecha. A bancada continua livre para cozinhar.

No app é igual. A tela (o body do Scaffold) é a bancada, livre para o conteúdo. O menu fica guardado numa gaveta presa à lateral do Scaffold. Abrir a gaveta cobre parte da tela com o menu e escurece o resto; tocar num item faz o que o item manda e fecha a gaveta.

Na cozinhaNo Flutter
A bancadaO body do Scaffold
A gaveta presa ao armárioO parâmetro drawer: do Scaffold
O puxadorO ícone ☰ na AppBar (ou o arrastar da borda esquerda)
Os talheres lá dentroOs itens da gaveta, quase sempre ListTile
Fechar a gavetaNavigator.pop(context), tocar fora dela ou arrastar de volta

1. A primeira gaveta

Basta entregar um Drawer ao parâmetro drawer do Scaffold. O resto o Flutter faz sozinho:

import 'package:flutter/material.dart';

void main() => runApp(const ReceitasApp());

class ReceitasApp extends StatelessWidget {
  const ReceitasApp({super.key});

  @override
  Widget build(BuildContext context) {
    return MaterialApp(
      debugShowCheckedModeBanner: false,
      theme: ThemeData(colorSchemeSeed: Colors.orange),
      home: const InicioPage(),
    );
  }
}

class InicioPage extends StatelessWidget {
  const InicioPage({super.key});

  @override
  Widget build(BuildContext context) {
    return Scaffold(
      appBar: AppBar(title: const Text('Receitas da Ana')),
      drawer: const Drawer(
        child: Center(child: Text('Eu sou a gaveta!')),
      ),
      body: const Center(child: Text('Toque no ícone ☰ lá em cima')),
    );
  }
}
drawer:
Um parâmetro do Scaffold, ao lado de appBar e body. Ele recebe o widget que vai morar na gaveta da esquerda. O Scaffold cuida de tudo: esconder a gaveta, abrir com animação, escurecer o fundo e fechar quando você toca fora.
Drawer(...)
A gaveta em si: um painel com a altura da tela, a largura de um menu (304 pixels lógicos, o padrão do Material) e o fundo e a sombra certos. Sozinho ele é só o "móvel vazio"; o conteúdo vai no child.
child:
O que aparece dentro da gaveta. Aqui, um texto centralizado. Na vida real, uma lista de itens (seção 2).
appBar: AppBar(...)
Repare que nenhum ícone de menu foi escrito. Quando o Scaffold tem um drawer e a AppBar não tem botão à esquerda, a AppBar coloca o ☰ sozinha, e o toque nele já abre a gaveta.

Com o app aberto, a tela fica assim, com o ☰ no canto superior esquerdo:

Tocando no ☰, a gaveta desliza da esquerda e o resto da tela fica escurecido:

Três jeitos de fechar, todos prontos sem uma linha a mais: tocar na parte escurecida, arrastar a gaveta para a esquerda ou usar o botão "voltar" do Android.

2. Um menu de verdade: DrawerHeader e ListTile

Uma gaveta de app quase sempre tem duas partes: um cabeçalho no topo (o nome do app, a foto do usuário) e uma lista de itens, cada um com ícone e texto. Como a lista pode crescer além da altura da tela, o child da gaveta costuma ser uma ListView:

import 'package:flutter/material.dart';

void main() => runApp(const ReceitasApp());

class ReceitasApp extends StatelessWidget {
  const ReceitasApp({super.key});

  @override
  Widget build(BuildContext context) {
    return MaterialApp(
      debugShowCheckedModeBanner: false,
      theme: ThemeData(colorSchemeSeed: Colors.orange),
      home: const InicioPage(),
    );
  }
}

class InicioPage extends StatelessWidget {
  const InicioPage({super.key});

  @override
  Widget build(BuildContext context) {
    return Scaffold(
      appBar: AppBar(title: const Text('Receitas da Ana')),
      drawer: Drawer(
        child: ListView(
          padding: EdgeInsets.zero,
          children: [
            DrawerHeader(
              decoration: BoxDecoration(
                color: Theme.of(context).colorScheme.primaryContainer,
              ),
              child: const Text('Receitas da Ana',
                  style: TextStyle(fontSize: 24)),
            ),
            ListTile(
              leading: const Icon(Icons.menu_book),
              title: const Text('Receitas'),
              onTap: () => Navigator.pop(context),
            ),
            ListTile(
              leading: const Icon(Icons.favorite),
              title: const Text('Favoritas'),
              onTap: () => Navigator.pop(context),
            ),
            ListTile(
              leading: const Icon(Icons.shopping_cart),
              title: const Text('Lista de compras'),
              onTap: () => Navigator.pop(context),
            ),
            const Divider(),
            ListTile(
              leading: const Icon(Icons.settings),
              title: const Text('Configurações'),
              onTap: () => Navigator.pop(context),
            ),
          ],
        ),
      ),
      body: const Center(child: Text('Bolo de cenoura')),
    );
  }
}
ListView(padding: EdgeInsets.zero, ...)
A lista que rola se os itens não couberem. O padding: EdgeInsets.zero tira o espaço que a ListView deixaria no topo (para fugir da barra de status do celular) e faz o cabeçalho colorido encostar no alto da gaveta. Sem essa linha, num celular de verdade, aparece uma faixa sem cor acima do cabeçalho (no navegador, onde não há barra de status, a diferença não aparece). A receita oficial de gaveta da documentação do Flutter também zera esse espaço.
DrawerHeader
Um cabeçalho pronto, com a altura, o espaçamento e a linha de baixo que o Material espera numa gaveta. O decoration é o mesmo BoxDecoration da aula Cores, Bordas e Sombras; o child é o que vai dentro.
Theme.of(context).colorScheme.primaryContainer
Uma cor tirada do tema do app (um tom claro da cor principal, aqui laranja), em vez de uma cor escrita à mão. Assim o cabeçalho combina com o resto e muda junto se o tema mudar. As cores do tema estão em Material 3 e ColorScheme.
ListTile
Uma linha com ícone (leading, "o que vem na frente") e texto (title). Ela já tem a altura certa para o dedo e o efeito de toque.
onTap: () => Navigator.pop(context)
O que acontece no toque. Por enquanto, só fechar a gaveta. Por baixo dos panos, a gaveta aberta funciona como uma "tela" empilhada por cima do app, e o Navigator.pop tira da pilha a de cima: a gaveta. Na seção 3, o toque também vai trocar o conteúdo.
Divider()
Uma linha fina que separa grupos de itens: aqui, as configurações ficam separadas das partes do app.

A árvore de widgets da gaveta:

Scaffold
 ├─ appBar: AppBar  (o ☰ aparece sozinho)
 ├─ drawer: Drawer
 │   └─ ListView
 │       ├─ DrawerHeader
 │       │   └─ Text 'Receitas da Ana'
 │       ├─ ListTile  Receitas
 │       ├─ ListTile  Favoritas
 │       ├─ ListTile  Lista de compras
 │       ├─ Divider
 │       └─ ListTile  Configurações
 └─ body: Center
     └─ Text 'Bolo de cenoura'
Por que o Drawer perdeu o const?

Na seção 1 o Drawer era const: nada nele dependia do app rodando. Agora ele usa o Theme.of(context) e o Navigator.pop(context), coisas que só existem com o app no ar, então não pode mais ser const. Os pedaços que continuam fixos (os Icon, os Text, o Divider) mantêm o const, como manda a boa prática.

3. Trocando o conteúdo da tela

Um menu que só fecha não serve para nada. O jeito mais simples de fazer cada item mostrar uma coisa diferente: guardar qual item foi escolhido num número (o índice) e montar o body a partir dele. Como esse número muda, a página vira um StatefulWidget:

import 'package:flutter/material.dart';

void main() => runApp(const ReceitasApp());

class ReceitasApp extends StatelessWidget {
  const ReceitasApp({super.key});

  @override
  Widget build(BuildContext context) {
    return MaterialApp(
      debugShowCheckedModeBanner: false,
      theme: ThemeData(colorSchemeSeed: Colors.orange),
      home: const InicioPage(),
    );
  }
}

class InicioPage extends StatefulWidget {
  const InicioPage({super.key});

  @override
  State<InicioPage> createState() => _InicioPageState();
}

class _InicioPageState extends State<InicioPage> {
  static const _titulos = ['Receitas', 'Favoritas', 'Lista de compras'];
  static const _icones = [Icons.menu_book, Icons.favorite, Icons.shopping_cart];
  int _escolhido = 0;

  void _escolher(int indice) {
    setState(() => _escolhido = indice);
    Navigator.pop(context);
  }

  @override
  Widget build(BuildContext context) {
    return Scaffold(
      appBar: AppBar(title: Text(_titulos[_escolhido])),
      drawer: Drawer(
        child: ListView(
          padding: EdgeInsets.zero,
          children: [
            const DrawerHeader(child: Text('Receitas da Ana')),
            for (var i = 0; i < _titulos.length; i++)
              ListTile(
                leading: Icon(_icones[i]),
                title: Text(_titulos[i]),
                selected: i == _escolhido,
                onTap: () => _escolher(i),
              ),
          ],
        ),
      ),
      body: Center(
        child: Text('Tela: ${_titulos[_escolhido]}',
            style: const TextStyle(fontSize: 22)),
      ),
    );
  }
}
int _escolhido = 0;
O estado da página: o índice do item escolhido. Começa em 0, "Receitas".
_escolher(int indice)
Faz as duas coisas que um item de menu precisa fazer: muda o índice com setState (o Flutter redesenha a tela com o novo título e o novo body) e fecha a gaveta com Navigator.pop.
for (var i = 0; ...) ListTile(...)
Um for dentro da lista de children (o "for de coleção" do Dart): gera um ListTile para cada título, sem repetir código.
selected: i == _escolhido
O ListTile do item atual fica destacado (ícone e texto na cor principal do tema). Assim a Ana sabe em que parte do app está quando abre a gaveta.
Text(_titulos[_escolhido])
O título da AppBar e o texto do meio acompanham o item escolhido.

E, abrindo a gaveta de novo, "Favoritas" aparece destacada:

Trocar o body ou abrir outra tela?

Aqui o menu troca só o conteúdo da mesma tela: a AppBar e a gaveta continuam lá. Também dá para cada item abrir uma tela nova com Navigator.push (aula Navigator) ou com rotas nomeadas (Rotas Nomeadas). Nesse caso, feche a gaveta antes de empilhar a tela nova (primeiro o pop, depois o push); senão, quando a Ana voltar, a gaveta ainda vai estar aberta.

4. Abrindo a gaveta por código

Às vezes a Ana quer um botão no meio da tela que abra o menu ("Ver todas as seções"). Quem sabe abrir e fechar a gaveta é o Scaffold, e o jeito de falar com ele é o Scaffold.of(context): "procure, a partir deste ponto da árvore, o Scaffold mais próximo acima de mim". Achado o Scaffold, é só pedir openDrawer().

O detalhe que pega todo mundo: o context do método build da página é o lugar da própria página na árvore, e a página fica acima do Scaffold que ela cria. Procurando "para cima" a partir dali, não há Scaffold nenhum. A saída é um Builder: um widget cuja única função é dar um context novo, já dentro do Scaffold:

import 'package:flutter/material.dart';

void main() => runApp(const ReceitasApp());

class ReceitasApp extends StatelessWidget {
  const ReceitasApp({super.key});

  @override
  Widget build(BuildContext context) {
    return MaterialApp(
      debugShowCheckedModeBanner: false,
      theme: ThemeData(colorSchemeSeed: Colors.orange),
      home: const InicioPage(),
    );
  }
}

class InicioPage extends StatelessWidget {
  const InicioPage({super.key});

  @override
  Widget build(BuildContext context) {
    return Scaffold(
      appBar: AppBar(title: const Text('Receitas da Ana')),
      drawer: const Drawer(
        child: Center(child: Text('Menu da Ana')),
      ),
      body: Center(
        child: Builder(
          builder: (contextDentro) => FilledButton.icon(
            onPressed: () => Scaffold.of(contextDentro).openDrawer(),
            icon: const Icon(Icons.menu),
            label: const Text('Ver todas as seções'),
          ),
        ),
      ),
    );
  }
}
Builder(builder: (contextDentro) => ...)
O Builder chama a função do builder passando o seu próprio context, que está dentro do body, portanto abaixo do Scaffold. O nome contextDentro é só para deixar isso claro; muita gente escreve context mesmo (e aí esse context "esconde" o de fora).
Scaffold.of(contextDentro)
Sobe pela árvore a partir do botão e encontra o Scaffold.
.openDrawer()
Abre a gaveta da esquerda, com a mesma animação do ☰. Os irmãos dele: openEndDrawer() (gaveta da direita, seção 5) e closeDrawer().

O que acontece sem o Builder, usando o context do build, está em Quando dá errado. Há ainda um segundo jeito, sem Builder: dar uma "chave" ao Scaffold (seção "Formas diferentes").

5. A gaveta do lado direito: endDrawer

O Scaffold tem uma segunda gaveta, do lado oposto: o endDrawer ("gaveta do fim"). Ela é boa para coisas secundárias, como filtros da lista de receitas. Quando ela existe, a AppBar põe sozinha um ícone de menu do lado direito:

import 'package:flutter/material.dart';

void main() => runApp(const ReceitasApp());

class ReceitasApp extends StatelessWidget {
  const ReceitasApp({super.key});

  @override
  Widget build(BuildContext context) {
    return MaterialApp(
      debugShowCheckedModeBanner: false,
      theme: ThemeData(colorSchemeSeed: Colors.orange),
      home: const InicioPage(),
    );
  }
}

class InicioPage extends StatelessWidget {
  const InicioPage({super.key});

  @override
  Widget build(BuildContext context) {
    return Scaffold(
      appBar: AppBar(title: const Text('Receitas da Ana')),
      drawer: const Drawer(
        child: Center(child: Text('Menu da Ana')),
      ),
      endDrawer: const Drawer(
        child: Center(child: Text('Filtros: doces, salgados, rápidas')),
      ),
      body: const Center(child: Text('Bolo de cenoura')),
    );
  }
}

"Esquerda" e "direita" aqui são, na verdade, "início" e "fim" da linha: num idioma escrito da direita para a esquerda, como o árabe, o Flutter inverte as duas gavetas sozinho.

6. O NavigationDrawer do Material 3

O Drawer com ListTile é o jeito clássico. O Material 3 trouxe uma gaveta pensada só para navegação, o NavigationDrawer: os itens são NavigationDrawerDestination ("destino"), e o item escolhido ganha um "pílula" colorida em volta, o indicador. Você não precisa controlar o selected de cada item: entrega o índice atual e recebe o toque num só lugar:

import 'package:flutter/material.dart';

void main() => runApp(const ReceitasApp());

class ReceitasApp extends StatelessWidget {
  const ReceitasApp({super.key});

  @override
  Widget build(BuildContext context) {
    return MaterialApp(
      debugShowCheckedModeBanner: false,
      theme: ThemeData(colorSchemeSeed: Colors.orange),
      home: const InicioPage(),
    );
  }
}

class InicioPage extends StatefulWidget {
  const InicioPage({super.key});

  @override
  State<InicioPage> createState() => _InicioPageState();
}

class _InicioPageState extends State<InicioPage> {
  static const _titulos = ['Receitas', 'Favoritas', 'Lista de compras'];
  int _escolhido = 0;

  @override
  Widget build(BuildContext context) {
    return Scaffold(
      appBar: AppBar(title: Text(_titulos[_escolhido])),
      drawer: NavigationDrawer(
        selectedIndex: _escolhido,
        onDestinationSelected: (indice) {
          setState(() => _escolhido = indice);
          Navigator.pop(context);
        },
        children: const [
          Padding(
            padding: EdgeInsets.fromLTRB(28, 16, 16, 10),
            child: Text('Receitas da Ana'),
          ),
          NavigationDrawerDestination(
            icon: Icon(Icons.menu_book_outlined),
            selectedIcon: Icon(Icons.menu_book),
            label: Text('Receitas'),
          ),
          NavigationDrawerDestination(
            icon: Icon(Icons.favorite_border),
            selectedIcon: Icon(Icons.favorite),
            label: Text('Favoritas'),
          ),
          NavigationDrawerDestination(
            icon: Icon(Icons.shopping_cart_outlined),
            selectedIcon: Icon(Icons.shopping_cart),
            label: Text('Lista de compras'),
          ),
        ],
      ),
      body: Center(
        child: Text('Tela: ${_titulos[_escolhido]}',
            style: const TextStyle(fontSize: 22)),
      ),
    );
  }
}
drawer: NavigationDrawer(...)
O NavigationDrawer vai no mesmo lugar do Drawer: o parâmetro drawer do Scaffold. O ☰ aparece do mesmo jeito.
selectedIndex: _escolhido
Qual destino está escolhido. A gaveta desenha o indicador nele.
onDestinationSelected: (indice) { ... }
Chamado quando a Ana toca num destino, com o índice dele. Contam só os NavigationDrawerDestination: o Padding do título não tem índice, então "Receitas" é o 0. Fechar a gaveta continua sendo trabalho seu (Navigator.pop).
NavigationDrawerDestination
Um item: icon (o ícone normal), selectedIcon (o ícone quando escolhido; o costume do Material 3 é o contorno no normal e o cheio no escolhido) e label (o texto).
children: const [...]
Como nada na lista muda, ela inteira pode ser const: quem muda é o selectedIndex, que fica fora dela.

Formas diferentes de fazer

Abrir a gaveta: três caminhos

Além do ☰ automático e do Builder da seção 4, existe a chave global: você cria uma GlobalKey<ScaffoldState>, entrega ao Scaffold e, de qualquer ponto da página, pede _chave.currentState!.openDrawer(), sem procurar nada na árvore:

class _InicioPageState extends State<InicioPage> {
  final _chave = GlobalKey<ScaffoldState>();

  @override
  Widget build(BuildContext context) {
    return Scaffold(
      key: _chave,
      appBar: AppBar(title: const Text('Receitas da Ana')),
      drawer: const Drawer(child: Center(child: Text('Menu da Ana'))),
      body: Center(
        child: FilledButton(
          onPressed: () => _chave.currentState!.openDrawer(),
          child: const Text('Ver todas as seções'),
        ),
      ),
    );
  }
}

(Só a parte que muda; a página precisa ser um StatefulWidget para guardar a chave. As chaves têm aula própria: Keys.)

Quando dá errado

Scaffold.of() com o context errado

A Ana tirou o Builder da seção 4 e usou o context do próprio build:

  @override
  Widget build(BuildContext context) {
    return Scaffold(
      appBar: AppBar(title: const Text('Receitas da Ana')),
      drawer: const Drawer(
        child: Center(child: Text('Menu da Ana')),
      ),
      body: Center(
        child: FilledButton.icon(
          onPressed: () => Scaffold.of(context).openDrawer(),
          icon: const Icon(Icons.menu),
          label: const Text('Ver todas as seções'),
        ),
      ),
    );
  }

O app compila e abre normalmente, com a mesma cara da foto da seção 4. O erro só aparece no toque do botão: a gaveta não abre, e o console (aqui, o do navegador, onde o laboratório rodou o app em modo debug) mostra:

[erro na página] Scaffold.of() called with a context that does not contain a Scaffold.
No Scaffold ancestor could be found starting from the context that was passed to Scaffold.of(). This usually happens when the context provided is from the same StatefulWidget as that whose build function actually creates the Scaffold widget being sought.
There are several ways to avoid this problem. The simplest is to use a Builder to get a context that is "under" the Scaffold. For an example of this, please see the documentation for Scaffold.of():
  https://api.flutter.dev/flutter/material/Scaffold/of.html
A more efficient solution is to split your build function into several widgets. This introduces a new context from which you can obtain the Scaffold. In this solution, you would have an outer widget that creates the Scaffold populated by instances of your new inner widgets, and then in these inner widgets you would use Scaffold.of().
A less elegant but more expedient solution is assign a GlobalKey to the Scaffold, then use the key.currentState property to obtain the ScaffoldState rather than using the Scaffold.of() function.

A gaveta não fecha depois do toque 
ListTile(
  leading: const Icon(Icons.favorite),
  title: const Text('Favoritas'),
  onTap: () => setState(() => _escolhido = 1),

Nenhuma mensagem de erro: a tela de trás até muda, mas fica escondida atrás da gaveta, que continua aberta. Para quem usa, parece que o toque "não fez nada". O Scaffold não fecha a gaveta sozinho quando um item é tocado: ele não sabe se aquele toque era de navegação ou, por exemplo, um interruptor de "modo escuro" que deve deixar a gaveta aberta. Como consertar: acrescente Navigator.pop(context); no onTap, depois do setState.

O ☰ sumiu

Dois motivos comuns, nenhum com mensagem de erro:

  • O Scaffold não tem appBar. Sem barra, não há onde pôr o ☰. A gaveta ainda existe e abre arrastando o dedo a partir da borda esquerda, mas ninguém adivinha isso. Ponha uma AppBar ou um botão que abra a gaveta (seção 4).
  • A AppBar tem um leading próprio. O leading é o espaço à esquerda do título; se você puser um widget ali (um logotipo, por exemplo), ele toma o lugar do ☰. Ou deixe o leading vazio, ou faça o seu próprio botão abrir a gaveta com Scaffold.of(context).openDrawer() dentro de um Builder.

O contrário também acontece: com automaticallyImplyLeading: false na AppBar, o ☰ some de propósito.

O cabeçalho com uma faixa em cima

Sem o padding: EdgeInsets.zero na ListView da gaveta, a lista deixa um espaço do tamanho da barra de status no topo, e o cabeçalho colorido "desce", deixando uma faixa da cor do fundo da gaveta acima dele. Não é erro, é a lista protegendo o conteúdo da barra de status. Como consertar: ListView(padding: EdgeInsets.zero, children: [...]); o DrawerHeader já sabe se afastar da barra de status sozinho.

class _InicioPageState extends State<InicioPage> {
  static const _titulos = ['Receitas', 'Favoritas'];
  int _escolhido = 0;

  @override
  Widget build(BuildContext context) {
    return Scaffold(
      appBar: AppBar(title: Text(_titulos[_escolhido])),
      drawer: NavigationDrawer(
        selectedIndex: _escolhido,
        onDestinationSelected: (indice) {
          setState(() => _escolhido = indice);
          Navigator.pop(context);
        },
        children: const [
          NavigationDrawerDestination(
            icon: Icon(Icons.menu_book),
            label: Text('Receitas'),
          ),
          NavigationDrawerDestination(
            icon: Icon(Icons.favorite),
            label: Text('Favoritas'),
          ),
        ],
      ),
      body: Center(child: Text('Tela: ${_titulos[_escolhido]}')),
    );
  }
}

Resumo

  • A gaveta (menu lateral) é o parâmetro drawer do Scaffold. Com uma AppBar, o ícone ☰ aparece sozinho; dá para abrir também arrastando da borda.
  • O conteúdo típico: Drawer → ListView(padding: EdgeInsets.zero) → DrawerHeader + ListTiles.
  • A gaveta não fecha sozinha no toque de um item: chame Navigator.pop(context).
  • Para trocar o conteúdo, guarde o índice escolhido no estado, mude com setState e destaque o item atual com selected.
  • Abrir por código: Scaffold.of(ctx).openDrawer() com um ctx abaixo do Scaffold (um Builder), ou uma GlobalKey<ScaffoldState>. Com o context errado: Scaffold.of() called with a context that does not contain a Scaffold.
  • endDrawer é a gaveta do lado direito, boa para filtros e opções secundárias.
  • No Material 3, o NavigationDrawer com NavigationDrawerDestination dá a gaveta de navegação com o indicador pronto (selectedIndex + onDestinationSelected).
