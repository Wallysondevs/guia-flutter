Flutter Tema Escuro

A Ana cozinha à noite com o celular apoiado no balcão, e a tela branca do app de receitas ofusca. O celular dela está no modo escuro, e os outros apps já obedecem: fundo escuro, letras claras. O dela, não. No Flutter, o modo escuro é um segundo tema: você descreve o tema claro no theme, o escuro no darkTheme, e o app escolhe sozinho qual usar, seguindo o celular.

Você vai aprender
  • A dar ao app um tema escuro com darkTheme e a paleta escura com brightness: Brightness.dark.
  • A escolher quem manda, com themeMode: o sistema, sempre claro ou sempre escuro.
  • A fazer um interruptor "Modo escuro" dentro do app.
  • A saber, num widget, se o tema atual é claro ou escuro.
  • Por que cores escritas à mão estragam o modo escuro, e como evitar.

Tudo nesta aula foi compilado com o Flutter 3.47 no laboratório do guia. Cada app foi fotografado duas vezes: com o navegador pedindo o modo claro e pedindo o modo escuro, como faria um celular. Antes, leia Temas e Material 3 e ColorScheme.

A ideia: a roupa de dia e a roupa de noite

A Ana tem o uniforme de cozinha branco para o dia e um avental escuro para a noite. É a mesma cozinheira, com o mesmo jeito de trabalhar; só muda a roupa. E quem decide qual roupa usar pode ser o relógio ("já escureceu?") ou ela mesma.

1. O segundo tema: darkTheme

import 'package:flutter/material.dart';

void main() => runApp(const ReceitasApp());

class ReceitasApp extends StatelessWidget {
  const ReceitasApp({super.key});

  @override
  Widget build(BuildContext context) {
    return MaterialApp(
      debugShowCheckedModeBanner: false,
      theme: ThemeData(colorSchemeSeed: Colors.green),
      darkTheme: ThemeData(
        colorSchemeSeed: Colors.green,
        brightness: Brightness.dark,
      ),
      home: const VitrinePage(),
    );
  }
}

class VitrinePage extends StatelessWidget {
  const VitrinePage({super.key});

  @override
  Widget build(BuildContext context) {
    return Scaffold(
      appBar: AppBar(title: const Text('Receitas da Ana')),
      body: ListView(
        padding: const EdgeInsets.all(16),
        children: [
          const Card(
            child: ListTile(
              leading: Icon(Icons.cake),
              title: Text('Bolo de cenoura'),
              subtitle: Text('40 min · fácil'),
            ),
          ),
          const SizedBox(height: 16),
          FilledButton(onPressed: () {}, child: const Text('Ver receita')),
          const SizedBox(height: 8),
          OutlinedButton(onPressed: () {}, child: const Text('Favoritar')),
        ],
      ),
      floatingActionButton: FloatingActionButton(
        onPressed: () {},
        child: const Icon(Icons.add),
      ),
    );
  }
}

O mesmo app, com o aparelho no modo claro e no modo escuro:

darkTheme:
O tema que o MaterialApp usa quando o modo escuro está valendo. Sem ele, o app fica claro sempre, mesmo com o celular no escuro.
colorSchemeSeed: Colors.green
A mesma semente do tema claro. Assim os dois temas são da mesma "família": o verde do botão escuro é o irmão do verde do botão claro.
brightness: Brightness.dark
O "brilho" do tema. Com Brightness.dark, a paleta é calculada para fundo escuro: surface quase preto, onSurface quase branco, e as cores de destaque mais claras, para continuarem visíveis.

Compare as duas fotos. No escuro, o fundo virou um quase-preto esverdeado e os textos ficaram claros. As cores de destaque se inverteram: o "Ver receita", que era verde-escuro com letra branca, virou verde-claro com letra escura; o botão flutuante, que era verde-claro, virou verde-escuro. Não é um "negativo" da foto clara: a paleta escura é calculada de novo, para cada cor ter contraste sobre o fundo escuro.

Repare que a VitrinePage não tem nenhuma cor escrita à mão: todos os componentes tiram as cores do tema, e por isso todos trocaram. É o que faz o modo escuro "funcionar de graça" (e o que dá errado quando você escreve cores à mão; veja Quando dá errado).

Com ColorScheme.fromSeed

Se o seu tema usa o jeito completo da aula Material 3, o brilho vai dentro do fromSeed: darkTheme: ThemeData(colorScheme: ColorScheme.fromSeed(seedColor: Colors.green, brightness: Brightness.dark)).

2. Quem manda: themeMode

O MaterialApp tem um terceiro parâmetro, themeMode ("modo do tema"), que decide qual dos dois temas usar:

return MaterialApp(
  theme: ThemeData(colorSchemeSeed: Colors.green),
  darkTheme: ThemeData(colorSchemeSeed: Colors.green, brightness: Brightness.dark),
  themeMode: ThemeMode.dark,
  home: const VitrinePage(),
);
ThemeMode.system
O padrão (se você não escrever themeMode, é este). Segue o aparelho: celular no escuro, app no escuro.
ThemeMode.light
Sempre o theme, ignorando o aparelho.
ThemeMode.dark
Sempre o darkTheme, ignorando o aparelho.

3. O interruptor "Modo escuro"

Muita gente gosta de escolher dentro do app. Como o themeMode fica no MaterialApp, quem guarda a escolha é o widget do app, que passa a ser um StatefulWidget, e a tela recebe uma função para avisar a troca (a ideia de Elevando o Estado):

import 'package:flutter/material.dart';

void main() => runApp(const ReceitasApp());

class ReceitasApp extends StatefulWidget {
  const ReceitasApp({super.key});

  @override
  State<ReceitasApp> createState() => _ReceitasAppState();
}

class _ReceitasAppState extends State<ReceitasApp> {
  bool _escuro = false;

  @override
  Widget build(BuildContext context) {
    return MaterialApp(
      debugShowCheckedModeBanner: false,
      theme: ThemeData(colorSchemeSeed: Colors.green),
      darkTheme: ThemeData(
        colorSchemeSeed: Colors.green,
        brightness: Brightness.dark,
      ),
      themeMode: _escuro ? ThemeMode.dark : ThemeMode.light,
      home: ConfigPage(
        escuro: _escuro,
        aoMudar: (valor) => setState(() => _escuro = valor),
      ),
    );
  }
}

class ConfigPage extends StatelessWidget {
  const ConfigPage({super.key, required this.escuro, required this.aoMudar});

  final bool escuro;
  final ValueChanged<bool> aoMudar;

  @override
  Widget build(BuildContext context) {
    return Scaffold(
      appBar: AppBar(title: const Text('Configurações')),
      body: ListView(
        children: [
          SwitchListTile(
            title: const Text('Modo escuro'),
            secondary: const Icon(Icons.dark_mode),
            value: escuro,
            onChanged: aoMudar,
          ),
        ],
      ),
    );
  }
}
bool _escuro = false;
A escolha da Ana, guardada no estado do app.
themeMode: _escuro ? ThemeMode.dark : ThemeMode.light
O MaterialApp lê a escolha. Quando o setState muda o _escuro, o MaterialApp é reconstruído e troca de tema com uma animação suave.
aoMudar: (valor) => setState(...)
A função que a tela chama quando o interruptor muda. O tipo ValueChanged<bool> é só um nome curto para "função que recebe um bool e não devolve nada".
SwitchListTile
Uma linha com texto, ícone e interruptor juntos (aula Checkbox, Switch e Radio).

E quando o app fecha?

O _escuro mora na memória: fechou o app, a escolha se perde e ele volta claro. Para lembrar, é preciso gravar a escolha no aparelho, assunto da aula Guardando Preferências. Um app caprichado ainda oferece as três opções (Sistema, Claro, Escuro), guardando um ThemeMode em vez de um bool.

Missão: o app só tem o tema claro. Acrescente um darkTheme com a mesma semente e brightness: Brightness.dark, e force o escuro com themeMode: ThemeMode.dark para conferir.

void main() => runApp(const ReceitasApp());

  const ReceitasApp({super.key});

  @override
  Widget build(BuildContext context) {
    return MaterialApp(
      debugShowCheckedModeBanner: false,
      theme: ThemeData(colorSchemeSeed: Colors.green),
      home: Scaffold(
        appBar: AppBar(title: const Text('Receitas da Ana')),
        body: Center(
          child: FilledButton(onPressed: () {}, child: const Text('Ver receita')),
        ),
      ),
    );
  }
}

4. Este widget está no escuro?

Às vezes um widget seu precisa saber: uma ilustração clara para o dia e outra para a noite, por exemplo. Há duas perguntas diferentes:

final temaEscuro = Theme.of(context).brightness == Brightness.dark;
final aparelhoEscuro = MediaQuery.platformBrightnessOf(context) == Brightness.dark;
Theme.of(context).brightness
O brilho do tema que está valendo. É quase sempre esta a pergunta certa: ela respeita o themeMode e o interruptor do app.
MediaQuery.platformBrightnessOf(context)
O que o aparelho pediu, sem olhar a escolha feita no app. Com themeMode: ThemeMode.dark num celular claro, a primeira diz dark e esta diz light.

Para uma cor que só existe no seu app (e não na paleta), o jeito simples é escolher pelo brilho: color: temaEscuro ? Colors.amber.shade200 : Colors.amber.shade800. Mas, antes, veja se algum papel do ColorScheme já serve: ele troca sozinho.

Formas diferentes de fazer

JeitoQuando usar
Só theme + darkTheme (sem themeMode)O mínimo que todo app deveria ter: segue o aparelho
themeMode fixo (.light ou .dark)Um app que tem identidade só clara ou só escura (um leitor noturno, um jogo)
themeMode guardado no estado do appQuando a pessoa escolhe dentro do app (de preferência com Sistema/Claro/Escuro)
Um ThemeData escuro escrito à mão (cores uma a uma)Só com um manual de marca que define o escuro; senão, a semente faz melhor

Quando dá errado

A cor escrita à mão que some no escuro 
body: const Center(
  child: Text(
    'Bolo de cenoura',
    style: TextStyle(fontSize: 24, color: Colors.black87),
  ),
),

No modo claro, tudo certo. No escuro, o fundo fica quase preto e o texto continua quase preto: na foto, dá para adivinhá-lo, mas num celular, com a tela menos brilhante, ele some. E nenhuma mensagem de erro avisa. O Colors.black87 é uma cor fixa; ela não sabe que o tema mudou. Como consertar: não escreva a cor (o Text já usa o onSurface do tema) ou use um papel da paleta: color: Theme.of(context).colorScheme.onSurface.

Pus ThemeMode.dark e o app continua claro 
return MaterialApp(
  theme: ThemeData(colorSchemeSeed: Colors.green),
  themeMode: ThemeMode.dark,
  home: const VitrinePage(),
);

Sem darkTheme, não há tema escuro para escolher, e o MaterialApp usa o theme mesmo com ThemeMode.dark. Também não há mensagem de erro. Como consertar: dê o darkTheme.

O tema escuro com outra cara 
theme: ThemeData(
  colorSchemeSeed: Colors.green,
  appBarTheme: const AppBarThemeData(centerTitle: true),
),
darkTheme: ThemeData(colorSchemeSeed: Colors.green, brightness: Brightness.dark),

No claro, o título fica no meio; no escuro, volta para a esquerda. O darkTheme é um tema separado: o que você personalizou no theme não passa para ele. Como consertar: monte os dois temas com uma função que recebe o brilho, assim tudo o que não é cor fica igual nos dois:

ThemeData criarTema(Brightness brilho) {
  return ThemeData(
    colorSchemeSeed: Colors.green,
    brightness: brilho,
    appBarTheme: const AppBarThemeData(centerTitle: true),
  );
}

E no app: theme: criarTema(Brightness.light), darkTheme: criarTema(Brightness.dark).

Resumo

  • O modo escuro é um segundo tema: darkTheme: ThemeData(colorSchemeSeed: cor, brightness: Brightness.dark), com a mesma semente do claro.
  • themeMode decide: system (padrão, segue o aparelho), light ou dark.
  • Para a pessoa escolher, guarde a escolha no estado do widget do app e passe ao themeMode.
  • Theme.of(context).brightness diz se o tema atual é escuro; MediaQuery.platformBrightnessOf, o que o aparelho pediu.
  • Cores escritas à mão não trocam com o tema: use os papéis do ColorScheme. E monte os dois temas com uma função, para não perder personalizações no escuro.
