Flutter JSON e Classes de Modelo

Na aula http, o app da lojinha recebeu os clientes do servidor e pegou o nome de cada um com cliente['name']. Funciona, mas é frágil: um erro de digitação na chave ('nmae') só aparece com o app rodando, o editor não sugere nada e cada tela precisa lembrar o formato do JSON. O jeito profissional é transformar o JSON, logo que ele chega, numa classe de modelo: uma classe Cliente com campos de verdade (nome, email, cidade), que o resto do app usa sem nunca mais ver um mapa.

Você vai aprender
  • O que é JSON e como o jsonDecode o transforma em Map e List do Dart.
  • Como escrever uma classe de modelo com o construtor factory Cliente.fromJson e o método toJson.
  • Como ler objetos dentro de objetos (o address com a city).
  • Outra forma: validar o JSON com os padrões do Dart 3 (switch).
  • Quando vale usar um gerador de código (json_serializable).
  • Os erros reais: a chave errada, o tipo errado e o JSON mal escrito.

Os exemplos rodaram no laboratório do guia (Flutter 3.47). Para a aula não depender da internet, o JSON está escrito dentro do próprio código, numa constante: é exatamente o texto que o resposta.body traria, no mesmo formato do JSONPlaceholder da aula anterior.

A ideia: a ficha de cadastro

Quando um cliente novo chega na lojinha, a Ana não anota os dados num papel solto ("Ana, ana@…, Recife"). Ela preenche uma ficha com campos impressos: Nome, E-mail, Cidade. Com a ficha, ninguém esquece um campo, ninguém escreve a cidade no lugar do e-mail, e qualquer funcionário sabe onde olhar.

O JSON que vem do servidor é o papel solto: um texto. A classe de modelo é a ficha. O fromJson é a pessoa que passa o papel a limpo para a ficha (conferindo cada campo), e o toJson faz o caminho de volta, quando o app precisa mandar a ficha para o servidor.

Revisão rápida: o JSON

JSON (JavaScript Object Notation) é o formato de texto mais usado para trocar dados na internet. Ele tem objetos entre { } (pares "chave": valor), listas entre [ ], textos sempre com aspas duplas, números, true/false e null. O jsonDecode (de dart:convert) faz a tradução:

No JSONNo Dart, depois do jsonDecode
{"id": 1, "name": "Ana"}Map<String, dynamic>
[ … ]List<dynamic>
"texto"String
1 / 1.5int / double
true, nullbool, null

O dynamic quer dizer "pode ser qualquer coisa": o Dart só descobre o tipo de verdade com o app rodando. É por isso que vale passar tudo para uma classe com tipos firmes o quanto antes.

1. A classe de modelo Cliente

import 'dart:convert';

import 'package:flutter/material.dart';

void main() => runApp(const MeuApp());

// O texto que o servidor mandaria (o mesmo formato do JSONPlaceholder).
const respostaDoServidor = '''
[
  {"id": 1, "name": "Ana Souza", "email": "ana@lojinha.com",
   "address": {"city": "Recife"}},
  {"id": 2, "name": "Bruno Lima", "email": "bruno@lojinha.com",
   "address": {"city": "Natal"}},
  {"id": 3, "name": "Carla Dias", "email": "carla@lojinha.com",
   "address": {"city": "Belém"}}
]
''';

class Cliente {
  final int id;
  final String nome;
  final String email;
  final String cidade;

  const Cliente({
    required this.id,
    required this.nome,
    required this.email,
    required this.cidade,
  });

  factory Cliente.fromJson(Map<String, dynamic> json) {
    return Cliente(
      id: json['id'] as int,
      nome: json['name'] as String,
      email: json['email'] as String,
      cidade: json['address']['city'] as String,
    );
  }

  Map<String, dynamic> toJson() => {
        'id': id,
        'name': nome,
        'email': email,
        'address': {'city': cidade},
      };
}

List<Cliente> lerClientes(String texto) {
  final lista = jsonDecode(texto) as List<dynamic>;
  return [
    for (final item in lista) Cliente.fromJson(item as Map<String, dynamic>),
  ];
}

class MeuApp extends StatelessWidget {
  const MeuApp({super.key});

  @override
  Widget build(BuildContext context) {
    final clientes = lerClientes(respostaDoServidor);
    print(jsonEncode(clientes.first.toJson()));
    return MaterialApp(
      debugShowCheckedModeBanner: false,
      home: Scaffold(
        appBar: AppBar(title: const Text('Clientes da Lojinha')),
        body: ListView(
          children: [
            for (final c in clientes)
              ListTile(
                leading: CircleAvatar(child: Text('${c.id}')),
                title: Text(c.nome),
                subtitle: Text('${c.email} · ${c.cidade}'),
              ),
          ],
        ),
      ),
    );
  }
}

O JSON de exemplo, num texto de várias linhas (as três aspas do Dart). Num app de verdade, seria o resposta.body do http.
class Cliente { final int id; final String nome; … }
A ficha. Campos final (não mudam depois de criados) e com os nossos nomes, em português: o JSON diz name, o app diz nome. A tradução acontece num lugar só.
factory Cliente.fromJson(Map<String, dynamic> json)
Um construtor com nome (fromJson, "a partir do JSON"). O factory permite que o construtor faça contas antes de criar o objeto (aqui, ler o mapa) e devolva o Cliente com return. Esse nome, fromJson, é uma convenção da comunidade Dart: qualquer programador reconhece.
id: json['id'] as int
Pega o valor da chave 'id' e confere que é um int (o as). Se não for, o app quebra ali mesmo, com uma mensagem clara (veja Quando dá errado), e não três telas depois.
cidade: json['address']['city'] as String
Objeto dentro de objeto: o address é outro mapa, e a city está dentro dele. A ficha da Ana não precisa do endereço inteiro: só guarda a cidade.
Map<String, dynamic> toJson()
O caminho de volta: monta um mapa com as chaves que o servidor entende. O jsonEncode transforma esse mapa em texto JSON.
List<Cliente> lerClientes(String texto)
Decodifica o texto (uma lista), e passa cada item pelo Cliente.fromJson. O item as Map<String, dynamic> diz ao Dart que cada item da lista é um objeto JSON.
c.nome, c.email, c.cidade
Na tela, nada de mapas: campos com nome e tipo. O editor sugere c.+Tab, e um erro de digitação (c.nmoe) nem compila.
print(jsonEncode(clientes.first.toJson()))
Só para conferir o toJson: mostra o primeiro cliente de volta em JSON, no console.

E o console mostrou o toJson do primeiro cliente:

{"id":1,"name":"Ana Souza","email":"ana@lojinha.com","address":{"city":"Recife"}}

Missão: um cliente novo se cadastrou. Acrescente no JSON um quarto objeto: {"id": 4, "name": "Davi Rocha", "email": "davi@lojinha.com", "address": {"city": "Manaus"}}. Cuidado com a vírgula entre o terceiro e o quarto objeto, e com as aspas duplas.

2. Outra forma: padrões do Dart 3

O fromJson com as quebra no primeiro campo errado. Com os padrões (patterns) do Dart 3, dá para conferir o formato inteiro de uma vez e decidir o que fazer se não bater. É a forma que a documentação do Dart mostra para "validar JSON que chega":

  factory Cliente.fromJson(Map<String, dynamic> json) {
    return switch (json) {
      {
        'id': int id,
        'name': String nome,
        'email': String email,
        'address': {'city': String cidade},
      } =>
        Cliente(id: id, nome: nome, email: email, cidade: cidade),
      _ => throw FormatException('Cliente inválido: $json'),
    };
  }
switch (json) { {…} => …, _ => … }
Uma expressão switch: compara o json com cada padrão, de cima para baixo, e devolve o valor do primeiro que combinar.
{'id': int id, 'name': String nome, …}
Um padrão de mapa: combina se o mapa tem essas chaves, com valores desses tipos; e já guarda cada valor numa variável (id, nome…). O 'address': {'city': String cidade} entra no objeto de dentro.
_ => throw FormatException(…)
O _ combina com qualquer coisa: se o mapa não tiver o formato esperado, lança um FormatException ("erro de formato") com uma mensagem que diz qual cliente veio errado.

Com o JSON certo, a tela fica igual à do exemplo 1 (conferido no laboratório). A diferença aparece quando o JSON vem errado; veja o último cenário de Quando dá errado.

Gerar o fromJson automaticamente

Num app com 30 classes de modelo, escrever fromJson e toJson à mão cansa e dá erro. Os pacotes json_serializable + json_annotation + build_runner geram esse código: você marca a classe com @JsonSerializable(), roda dart run build_runner build, e aparece um arquivo cliente.g.dart com as funções prontas. A documentação oficial explica as duas formas em JSON and serialization (docs.flutter.dev). Para começar, e para apps pequenos, a forma manual desta aula é a recomendada.

FormaQuando usar
json['chave'] direto, sem classeUm teste rápido. Evite em app de verdade.
Classe com fromJson/toJson e asO padrão para a maioria dos apps; simples de ler.
fromJson com switch e padrõesQuando o JSON pode vir incompleto e você quer uma mensagem de erro sua.
json_serializable (gerador)Muitas classes, JSON grande, equipe.

Tipo errado

O servidor mudou e passou a mandar o id do primeiro cliente como texto: "id": "1" (com aspas). O fromJson continua com json['id'] as int:

The following _TypeError was thrown building MeuApp(dirty):
TypeError: "1": type 'String' is not a subtype of type 'int'
…
package:app/main.dart 34:22                                                  fromJson

"O valor "1" é do tipo String, que não é um subtipo de int": o json['id'] as int (linha 34) recebeu um texto. É o tipo de erro que aparece quando o servidor muda sem avisar. Como consertar: se o servidor pode mandar das duas formas, converta: id: int.parse('${json['id']}'); se não deveria, avise quem cuida do servidor. A vantagem do as é que o erro aparece aqui, com a linha certa, e não lá na frente numa conta que dá errado.

JSON mal escrito

No terceiro cliente, a chave name ficou com aspas simples: 'name': "Carla Dias". No Dart, aspas simples valem; no JSON, não:

The following FormatException was thrown building MeuApp(dirty):
SyntaxError: Expected double-quoted property name in JSON at position 208 (line 6 column 13)
…
dart-sdk/lib/convert/json.dart 160:12                                        jsonDecode

Agora o erro é um FormatException ("erro de formato"), lançado pelo jsonDecode (linha 50): "era esperado um nome de propriedade com aspas duplas, na posição 208 (linha 6, coluna 13)". A linha 6 e a coluna 13 são do texto JSON, e não do arquivo .dart: na sexta linha do texto, a coluna 13 é a aspa simples de 'name'. (O texto SyntaxError: … é o do navegador, porque no laboratório o app roda na web; num celular, o FormatException vem com uma mensagem própria do Dart, também apontando a posição.) Como consertar: no JSON, chaves e textos sempre com aspas duplas, e nada de vírgula depois do último item.

Chave errada, com o fromJson de padrões

Com a versão do switch (seção 2), o segundo cliente veio com "nome" no lugar de "name":

The following FormatException was thrown building MeuApp(dirty):
Cliente inválido: {id: 2, nome: Bruno Lima, email: bruno@lojinha.com, address: {city: Natal}}
…

O mapa do Bruno não combinou com o padrão (falta 'name'), então caiu no _ => throw FormatException('Cliente inválido: $json'). Compare com o primeiro cenário: lá, a mensagem era técnica (type 'Null' is not a subtype…); aqui, você escolheu o texto e incluiu o cliente inteiro, e fica fácil ver que a chave veio como nome. Num app de verdade, esse erro iria parar no snapshot.hasError do FutureBuilder, numa tela amigável, e não na tela vermelha.

Resumo

  • jsonDecode transforma o texto JSON em Map<String, dynamic> e List<dynamic>; jsonEncode faz o caminho de volta.
  • Passe o JSON para uma classe de modelo logo que ele chega: factory Classe.fromJson(Map<String, dynamic> json) e Map<String, dynamic> toJson().
  • Use as Tipo em cada campo: se o servidor mandar algo diferente, o erro aparece na hora, no lugar certo.
  • Objetos aninhados: json['address']['city']; ou padrões do Dart 3, que conferem o formato inteiro.
  • No JSON, textos e chaves usam aspas duplas; aspas simples ou vírgula sobrando quebram o jsonDecode.
