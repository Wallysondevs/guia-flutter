Flutter Dismissible

No aplicativo de e-mail do seu celular, você arrasta uma mensagem para o lado e ela some. Na lista de compras da Ana, comprou o leite? Arrasta, e o leite sai da lista. Esse gesto é tão comum que o Flutter tem um widget pronto para ele: o Dismissible. Em inglês, dismiss quer dizer "dispensar, mandar embora"; um Dismissible é "uma peça que pode ser mandada embora" com um arrasto.

Você vai aprender
  • Como embrulhar um item da lista num Dismissible para ele poder ser arrastado para fora da tela.
  • Por que o Dismissible exige uma key, e qual valor usar nela.
  • Como tirar o item da sua lista de dados no onDismissed (o widget não faz isso sozinho).
  • Como mostrar um fundo vermelho com uma lixeira (background) e um fundo diferente para cada lado (secondaryBackground).
  • Como escolher a direção do arrasto (direction) e perguntar "tem certeza?" antes de apagar (confirmDismiss).
  • Como oferecer um Desfazer com um SnackBar.
  • Os erros reais: o item apagado que continua na árvore e as chaves repetidas.

Esta aula usa o que você viu em ListView.builder, setState e Keys. Os apps rodaram no Flutter do laboratório, e as fotos são das telas de verdade.

A ideia: o papelzinho que você amassa e joga fora

Imagine a lista de compras da Ana escrita em papeizinhos, um item em cada, presos na geladeira. Comprou o leite? Ela puxa o papel do leite para o lado e joga no lixo. Três coisas acontecem nessa cena:

  1. O papel acompanha a mão enquanto ela puxa. Se ela soltar no meio do caminho, o papel volta para o lugar.
  2. Se ela puxar até o fim, o papel sai da geladeira e os outros papéis sobem para tapar o buraco.
  3. Ela risca o leite da lista que está na cabeça dela; senão, amanhã escreveria o papel do leite de novo.

O Dismissible cuida dos passos 1 e 2: a animação do arrasto, o "volta para o lugar" e o espaço que fecha. O passo 3 é seu: tirar o item da List do seu app. Se você esquecer, o Flutter reclama (está em Quando dá errado).

1. O primeiro Dismissible

A lista de compras da Ana, com cada item embrulhado num Dismissible:

import 'package:flutter/material.dart';

void main() => runApp(const MaterialApp(home: ListaDeCompras()));

class ListaDeCompras extends StatefulWidget {
  const ListaDeCompras({super.key});

  @override
  State<ListaDeCompras> createState() => _ListaDeComprasState();
}

class _ListaDeComprasState extends State<ListaDeCompras> {
  final List<String> itens = ['Leite', 'Pão', 'Ovos', 'Café', 'Banana'];

  @override
  Widget build(BuildContext context) {
    return Scaffold(
      appBar: AppBar(title: const Text('Lista de compras')),
      body: ListView.builder(
        itemCount: itens.length,
        itemBuilder: (context, index) {
          final item = itens[index];
          return Dismissible(
            key: ValueKey(item),
            onDismissed: (direction) {
              setState(() {
                itens.removeAt(index);
              });
            },
            child: ListTile(title: Text(item)),
          );
        },
      ),
    );
  }
}
StatefulWidget
A lista muda (itens saem dela), então a tela precisa de estado (veja StatefulWidget). A List<String> itens mora no State.
Dismissible(…)
O "embrulho" que deixa o filho ser arrastado para fora. Ele não desenha nada sozinho: o que aparece é o child.
key: ValueKey(item)
Obrigatória. Uma etiqueta que diz ao Flutter qual item é este, mesmo depois que a lista muda de tamanho. O valor tem de ser único e estável: o mesmo item, a mesma chave, sempre. Aqui o próprio texto serve, porque não há dois itens iguais. (Mais sobre isso em Qual chave usar.)
onDismissed: (direction) { … }
A função que o Flutter chama depois que a animação terminou e o item saiu da tela. O parâmetro direction diz para que lado ele foi. É aqui que você faz o passo 3 da geladeira.
setState(() { itens.removeAt(index); })
Tira o item da lista e avisa o Flutter para redesenhar a tela (veja setState). O ListView.builder passa a ter um item a menos.
child: ListTile(…)
O que aparece na tela e o que se move com o dedo: a linha da lista (veja Card e ListTile).

Repare que nada na tela diz que os itens podem ser arrastados: o Dismissible é invisível até alguém pôr o dedo. Ao arrastar o Leite para o lado, ele acompanha o dedo; se você soltar antes de chegar a 40% da largura (o padrão do dismissThresholds), ele volta para o lugar; se passar disso, ele desliza para fora, o espaço dele encolhe e o Pão sobe. Só então o onDismissed roda.

2. O fundo que aparece por trás: background

No primeiro exemplo, quando o item anda, aparece só o fundo branco da tela. Fica estranho: a pessoa não sabe o que vai acontecer. O comum é mostrar, por trás do item, uma faixa vermelha com uma lixeira. Para isso existe o parâmetro background ("fundo"):

return Dismissible(
  key: ValueKey(item),
  background: Container(
    color: Colors.red,
    alignment: Alignment.centerLeft,
    padding: const EdgeInsets.symmetric(horizontal: 20),
    child: const Icon(Icons.delete, color: Colors.white),
  ),
  onDismissed: (direction) {
    setState(() {
      itens.removeAt(index);
    });
  },
  child: ListTile(title: Text(item)),
);
background:
Um widget qualquer, desenhado atrás do child. Ele fica parado; é o child que anda e vai revelando o fundo.
Container(color: Colors.red, …)
A faixa vermelha, do tamanho do item (veja Container).
alignment: Alignment.centerLeft
Põe a lixeira no meio da altura, encostada à esquerda: é o lado que aparece primeiro quando o item é arrastado para a direita.
padding: …horizontal: 20
Afasta a lixeira 20 pixels da borda, para não ficar colada.

Um fundo para cada lado: secondaryBackground

Se o item pode ir para os dois lados, o background aparece nos dois, e a lixeira à esquerda fica escondida quando o arrasto é para a esquerda. Use o secondaryBackground ("fundo secundário") para o arrasto da direita para a esquerda. Um uso clássico: para a direita, "comprado" (verde); para a esquerda, "apagar" (vermelho):

return Dismissible(
  key: ValueKey(item),
  background: Container(
    color: Colors.green,
    alignment: Alignment.centerLeft,
    padding: const EdgeInsets.symmetric(horizontal: 20),
    child: const Icon(Icons.check, color: Colors.white),
  ),
  secondaryBackground: Container(
    color: Colors.red,
    alignment: Alignment.centerRight,
    padding: const EdgeInsets.symmetric(horizontal: 20),
    child: const Icon(Icons.delete, color: Colors.white),
  ),
  onDismissed: (direction) {
    final acao = direction == DismissDirection.startToEnd ? 'comprado' : 'apagado';
    setState(() {
      itens.removeAt(index);
    });
    debugPrint('$item: $acao');
  },
  child: ListTile(title: Text(item)),
);

O direction que chega no onDismissed diz o lado: DismissDirection.startToEnd ("do começo para o fim", isto é, da esquerda para a direita em português) ou DismissDirection.endToStart (da direita para a esquerda). Assim, o mesmo gesto pode fazer duas coisas diferentes.

Por que "start" e "end", e não "left" e "right"?

Porque há línguas escritas da direita para a esquerda, como o árabe e o hebraico. Nelas, o "começo" da linha fica à direita, e o Flutter inverte os lados sozinho. Em português, start = esquerda e end = direita.

3. Só para um lado: direction

Por padrão, o item vai para a esquerda e para a direita (DismissDirection.horizontal). Para aceitar só um lado, passe o direction:

return Dismissible(
  key: ValueKey(item),
  direction: DismissDirection.endToStart,
  background: Container(
    color: Colors.red,
    alignment: Alignment.centerRight,
    padding: const EdgeInsets.symmetric(horizontal: 20),
    child: const Icon(Icons.delete, color: Colors.white),
  ),
  onDismissed: (direction) {
    setState(() {
      itens.removeAt(index);
    });
  },
  child: ListTile(title: Text(item)),
);

Agora o item só sai arrastado para a esquerda; para a direita, ele nem se mexe. Repare que, com uma direção só, o fundo vai no background mesmo (com a lixeira à direita, que é o lado que aparece).

DismissDirection.O item sai…
horizontal (padrão)para a esquerda ou para a direita
startToEndsó para a direita (em português)
endToStartsó para a esquerda (em português)
verticalpara cima ou para baixo (útil em listas que rolam para o lado)
up / downsó para cima / só para baixo
nonenão sai: o arrasto fica desligado

4. "Tem certeza?": confirmDismiss

Apagar com um arrasto é rápido, rápido até demais: um dedo distraído e lá se foi a receita de bolo da avó. O confirmDismiss ("confirmar a dispensa") é chamado quando o arrasto chega ao fim, antes de o item sumir. Ele devolve um Future<bool?>: true deixa o item ir; false (ou null) faz o item voltar para o lugar.

return Dismissible(
  key: ValueKey(item),
  background: Container(color: Colors.red),
  confirmDismiss: (direction) {
    return showDialog<bool>(
      context: context,
      builder: (context) => AlertDialog(
        title: const Text('Apagar item?'),
        content: Text('Tirar "$item" da lista?'),
        actions: [
          TextButton(
            onPressed: () => Navigator.pop(context, false),
            child: const Text('Cancelar'),
          ),
          FilledButton(
            onPressed: () => Navigator.pop(context, true),
            child: const Text('Apagar'),
          ),
        ],
      ),
    );
  },
  onDismissed: (direction) {
    setState(() {
      itens.removeAt(index);
    });
  },
  child: ListTile(title: Text(item)),
);
confirmDismiss: (direction) { … }
Recebe a direção (para você poder perguntar só num dos lados) e tem de devolver um Future<bool?>, uma resposta que "chega depois" (veja o Guia Dart, aulas de assincronia).
showDialog<bool>(…)
Abre a caixinha de pergunta e devolve um Future<bool?> com o valor que o botão mandou no Navigator.pop. É exatamente o tipo que o confirmDismiss quer, então dá para devolver direto. Os diálogos têm aula própria: Diálogos e SnackBar.
Navigator.pop(context, false)
Fecha o diálogo respondendo false: o item volta.
Navigator.pop(context, true)
Fecha respondendo true: o item sai e o onDismissed roda.

Se a pessoa tocar fora do diálogo, ele fecha sem resposta: o Future termina com null, e o Dismissible trata null como "não": o item volta.

5. Desfazer com um SnackBar

Outra forma de proteger contra o dedo distraído, mais moderna: apagar na hora, sem perguntar, mas mostrar uma barrinha embaixo com o botão Desfazer por alguns segundos. É o que o Gmail faz. A barrinha é o SnackBar (veja Diálogos e SnackBar):

onDismissed: (direction) {
  setState(() {
    itens.removeAt(index);
  });
  ScaffoldMessenger.of(context).showSnackBar(
    SnackBar(
      content: Text('$item apagado'),
      action: SnackBarAction(
        label: 'Desfazer',
        onPressed: () {
          setState(() {
            itens.insert(index, item);
          });
        },
      ),
    ),
  );
},
itens.removeAt(index)
Apaga na hora, como antes.
ScaffoldMessenger.of(context).showSnackBar(…)
Mostra a barrinha no pé do Scaffold.
SnackBarAction(label: 'Desfazer', onPressed: …)
O botão dentro da barrinha. Quando tocado, devolve o item para a mesma posição com itens.insert(index, item). As variáveis item e index continuam valendo dentro da função, porque ela as "lembra" do momento em que foi criada.

Como o item volta com o mesmo texto, ele volta com a mesma chave (ValueKey('Leite')), e o Flutter o desenha de novo no lugar certo, sem animação de arrasto.

O app completo, com uma lixeira para quem não arrasta

Aqui o código de apagar foi para uma função, apagar(index), chamada pelo arrasto e por um botão de lixeira no fim de cada linha (o trailing do ListTile). Assim, quem não sabe que dá para arrastar também consegue apagar:

import 'package:flutter/material.dart';

void main() => runApp(const MaterialApp(home: ListaDeCompras()));

class ListaDeCompras extends StatefulWidget {
  const ListaDeCompras({super.key});

  @override
  State<ListaDeCompras> createState() => _ListaDeComprasState();
}

class _ListaDeComprasState extends State<ListaDeCompras> {
  final List<String> itens = ['Leite', 'Pão', 'Ovos', 'Café', 'Banana'];

  void apagar(int index) {
    final item = itens[index];
    setState(() {
      itens.removeAt(index);
    });
    ScaffoldMessenger.of(context).showSnackBar(
      SnackBar(
        content: Text('$item apagado'),
        action: SnackBarAction(
          label: 'Desfazer',
          onPressed: () {
            setState(() {
              itens.insert(index, item);
            });
          },
        ),
      ),
    );
  }

  @override
  Widget build(BuildContext context) {
    return Scaffold(
      appBar: AppBar(title: const Text('Lista de compras')),
      body: ListView.builder(
        itemCount: itens.length,
        itemBuilder: (context, index) {
          final item = itens[index];
          return Dismissible(
            key: ValueKey(item),
            background: Container(
              color: Colors.red,
              alignment: Alignment.centerLeft,
              padding: const EdgeInsets.symmetric(horizontal: 20),
              child: const Icon(Icons.delete, color: Colors.white),
            ),
            onDismissed: (direction) => apagar(index),
            child: ListTile(
              title: Text(item),
              trailing: IconButton(
                icon: const Icon(Icons.delete_outline),
                tooltip: 'Apagar $item',
                onPressed: () => apagar(index),
              ),
            ),
          );
        },
      ),
    );
  }
}

Qual chave usar

A key é o que permite ao Flutter saber que o "Pão" que agora está na posição 0 é o mesmo "Pão" que antes estava na posição 1. As regras:

  • Única na lista: com duas chaves iguais, o Flutter não tem como saber qual dos dois itens é qual. Cuidado: numa ListView.builder ele nem sempre avisa (no lab, uma lista com dois ValueKey('Leite') rodou sem mensagem nenhuma), então o erro passa calado.
  • Estável: o mesmo item tem de ter a mesma chave em todo build. Nada de UniqueKey() criada dentro do itemBuilder (ela muda a cada desenho) nem de ValueKey(index) (a posição muda quando um item sai, e o "Pão" herdaria a chave do "Leite").
  • O ideal é um identificador do dado: o id que veio do banco de dados, por exemplo ValueKey(tarefa.id). Quando o texto pode se repetir (dois "Leite" na lista), o texto não serve; use o id.
ChaveServe?
ValueKey(tarefa.id)A melhor: única e estável
ValueKey(item) (o texto)Só se o texto nunca se repetir
ObjectKey(tarefa)Serve se o objeto é sempre o mesmo (não é recriado a cada build)
ValueKey(index)Não: a posição muda quando um item sai
UniqueKey() dentro do itemBuilderNão: é uma chave nova a cada desenho

Formas diferentes de fazer

SituaçãoO que usar
Apagar com um gesto, sem perigo de perder nada importanteDismissible com onDismissed
Apagar algo que faz falta (uma receita, um contato)Dismissible + SnackBar com Desfazer, ou confirmDismiss com diálogo
Arrastar com um significado para cada lado (arquivar × apagar)background + secondaryBackground e o direction do onDismissed
Quem não sabe arrastar (ou usa leitor de tela) também precisa apagarAlém do arrasto, um botão: ListTile(trailing: IconButton(icon: Icon(Icons.delete), …))

Sempre ofereça outro caminho

O arrasto é invisível: ninguém sabe que ele existe até tentar. Um botão de lixeira no trailing do ListTile, que chama o mesmo código de apagar, ajuda quem nunca usou o app e quem usa leitor de tela.

Quando dá errado

O item saiu da tela, mas não saiu da lista

Um engano muito comum: trocar o removeAt pelo remove. Os dois existem, mas fazem coisas diferentes: removeAt(0) tira o item da posição 0; remove(0) procura o valor 0 na lista. Numa lista de textos não existe o número 0, então nada sai. O app compila e roda; só o flutter analyze (e o sublinhado do editor) dá uma dica discreta: info • The argument type 'int' isn't related to 'String'. … • collection_methods_unrelated_type ("o tipo int não tem relação com String").

onDismissed: (direction) {
  setState(() {
    itens.remove(index); // errado: procura o número index, que não está na lista
  });
},

Na maioria dos widgets a key é opcional; no Dismissible ela é required justamente porque sem ela o Flutter não consegue acompanhar qual item saiu. A seta ^ aponta o parêntese do Dismissible( na linha 23. Como consertar: key: ValueKey(item) (ou o id do dado).

secondaryBackground sem background 
return Dismissible(
  key: ValueKey(item),
  secondaryBackground: Container(color: Colors.red),
  onDismissed: …,
  child: ListTile(title: Text(item)),
);

Compila, mas o Flutter acusa o erro logo ao montar a lista, antes de qualquer arrasto. O começo da mensagem (do mesmo teste da Ana):

══╡ EXCEPTION CAUGHT BY WIDGETS LIBRARY ╞═══════════════════════════════════════════════════════════
The following assertion was thrown building:
'package:flutter/src/widgets/dismissible.dart': Failed assertion: line 118 pos 15:
'secondaryBackground == null || background != null': is not true.

Uma assertion ("afirmação") é uma conferência que o próprio Flutter faz no modo debug. Esta diz: "ou não tem secondaryBackground, ou tem background". O fundo secundário é só para o segundo lado; o primeiro tem de existir. Como consertar: passe também o background (ou troque o secondaryBackground por background, se for um fundo só).

Referência rápida

ParâmetroO que faz
key (obrigatório)Identifica o item; única e estável
child (obrigatório)O que aparece e se move com o dedo
onDismissed: (direction) {…}Roda depois que o item saiu; tire-o dos dados aqui, com setState
backgroundFundo revelado ao arrastar (para os dois lados, se não houver secondaryBackground)
secondaryBackgroundFundo do arrasto da direita para a esquerda; exige background
directionPara que lados o item pode ir (padrão DismissDirection.horizontal)
confirmDismiss: (direction) async {…}Pergunta antes; true deixa ir, false/null faz voltar
dismissThresholdsQuanto arrastar para valer (padrão: 40% da largura, 0.4)
movementDuration / resizeDurationDuração da volta/saída e do "fechar o buraco"

Missão final: arquivar ou apagar

Missão: na lista de compras abaixo, faça o arrasto para a direita mostrar um fundo verde com Icons.check (background) e o arrasto para a esquerda, um fundo vermelho com Icons.delete (secondaryBackground). No onDismissed, use direction == DismissDirection.startToEnd para escolher o texto do SnackBar: "Leite comprado" ou "Leite apagado".

import 'package:flutter/material.dart';

void main() => runApp(const MaterialApp(home: ListaDeCompras()));

class ListaDeCompras extends StatefulWidget {
  const ListaDeCompras({super.key});

  @override
  State<ListaDeCompras> createState() => _ListaDeComprasState();
}

class _ListaDeComprasState extends State<ListaDeCompras> {
  final List<String> itens = ['Leite', 'Pão', 'Ovos', 'Café', 'Banana'];

  @override
  Widget build(BuildContext context) {
    return Scaffold(
      appBar: AppBar(title: const Text('Lista de compras')),
      body: ListView.builder(
        itemCount: itens.length,
        itemBuilder: (context, index) {
          final item = itens[index];
          return Dismissible(
            key: ValueKey(item),
            background: Container(color: Colors.red),
            onDismissed: (direction) {
              setState(() {
                itens.removeAt(index);
              });
              ScaffoldMessenger.of(context).showSnackBar(
                SnackBar(content: Text('$item apagado')),
              );
            },
            child: ListTile(title: Text(item)),
          );
        },
      ),
    );
  }
}

import 'package:flutter/material.dart';

void main() => runApp(const MaterialApp(home: ListaDeCompras()));

class ListaDeCompras extends StatefulWidget {
  const ListaDeCompras({super.key});

  @override
  State<ListaDeCompras> createState() => _ListaDeComprasState();
}

class _ListaDeComprasState extends State<ListaDeCompras> {
  final List<String> itens = ['Leite', 'Pão', 'Ovos', 'Café', 'Banana'];

  @override
  Widget build(BuildContext context) {
    return Scaffold(
      appBar: AppBar(title: const Text('Lista de compras')),
      body: ListView.builder(
        itemCount: itens.length,
        itemBuilder: (context, index) {
          final item = itens[index];
          return Dismissible(
            key: ValueKey(item),
            background: Container(
              color: Colors.green,
              alignment: Alignment.centerLeft,
              padding: const EdgeInsets.symmetric(horizontal: 20),
              child: const Icon(Icons.check, color: Colors.white),
            ),
            secondaryBackground: Container(
              color: Colors.red,
              alignment: Alignment.centerRight,
              padding: const EdgeInsets.symmetric(horizontal: 20),
              child: const Icon(Icons.delete, color: Colors.white),
            ),
            onDismissed: (direction) {
              final acao = direction == DismissDirection.startToEnd
                  ? 'comprado'
                  : 'apagado';
              setState(() {
                itens.removeAt(index);
              });
              ScaffoldMessenger.of(context).showSnackBar(
                SnackBar(content: Text('$item $acao')),
              );
            },
            child: ListTile(title: Text(item)),
          );
        },
      ),
    );
  }
}

Resumo

  • O Dismissible embrulha um item e deixa a pessoa arrastá-lo para fora da tela; ele cuida da animação e de fechar o buraco.
  • A key é obrigatória e tem de ser única e estável: de preferência o id do dado; nunca o index.
  • No onDismissed, tire o item da sua lista com setState. Sem isso, o Flutter reclama que o item dispensado "ainda faz parte da árvore".
  • background é o fundo revelado pelo arrasto; secondaryBackground, o do arrasto para a esquerda. direction limita os lados.
  • Para não perder nada por engano: confirmDismiss (pergunta antes) ou SnackBar com Desfazer (desfaz depois).
