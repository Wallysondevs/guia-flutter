Flutter sqflite

O shared_preferences guarda coisas soltas: um número, um tema, um nome. Mas a lista de compras da Ana tem dezenas de itens, cada um com nome, quantidade e se já foi comprado; o app de receitas tem centenas de receitas. Para isso, o celular tem um banco de dados de verdade dentro dele: o SQLite. No Flutter, quem conversa com ele é o pacote sqflite.

Você vai aprender
  • O que é o SQLite e quando ele é a escolha certa.
  • Como acrescentar os pacotes sqflite e path.
  • Como abrir o banco e criar a tabela (openDatabase, onCreate, version).
  • As quatro operações: insert (pôr), query (ler), update (mudar) e delete (apagar), com whereArgs.
  • Um app completo: a lista de compras que continua lá quando o app é fechado.
  • Onde o sqflite funciona, e o que acontece se você tentar rodar no navegador.
Sobre as telas desta aula

O laboratório do guia fotografa os apps rodando no navegador, e o sqflite não funciona no navegador: segundo a documentação oficial, ele roda em Android, iOS e macOS. Por isso, nesta aula, o código foi conferido no laboratório (o flutter pub add e o flutter analyze abaixo são reais, com o Flutter 3.47), mas o comportamento do app num celular é ilustrativo, baseado na receita oficial Persist data with SQLite (docs.flutter.dev) e na página do pacote no pub.dev. As telas fotografadas são a do erro no navegador (seção Quando dá errado) e a da versão de treino, com um banco de mentirinha na memória (seção 4).

A ideia: um caderno com colunas

Pense num caderno de controle com as folhas riscadas em colunas: nº, item, quantidade. Cada linha é um item da lista de compras. Um banco de dados é isso: tabelas (as folhas) com colunas (os campos) e linhas (os registros). O SQLite guarda esse caderno inteiro num único arquivo dentro do aparelho; você conversa com ele numa linguagem própria, o SQL.

idnome
1Leite
2Pão
3Café

A tabela itens da lista de compras, com duas colunas: id (um número que o próprio banco dá a cada linha) e nome.

Não sabe SQL?

Para esta aula, bastam quatro ideias: CREATE TABLE (criar a folha), INSERT (escrever uma linha), SELECT (ler) e DELETE (apagar). O sqflite tem métodos prontos (insert, query, delete) que escrevem o SQL por você. Para aprender SQL de verdade, veja o Guia SQL, que usa justamente o SQLite.

2. Abrir o banco e criar a tabela

import 'package:path/path.dart';
import 'package:sqflite/sqflite.dart';

class BancoCompras {
  static Database? _db;

  static Future<Database> abrir() async {
    return _db ??= await openDatabase(
      join(await getDatabasesPath(), 'compras.db'),
      version: 1,
      onCreate: (db, version) {
        return db.execute(
          'CREATE TABLE itens(id INTEGER PRIMARY KEY AUTOINCREMENT, nome TEXT NOT NULL)',
        );
      },
    );
  }
}
class BancoCompras
Uma classe que junta tudo o que mexe no banco. Assim, as telas não precisam saber SQL: só chamam BancoCompras.listar(), BancoCompras.inserir(…).
static Database? _db e _db ??= …
Guarda o banco aberto. O ??= do Dart quer dizer "se ainda for nulo, abra e guarde; se já tiver, use o que tem". Assim o arquivo é aberto uma vez só.
getDatabasesPath()
A pasta onde o sistema deixa o app guardar bancos de dados (no Android, a pasta databases do app).
join(…, 'compras.db')
Do pacote path: junta a pasta e o nome do arquivo com a barra certa para o sistema. A receita oficial chama isso de "boa prática".
version: 1
A versão do formato do banco (das tabelas). Quando um dia você acrescentar uma coluna, muda para 2 e usa o onUpgrade para atualizar os bancos dos usuários que já têm o app.
onCreate: (db, version) { … }
Roda só na primeira vez, quando o arquivo ainda não existe. É aqui que se criam as tabelas.
CREATE TABLE itens(…)
O SQL que cria a tabela: id INTEGER PRIMARY KEY AUTOINCREMENT é um número que identifica a linha e que o banco preenche sozinho (1, 2, 3…); nome TEXT NOT NULL é um texto obrigatório.

3. As quatro operações

  static Future<List<Item>> listar() async {
    final db = await abrir();
    final linhas = await db.query('itens', orderBy: 'id');
    return [
      for (final {'id': id as int, 'nome': nome as String} in linhas)
        Item(id: id, nome: nome),
    ];
  }

  static Future<void> inserir(String nome) async {
    final db = await abrir();
    await db.insert('itens', {'nome': nome});
  }

  static Future<void> renomear(int id, String novoNome) async {
    final db = await abrir();
    await db.update('itens', {'nome': novoNome}, where: 'id = ?', whereArgs: [id]);
  }

  static Future<void> apagar(int id) async {
    final db = await abrir();
    await db.delete('itens', where: 'id = ?', whereArgs: [id]);
  }
db.query('itens', orderBy: 'id')
Lê as linhas da tabela, em ordem de id. Devolve uma List<Map<String, Object?>>: cada linha é um mapa, como {'id': 1, 'nome': 'Leite'}.
for (final {'id': id as int, 'nome': nome as String} in linhas)
Um padrão do Dart 3 que, em cada mapa, pega o id e o nome já com o tipo certo, e monta um Item. É o jeito que a receita oficial usa. (Os mapas e as classes de modelo são o assunto de JSON e Classes de Modelo.)
db.insert('itens', {'nome': nome})
Escreve uma linha nova. As chaves do mapa são os nomes das colunas. O id não vai: o banco preenche.
db.update(…, where: 'id = ?', whereArgs: [id])
Muda as linhas que combinam com o where. O ? é um "espaço reservado" que o sqflite preenche com o valor de whereArgs.
db.delete('itens', where: 'id = ?', whereArgs: [id])
Apaga as linhas que combinam. Sem o where, apaga a tabela inteira.
Sempre whereArgs, nunca 'id = $id'

A receita oficial é taxativa: use sempre whereArgs e nunca monte o where com interpolação (where: 'nome = $nome'). Com interpolação, um texto digitado pelo usuário com aspas pode virar um pedaço de SQL (o ataque se chama SQL injection) ou simplesmente quebrar o comando.

4. O app completo: a lista de compras

import 'package:flutter/material.dart';
import 'package:path/path.dart';
import 'package:sqflite/sqflite.dart';

void main() => runApp(const MeuApp());

class Item {
  final int? id;
  final String nome;

  const Item({this.id, required this.nome});
}

class BancoCompras {
  static Database? _db;

  static Future<Database> abrir() async {
    return _db ??= await openDatabase(
      join(await getDatabasesPath(), 'compras.db'),
      version: 1,
      onCreate: (db, version) {
        return db.execute(
          'CREATE TABLE itens(id INTEGER PRIMARY KEY AUTOINCREMENT, nome TEXT NOT NULL)',
        );
      },
    );
  }

  static Future<List<Item>> listar() async {
    final db = await abrir();
    final linhas = await db.query('itens', orderBy: 'id');
    return [
      for (final {'id': id as int, 'nome': nome as String} in linhas)
        Item(id: id, nome: nome),
    ];
  }

  static Future<void> inserir(String nome) async {
    final db = await abrir();
    await db.insert('itens', {'nome': nome});
  }

  static Future<void> renomear(int id, String novoNome) async {
    final db = await abrir();
    await db.update('itens', {'nome': novoNome}, where: 'id = ?', whereArgs: [id]);
  }

  static Future<void> apagar(int id) async {
    final db = await abrir();
    await db.delete('itens', where: 'id = ?', whereArgs: [id]);
  }
}

class MeuApp extends StatelessWidget {
  const MeuApp({super.key});

  @override
  Widget build(BuildContext context) {
    return const MaterialApp(
      debugShowCheckedModeBanner: false,
      home: TelaCompras(),
    );
  }
}

class TelaCompras extends StatefulWidget {
  const TelaCompras({super.key});

  @override
  State<TelaCompras> createState() => _TelaComprasState();
}

class _TelaComprasState extends State<TelaCompras> {
  final _campo = TextEditingController();
  List<Item> _itens = [];

  @override
  void initState() {
    super.initState();
    _recarregar();
  }

  @override
  void dispose() {
    _campo.dispose();
    super.dispose();
  }

  Future<void> _recarregar() async {
    final itens = await BancoCompras.listar();
    setState(() => _itens = itens);
  }

  Future<void> _adicionar() async {
    final nome = _campo.text.trim();
    if (nome.isEmpty) return;
    await BancoCompras.inserir(nome);
    _campo.clear();
    await _recarregar();
  }

  Future<void> _apagar(Item item) async {
    await BancoCompras.apagar(item.id!);
    await _recarregar();
  }

  @override
  Widget build(BuildContext context) {
    return Scaffold(
      appBar: AppBar(title: const Text('Compras da Ana')),
      body: Column(
        children: [
          Padding(
            padding: const EdgeInsets.all(16),
            child: Row(
              children: [
                Expanded(
                  child: TextField(
                    controller: _campo,
                    decoration: const InputDecoration(labelText: 'Item'),
                  ),
                ),
                const SizedBox(width: 8),
                FilledButton(
                  onPressed: _adicionar,
                  child: const Text('Adicionar'),
                ),
              ],
            ),
          ),
          Expanded(
            child: ListView(
              children: [
                for (final item in _itens)
                  ListTile(
                    title: Text(item.nome),
                    trailing: IconButton(
                      tooltip: 'Apagar',
                      icon: const Icon(Icons.delete_outline),
                      onPressed: () => _apagar(item),
                    ),
                  ),
              ],
            ),
          ),
        ],
      ),
    );
  }
}

_itens e _recarregar()
A tela guarda a lista num campo comum e, depois de cada mudança no banco, lê tudo de novo e chama setState. É o jeito mais simples (e suficiente para listas de algumas centenas de itens).
initState() { _recarregar(); }
Ao abrir a tela, lê o que já estava no banco: é aqui que a lista "volta" depois de o app ser fechado.
_adicionar()
Lê o campo, ignora texto vazio, grava no banco, limpa o campo e recarrega a lista.
IconButton(tooltip: 'Apagar', …)
Apaga a linha pelo id. O item.id! é seguro: todo item que veio do banco tem id.

No celular (ilustrativo): na primeira vez, a lista aparece vazia, só com o campo Item e o botão Adicionar. A Ana digita "Leite", toca em Adicionar; depois "Pão" e "Café". Os três aparecem na lista, cada um com uma lixeira à direita. Ela fecha o app (tira até da lista de apps abertos) e abre de novo: os três itens continuam lá, porque estão no arquivo compras.db, e não na memória.

Para praticar a tela sem o sqflite (o DartPad do editor roda no navegador e não tem esse pacote), a caixa abaixo traz o mesmo app com um banco de mentirinha: uma classe BancoCompras com os mesmos métodos (listar, inserir, apagar), mas guardando numa lista na memória. Repare que a tela não mudou nada: é a vantagem de juntar o acesso ao banco numa classe. (Na memória, claro, a lista some quando o app fecha.)

Missão: a Ana prefere a lista em ordem alfabética. No listar() do banco de mentirinha, devolva a lista ordenada pelo nome: return [..._itens]..sort((a, b) => a.nome.compareTo(b.nome));. Adicione "Pão", "Café" e "Arroz" e veja a ordem. (No sqflite de verdade, o mesmo efeito é o orderBy: 'nome' do query.)

class BancoCompras {
  static final List<Item> _itens = [];

Quando dá errado

Rodou no navegador (flutter run -d chrome)

O laboratório compilou o app completo da seção 4 para a web e abriu no navegador. A tela abriu, mas sem nada da lista:

Error
Object.wrapException (http://127.0.0.1:45629/main.dart.js:7801:47)
databaseFactory_closure.call$0 (http://127.0.0.1:45629/main.dart.js:188552:15)
Object.databaseFactory (http://127.0.0.1:45629/main.dart.js:48783:48)
Object.getDatabasesPath (http://127.0.0.1:45629/main.dart.js:49878:16)

O console do navegador mostrou um erro e o caminho dele, de baixo para cima: o getDatabasesPath (chamado no abrir(), quando o initState pediu a lista) tentou pegar a "fábrica de bancos" do sqflite (databaseFactory), e no navegador não existe nenhuma. Os nomes vêm do JavaScript que o Flutter gerou para a web (main.dart.js), por isso não aparecem as linhas do seu main.dart. Tocar em Adicionar também falharia, pelo mesmo motivo. Como consertar: rode num celular ou emulador Android, num iPhone/simulador iOS ou no macOS. Se o app também precisa da web, use uma solução que funcione lá (o shared_preferences para dados pequenos, ou um pacote de banco com suporte à web; confira a aba de plataformas no pub.dev antes de escolher).

Mudou a tabela, mas o banco antigo continua lá

A Ana acrescentou uma coluna quantidade no CREATE TABLE e rodou de novo. No celular dela, o app reclama que a coluna não existe. Por quê? O onCreate só roda quando o arquivo ainda não existe, e o compras.db já existia, com a tabela antiga. Como consertar: suba a version para 2 e escreva um onUpgrade que faz ALTER TABLE itens ADD COLUMN quantidade INTEGER. Durante o desenvolvimento, desinstalar o app também apaga o banco (e os dados de teste). (Ilustrativo.)

Esqueceu o await

Escrever BancoCompras.inserir(nome); sem await e logo depois _recarregar() pode ler a lista antes de o item ser gravado: o item novo só aparece no próximo toque. Toda operação do sqflite devolve um Future; espere por ela com await antes de usar o resultado.

Resumo

  • O SQLite é um banco de dados num arquivo, dentro do aparelho; o sqflite é o pacote que fala com ele (Android, iOS e macOS; não roda na web).
  • Abra com openDatabase(join(await getDatabasesPath(), 'x.db'), version: 1, onCreate: …) e crie as tabelas no onCreate.
  • insert, query, update e delete, sempre com where: 'id = ?' + whereArgs, nunca com interpolação.
  • Junte o acesso ao banco numa classe (BancoCompras) e, na tela, recarregue a lista com setState depois de cada mudança.
  • Mudou as tabelas? Suba a version e use o onUpgrade.
