Flutter Checkbox, Switch e Radio

Nem tudo se responde digitando. "Aceito os termos": sim ou não. "Modo escuro": ligado ou desligado. "Tamanho da pizza": pequena, média ou grande. Para essas perguntas, o Material tem três controles prontos: a caixa de marcar (Checkbox), a chave de ligar e desligar (Switch) e o botão de opção (Radio), em que só um do grupo fica marcado.

Você vai aprender
  • A regra dos três: o valor mora no seu estado, e o onChanged avisa quando a pessoa quer trocá-lo.
  • Checkbox e CheckboxListTile (a linha inteira clicável, com texto).
  • Switch e SwitchListTile.
  • Escolha única com RadioGroup e RadioListTile, o jeito atual (o antigo, com groupValue em cada Radio, ficou obsoleto depois do Flutter 3.32).
  • Como desligar um controle (onChanged: null) e qual usar em cada caso.
  • Os erros reais: bool × bool? e a caixa que não marca.

A ideia: o interruptor da parede não lembra de nada

Parece estranho, mas o Checkbox do Flutter não guarda se está marcado. Ele é como um desenho de interruptor: mostra "ligado" ou "desligado" conforme você mandar (o parâmetro value). Quando a pessoa toca nele, ele não muda sozinho; ele avisa você ("querem trocar para true") pelo onChanged. Quem decide e guarda o novo valor é o seu State, com setState.

  1. O estado tem bool aceito = false;.
  2. O build desenha Checkbox(value: aceito, …): desmarcado.
  3. A pessoa toca. O Flutter chama onChanged(true).
  4. Você faz setState(() => aceito = true), e o build desenha a caixa marcada.

Os três controles desta aula funcionam assim. Esse jeito se chama controle controlado: o valor vem de fora, o widget só mostra e avisa.

1. Checkbox: a caixa de marcar

import 'package:flutter/material.dart';

void main() => runApp(const MaterialApp(home: Termos()));

class Termos extends StatefulWidget {
  const Termos({super.key});

  @override
  State<Termos> createState() => _TermosState();
}

class _TermosState extends State<Termos> {
  bool aceito = false;

  @override
  Widget build(BuildContext context) {
    return Scaffold(
      appBar: AppBar(title: const Text('Cadastro')),
      body: Column(
        children: [
          Row(
            children: [
              Checkbox(
                value: aceito,
                onChanged: (novo) {
                  setState(() {
                    aceito = novo!;
                  });
                },
              ),
              const Text('Li e aceito os termos'),
            ],
          ),
          FilledButton(
            onPressed: aceito ? () {} : null,
            child: const Text('Continuar'),
          ),
        ],
      ),
    );
  }
}
bool aceito = false;
O valor, no estado. A caixa começa desmarcada.
value: aceito
O que a caixa mostra: true = marcada (com o ✓), false = vazia.
onChanged: (novo) { … }
Chamado no toque, com o valor que a caixa quer ter. O tipo é bool? (pode ser nulo), porque existe uma caixa de três estados (o tristate, mais abaixo). Por isso o ! em novo!: numa caixa comum ele nunca vem nulo.
onPressed: aceito ? () {} : null
Um bônus: o botão Continuar só fica ativo com a caixa marcada. onPressed: null deixa qualquer botão cinza e sem toque (veja Botões).

A linha inteira clicável: CheckboxListTile

No exemplo acima, só o quadradinho responde ao toque: tocar no texto não faz nada. E o quadradinho é pequeno para um dedo. O CheckboxListTile junta a caixa e o texto numa linha de lista (veja Card e ListTile), e a linha inteira fica clicável:

CheckboxListTile(
  title: const Text('Li e aceito os termos'),
  subtitle: const Text('Você pode ler os termos no site'),
  value: aceito,
  onChanged: (novo) {
    setState(() {
      aceito = novo!;
    });
  },
)

No app da seção 1 com este CheckboxListTile no lugar do Row, a Ana tocou no texto (não na caixa). A caixa marcou e o Continuar acendeu:

Por padrão, a caixa fica à direita (no fim da linha). Para pôr à esquerda: controlAffinity: ListTileControlAffinity.leading.

2. Switch: a chave de ligar e desligar

O Switch é o mesmo sim/não, com outra cara: uma chavinha que desliza. A diferença é de sentido: o Checkbox é "marque o que se aplica" (escolher itens, aceitar algo); o Switch é "ligue ou desligue" uma configuração que vale na hora (Wi-Fi, notificações, modo escuro).

import 'package:flutter/material.dart';

void main() => runApp(const MaterialApp(home: Configuracoes()));

class Configuracoes extends StatefulWidget {
  const Configuracoes({super.key});

  @override
  State<Configuracoes> createState() => _ConfiguracoesState();
}

class _ConfiguracoesState extends State<Configuracoes> {
  bool notificacoes = true;
  bool somNoturno = false;

  @override
  Widget build(BuildContext context) {
    return Scaffold(
      appBar: AppBar(title: const Text('Configurações')),
      body: Column(
        children: [
          SwitchListTile(
            title: const Text('Notificações'),
            subtitle: const Text('Avisar quando chegar pedido'),
            value: notificacoes,
            onChanged: (novo) {
              setState(() {
                notificacoes = novo;
              });
            },
          ),
          SwitchListTile(
            title: const Text('Som à noite'),
            value: somNoturno,
            onChanged: notificacoes
                ? (novo) {
                    setState(() {
                      somNoturno = novo;
                    });
                  }
                : null,
          ),
        ],
      ),
    );
  }
}
SwitchListTile(…)
A chave com texto, na linha inteira clicável. Existe também o Switch sozinho, com os mesmos value e onChanged.
onChanged: (novo) { … notificacoes = novo; }
Aqui não tem !: no Switch, o valor é bool (não existe chave "meio ligada"), diferente do Checkbox.
onChanged: notificacoes ? (novo) {…} : null
Com as notificações desligadas, o onChanged vira null, e a chave "Som à noite" fica desativada: cinza e sem resposta ao toque. Vale para os três controles da aula.

3. Radio: só um do grupo

Pizza pequena, média ou grande: marcar uma desmarca as outras. É como os botões de estação dos rádios antigos de carro (daí o nome): apertar um faz o outro saltar. No Flutter atual, o grupo é um widget, o RadioGroup, que guarda qual opção está escolhida e avisa quando muda; dentro dele, cada RadioListTile só diz o seu valor:

import 'package:flutter/material.dart';

void main() => runApp(const MaterialApp(home: Pedido()));

enum Tamanho { pequena, media, grande }

class Pedido extends StatefulWidget {
  const Pedido({super.key});

  @override
  State<Pedido> createState() => _PedidoState();
}

class _PedidoState extends State<Pedido> {
  Tamanho? tamanho = Tamanho.media;

  @override
  Widget build(BuildContext context) {
    return Scaffold(
      appBar: AppBar(title: const Text('Pizza')),
      body: RadioGroup<Tamanho>(
        groupValue: tamanho,
        onChanged: (novo) {
          setState(() {
            tamanho = novo;
          });
        },
        child: Column(
          children: [
            const RadioListTile(value: Tamanho.pequena, title: Text('Pequena')),
            const RadioListTile(value: Tamanho.media, title: Text('Média')),
            const RadioListTile(value: Tamanho.grande, title: Text('Grande')),
            Text('Escolhida: ${tamanho?.name}'),
          ],
        ),
      ),
    );
  }
}
enum Tamanho { pequena, media, grande }
As opções possíveis, num enum (uma lista fechada de valores; veja o Guia Dart). Poderia ser String ou int, mas com enum o Dart avisa se você escrever uma opção que não existe.
Tamanho? tamanho = Tamanho.media;
A opção escolhida, no estado. É Tamanho? (pode ser nula) porque um grupo pode começar sem nada marcado.
RadioGroup<Tamanho>(groupValue: …, onChanged: …, child: …)
O grupo. groupValue é o valor escolhido; onChanged recebe o valor do botão tocado. Todos os Radio/RadioListTile que estiverem dentro do child, em qualquer profundidade, fazem parte do grupo.
RadioListTile(value: Tamanho.pequena, title: …)
Cada opção diz só o seu valor. Está marcada quando o seu value é igual ao groupValue do grupo. O tipo (RadioListTile<Tamanho>) o Dart descobre sozinho pelo value.
tamanho?.name
O nome da opção do enum como texto: 'media'.
O jeito antigo, que você vai ver em tutoriais

Nas versões antigas do Flutter, cada Radio recebia o groupValue e o onChanged: Radio(value: …, groupValue: tamanho, onChanged: …). Isso ainda compila, mas ficou obsoleto (deprecated) depois do 3.32 (a mensagem diz deprecated after v3.32.0-0.0.pre), e o flutter analyze reclama:

   info • 'groupValue' is deprecated and shouldn't be used. Use a RadioGroup ancestor to manage group value instead. This feature was deprecated after v3.32.0-0.0.pre. Try replacing the use of the deprecated member with the replacement • lib/main.dart:25:13 • deprecated_member_use
   info • 'onChanged' is deprecated and shouldn't be used. Use RadioGroup to handle value change instead. This feature was deprecated after v3.32.0-0.0.pre. Try replacing the use of the deprecated member with the replacement • lib/main.dart:26:13 • deprecated_member_use

"groupValue está obsoleto e não deveria ser usado. Use um RadioGroup acima para cuidar do valor do grupo." É um info (uma dica), não um erro: o app roda. Mas o que é obsoleto pode ser removido numa versão futura.

Prefira a versão ListTile

CheckboxListTile, SwitchListTile e RadioListTile deixam a linha inteira clicável, com uma área de toque grande, e os leitores de tela leem o texto junto com o controle. Use o controle sozinho só quando ele vai num lugar sem texto (dentro de uma tabela, por exemplo).

Quando dá errado

A caixa não marca 
Checkbox(
  value: aceito,
  onChanged: (novo) {
    aceito = novo!;
  },
)

Nenhuma mensagem de erro: a pessoa toca, a variável muda, mas a tela continua igual. Faltou o setState: sem ele, o Flutter não sabe que precisa redesenhar (veja setState). O mesmo acontece se você esquecer o onChanged inteiro ou usar um valor fixo (value: false): lembre que o controle não guarda nada sozinho. Como consertar: setState(() { aceito = novo!; });.

bool no lugar de bool? no Checkbox

No Switch o onChanged recebe bool; no Checkbox, bool?. Quem escreve o tipo do parâmetro à mão costuma trocar os dois:

Checkbox(
  value: aceito,
  onChanged: (bool novo) {
    setState(() {
      aceito = novo;
    });
  },
)

Com essa troca no app da seção 1, ele nem compila. O flutter analyze (e o editor, sublinhando em vermelho) mostra:

  error • The argument type 'void Function(bool)' can't be assigned to the parameter type 'ValueChanged<bool?>?'.  • lib/main.dart:25:28 • argument_type_not_assignable

"O tipo do argumento, uma função que recebe bool, não pode ser usado onde se espera um ValueChanged<bool?>?" (uma função que recebe bool?; o ? do fim diz que a função toda pode faltar, que é o onChanged: null). A posição 25:28 é o começo do (bool novo). Como consertar: não escreva o tipo, deixe o Dart descobrir: onChanged: (novo) { … aceito = novo!; }; ou escreva certo: (bool? novo).

Caixa com valor nulo, sem tristate

A Ana declarou bool? aceito; (sem valor inicial, então null) e passou para o Checkbox. Compila, mas, ao abrir a tela:

══╡ EXCEPTION CAUGHT BY WIDGETS LIBRARY ╞═══════════════════════════════════════════════════════════
The following assertion was thrown building Termos(dirty, state: _TermosState#6860a):
'package:flutter/src/material/checkbox.dart': Failed assertion: line 105 pos 15: 'tristate || value
!= null': is not true.

"Afirmação falhou: tristate || value != null não é verdade." Ou seja: o valor só pode ser null se a caixa for de três estados. Como consertar: dê um valor inicial (bool aceito = false;), ou, se você quer mesmo o terceiro estado (um tracinho: "alguns marcados", como o "selecionar todos" de uma lista), passe tristate: true.

Resumo

  • Checkbox, Switch e Radio não guardam nada: o valor mora no seu estado, e o onChanged + setState o troca.
  • No Checkbox, o valor é bool? (use novo!); no Switch, bool.
  • Escolha única: um RadioGroup com groupValue e onChanged, e dentro dele um RadioListTile por opção, cada um com o seu value.
  • onChanged: null desativa o controle.
  • Prefira as versões ListTile: a linha toda é clicável e tem texto.
