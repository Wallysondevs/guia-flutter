Flutter Responsivo

O mesmo app Flutter roda num celular de 6 polegadas, num tablet e na janela do computador. Se a tela foi pensada só para o celular, no computador ela vira uma lista esticada de ponta a ponta, com um mar de espaço vazio; se foi pensada só para o computador, no celular ela não cabe e aparecem as listras amarelas e pretas do overflow. Um app responsivo é o que responde ao tamanho da tela: mostra uma coluna no celular e duas no tablet, mais cartões por linha quando sobra espaço. Nesta aula você aprende as duas ferramentas para isso: MediaQuery e LayoutBuilder.

Você vai aprender
  • Como saber o tamanho da tela com MediaQuery.sizeOf(context) e a orientação com MediaQuery.orientationOf(context).
  • O que são pixels lógicos e por que a "largura" de um celular é 390, e não 1170.
  • Como escolher entre dois layouts com LayoutBuilder e um ponto de quebra (600).
  • Como fazer uma grade que muda sozinha o número de colunas (SliverGridDelegateWithMaxCrossAxisExtent).
  • Qual usar: MediaQuery ou LayoutBuilder.
  • O erro de overflow que aparece quando o layout não se adapta, e como consertar.

As telas desta aula foram fotografadas no laboratório do guia, com o Flutter 3.47, em dois tamanhos: 390 de largura (um celular comum) e 1024 de largura (um tablet deitado ou uma janela de computador).

A ideia: a mesma loja em dois balcões

A Ana vende bolos numa feira. Quando ganha uma barraca pequena, ela empilha os bolos numa prateleira só, um embaixo do outro. Quando ganha uma barraca grande, ela não empilha do mesmo jeito deixando metade da mesa vazia: põe os bolos de um lado e uma plaquinha com a receita do outro. Os bolos são os mesmos; o arranjo muda conforme o espaço.

No Flutter é igual. Os widgets (as peças da tela) são os mesmos; o que muda é como você os arruma. Para isso, o app precisa responder a uma pergunta: quanto espaço eu tenho? Há duas formas de perguntar:

  • MediaQuery: "qual é o tamanho da tela inteira (da janela)?"
  • LayoutBuilder: "qual é o espaço que o meu pai me deu, aqui neste pedaço da tela?"

1. Quanto mede a tela: MediaQuery.sizeOf

import 'package:flutter/material.dart';

void main() => runApp(const MeuApp());

class MeuApp extends StatelessWidget {
  const MeuApp({super.key});

  @override
  Widget build(BuildContext context) {
    return const MaterialApp(
      debugShowCheckedModeBanner: false,
      home: TelaTamanho(),
    );
  }
}

class TelaTamanho extends StatelessWidget {
  const TelaTamanho({super.key});

  @override
  Widget build(BuildContext context) {
    final tamanho = MediaQuery.sizeOf(context);
    final largura = tamanho.width.toStringAsFixed(0);
    final altura = tamanho.height.toStringAsFixed(0);
    final deitado = MediaQuery.orientationOf(context) == Orientation.landscape;

    return Scaffold(
      appBar: AppBar(title: const Text('Receitas da Ana')),
      body: Center(
        child: Text(
          'Largura: $largura\nAltura: $altura\n${deitado ? 'Deitado' : 'Em pé'}',
          textAlign: TextAlign.center,
          style: const TextStyle(fontSize: 28),
        ),
      ),
    );
  }
}
MediaQuery.sizeOf(context)
Devolve um Size com a largura (width) e a altura (height) da tela, em pixels lógicos (veja abaixo). O context é o "endereço" do widget na árvore: é por ele que o Flutter acha a informação do aparelho, guardada lá em cima, perto do MaterialApp.
tamanho.width.toStringAsFixed(0)
A largura é um double (pode ter casas decimais, como 392.7). O toStringAsFixed(0) do Dart mostra sem casas decimais.
MediaQuery.orientationOf(context)
Devolve Orientation.portrait ("retrato", em pé: mais alto que largo) ou Orientation.landscape ("paisagem", deitado: mais largo que alto).
final deitado = … == Orientation.landscape
Um bool que o texto usa para escrever "Deitado" ou "Em pé".

A mesma tela, em dois tamanhos:

Pixels lógicos: por que 390, e não 1170?

Um iPhone 14 tem 1170 pontinhos de luz (pixels físicos) na largura, mas o Flutter diz que ele tem 390 de largura. É que o Flutter mede em pixels lógicos: uma unidade que tem mais ou menos o mesmo tamanho físico em qualquer aparelho (cerca de 38 por centímetro). A tela do iPhone tem 3 pixels físicos para cada pixel lógico (MediaQuery.devicePixelRatioOf(context) devolve 3.0). Graças a isso, um botão de 48 de altura tem o mesmo tamanho no dedo num celular barato e num caríssimo. Todas as medidas do Flutter (width: 200, EdgeInsets.all(8), fontSize: 28) são em pixels lógicos.

sizeOf ou of(context).size?

Em códigos mais antigos você vai ver MediaQuery.of(context).size. Funciona, mas tem um custo escondido: o widget passa a ser reconstruído quando qualquer informação do MediaQuery muda (o teclado abrindo, o brilho, o tamanho da fonte do sistema…). O MediaQuery.sizeOf(context) (desde o Flutter 3.10) só reconstrói quando o tamanho muda. Prefira os métodos específicos: sizeOf, orientationOf, paddingOf, textScalerOf.

2. Escolher o layout pelo espaço: LayoutBuilder

Agora o app de receitas de verdade. No celular, ele mostra só a lista. Com 600 ou mais de largura, mostra a lista à esquerda e a receita à direita (esse arranjo se chama lista e detalhe, e é o que o app de e-mail do tablet faz).

import 'package:flutter/material.dart';

void main() => runApp(const MeuApp());

const receitas = ['Bolo de cenoura', 'Feijoada', 'Pão de queijo', 'Brigadeiro', 'Lasanha'];

class MeuApp extends StatelessWidget {
  const MeuApp({super.key});

  @override
  Widget build(BuildContext context) {
    return const MaterialApp(
      debugShowCheckedModeBanner: false,
      home: TelaReceitas(),
    );
  }
}

class TelaReceitas extends StatelessWidget {
  const TelaReceitas({super.key});

  @override
  Widget build(BuildContext context) {
    return Scaffold(
      appBar: AppBar(title: const Text('Receitas da Ana')),
      body: LayoutBuilder(
        builder: (context, constraints) {
          if (constraints.maxWidth < 600) {
            return const ListaReceitas();
          }
          return const Row(
            children: [
              SizedBox(width: 300, child: ListaReceitas()),
              VerticalDivider(width: 1),
              Expanded(child: DetalheReceita()),
            ],
          );
        },
      ),
    );
  }
}

class ListaReceitas extends StatelessWidget {
  const ListaReceitas({super.key});

  @override
  Widget build(BuildContext context) {
    return ListView(
      children: [
        for (final nome in receitas)
          ListTile(
            leading: const Icon(Icons.restaurant_menu),
            title: Text(nome),
          ),
      ],
    );
  }
}

class DetalheReceita extends StatelessWidget {
  const DetalheReceita({super.key});

  @override
  Widget build(BuildContext context) {
    return const Center(
      child: Column(
        mainAxisSize: MainAxisSize.min,
        children: [
          Icon(Icons.cake, size: 96, color: Colors.brown),
          SizedBox(height: 16),
          Text('Bolo de cenoura', style: TextStyle(fontSize: 32)),
          Text('3 cenouras, 3 ovos, 2 xícaras de farinha'),
        ],
      ),
    );
  }
}
LayoutBuilder(builder: (context, constraints) { … })
Um widget que espera saber o espaço antes de decidir o que desenhar. O Flutter chama o builder passando as constraints (as "restrições": a largura e a altura mínimas e máximas que o pai permite; veja Como o Flutter Calcula Tamanhos). Se o espaço mudar (a janela foi redimensionada, o celular girou), o builder roda de novo.
constraints.maxWidth < 600
A largura máxima disponível para este widget. O 600 é o ponto de quebra (em inglês, breakpoint): abaixo dele, layout de celular; a partir dele, layout de tablet. O Material 3 usa 600 como a fronteira entre "compacto" (celular) e "médio" (tablet pequeno, celular dobrável aberto).
return const ListaReceitas()
No celular, só a lista, ocupando a tela inteira.
Row(children: [SizedBox(width: 300, …), VerticalDivider(width: 1), Expanded(…)])
No tablet: a lista com 300 de largura fixa, uma linha vertical fininha separando, e a receita ocupando todo o resto com o Expanded.
ListaReceitas e DetalheReceita
Widgets pequenos, cada um com a sua parte. Repare que a ListaReceitas é a mesma nos dois layouts: só muda onde ela fica. Separar em widgets é o que torna isso fácil.

3. Uma grade que muda de colunas sozinha

Nem sempre você precisa de um if. Alguns widgets já sabem se adaptar. A GridView com SliverGridDelegateWithMaxCrossAxisExtent recebe a largura máxima de cada cartão e calcula quantas colunas cabem:

import 'package:flutter/material.dart';

void main() => runApp(const MeuApp());

const receitas = ['Bolo de cenoura', 'Feijoada', 'Pão de queijo', 'Brigadeiro', 'Lasanha', 'Pudim', 'Coxinha', 'Quindim'];

class MeuApp extends StatelessWidget {
  const MeuApp({super.key});

  @override
  Widget build(BuildContext context) {
    return MaterialApp(
      debugShowCheckedModeBanner: false,
      home: Scaffold(
        appBar: AppBar(title: const Text('Receitas da Ana')),
        body: GridView(
          padding: const EdgeInsets.all(8),
          gridDelegate: const SliverGridDelegateWithMaxCrossAxisExtent(
            maxCrossAxisExtent: 200,
            mainAxisSpacing: 8,
            crossAxisSpacing: 8,
          ),
          children: [
            for (final nome in receitas)
              Card(
                child: Center(
                  child: Text(nome, textAlign: TextAlign.center),
                ),
              ),
          ],
        ),
      ),
    );
  }
}
SliverGridDelegateWithMaxCrossAxisExtent
O "delegado" (quem decide o tamanho das casas da grade). O nome é comprido, mas a ideia é simples: "cada casa tem no máximo maxCrossAxisExtent de largura; ponha quantas colunas couberem".
maxCrossAxisExtent: 200
No máximo 200 de largura por cartão. O Flutter faz a conta espaço ÷ (200 + crossAxisSpacing) e arredonda para cima: com 390 de tela (374 tirando o padding), 374 ÷ 208 dá 1,8, ou seja, 2 colunas; com 1024 (1008 sem o padding), 1008 ÷ 208 dá 4,8, ou seja, 5 colunas. Depois, divide o espaço por igual entre elas, e cada cartão fica um pouco menor que 200.
mainAxisSpacing e crossAxisSpacing
O espaço entre as linhas e entre as colunas.

Outros widgets que se adaptam sozinhos: o Wrap (põe os filhos lado a lado e quebra a linha quando não cabe mais) e o Expanded/Flexible (divide o espaço em proporções, e não em medidas fixas).

Formas diferentes de fazer, e qual usar

FerramentaPergunta que ela respondeQuando usar
MediaQuery.sizeOf(context)Qual o tamanho da tela (janela) inteira?Decisões da tela toda: mostrar um Drawer no celular e um menu fixo no tablet; esconder algo em telas baixas.
LayoutBuilderQual o espaço que este widget recebeu do pai?Um pedaço da tela que muda de arranjo. Funciona mesmo quando o widget está dentro de um painel estreito numa tela larga, porque mede o espaço dele.
MediaQuery.orientationOf(context) ou OrientationBuilderA tela está em pé ou deitada?Quando o que importa é a proporção (por exemplo, 2 colunas em pé e 4 deitado).
GridView com MaxCrossAxisExtent, Wrap, Expanded(nenhuma: se adaptam sozinhos)Sempre que der. Menos if no código, menos coisa para dar errado.
Regra prática

Comece com widgets que se adaptam sozinhos (Expanded, Wrap, grades com largura máxima). Quando precisar trocar o arranjo inteiro, use LayoutBuilder. Guarde o MediaQuery para decisões que valem para a tela toda.

Quando dá errado

Larguras fixas que não cabem no celular

A Ana fez a tela no computador, com três cartões de 200 de largura lado a lado. No computador, ficou ótimo. No celular:

import 'package:flutter/material.dart';

void main() => runApp(const MeuApp());

class MeuApp extends StatelessWidget {
  const MeuApp({super.key});

  @override
  Widget build(BuildContext context) {
    return MaterialApp(
      debugShowCheckedModeBanner: false,
      home: Scaffold(
        appBar: AppBar(title: const Text('Receitas da Ana')),
        body: const Row(
          children: [
            SizedBox(width: 200, child: Card(child: Center(child: Text('Bolo')))),
            SizedBox(width: 200, child: Card(child: Center(child: Text('Feijoada')))),
            SizedBox(width: 200, child: Card(child: Center(child: Text('Pudim')))),
          ],
        ),
      ),
    );
  }
}

Linha por linha: EXCEPTION CAUGHT BY RENDERING LIBRARY é "exceção pega pela biblioteca de desenho"; A RenderFlex overflowed by 210 pixels on the right diz que um RenderFlex (a peça por trás do Row e do Column) estourou 210 pixels para a direita: três cartões de 200 somam 600, e a tela tem 390 (600 − 390 = 210). O parágrafo seguinte explica que a borda que estourou foi marcada com as listras e sugere um Expanded. A linha constraints: BoxConstraints(0.0<=w<=390.0, …) mostra o espaço que o Row recebeu: no máximo 390 de largura. (Cortamos as linhas marcadas com …. No seu flutter run, aparece também The relevant error-causing widget was: Row, com o arquivo e a linha do Row.) Como consertar: não use larguras fixas que somam mais que a menor tela. Troque os SizedBox(width: 200, …) por Expanded(child: …) (os três dividem o espaço que houver), use um Wrap (o terceiro cartão desce para a linha de baixo) ou um LayoutBuilder que mostra os cartões em coluna no celular.

Usou o MediaQuery quando o certo era o LayoutBuilder

Na tela de lista e detalhe do tablet, a Ana pôs dentro do painel de detalhe (que tem uns 700 de largura) um teste if (MediaQuery.sizeOf(context).width > 1000) para mostrar duas colunas de ingredientes. Num tablet de 1024, o teste dá verdadeiro, mas o painel tem só 723 de largura: as duas colunas ficam espremidas. O MediaQuery mede a tela; o painel é menor que ela. Como consertar: dentro de um pedaço da tela, pergunte o espaço daquele pedaço com LayoutBuilder e constraints.maxWidth.

Testou só no seu aparelho

O erro mais comum não aparece no seu celular: aparece no da sua tia, que tem uma tela menor ou a fonte do sistema no tamanho grande. Como evitar: rode o app no navegador (flutter run -d chrome, veja Rodando o App) e arraste a borda da janela, do estreito ao largo; procure as listras de overflow.

Resumo

  • Um app responsivo muda o arranjo dos widgets conforme o espaço; os widgets em si continuam os mesmos.
  • O Flutter mede tudo em pixels lógicos: um celular comum tem cerca de 390 de largura.
  • MediaQuery.sizeOf(context) dá o tamanho da tela inteira; MediaQuery.orientationOf(context), a orientação.
  • LayoutBuilder dá o espaço que aquele widget recebeu (constraints.maxWidth) e roda de novo quando ele muda.
  • Use um ponto de quebra (600 é o do Material 3) para trocar de layout: lista no celular, lista e detalhe no tablet.
  • Prefira o que se adapta sozinho: Expanded, Wrap, grades com maxCrossAxisExtent. Larguras fixas somando mais que a tela dão overflow.
