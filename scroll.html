Flutter Rolagem

Nem toda tela que rola é uma lista. A página de uma receita tem uma foto, um título, os ingredientes e o modo de preparo: peças diferentes, uma embaixo da outra, que juntas passam da altura do celular. Para isso existe o SingleChildScrollView ("visão de rolagem de um filho só"): você põe a sua Column dentro dele, e a tela inteira passa a rolar. Nesta aula você também vai ver a barra de rolagem, um botão de "voltar ao topo" e o erro de misturar duas coisas que rolam.

Você vai aprender
  • Como fazer uma tela rolar com SingleChildScrollView.
  • Como rolar para o lado com scrollDirection: Axis.horizontal.
  • Como mostrar a barra de rolagem (Scrollbar).
  • Como rolar pelo código com um ScrollController (o botão "voltar ao topo").
  • O erro real de pôr uma ListView dentro de um SingleChildScrollView, e o shrinkWrap.

As telas e o console desta aula vieram de um Flutter de verdade, no laboratório da Ana, em tamanho de celular, com fotos antes e depois de rolar.

A ideia: o cardápio comprido

O cardápio da padaria não cabe no quadro da parede, então o dono o escreveu num papel comprido, preso num rolo: quem quer ler o resto, puxa o papel. O SingleChildScrollView é esse rolo para um filho (em geral, uma Column com tudo dentro). Ele deixa o filho ser tão alto quanto precisar e mostra só a parte que cabe na janela.

SingleChildScrollView(…)
A área que rola. Ela tem um filho só (child), por isso tudo vai dentro de uma Column.
padding: const EdgeInsets.all(16)
Um respiro em volta do conteúdo, que rola junto com ele.
Column(crossAxisAlignment: CrossAxisAlignment.start, …)
As peças da página, uma embaixo da outra, alinhadas à esquerda (veja Alinhamento).
Container(height: 200, …)
O lugar da foto do bolo: um retângulo laranja com o ícone, só para ocupar o espaço de uma imagem.
'…\n…'
O \n quebra a linha dentro do texto. Duas strings lado a lado ('…' '…') viram uma só: é um jeito de escrever um texto comprido em várias linhas do código.
height: 1.6
No TextStyle, a altura da linha: 1,6 vez o tamanho da letra, para o texto respirar (veja Estilos de Texto).

Sem o SingleChildScrollView, essa página daria o erro de overflow (as listras embaixo). Com ele, a página tem a altura que precisa, e o fim aparece quando a Ana arrasta o dedo. A conta deu pouco mais que a tela: ao rolar, a página só subiu até o fim do texto, e a barra do título ficou acinzentada, como nas listas.

2. Rolagem para o lado

Lembra das etiquetas da aula de overflow? Além do Wrap, outra saída é deixar a fileira rolar para o lado:

        body: const Padding(
          padding: EdgeInsets.symmetric(vertical: 16),
          child: SingleChildScrollView(
            scrollDirection: Axis.horizontal,
            child: Row(
              children: [
                SizedBox(width: 16),
                Chip(label: Text('Doce')),
                SizedBox(width: 8),
                Chip(label: Text('Sem glúten')),
                SizedBox(width: 8),
                Chip(label: Text('Forno')),
                SizedBox(width: 8),
                Chip(label: Text('40 minutos')),
                SizedBox(width: 8),
                Chip(label: Text('Fácil')),
                SizedBox(width: 16),
              ],
            ),
          ),
        ),
scrollDirection: Axis.horizontal
O SingleChildScrollView rola na horizontal, e o filho (a Row) pode ser tão largo quanto precisar.
SizedBox(width: 16) nas pontas
Um respiro no começo e no fim da fileira, que rola junto.

"Doce", "Sem glúten", "Forno" e "40 minutos" aparecem, encostando na borda direita; o "Fácil" está fora da tela, à espera de uma arrastada para o lado. Sem listras: quem não cabe não transbordou, só ainda não apareceu. Qual usar? O Wrap mostra tudo de uma vez, em várias linhas; a rolagem lateral economiza altura, mas esconde parte das etiquetas.

3. Barra de rolagem e "voltar ao topo"

Numa página comprida, ajuda mostrar onde o usuário está (a barra de rolagem) e dar um atalho para voltar ao começo. Para rolar pelo código, você precisa de um ScrollController ("controlador de rolagem"), o "volante" da área que rola:

import 'package:flutter/material.dart';

void main() => runApp(const MeuApp());

class MeuApp extends StatelessWidget {
  const MeuApp({super.key});

  @override
  Widget build(BuildContext context) {
    return const MaterialApp(home: Passos());
  }
}

class Passos extends StatefulWidget {
  const Passos({super.key});

  @override
  State<Passos> createState() => _PassosState();
}

class _PassosState extends State<Passos> {
  final _controle = ScrollController();

  @override
  void dispose() {
    _controle.dispose();
    super.dispose();
  }

  void _voltarAoTopo() {
    _controle.animateTo(
      0,
      duration: const Duration(milliseconds: 500),
      curve: Curves.easeOut,
    );
  }

  @override
  Widget build(BuildContext context) {
    return Scaffold(
      appBar: AppBar(title: const Text('Passo a passo')),
      floatingActionButton: FloatingActionButton(
        onPressed: _voltarAoTopo,
        tooltip: 'Voltar ao topo',
        child: const Icon(Icons.arrow_upward),
      ),
      body: Scrollbar(
        controller: _controle,
        thumbVisibility: true,
        child: SingleChildScrollView(
          controller: _controle,
          child: Column(
            children: [
              for (var i = 1; i <= 20; i++)
                ListTile(
                  leading: CircleAvatar(child: Text('$i')),
                  title: Text('Passo $i da receita'),
                ),
            ],
          ),
        ),
      ),
    );
  }
}
final _controle = ScrollController();
O controlador, criado uma vez no State. Ele sabe a posição da rolagem e consegue mudá-la.
_controle.dispose();
Como tudo o que é criado no State e tem um dispose, o controlador é descartado quando o widget sai da tela (veja Ciclo de Vida).
_controle.animateTo(0, duration: …, curve: Curves.easeOut)
"Role, com animação, até a posição 0 (o topo), em meio segundo, desacelerando no fim." Para pular sem animação, existe o _controle.jumpTo(0).
Scrollbar(controller: _controle, thumbVisibility: true, …)
A barra de rolagem na lateral. O thumbVisibility: true deixa o "polegar" (o pedaço que anda) sempre visível; sem ele, a barra só aparece durante a rolagem.
SingleChildScrollView(controller: _controle, …)
O mesmo controlador ligado à área que rola: assim o botão e a barra mexem na mesma rolagem.
FloatingActionButton(tooltip: 'Voltar ao topo', …)
O botão redondo flutuante, no canto de baixo, com uma seta para cima.

Na primeira foto, a Ana rolou até o fim (o passo 20) e a barra cinza da direita está embaixo. Um toque no botão com a seta e, meio segundo depois, a lista voltou ao passo 1, com a barra lá em cima.

Formas diferentes de rolar: qual usar

SituaçãoUse
Uma tela com peças diferentes que passa da altura (receita, perfil, formulário)SingleChildScrollView + Column
Muitos itens parecidosListView / ListView.builder
Itens em gradeGridView
Uma fileira que não cabe na larguraSingleChildScrollView(scrollDirection: Axis.horizontal), ou Wrap para quebrar a linha
Lista grande com cabeçalho e outras peças que rolam juntosUma ListView só, com o cabeçalho como primeiro item (ou CustomScrollView, assunto avançado)
O SingleChildScrollView monta tudo

Ao contrário da ListView.builder, ele monta o filho inteiro, mesmo a parte fora da tela. Para uma página de receita, ótimo. Para 500 comentários, use uma lista com builder.

Quando dá errado

Uma ListView dentro do SingleChildScrollView

É o mesmo erro da ListView dentro de uma Column, agora com a frase que explica o caso: This situation typically happens when a scrollable widget is nested inside another scrollable widget, "acontece quando um widget que rola está dentro de outro que rola". O SingleChildScrollView dá à Column altura infinita, e a ListView quer ocupar "toda a altura que recebeu". A linha main.dart:18:15 aponta a ListView. Como consertar, de dois jeitos:

  • Se os itens são poucos, troque a ListView por uma Column (ou por um for dentro da Column de fora): não precisa de duas rolagens.
  • Ou diga à ListView para ter só a altura dos itens e não rolar sozinha:
              ListView(
                shrinkWrap: true,
                physics: const NeverScrollableScrollPhysics(),
                children: const [ … ],
              ),

shrinkWrap: true ("encolher para embrulhar") faz a lista ter a altura da soma dos itens, em vez de "toda a altura"; NeverScrollableScrollPhysics() ("física que nunca rola") desliga a rolagem própria dela, para só a de fora rolar. Atenção: com shrinkWrap, a lista monta todos os itens; para listas grandes, prefira uma ListView só, com a foto e o título como os primeiros itens.

Expanded dentro do SingleChildScrollView

Também não combina: dentro da rolagem, a altura é infinita, e o Expanded não tem "o que sobrou" para ocupar. O erro é RenderFlex children have non-zero flex but incoming height constraints are unbounded, com a tela em branco; a mensagem real, explicada, está em O Famoso Erro de Overflow.

Resumo

  • SingleChildScrollView faz um filho (uma Column) rolar: é a solução para telas de peças diferentes mais altas que o celular.
  • scrollDirection: Axis.horizontal rola para o lado.
  • Scrollbar mostra a barra; um ScrollController rola pelo código (animateTo, jumpTo) e precisa de dispose.
  • Rolagem dentro de rolagem dá Vertical viewport was given unbounded height: troque a lista de dentro por uma Column, ou use shrinkWrap: true + NeverScrollableScrollPhysics().
  • Muitos itens? Prefira uma ListView.builder, que só monta o que aparece.
