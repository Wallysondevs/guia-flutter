Flutter Material 3 e ColorScheme

Na aula Temas, uma linha (colorSchemeSeed: Colors.green) pintou o app inteiro. Mas que verde vai no botão? E no fundo do cartão, na pílula da barra de baixo, no texto em cima do botão? Quem decide é o ColorScheme ("esquema de cores"): uma paleta em que cada cor tem um papel, como os atores de uma peça. Esta aula mostra a paleta por dentro, conta o que é o Material 3, o sistema de design que dá essas regras, e ensina a ajustar a paleta sem perder a harmonia.

Você vai aprender
  • O que é o Material Design 3 e o que mudou em relação ao Material 2.
  • Os papéis das cores: primary, secondary, tertiary, error, surface, os ...Container e os pares on....
  • A criar a paleta com ColorScheme.fromSeed e a trocar uma cor só, sem perder as outras.
  • As variantes de paleta (dynamicSchemeVariant): mais viva, mais fiel à semente, em tons de cinza…
  • Qual componente usa qual cor, para saber o que muda quando você mexe num papel.
  • Os erros reais: colorSchemeSeed e colorScheme juntos, e o texto invisível por usar a cor errada.

Tudo nesta aula foi compilado com o Flutter 3.47 no laboratório do guia.

A ideia: o elenco de uma peça

Numa peça de teatro, cada ator tem um papel: o protagonista, o coadjuvante, o figurante, o cenário. Trocar o ator do protagonista não muda o papel: quem fizer o papel continua no centro do palco. O ColorScheme é o elenco das cores: o papel primary é sempre a cor de destaque (o botão principal), o papel surface é sempre o "cenário" (o fundo). Você troca as cores; os componentes continuam sabendo qual papel usar.

PapelPara que serveExemplos
primary / onPrimaryA cor de destaque principal e o texto sobre elaFilledButton, Switch ligado, links
primaryContainer / onPrimaryContainerUm tom suave da principal, para áreas de destaqueO botão flutuante (FloatingActionButton)
secondary / secondaryContainerDestaques menores, que não devem competir com o principalA pílula do NavigationBar, chips selecionados
tertiary / tertiaryContainerUm contraste, para equilibrar ou chamar atenção de outro jeitoUm selo "novo", um gráfico
error / errorContainerErros e avisosCampo de formulário inválido, Badge
surface / onSurfaceO fundo e o texto comumO fundo do Scaffold e da AppBar
surfaceContainerLowest … surfaceContainerHighestCinco fundos um pouco mais escuros que o surface, para separar camadasCard (Low), NavigationBar (o do meio, surfaceContainer)
outline / outlineVariantBordas e divisóriasOutlinedButton, Divider

Os exemplos da tabela foram conferidos no código do próprio Flutter 3.47: é de lá que cada componente tira a cor quando você não diz nada.

1. O que é o Material 3

Material Design é o sistema de design do Google: um conjunto de regras sobre cores, letras, formas e movimento, que os apps Android (e muitos outros) seguem. A terceira versão, o Material 3 (também chamado de Material You), trouxe a paleta gerada a partir de uma cor, formas mais arredondadas, botões e barras novos (FilledButton, NavigationBar, NavigationDrawer) e os papéis de cor desta aula.

No Flutter, o Material 3 é o padrão desde a versão 3.16: você não precisa ligar nada. O parâmetro useMaterial3 do ThemeData ainda existe e, com false, volta ao visual antigo, o Material 2 (seção "Formas diferentes").

2. A paleta por dentro

Para enxergar a paleta, o app abaixo desenha uma faixa para cada papel, pintada com a cor do papel e escrita com a cor "on" dele:

import 'package:flutter/material.dart';

void main() => runApp(const PaletaApp());

class PaletaApp extends StatelessWidget {
  const PaletaApp({super.key});

  @override
  Widget build(BuildContext context) {
    return MaterialApp(
      debugShowCheckedModeBanner: false,
      theme: ThemeData(colorSchemeSeed: Colors.green),
      home: const PaletaPage(),
    );
  }
}

class PaletaPage extends StatelessWidget {
  const PaletaPage({super.key});

  @override
  Widget build(BuildContext context) {
    final c = Theme.of(context).colorScheme;
    final papeis = [
      ('primary', c.primary, c.onPrimary),
      ('primaryContainer', c.primaryContainer, c.onPrimaryContainer),
      ('secondary', c.secondary, c.onSecondary),
      ('secondaryContainer', c.secondaryContainer, c.onSecondaryContainer),
      ('tertiary', c.tertiary, c.onTertiary),
      ('tertiaryContainer', c.tertiaryContainer, c.onTertiaryContainer),
      ('error', c.error, c.onError),
      ('surface', c.surface, c.onSurface),
      ('surfaceContainer', c.surfaceContainer, c.onSurface),
      ('surfaceContainerHighest', c.surfaceContainerHighest, c.onSurface),
      ('outline', c.outline, c.surface),
    ];
    return Scaffold(
      appBar: AppBar(title: const Text('A paleta da Ana')),
      body: ListView(
        children: [
          for (final (nome, fundo, texto) in papeis)
            Container(
              color: fundo,
              padding: const EdgeInsets.all(16),
              child: Text(nome, style: TextStyle(color: texto)),
            ),
        ],
      ),
    );
  }
}
final c = Theme.of(context).colorScheme;
A paleta do tema atual. Cada papel é uma propriedade: c.primary, c.onPrimary…
('primary', c.primary, c.onPrimary)
Um registro (record) do Dart com três valores: o nome, a cor do papel e a cor do texto sobre ela. O for (final (nome, fundo, texto) in papeis) desmonta cada registro nas três variáveis.

Repare em três coisas. Os papéis vêm em pares de tom: o primary é um verde-escuro e o primaryContainer, um verde-claro da mesma família. O secondary é um verde acinzentado, mais discreto, e o tertiary é um azul-petróleo: uma cor diferente, escolhida pelo Flutter para combinar com o verde. E o texto de cada faixa (a cor on…) é branco nas faixas escuras e escuro nas claras, sempre legível, sem você escolher nada. O error é vermelho em qualquer paleta.

3. ColorScheme.fromSeed: a paleta com ajustes

O colorSchemeSeed é um atalho. O jeito completo é criar o ColorScheme você mesmo, com ColorScheme.fromSeed, e entregá-lo no colorScheme do ThemeData. As duas linhas abaixo dão o mesmo resultado:

theme: ThemeData(colorSchemeSeed: Colors.green),

theme: ThemeData(colorScheme: ColorScheme.fromSeed(seedColor: Colors.green)),

A vantagem do jeito completo: dá para trocar um papel e deixar o resto calculado. A Ana gostou de tudo, mas quer o terciário num laranja de cenoura:

theme: ThemeData(
  colorScheme: ColorScheme.fromSeed(
    seedColor: Colors.green,
    tertiary: const Color(0xFFE65100),
  ),
),
ColorScheme.fromSeed(seedColor: ...)
Gera a paleta inteira a partir da semente, como o colorSchemeSeed.
tertiary: const Color(0xFFE65100)
Qualquer papel pode ser passado à mão e vence o calculado. 0xFFE65100 é a cor em hexadecimal: FF de opacidade total e E65100, o laranja (aula Cores, Bordas e Sombras). Atenção: o onTertiary continua o calculado; se você trocar um papel por uma cor muito diferente, confira se o texto sobre ela ainda é legível.

Missão: troque o colorSchemeSeed por um colorScheme: ColorScheme.fromSeed(seedColor: ...) com a semente que você quiser, e veja a paleta inteira mudar.

4. Variantes da paleta: dynamicSchemeVariant

A mesma semente pode virar paletas de "personalidades" diferentes. O fromSeed tem o parâmetro dynamicSchemeVariant ("variante do esquema"), e o padrão, tonalSpot, dá cores calmas, um pouco apagadas. O app abaixo mostra quatro variantes da mesma semente verde, lado a lado:

import 'package:flutter/material.dart';

void main() => runApp(const VariantesApp());

class VariantesApp extends StatelessWidget {
  const VariantesApp({super.key});

  @override
  Widget build(BuildContext context) {
    const variantes = [
      DynamicSchemeVariant.tonalSpot,
      DynamicSchemeVariant.fidelity,
      DynamicSchemeVariant.vibrant,
      DynamicSchemeVariant.monochrome,
    ];
    return MaterialApp(
      debugShowCheckedModeBanner: false,
      home: Scaffold(
        appBar: AppBar(title: const Text('Semente verde')),
        body: ListView(
          padding: const EdgeInsets.all(12),
          children: [
            for (final v in variantes) Faixa(variante: v),
          ],
        ),
      ),
    );
  }
}

class Faixa extends StatelessWidget {
  const Faixa({super.key, required this.variante});

  final DynamicSchemeVariant variante;

  @override
  Widget build(BuildContext context) {
    final c = ColorScheme.fromSeed(
      seedColor: Colors.green,
      dynamicSchemeVariant: variante,
    );
    final cores = [c.primary, c.primaryContainer, c.secondary, c.tertiary, c.surfaceContainer];
    return Padding(
      padding: const EdgeInsets.only(bottom: 16),
      child: Column(
        crossAxisAlignment: CrossAxisAlignment.start,
        children: [
          Text(variante.name),
          const SizedBox(height: 4),
          Row(
            children: [
              for (final cor in cores)
                Expanded(child: Container(height: 48, color: cor)),
            ],
          ),
        ],
      ),
    );
  }
}

Na tonalSpot, os verdes são apagados e o terciário é um azul-petróleo. Na fidelity, o primeiro quadrado é um verde bem mais vivo, perto do Colors.green, e o terciário virou um vinho. A vibrant tem o primaryContainer num verde-limão bem saturado. A monochrome ignora o verde: só preto e cinzas. Todas foram geradas da mesma semente.

VariantePersonalidade
tonalSpot (padrão)Calma, tons suaves; a recomendada para a maioria dos apps
fidelityFiel à semente: o primary fica bem perto da cor que você deu (boa para cores de marca)
vibrantCores mais saturadas e vivas
monochromeSó cinzas, ignorando a cor da semente
neutral, expressive, content, rainbow, fruitSaladOutras personalidades; experimente no editor

Formas diferentes de fazer

Material 3 × Material 2

Com useMaterial3: false, o Flutter volta ao visual antigo. A mesma vitrine da aula Temas, com semente verde, nos dois sistemas:

theme: ThemeData(colorSchemeSeed: Colors.green, useMaterial3: false),

No Material 2, a AppBar volta a ser colorida (verde-escuro com título branco, à esquerda), o botão contornado tem cantos quase retos, o cartão tem sombra e fundo branco, o interruptor desativado é menor e o botão flutuante é um círculo escuro, não mais o quadrado arredondado verde-claro do Material 3. Compare com a foto temas-2 da aula Temas.

Jeito de definir as coresQuando usar
colorSchemeSeed: corO mais simples: uma cor e pronto
colorScheme: ColorScheme.fromSeed(seedColor: cor, ...)Quando quer trocar um papel ou escolher a variante
colorScheme: ColorScheme(brightness: ..., primary: ..., onPrimary: ..., ...)Paleta 100% à mão (exige todos os papéis obrigatórios); para quem tem um manual de marca fechado
useMaterial3: falseSó para manter um app antigo com o visual de antes; o Material 2 não recebe novidades

Quando dá errado

colorSchemeSeed e colorScheme juntos 
theme: ThemeData(
  colorSchemeSeed: Colors.green,
  colorScheme: ColorScheme.fromSeed(seedColor: Colors.orange),
),

A regra que falhou, na linha 431 do theme_data.dart (o arquivo do Flutter que define o ThemeData), diz: "o colorSchemeSeed tem de ser nulo ou o colorScheme tem de ser nulo". Em outras palavras: um ou outro, nunca os dois. O widget apontado é o PaletaApp, criado na linha 3 do main.dart (o runApp(const PaletaApp())), porque é no build dele que o ThemeData é montado.

Como consertar: escolha um dos dois. O colorSchemeSeed é o atalho do colorScheme: ColorScheme.fromSeed(...); os dois juntos seriam duas respostas para a mesma pergunta.

O texto que sumiu 
Container(
  color: c.primary,
  padding: const EdgeInsets.all(16),
  child: Text('Receita do dia', style: TextStyle(color: c.primary)),
),
Container(
  color: c.primary,
  padding: const EdgeInsets.all(16),
  child: Text('Receita do dia', style: TextStyle(color: c.onPrimary)),
),

Nenhuma mensagem de erro: o texto está lá, mas na mesma cor do fundo. Como consertar: use sempre o par: fundo primary → texto onPrimary; fundo primaryContainer → texto onPrimaryContainer; fundo surface → texto onSurface. O par foi calculado para ter contraste, no claro e no escuro.

Resumo

  • O Material 3 é o sistema de design padrão do Flutter desde a 3.16: paleta gerada de uma semente, formas arredondadas, componentes novos.
  • O ColorScheme é a paleta, com papéis: primary, secondary, tertiary, error, surface (e os surfaceContainer…), outline. Cada fundo tem o seu par on… para o texto.
  • Os componentes usam papéis fixos: FilledButton → primary; botão flutuante → primaryContainer; Card → surfaceContainerLow; pílula do NavigationBar → secondaryContainer.
  • ColorScheme.fromSeed(seedColor:) = o colorSchemeSeed, com a chance de trocar papéis e de escolher a dynamicSchemeVariant.
  • Não use colorSchemeSeed e colorScheme juntos; e escreva sempre com o par on… do fundo.
