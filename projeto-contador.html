Flutter Projeto: Contador Turbinado

Todo projeto Flutter novo nasce com um contador: um número e um botão +. Neste projeto, a Ana pega essa ideia e a turbina: botões de somar, subtrair e zerar, um seletor de "passo" (contar de 1 em 1, de 5 em 5 ou de 10 em 10), a cor do número mudando conforme o valor e uma meta que comemora quando é batida. No caminho, você junta quase tudo o que viu até aqui num app só e, no fim, escreve testes de verdade para ele.

O que você vai construir e praticar
  • MaterialApp com tema Material 3 a partir de uma cor (Temas).
  • Um StatefulWidget com três informações no estado: o valor, o passo e a meta (StatefulWidget, setState).
  • FilledButton, OutlinedButton, TextButton e o botão desabilitado (Botões).
  • SegmentedButton para escolher o passo.
  • Texto e cor que mudam conforme o estado (uma função que escolhe a cor).
  • Testes de widget, incluindo uma falha real e como consertá-la (Testes de Widget).

Todas as telas desta página são fotos do app rodando no Flutter 3.47.7; as saídas de terminal vieram da máquina da Ana. Você pode fazer o projeto inteiro no editor do guia, ou num projeto seu criado com flutter create contador_turbinado (veja Criando um Projeto).

O plano

Antes de escrever código, a Ana desenhou a tela num papel, de cima para baixo:

Scaffold
├── AppBar: "Contador Turbinado"
└── Padding
    └── Column (centralizada)
        ├── Text  ← o valor, enorme (96), com cor que muda
        ├── Text  ← "Meta: 10" ou "Meta batida! 🎉"
        ├── Text  "Passo"
        ├── SegmentedButton  [ 1 | 5 | 10 ]
        ├── Row
        │   ├── OutlinedButton "Subtrair"
        │   └── FilledButton   "Somar"
        └── TextButton "Zerar"  ← desabilitado quando o valor já é 0

E listou o que muda com o tempo (o estado): o valor e o passo. A meta não muda: vira uma constante. Tudo o mais (a cor, a frase da meta, se o Zerar está ligado) é calculado a partir do valor, a cada build. Essa é a regra de ouro: guarde no estado só o mínimo; o resto, calcule.

Passo 2: o estado e o primeiro botão

class TelaContador extends StatefulWidget {
  const TelaContador({super.key});

  @override
  State<TelaContador> createState() => _TelaContadorState();
}

class _TelaContadorState extends State<TelaContador> {
  int _valor = 0;

  void _somar() => setState(() => _valor++);

  @override
  Widget build(BuildContext context) {
    return Scaffold(
      appBar: AppBar(title: const Text('Contador Turbinado')),
      body: Center(
        child: Text('$_valor', style: const TextStyle(fontSize: 96)),
      ),
      floatingActionButton: FloatingActionButton(
        onPressed: _somar,
        child: const Icon(Icons.add),
      ),
    );
  }
}

Isto já é o contador clássico. O _ na frente de _valor e _somar os deixa privados ao arquivo: ninguém de fora mexe no estado. O setState avisa o Flutter "mudei o valor, redesenhe".

Passo 3: o passo, Subtrair e Zerar

Agora o estado ganha o passo, e os botões viram três funções pequenas:

  static const meta = 10;
  int _valor = 0;
  int _passo = 1;

  void _somar() => setState(() => _valor += _passo);
  void _subtrair() => setState(() => _valor -= _passo);
  void _zerar() => setState(() => _valor = 0);
static const meta = 10;
A meta é a mesma para sempre: static const ("constante da classe"). Não vai no estado.
_valor += _passo
Soma o passo atual, seja 1, 5 ou 10.

E o seletor do passo, com SegmentedButton (botões grudados, em que um fica marcado):

SegmentedButton<int>(
  segments: const [
    ButtonSegment(value: 1, label: Text('1')),
    ButtonSegment(value: 5, label: Text('5')),
    ButtonSegment(value: 10, label: Text('10')),
  ],
  selected: {_passo},
  onSelectionChanged: (escolha) =>
      setState(() => _passo = escolha.first),
),
SegmentedButton<int>
O <int> diz o tipo do valor de cada segmento.
segments: [ButtonSegment(value: 1, label: Text('1')), …]
Os segmentos: o valor de cada um e o que aparece escrito.
selected: {_passo}
Quais estão marcados. É um conjunto (Set, com chaves {}), porque o SegmentedButton também permite marcar vários. Aqui, sempre um.
onSelectionChanged: (escolha) => …
Chamado quando a pessoa toca num segmento. escolha é o novo conjunto; escolha.first, o valor escolhido.

Passo 4: cor, meta e o Zerar inteligente

A cor do número sai de uma função que olha o valor:

  Color _corDoValor(ColorScheme cores) {
    if (_valor < 0) return cores.error;
    if (_valor >= meta) return Colors.green.shade700;
    return cores.onSurface;
  }
  • Negativo: cores.error, o vermelho de erro do tema.
  • Bateu a meta: verde-escuro.
  • No meio: cores.onSurface, a cor normal do texto.

A frase da meta usa o operador ternário (condição ? se_sim : se_não):

Text(
  _valor >= meta ? 'Meta batida! 🎉' : 'Meta: $meta',
  style: const TextStyle(fontSize: 20),
),

E o Zerar fica desligado quando não há o que zerar. Em Flutter, um botão com onPressed: null aparece apagado e não responde:

TextButton(
  onPressed: _valor == 0 ? null : _zerar,
  child: const Text('Zerar'),
),

class TelaContador extends StatefulWidget {
  const TelaContador({super.key});

  @override
  State<TelaContador> createState() => _TelaContadorState();
}

class _TelaContadorState extends State<TelaContador> {
  static const meta = 10;
  int _valor = 0;
  int _passo = 1;

  void _somar() => setState(() => _valor += _passo);
  void _subtrair() => setState(() => _valor -= _passo);
  void _zerar() => setState(() => _valor = 0);

  Color _corDoValor(ColorScheme cores) {
    if (_valor < 0) return cores.error;
    if (_valor >= meta) return Colors.green.shade700;
    return cores.onSurface;
  }

  @override
  Widget build(BuildContext context) {
    final cores = Theme.of(context).colorScheme;
    return Scaffold(
      appBar: AppBar(
        title: const Text('Contador Turbinado'),
        backgroundColor: cores.primaryContainer,
      ),
      body: Padding(
        padding: const EdgeInsets.all(24),
        child: Column(
          mainAxisAlignment: MainAxisAlignment.center,
          children: [
            Text(
              '$_valor',
              key: const Key('valor'),
              style: TextStyle(
                fontSize: 96,
                fontWeight: FontWeight.bold,
                color: _corDoValor(cores),
              ),
            ),
            const SizedBox(height: 8),
            Text(
              _valor >= meta ? 'Meta batida! 🎉' : 'Meta: $meta',
              style: const TextStyle(fontSize: 20),

Quando dá errado

O número não muda ao tocar

Você escreveu void _somar() { _valor += _passo; }, sem o setState. O valor muda na memória, mas ninguém avisou o Flutter para redesenhar. Como resolver: setState(() => _valor += _passo).

O seletor não marca o segmento tocado

O onSelectionChanged está vazio, ou não chama setState. O SegmentedButton só mostra o que está em selected; quem muda isso é você. Como resolver: onSelectionChanged: (escolha) => setState(() => _passo = escolha.first).

Teste acha "too many"

Como você viu acima: o texto procurado aparece em mais de um lugar. Como resolver: dê uma Key ao widget que interessa e procure por ela.

A meta virou parte do estado

Se a meta ficasse como int _meta = 10; no estado sem nunca mudar, o app funcionaria, mas o código mentiria ("isto muda"). Como resolver: o que não muda é static const; o que é calculado (cor, frase) não vai no estado.

Desafios para turbinar mais

  1. Limite mínimo: não deixe o valor passar de -10 (desligue o Subtrair quando chegar lá, como o Zerar).
  2. Histórico: guarde numa lista os últimos 5 valores e mostre embaixo (veja ListView).
  3. Meta escolhida: troque a constante por um Slider de 5 a 50 (veja Slider e Dropdown). Agora a meta muda: ela vai para o estado.
  4. Lembrar o valor: ao fechar e abrir o app, o valor volta. Veja SharedPreferences.
  5. Mais testes: escreva um que confira a cor vermelha quando o valor fica negativo (tester.widget<Text>(…).style!.color).

Resumo

  • Planeje antes: desenhe a árvore e separe o que muda (estado: valor e passo) do que é fixo (static const meta) e do que é calculado (cor, frase, botão ligado).
  • Cada ação é uma função pequena com setState.
  • SegmentedButton escolhe uma opção entre poucas; onPressed: null desliga um botão.
  • Testes pegam ambiguidades: uma Key no widget certo deixa o teste firme.
