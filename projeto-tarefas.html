Flutter Projeto: Lista de Tarefas

A lista de tarefas é o "olá, mundo" dos apps que guardam coisas: você digita, a tarefa aparece na lista, você marca quando termina e arrasta para o lado para apagar. A Ana usa uma para não esquecer as encomendas de bolo. Neste projeto, você constrói o app dela em 3 versões, cada uma com o código completo, a foto real da tela e uma missão no editor. É aqui que estado, listas e campos de texto trabalham juntos pela primeira vez.

Você vai aprender
  • Versão 1: guardar uma lista no estado e mostrá-la com ListView.builder.
  • Versão 2: ler o que a pessoa digita com TextField e TextEditingController, e acrescentar à lista com setState.
  • Versão 3: trocar os textos por uma classe de modelo (Tarefa), marcar como feita com CheckboxListTile e apagar arrastando com Dismissible.
  • O erro real de colocar um ListView dentro de uma Column sem Expanded, e como resolver.

Aulas que ajudam: setState, ListView.builder, Campos de Texto, Checkbox, Switch e Radio, Arrastar para Apagar e Expanded e Flexible.

O plano

Pense numa lista de papel presa na geladeira: um título no alto, as tarefas uma embaixo da outra, um espaço para escrever a próxima, um "risco" em cima do que já foi feito. No app, cada parte vira uma peça:

TarefasApp (MaterialApp)
└── TarefasPage (Scaffold, com estado: a lista de tarefas)
    ├── appBar: AppBar → 'Tarefas (1/3)'
    └── body: Column
        ├── Padding → Row
        │   ├── Expanded → TextField ('Nova tarefa')
        │   └── FilledButton ('Adicionar')
        └── Expanded → ListView.builder
            └── (para cada tarefa) Dismissible → CheckboxListTile

A peça mais importante não aparece na tela: é a lista de tarefas guardada no estado. A tela é só um "retrato" dessa lista. Adicionar, marcar e apagar são sempre a mesma receita: mudar a lista dentro de setState e deixar o Flutter redesenhar.

Versão 1: a lista na tela

Comece com três tarefas já escritas no código. A página já nasce como StatefulWidget, porque a lista vai mudar nas próximas versões.

import 'package:flutter/material.dart';

final List<String> _tarefas = [ … ];
A lista no estado. É final porque a variável sempre aponta para a mesma lista; o conteúdo da lista pode mudar (acrescentar, tirar). O _ deixa o campo privado.
ListView.builder(
Uma lista rolável que constrói cada linha só quando ela vai aparecer na tela. Com 3 tarefas tanto faz; com 300, faz muita diferença (veja ListView.builder).
itemCount: _tarefas.length
Quantas linhas a lista tem. Sempre ligue ao tamanho da sua lista: assim, quando a lista crescer, a tela acompanha.
itemBuilder: (context, index) { … }
Uma função que o Flutter chama para cada linha, com o index (posição: 0, 1, 2…). Ela devolve o widget daquela linha.
ListTile(leading: …, title: Text(_tarefas[index]))
A linha em si: um círculo vazio à esquerda e o texto da tarefa daquela posição.

As três tarefas aparecem uma embaixo da outra, cada uma com o círculo vazio (o ícone radio_button_unchecked) e a mesma altura, que o ListTile define sozinho. O resto da tela fica vazio, mas a lista ocupa a altura toda: se houvesse 50 tarefas, ela rolaria.

Missão: acrescente duas tarefas à lista: 'Comprar ovos' e 'Lavar as formas'. Repare que você não mexe em nada do ListView: o itemCount acompanha sozinho.

Versão 2: digitar e adicionar

Agora a Ana quer escrever tarefas novas sem mexer no código. No alto da tela entram um campo de texto e um botão Adicionar. Para ler o que foi digitado, o campo recebe um controlador (TextEditingController): um objeto que guarda o texto do campo e deixa você ler e limpar esse texto pelo código.

import 'package:flutter/material.dart';

void main() => runApp(const TarefasApp());

class TarefasApp extends StatelessWidget {
  const TarefasApp({super.key});

  @override
  Widget build(BuildContext context) {
    return MaterialApp(
      title: 'Tarefas da Ana',
      debugShowCheckedModeBanner: false,
      theme: ThemeData(colorSchemeSeed: Colors.indigo),
      home: const TarefasPage(),
    );
  }
}

class TarefasPage extends StatefulWidget {
  const TarefasPage({super.key});

  @override
  State<TarefasPage> createState() => _TarefasPageState();
}

class _TarefasPageState extends State<TarefasPage> {
  final List<String> _tarefas = [
    'Comprar farinha',
    'Assar o bolo de cenoura',
    'Entregar a encomenda da Dona Rosa',
  ];
  final _controller = TextEditingController();

  void _adicionar() {
    final texto = _controller.text.trim();
    if (texto.isEmpty) return;
    setState(() {
      _tarefas.add(texto);
    });
    _controller.clear();
  }

  @override
  void dispose() {
    _controller.dispose();
    super.dispose();
  }

  @override
  Widget build(BuildContext context) {
    return Scaffold(
      appBar: AppBar(title: const Text('Tarefas da Ana')),
      body: Column(
        children: [
          Padding(
            padding: const EdgeInsets.all(16),
            child: Row(
              children: [
                Expanded(
                  child: TextField(
                    controller: _controller,
                    decoration: const InputDecoration(
                      labelText: 'Nova tarefa',
                      border: OutlineInputBorder(),
                    ),
                    onSubmitted: (_) => _adicionar(),
                  ),
                ),
                const SizedBox(width: 8),
                FilledButton(
                  onPressed: _adicionar,
                  child: const Text('Adicionar'),
                ),
              ],
            ),
          ),
          Expanded(
            child: ListView.builder(
              itemCount: _tarefas.length,
              itemBuilder: (context, index) {
                return ListTile(
                  leading: const Icon(Icons.radio_button_unchecked),
                  title: Text(_tarefas[index]),
                );
              },
            ),
          ),
        ],
      ),
    );
  }
}
final _controller = TextEditingController();
O controlador do campo, criado uma vez, junto com o estado.
_controller.text.trim()
O texto digitado, sem espaços nas pontas. Se a pessoa digitou só espaços, sobra uma string vazia.
if (texto.isEmpty) return;
Não deixa entrar tarefa em branco: se não há texto, a função para aqui.
setState(() { _tarefas.add(texto); });
Acrescenta a tarefa no fim da lista e avisa o Flutter para redesenhar. O itemCount passa de 3 para 4, e a linha nova aparece.
_controller.clear();
Esvazia o campo, pronto para a próxima tarefa.
void dispose() { _controller.dispose(); … }
Quando a tela sai de cena, o controlador é descartado e libera a memória. Todo controlador que você cria, você descarta (veja Ciclo de Vida do Widget).
Expanded(child: TextField(…))
Dentro de um Row, o campo de texto precisa saber quanto de largura pode usar. O Expanded dá a ele todo o espaço que o botão não usar.
onSubmitted: (_) => _adicionar()
Apertar Enter (ou o "OK" do teclado do celular) também adiciona. O _ é o texto que o campo manda, que não usamos aqui (já temos o controlador).
Expanded(child: ListView.builder(…))
A lista ocupa todo o resto da altura, abaixo do campo. Sem esse Expanded, o app quebra: veja Quando dá errado.

No lab, a foto foi tirada depois de clicar no campo e digitar Comprar ovos. Repare no rótulo: com o campo em foco, o labelText "Nova tarefa" subiu e ficou pequeno, encaixado na borda (é o comportamento do OutlineInputBorder). Em seguida, um clique em Adicionar:

As três linhas do _adicionar aparecem na foto: a tarefa entrou no fim da lista (add), a tela foi redesenhada (setState) e o campo ficou vazio de novo (clear), com o rótulo de volta ao meio.

Missão: a Ana prefere ver a tarefa mais nova no topo. Troque _tarefas.add(texto) por _tarefas.insert(0, texto) (inserir na posição 0). Digite uma tarefa e aperte Adicionar para conferir.

Versão 3: marcar como feita e apagar arrastando

Uma tarefa agora tem duas informações: o título e se já foi feita. Uma String sozinha não dá conta, então cada tarefa vira um objeto de uma classe pequena, a classe de modelo Tarefa (o mesmo jeito de pensar da aula JSON e Classes de Modelo). Na tela, cada linha ganha uma caixa de seleção, o texto fica riscado quando a tarefa está feita, e arrastar a linha para o lado apaga a tarefa. A barra do topo mostra quantas já foram feitas.

import 'package:flutter/material.dart';

void main() => runApp(const TarefasApp());

class Tarefa {
  Tarefa(this.titulo, {this.feita = false});

  final String titulo;
  bool feita;
}

class TarefasApp extends StatelessWidget {
  const TarefasApp({super.key});

  @override
  Widget build(BuildContext context) {
    return MaterialApp(
      title: 'Tarefas da Ana',
      debugShowCheckedModeBanner: false,
      theme: ThemeData(colorSchemeSeed: Colors.indigo),
      home: const TarefasPage(),
    );
  }
}

class TarefasPage extends StatefulWidget {
  const TarefasPage({super.key});

  @override
  State<TarefasPage> createState() => _TarefasPageState();
}

class _TarefasPageState extends State<TarefasPage> {
  final List<Tarefa> _tarefas = [
    Tarefa('Comprar farinha', feita: true),
    Tarefa('Assar o bolo de cenoura'),
    Tarefa('Entregar a encomenda da Dona Rosa'),
  ];
  final _controller = TextEditingController();

  void _adicionar() {
    final texto = _controller.text.trim();
    if (texto.isEmpty) return;
    setState(() {
      _tarefas.add(Tarefa(texto));
    });
    _controller.clear();
  }

  @override
  void dispose() {
    _controller.dispose();
    super.dispose();
  }

  @override
  Widget build(BuildContext context) {
    final feitas = _tarefas.where((t) => t.feita).length;
    return Scaffold(
      appBar: AppBar(title: Text('Tarefas ($feitas/${_tarefas.length})')),
      body: Column(
        children: [
          Padding(
            padding: const EdgeInsets.all(16),
            child: Row(
              children: [
                Expanded(
                  child: TextField(
                    controller: _controller,
                    decoration: const InputDecoration(
                      labelText: 'Nova tarefa',
                      border: OutlineInputBorder(),
                    ),
                    onSubmitted: (_) => _adicionar(),
                  ),
                ),
                const SizedBox(width: 8),
                FilledButton(
                  onPressed: _adicionar,
                  child: const Text('Adicionar'),
                ),
              ],
            ),
          ),
          Expanded(
            child: ListView.builder(
              itemCount: _tarefas.length,
              itemBuilder: (context, index) {
                final tarefa = _tarefas[index];
                return Dismissible(
                  key: ObjectKey(tarefa),
                  background: Container(color: Colors.red.shade300),
                  onDismissed: (_) {
                    setState(() {
                      _tarefas.remove(tarefa);
                    });
                  },
                  child: CheckboxListTile(
                    value: tarefa.feita,
                    onChanged: (valor) {
                      setState(() {
                        tarefa.feita = valor ?? false;
                      });
                    },
                    controlAffinity: ListTileControlAffinity.leading,
                    title: Text(
                      tarefa.titulo,
                      style: TextStyle(
                        decoration:
                            tarefa.feita ? TextDecoration.lineThrough : null,
                      ),
                    ),
                  ),
                );
              },
            ),
          ),
        ],
      ),
    );
  }
}
class Tarefa { … final String titulo; bool feita; }
A classe de modelo. O título nunca muda (final); o feita muda quando a Ana marca a caixa. O {this.feita = false} é um parâmetro nomeado opcional: Tarefa('X') nasce não feita; Tarefa('X', feita: true) nasce feita.
final List<Tarefa> _tarefas
A lista agora guarda objetos Tarefa, e não textos.
final feitas = _tarefas.where((t) => t.feita).length;
Conta as tarefas feitas: o where filtra as que têm feita verdadeiro, e o length conta quantas sobraram. Como isso fica dentro do build, o número é recalculado a cada setState.
Text('Tarefas ($feitas/${_tarefas.length})')
O título da barra, com interpolação. Para uma expressão com ponto (_tarefas.length), o Dart pede as chaves: ${…}.
Dismissible(key: ObjectKey(tarefa), …)
Deixa a linha ser arrastada para o lado. A key é obrigatória e precisa identificar aquela tarefa: o ObjectKey usa o próprio objeto como identidade (veja Keys).
background: Container(color: Colors.red.shade300)
O fundo vermelho que aparece por trás enquanto a linha é arrastada.
onDismissed: (_) { setState(() { _tarefas.remove(tarefa); }); }
Quando a linha sai da tela, a tarefa sai da lista. Este passo não é opcional: o Dismissible só esconde a linha; quem apaga o dado é você.
CheckboxListTile(value: …, onChanged: …)
Uma linha de lista com caixa de seleção. value diz se a caixa está marcada; onChanged recebe o valor novo quando a pessoa toca. Esse valor é bool? (pode ser nulo), por isso o valor ?? false.
controlAffinity: ListTileControlAffinity.leading
Põe a caixa à esquerda do texto (o padrão é à direita).
decoration: tarefa.feita ? TextDecoration.lineThrough : null
O "risco" no meio do texto, só nas tarefas feitas (veja Estilos de Texto).

O título da barra já é calculado: Tarefas (1/3), porque só "Comprar farinha" nasceu com feita: true. Essa é a única linha com a caixa marcada e o texto riscado. Os círculos da versão 1 deram lugar às caixas quadradas do CheckboxListTile, à esquerda por causa do controlAffinity. O Dismissible não aparece na foto: ele só se mostra quando alguém arrasta uma linha, e aí surge o fundo vermelho por trás.

Missão: faça o app já abrir com duas tarefas feitas: marque também 'Assar o bolo de cenoura' com feita: true. O título da barra deve mudar para Tarefas (2/3). Depois, toque nas caixas e arraste uma linha para o lado.

Formas diferentes de fazer

Apagar: arrastar ou um botão de lixeira?

Em vez do Dismissible, dá para pôr um ícone de lixeira no fim da linha, com o secondary do CheckboxListTile:

CheckboxListTile(
  value: tarefa.feita,
  onChanged: (valor) => setState(() => tarefa.feita = valor ?? false),
  controlAffinity: ListTileControlAffinity.leading,
  title: Text(tarefa.titulo),
  secondary: IconButton(
    icon: const Icon(Icons.delete_outline),
    onPressed: () => setState(() => _tarefas.remove(tarefa)),
  ),
),

Qual usar: arrastar é rápido e comum em celular, mas ninguém descobre o gesto sozinho na primeira vez. O botão é visível e funciona igual no computador. Muitos apps usam os dois. Para não perder nada por engano, mostre um SnackBar com "Desfazer" depois de apagar (veja Diálogos e SnackBar).

Uma lista de Strings ou uma classe de modelo?

Também daria para guardar duas listas paralelas (List<String> titulos e List<bool> feitas). Funciona até o dia em que você apaga de uma e esquece da outra, e os riscos passam a cair nas tarefas erradas. Qual usar: quando um item tem mais de uma informação, crie uma classe. É assim que os apps maiores se organizam (veja Organizando um App Maior).

O que cada parte quer dizer:

EXCEPTION CAUGHT BY RENDERING LIBRARY
"Exceção capturada pela biblioteca de desenho": o erro aconteceu na hora de calcular tamanhos e posições, e não no seu código de lógica.
Vertical viewport was given unbounded height.
"A área de rolagem vertical recebeu uma altura sem limite." O ListView é uma área de rolagem (viewport) e quer ocupar toda a altura que receber. A Column, por sua vez, deixa cada filho ter a altura que quiser. Resultado: a lista pede "toda a altura possível" e ganha "infinito".
constraints: BoxConstraints(0.0<=w<=390.0, 0.0<=h<=Infinity)
A prova do problema: a largura vai até 390 (a tela do lab), mas a altura vai até Infinity, infinito.
size: MISSING
"Tamanho: faltando". Sem tamanho, a lista não pode ser desenhada.
Another exception was thrown: … RenderBox was not laid out
"Outra exceção: a caixa não foi posicionada." São consequências do primeiro erro, uma para cada peça acima da lista. Leia sempre o primeiro erro do bloco.

Na tela, o estrago é grande: como a coluna inteira não conseguiu se organizar, nem o campo nem o botão foram desenhados direito (só sobrou a borda de baixo do campo), e nenhuma tarefa apareceu.

Como resolver: diga à lista quanto de altura ela tem. O jeito mais comum é o Expanded (a lista fica com todo o resto da coluna), como na versão 2. Outra saída é um SizedBox(height: 300, child: ListView…), com altura fixa. A aula Como o Flutter Calcula Tamanhos explica o porquê em detalhe.

Resumo

  • A tela é um retrato da lista guardada no estado: adicionar, marcar e apagar é sempre mudar a lista dentro de setState.
  • ListView.builder com itemCount: lista.length acompanha o tamanho da lista sozinho.
  • TextEditingController lê e limpa o campo de texto; crie-o no estado e descarte-o no dispose.
  • Dentro de Row e Column, TextField e ListView precisam de um tamanho: use Expanded.
  • Quando um item tem mais de uma informação, crie uma classe de modelo (Tarefa).
  • CheckboxListTile marca; Dismissible (com uma key única) apaga arrastando, mas é você quem remove o item da lista no onDismissed.
