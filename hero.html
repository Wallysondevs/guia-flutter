Flutter Hero

Você toca na foto de um produto numa loja on-line e a foto, em vez de sumir, voa e cresce até virar a foto grande da tela de detalhes. Na volta, ela encolhe e pousa de novo no lugar dela na lista. Esse efeito tem nome no Flutter: animação Hero ("herói"), e é uma das mais fáceis de fazer. Basta embrulhar o elemento nas duas telas com um Hero e dar a eles o mesmo nome.

Você vai aprender
  • Como o Hero liga um widget de uma tela a um widget de outra pela tag.
  • A fazer o ícone de uma receita voar da lista para a tela de detalhes (e voltar).
  • Por que cada tag tem de ser única dentro de uma tela.
  • O erro real das tags repetidas, linha por linha.
Sobre as fotos desta aula

As fotos do laboratório mostram as duas pontas do voo: a lista (antes do toque) e a tela de detalhes (depois). O voo em si, só no Experimente.

A ideia: o mesmo ator em dois cenários

No teatro, um ator sai de um cenário e entra no outro. A plateia entende que é a mesma pessoa, porque ela tem o mesmo rosto. O Flutter faz isso com widgets: na hora de trocar de tela (veja Navigator), ele procura, na tela que sai e na que entra, os Hero que têm a mesma tag (a mesma "etiqueta"). Para cada par, ele tira o widget da tela velha e o faz voar, mudando de tamanho e de lugar, até a posição do par na tela nova.

Tela da lista                      Tela de detalhe
ListTile                           Column
 └─ Hero(tag: 'Bolo de cenoura')    └─ Hero(tag: 'Bolo de cenoura')
     └─ Icon(size: 40)   ──voa──▶       └─ Icon(size: 200)

1. A lista de receitas que voa

import 'package:flutter/material.dart';

void main() => runApp(const MaterialApp(
      debugShowCheckedModeBanner: false,
      home: TelaLista(),
    ));

class Receita {
  final String nome;
  final IconData icone;
  final Color cor;
  const Receita(this.nome, this.icone, this.cor);
}

const receitas = [
  Receita('Bolo de cenoura', Icons.cake, Colors.orange),
  Receita('Café coado', Icons.coffee, Colors.brown),
  Receita('Pizza da Ana', Icons.local_pizza, Colors.red),
];

class TelaLista extends StatelessWidget {
  const TelaLista({super.key});

  @override
  Widget build(BuildContext context) {
    return Scaffold(
      appBar: AppBar(title: const Text('Receitas')),
      body: ListView(
        children: [
          for (final r in receitas)
            ListTile(
              leading: Hero(
                tag: r.nome,
                child: Icon(r.icone, color: r.cor, size: 40),
              ),
              title: Text(r.nome),
              onTap: () => Navigator.push(
                context,
                MaterialPageRoute(builder: (context) => TelaDetalhe(receita: r)),
              ),
            ),
        ],
      ),
    );
  }
}

class TelaDetalhe extends StatelessWidget {
  const TelaDetalhe({super.key, required this.receita});

  final Receita receita;

  @override
  Widget build(BuildContext context) {
    return Scaffold(
      appBar: AppBar(title: Text(receita.nome)),
      body: Column(
        children: [
          const SizedBox(height: 32),
          Center(
            child: Hero(
              tag: receita.nome,
              child: Icon(receita.icone, color: receita.cor, size: 200),
            ),
          ),
          const Padding(
            padding: EdgeInsets.all(24),
            child: Text('Modo de preparo: misture tudo, asse e sirva.'),
          ),
        ],
      ),
    );
  }
}
Hero(tag: r.nome, child: Icon(…, size: 40))
Na lista, o ícone pequeno de cada receita vai dentro de um Hero. A tag é o nome da receita: cada linha tem uma tag diferente.
onTap: () => Navigator.push(…)
O toque abre a tela de detalhe, passando a receita (veja Passando Dados entre Telas). É essa troca de tela que dispara o voo: o Hero não faz nada sozinho.
Hero(tag: receita.nome, child: Icon(…, size: 200))
Na tela de detalhe, o mesmo ícone, grande, com a mesma tag. É assim que o Flutter sabe que os dois são o "mesmo ator".
tag
Pode ser qualquer objeto (texto, número, o id do produto), desde que seja igual nas duas telas e único em cada uma.
Antes: a listaDepois do toque em "Bolo de cenoura"

Entre as duas fotos, durante a transição de tela (uma fração de segundo), o bolo laranja sai do canto da linha, cresce e para no meio da tela nova. Ao voltar (a seta da AppBar), o voo acontece ao contrário, sem uma linha a mais de código.

Missão: neste código, só a lista tem Hero. Rode e toque numa receita: a tela troca, mas o ícone não voa. Na TelaDetalhe, embrulhe o ícone grande num Hero com tag: receita.nome e rode de novo. Toque na seta de voltar para ver o voo de volta.

2. Detalhes que ajudam

  • Os dois filhos devem ser parecidos. O Flutter anima o tamanho e a posição, não troca um desenho por outro. Se na lista é um ícone e no detalhe é uma foto, o voo mostra o filho da tela nova esticado no caminho.
  • Texto dentro de Hero pode aparecer com sublinhado amarelo durante o voo (ele voa fora do Scaffold, sem o estilo de texto do tema). Embrulhe o texto num Material(type: MaterialType.transparency, child: …).
  • Imagens: é o uso mais comum (a foto do produto). Funciona igual com Image.network e Image.asset (veja Imagens).
  • Para mudar o caminho do voo (em arco em vez de linha reta) existe o parâmetro createRectTween, para quem quiser se aprofundar.

Quando dá errado

A mesma tag em várias linhas

A Ana deu a mesma tag para todas as linhas da lista: Hero(tag: 'receita', …). O app abre normal, mas, ao tocar em "Bolo de cenoura", o console mostra:

══╡ EXCEPTION CAUGHT BY SCHEDULER LIBRARY ╞═════════════════════════════════════════════════════════
The following assertion was thrown during a scheduler callback:
There are multiple heroes that share the same tag within a subtree.
Within each subtree for which heroes are to be animated (i.e. a PageRoute subtree), each Hero must
have a unique non-null tag.
In this case, multiple heroes had the following tag: receita
├# Here is the subtree for one of the offending heroes: Hero
…
EXCEPTION CAUGHT BY SCHEDULER LIBRARY
O erro veio do "agendador", a parte do Flutter que roda as coisas de cada quadro, como as animações de troca de tela.
There are multiple heroes that share the same tag within a subtree
"Há vários heróis com a mesma tag na mesma subárvore" (na mesma tela).
each Hero must have a unique non-null tag
"Cada Hero precisa de uma tag única e não nula" dentro de cada PageRoute (cada tela do Navigator).
multiple heroes had the following tag: receita
A tag repetida: receita. É a pista para achar o erro no código.

A tela de detalhe ainda abre (no lab, ela apareceu igual à da segunda foto), mas sem voo. Com 3 linhas, o Flutter não tem como saber qual dos 3 bolos deve voar. Como consertar: uma tag diferente por linha, ligada ao dado: tag: r.nome (ou o id do produto).

Tags diferentes nas duas telas: não voa, e não avisa

Se a lista usa tag: r.nome e o detalhe usa tag: 'detalhe-${receita.nome}', cada Hero fica sem par. Não há erro: a tela troca do jeito normal, como se não houvesse Hero. Como consertar: confira se a expressão da tag dá exatamente o mesmo valor dos dois lados.

Referência rápida

EscritaO que faz
Hero(tag: x, child: …)Marca o widget para voar até o Hero de mesma tag na outra tela
tagQualquer objeto; igual nas duas telas, único em cada uma
Navigator.push / popA troca de tela que dispara o voo (ida e volta)
Material(type: MaterialType.transparency, child: Text(…))Evita o sublinhado amarelo em texto que voa

Resumo

  • Hero(tag: …, child: …) nas duas telas, com a mesma tag, faz o widget voar na troca de tela, na ida e na volta.
  • A tag pode ser qualquer objeto (o nome, o id); ela tem de ser única dentro de cada tela.
  • O voo anima tamanho e posição; os filhos dos dois lados devem ser parecidos.
  • Tags repetidas na mesma tela dão o erro There are multiple heroes that share the same tag within a subtree.
